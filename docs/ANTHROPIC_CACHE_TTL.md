# Anthropic 缓存 TTL

管理员在「设置 → 网关 → Claude 缓存」卡片的「缓存时长（跟随全局的密钥）」一行选择默认 TTL：`5m`（默认）或 `1h`。这一行与「自动补缓存」共用卡片和保存按钮，保存只提交改动过的项，只改时长不会重新校验分组；「请求转发行为」卡片不再提交该设置（2026-10-31 起）。用户在 API 密钥创建、编辑弹窗中选择自己的偏好。设置只影响当前已有构造器支持、且实际转给 Claude 的 Anthropic Messages 请求：原生 Messages、现有 Chat/Responses → Anthropic 转换、API Key 透传、OAuth/SetupToken，以及现有 Vertex 原生/转换路径。Bedrock 本轮仅覆盖原生 Messages（Bearer/SigV4）；Chat/Responses → Bedrock 没有对应转换构造器或 eventstream 解码器，不在本变更范围。该组合目前可能返回既有上游认证或通用转发错误，并非显式 unsupported 响应；新增 Bedrock 转换留待后续。

TTL 选项调整已有缓存声明的有效期；[自动补缓存](CLAUDE_CACHE_FALLBACK.md) 按既有分组授权补断点；账号「缓存写入计费分类覆盖」只调整结算分类。三者各自配置，不会互相开启。

## API 密钥偏好

| `anthropic_cache_ttl_mode` | 界面 | 行为 |
|---|---|---|
| `inherit` | 跟随全局（显示当前默认） | 接纳请求时读取一次管理员默认 |
| `off` | 不覆写 TTL（保留客户端设置） | TTL 处理本身不增删、改写缓存声明 |
| `5m` | 强制 5 分钟缓存 | 已有合法 ephemeral 声明统一为 5m |
| `1h` | 强制 1 小时缓存 | 已有合法 ephemeral 声明统一为 1h |

`off` 不表示关闭供应商缓存，也不关闭分组补断点或 OAuth 既有断点。无断点且没有其他注入路径时，选择 1h 不会创建缓存。切换偏好不会清除已经存在的上游缓存。模型最小缓存长度、前缀一致性、请求间隔和供应商实现仍会影响命中。

表单仅在 Claude、TypeSafe、组合分组，以及平台清单明确包含 Claude → Anthropic 路由的多协议分组显示；其他分组隐藏选项，切组保留偏好。混合分组中只对实际 Claude 请求生效，不根据分组名或单纯的 Anthropic 兼容端点猜测模型供应商。Key 列表在适用分组的名称下显示偏好，不增加管理页面。

Key 创建接口省略该字段采用 `inherit`；更新接口省略保持原值。显式空字符串和非法枚举返回 400。Key 列表保留原分页字段，新增 `meta.anthropic_cache_ttl_default: "5m" | "1h"`，只公开此默认值，不公开管理端设置。管理员设置字段为 `anthropic_cache_ttl_default`，仅接受 `5m/1h`。

修改 Key 后沿用现有鉴权缓存失效机制。全局设置保存后更新本实例，其他实例按既有设置缓存刷新。已接纳请求及其重试使用冻结快照，之后的新请求才使用新值。

## 最终请求与供应商边界

协议转换、模型映射、正文整理、分组 system 提示词及既有补断点先执行，再统一 TTL、执行供应商能力清理，最后构造和签名 HTTP 请求。适用性取决于实际账号、映射后模型和出站协议；Anthropic 兼容接口承载 Kimi、DeepSeek、GLM 等模型时不应用 Claude TTL。

只访问顶层、tools、system 和 messages 内容块的协议字段，不递归改工具 schema、工具入参或用户数据。保留合法声明的类型、其他属性、内容和断点位置。缓存变换只属于当前尝试，不回写跨尝试的共享正文；同号重试、换号及兜底组重新判定实际出口。

顶层 automatic 与显式断点共同占最多四个槽位。空间不足时不新增断点，不任意删除合法客户端声明；顶层和末块 TTL 冲突等剩余非法组合沿现有错误路径返回。强制项先统一 TTL，`off` 保留合法混合 TTL，既有长 TTL 位于短 TTL 之前的顺序保护继续适用。官方的 20 块 lookback 意味着移动断点不等于必然破坏前缀命中。

thinking、redacted_thinking、空文本和延迟加载工具不能新增缓存标记。旧 Bedrock integration 不支持顶层 automatic；模型支持 1h 不等于 integration 支持所有声明。能力清理后的字段不会在签名前补回。`/messages/count_tokens` 不运行 TTL 覆写或补断点，不创建、刷新缓存，也不承诺已应用 TTL。转到其他供应商的请求不应用 Claude TTL。

## 用量、计费与预留

供应商的 `cache_creation.ephemeral_5m_input_tokens`、`ephemeral_1h_input_tokens` 及字段是否出现，贯穿原生请求及现有 Anthropic/Vertex Chat/Responses 转换的流式与非流式内部用量；Bedrock 仅覆盖原生 Messages。后续事件省略字段保留先前值，显式 0 清零；累计事件不相加。总创建字段省略时内部可由明确子桶合计；明确 0 仍为 0，不反写供应商响应。OpenAI 标准响应不添加非标准 TTL 字段。

请求 1h 不证明供应商实际写了 1h，缺失明细不会按 Key 偏好填桶。设总创建量为 C、5m 为 A、1h 为 B：

| 供应商报告 | 结算 |
|---|---|
| A+B=C | 分别按本站报价计费 |
| 全部 TTL 明细缺失 | 未知部分按基础缓存写入价（5m 档）计费 |
| 0<A+B<C | 已知桶按各自价格，差额按基础写入价补齐；不伪造原始 5m 桶 |
| A+B>C>0 | 按现有确定性分配规则以 C 封顶，并记录不一致 |
| C 明确为 0、A+B>0 | 创建总量按 0 封顶并记录不一致；不把明确 0 当省略 |

不追补历史收费。渠道显式价格、用户/分组倍率、账号统计价格和长上下文规则继续生效；渠道只配置一个缓存写价时两 TTL 同价。1h 写入通常更贵，实际价格以本站已解析报价为准，不硬编码通用读取折扣。Sonnet 5.5 官方回退读取价为 $0.10/MTok；管理员显式报价不自动修改。

账号字段 `cache_ttl_override_enabled/target` 保留独立权限，界面称「缓存写入计费分类覆盖」。与 ForceCacheBilling 一样，只改结算副本，不再将计费桶反写上游响应；`cache_ttl_overridden` 标记「计费调整」。这些调整后的桶不能作为真实缓存效率。旧全局 TTL 注入隐式按 5m 结算的联动已移除。

余额预留按实际可能的冷写风险区分无风险、5m、1h，包括客户端声明和既有注入路径。存在风险时取本站对应 TTL 写价与普通输入价较高者，复用候选模型/账号映射上界，并禁用历史命中比例折扣。没有断点也不存在注入路径时，不因选择 1h 无条件提高预留。预留不是扣款，最终仍按供应商用量及显式商业计费规则结算。

## 观测

现有用户与管理员用量接口增加两个可空字段：

| 字段 | 含义 |
|---|---|
| `anthropic_cache_ttl_policy` | 最终结算尝试适用的冻结策略 `off/5m/1h`；历史与非目标出口为 NULL |
| `anthropic_cache_ttl_applied` | 最终能力清理后，至少一个合法 ephemeral 声明且全部符合指定 5m/1h 时为 true，原值已相同也算；off、无断点或未满足为 false；历史与非目标为 NULL |

使用记录页面（用户与管理员）不显示这两个字段：0.4.15 曾在列表和 Token 详情显示「TTL 策略 · 已应用/未应用」，升级前创建的 Key 为 off，几乎每行都是「不覆写 TTL · 未应用」，没有排障价值，2026-10-31 按用户要求移除。接口仍原样返回两个字段，NULL 表示未记录，不等于未应用。供应商 TTL 明细缺失或部分缺失时，Token 详情仍显示相应计费提示。「已应用」仅描述最终请求，不证明供应商采用 TTL 或缓存命中；不从读取 Token 反推 TTL，也不继承失败尝试的观测。

诊断复用现有缓存/结算结构化事件，记录策略来源、最终策略和应用结果、供应商 aggregate/raw5m/raw1h、缺失/不一致及计费覆盖，避免记录正文或凭据；具体事件以实现所在服务的既有日志入口为准。账单桶可能经商业覆盖，两列策略并非完整财务账本。上线观察应排除覆盖影响，按模型/账号/入口/策略比较读取占比、创建费用、TTL 明细完整率、长上下文 TTFT 与端到端首输出。

## 迁移与回退

新增迁移 `286_anthropic_cache_ttl.sql`；既有 332 项 SQL/checksum 保持不变，只追加一项。`api_keys.anthropic_cache_ttl_mode` 先以 `off` 加列以保留存量 Key 的客户端选择，再在同一迁移事务中将新行默认改为 `inherit`，并增加四态约束。全局默认 5m，旧 Key 编辑时仍保留 off，用户可主动更改。

usage 只加上述两个可空列，不回填、不加索引。PostgreSQL 的 ALTER 需要表锁，新增 Key 约束可能扫描存量行；按实际版本、表规模和长事务情况预留低峰窗口，不能以无回填等同于无锁。

升级前检查旧版全局 1h 注入、消息断点重写及 OAuth 计费补贴是否启用。旧设置退出运行路径，不保留常驻双轨逻辑。旧消息重写曾先清理再重建 messages 断点，现在正式退役；这属于有意的声明优先行为变更，不自动开启任何分组补断点，也不把旧 true 映射为新全局启用。依赖旧策略的部署须先明确接受断点变化，配置现有分组补断点；需要保留补贴时转为已有账号的显式计费分类覆盖，保留已配置的覆盖值。

旧二进制可忽略新增列，但不执行新 TTL 语义；回退前停用新偏好入口并明确恢复旧全局策略，不能声称行为等价。不删除新列、不回算历史账单。部署流程见 [部署说明](../deploy/README.md#anthropic-缓存-ttl-升级与回退)。真实供应商 TTL 与命中仍需在获授权的环境验证，本地受控上游不能证明所有中转能力。
