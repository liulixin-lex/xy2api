# 分组分类

分组分类用于在管理端整理数量较多的分组。一个分组可以加入多个分类，也可以不加入分类；分类名称、顺序和成员关系由管理员维护。

分类是独立的后台元数据，保存在 `group_categories` 和 `group_category_members` 两张表中。它不写入 `groups`，不参与请求路由、调度、计费或用户端响应，也不进入 API Key 鉴权快照。分类写入不会触发调度重建或鉴权缓存失效；`/api/v1/groups/available` 和现有分组 DTO 保持不变。

## 管理与选择

管理员可以新增、改名、拖动排序和删除分类。管理弹窗中的“保存”一次提交全部改动，“取消”会放弃未保存的改动。删除仍有分组的分类时，保存前会要求确认；删除只移除分类关系，不删除分组。分组列表显示分类列，并可以按分类筛选；分类列可通过列设置隐藏。

创建或编辑分组时可以勾选多个分类。复制分组会复制其分类。分组保存成功后再保存分类关系；如果第二步失败，页面会提示分组已保存、分类未保存，不会把已创建的分组报告为创建失败。

账号的分组选择器可按分类切换显示。只有包含当前账号可选分组的分类才显示为标签；点击当前标签会回到全部分组，不单独提供“全部”标签。方向键及 Home/End 只移动标签焦点，Enter/Space 切换筛选。分类筛选只改变可见列表，不会清除其他分类下已经勾选的分组。创建账号、编辑账号、批量编辑账号和账号列表的分组弹窗启用分类标签，公告定向编辑器不启用。未启用分类标签或没有分类时，分组选择器保持原有显示方式。

账号列表的分组单元格最多显示三个分组徽章，点击单元格会打开居中的宽版弹窗，分组列表最高占屏幕高度的 60%，分组名完整显示。弹窗加载账号详情以保留原有分组顺序，也显示并保留已绑定但停用的分组。取消不保存；确认时只提交 `group_ids`，新选的分组追加在原有分组之后。混合渠道冲突会先请求确认；其他保存错误会让弹窗保持打开。账号列表分类筛选与分组筛选同时生效，已选分类被删除后会回到“全部分类”。

简单模式不显示任何分类界面，但分类和成员关系会保留；接口和数据可以继续使用。调度评分池不跟随账号分类筛选，和 IQ 状态筛选的行为一致。

分类名称最多 32 个字符，最多 50 个分类，名称按不区分大小写的方式去重。分类名称只是后台标签：“专属分组”这个分类名不会改变分组的 `is_exclusive`；分组的公开或专属权限仍由现有“专属”设置决定。

## 管理接口与筛选

以下路径均以 `/api/v1/admin` 为前缀：

| 方法与路径 | 用途 |
|---|---|
| `GET /group-categories` | 获取分类及每个分类的分组 ID |
| `PUT /group-categories` | 按 `items` 顺序新增、改名和排序；只删除 `deleted_ids` 中的分类 |
| `PUT /group-categories/groups/:group_id` | 用 `category_ids` 替换一个分组的分类；不存在的分类 ID 会忽略 |

分类筛选参数 `group_category=<id>` 可用于以下账号和分组列表路径：

| 方法与路径 | 说明 |
|---|---|
| `GET /groups` | 筛选分组列表 |
| `GET /accounts` | 筛选账号列表 |
| `GET /accounts/upstream-billing-rates` | 让上游计费列跟随账号列表筛选 |
| `GET /accounts/data` | 让账号数据导出跟随分类筛选 |
| `POST /accounts/bulk-update` | 在 `filters.group_category` 中指定分类，批量操作只选中匹配账号 |

账号匹配条件是账号绑定的任一未删除分组属于所选分类；再与其他账号筛选条件合并。空参数表示不筛选，非法值返回 `400 INVALID_GROUP_CATEGORY_FILTER`，有效但不存在的分类 ID 返回空列表。调度评分池不使用该筛选。

接口错误码如下（分类名称先去掉首尾空白）：

| 错误码 | HTTP 状态 | 条件 |
|---|---|---|
| `GROUP_CATEGORY_NAME_INVALID` | 400 | 名称为空、超过 32 个字符、含控制字符或不是合法 UTF-8 |
| `GROUP_CATEGORY_NAME_DUPLICATE` | 409 | 保存后的分类名称不区分大小写重复（含并发保留项） |
| `GROUP_CATEGORY_LIMIT` | 400 | 保存后的分类总数超过 50（含并发保留项） |
| `GROUP_CATEGORY_IDS_INVALID` | 400 | 成员或删除 ID 非正数或数量超过 50；保存项 ID 为负数或重复 |
| `INVALID_GROUP_CATEGORY_FILTER` | 400 | 非空筛选值无法解析为正的 64 位整数 |
| `GROUP_NOT_FOUND` | 404 | 成员关系接口的分组不存在或已软删除（路径 ID 格式非法或非正数由处理器返回 400） |

## 并发与删除

分类列表保存在数据库表锁下串行执行。名称去重与 50 个分类上限在锁内检查；一次保存中允许交换分类名称。请求未列出、也未列入 `deleted_ids` 的并发新增分类会保留，并排在本次提交的分类之后。改名和排序按最后一次保存生效，只有明确列入 `deleted_ids` 的分类会删除。

同一分组的分类关系替换会在分组行锁下串行执行。保存时不存在的分类 ID 会忽略；若分组不存在或已软删除，则返回 404。删除分类由外键级联移除其成员关系。分组软删除时保留成员行，查询分类成员和账号筛选时跳过已软删除分组；硬删除分组时由外键级联清理成员行。
