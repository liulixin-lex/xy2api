# OpenAI 智商检测

## 本地新增：检测排期与故障恢复

检测设置使用与账号编辑其他区域一致的下拉框，支持搜索和自定义模型；“同步上游支持的模型”只更新可选列表并保留当前选择。思考深度显示中文档位，预算、超时、回答格式及共享配额组收在“高级设置”中。检测记录优先展示状态、答案、模型、深度和耗时，原始回答和诊断默认折叠。保留数量已由两轮改为三轮，已有记录不补造；更新后第四轮开始时清理最早一轮，无需数据库迁移。

编辑账号可设置固定／节约模式、最大间隔、每日请求预算（UTC）和30～300秒总超时。旧账号默认固定间隔、120秒；未显式保存预算时使用 `ceil(1440 / 基础间隔)`，15分钟为96次。保存过的预算独立于间隔。批量编辑只改勾选字段。

节约模式连续3次聪明后使用2倍间隔，连续6次后使用4倍间隔，受所设最大间隔限制；单次回答的判分和调度限制立即生效。基础15分钟、最大60分钟时，稳定阶段理论每天96次降为24次，最长排期等待也从15分钟变为60分钟，另加扫描、排队与请求耗时。

任务先排队，取得账号真实并发名额、通过账号和共享组预算检查后才创建一轮记录。账号忙、人工停用、本地健康冷却、预算不足时显示延期，保留上一评分，不占用三轮记录名额。已提交开始事务的请求即使进程退出、无法确认是否送达，也保守计为一次尝试；计数不是上游计费凭证。

手动“立即检测”合并同账号待执行任务，仍遵守最小间隔、UTC日预算及上游 `Retry-After`。暂停后处理原因，再用该入口恢复排队；开关、模型修改和重新排队不清零预算或已知上游冷却。关闭蓝色开关仍立即解除检测自身的调度限制。

明确额度不足、认证／权限失败、模型或参数不支持会暂停自动检测。临时网络错误和5xx退避至基础间隔的1／2／4倍，最长不少于基础间隔且通常为60分钟；同配置连续3次协议错误暂停。真实失败仍记未知并解除检测自身限制，尚未发送的延期不改评分。合法 `Retry-After` 是不得提前发送的下限；超大等待值暂停并保留阻止再次发送的状态。

列表保留开关、评分和必要的状态图标，点击评分进入检测记录。执行状态、延期原因、最近检测、下次可执行、连续等待次数和当日剩余预算集中在检测记录中；打开后自动刷新，关闭后停止请求。过期不是新评分，不会自动将降智变成未知。记录可下载最近三轮诊断，包含配置、时间和有界错误码／用量，不含凭据、原始上游错误消息、业务对话或推理正文。模型返回的名称仅为上游声明。

繁忙调度按空余名额判断，不再要求业务并发为零。有空闲名额就立即在原上限内竞争，不再额外预留一个名额或要求先延期三次。短暂满载时在本次任务内等待250/500/1000毫秒后重试，最多四次原子获取；获得名额就直接检测，持续满载才记录一次延期。繁忙重试间隔为15～30秒，另加扫描等待。Redis故障显示“并发服务暂不可用”，不再误记为账号繁忙。满载时仍必须等待，不能保证固定时间内检测；等待不消耗检测预算或历史记录。源码规范与生产只读审计限制见 `openspec/changes/iq-detection-operations/`。

部署配置（所有副本应一致，变更后重启服务）：

```bash
IQ_CHECK_MAX_CONCURRENCY=2
IQ_CHECK_QUOTA_GROUPS='{"project-a":{"daily_limit":96,"min_interval_seconds":60}}'
```

并发可设1～10。共享组仅按管理员明确填写的真实配额关系使用，不从域名推断；未配置的组延期。组的冷却和当前UTC日计数持久化于追加迁移243，账号计数保存在原 `iq_check` JSON；不会积累对话历史。配置的配额值是本项目限制，不代表上游官方限额；上游另有RPM/TPM限制时仍须遵循其规则与返回的冷却。

普通API key探测标识为 `XY2API-IQ-Monitor/1`，禁用自动HTTP重定向；OAuth保留现有认证协议及插件传输。核心每轮发起一次应用层调用，未实现重复作答重试；插件内部尝试数无法由本协议核实，在诊断中显示 `plugin_attempts_unknown`。`store:false` 不表示关闭上游监控。本次优化不提供用户行为伪装或规避反滥用检测，也不承诺能消除服务方误分类。

升级前备份数据库，并停止旧版本检测工作进程后统一升级所有副本，避免旧版本写回 JSON 时丢失新预算字段。243仅追加表并替换批量配置函数，不改历史迁移。源码回滚工具不会回滚数据库。真实账号验收、提交、发版和生产部署需另行执行。

账号列表中，“调度”之后的蓝色开关启用糖果题检测。仅 OpenAI 账号可用；新建、复制和导入账号默认关闭。检测间隔为 1～1440 分钟，默认 15 分钟。

## 检测配置

编辑账号时，检测区域依次显示间隔、模型、思考深度。模型默认为 `gpt-6-astra`，思考深度默认为 `low`。可直接输入完整模型 ID，也可点击“拉取模型”，从该账号上游返回的目录中选择。请求使用输入的原始模型 ID，不经过账号模型映射，不自动换模型或重试。

目录读取不会修改账号白名单、分组、检测状态或模型元数据；OAuth 正常令牌刷新沿用现有流程。缓存有效期为 5 分钟，手动再次拉取刷新目录。失败时允许继续自定义；旧目录明确标记过期。目录中的模型来源与能力来源分开显示：上游仅返回 ID 时，不能推断它支持某种思考深度。Astra 的参考深度仅作参考，不代表该账号调用已验证。上游明确不支持的深度在表单阻止保存；能力未知时允许输入自定义值。

`upstream_default` 表示不发送思考深度参数；`none` 表示显式发送 `none`，两者不同。每轮记录任务领取时的模型、深度、协议和格式设置，另外展示上游报告的模型名称；项目无法验证第三方是否真正执行了所声明的模型。

默认兼容模式在两个协议中都请求简洁 `{"answer":整数}`。严格模式另外请求 JSON Schema：Responses 使用 `text.format`，Chat Completions 使用 `response_format.json_schema`。标准答案不写入提示或 Schema。上游不支持模型、参数或 Schema 时记为未知，不隐式回退；未遵循格式但答案明确时照常判分，并记录格式不合规。

批量编辑仅修改勾选字段，未勾选的字段保留各账号原值。只修改检测间隔不会重置智商状态或使正在执行的任务失效；修改模型、深度、输出约束、凭据、连接地址、协议、请求头或代理/TLS 配置时，检测重置为未知并重新排队。正常令牌轮换不使任务失效。复制和导入可以保留配置，但强制关闭检测、状态未知，不带历史和限制。

## 判定与恢复

每次会话独立，发送 `store:false`，不携带历史、会话 ID 或 `previous_response_id`。推理和 commentary 内容不参与判分。

| 完整最终回答 | 结果 |
| --- | --- |
| `{"answer":21}`、纯数字 `21`、明确结论为 21 的解释文字 | 聪明 |
| 明确最终答案为 29 或其他数值 | 降智 |
| 含糊、冲突、拒答、无法提取答案、重复 JSON 字段或无效结构 | 未知 |
| 网络、鉴权、额度、模型不支持、协议错误、响应不完整或超出限制 | 未知 |

数值按精确值比较，例如 `21.0000000000000001` 不等于 21。文本解析识别明确结论、更正、否定和反例；未识别到可靠最终答案时返回未知。它是这道糖果题的检测，不能由单题推出模型所有能力。

仅“开启且降智”阻止后续请求分配。聪明、未知或关闭检测都解除检测自身限制，不修改人工状态、调度开关或其他健康、过期及配额限制。**想继续使用被检测停用的账号，关闭该账号的蓝色智商检测开关**；原有规则允许时即可恢复。已开始的业务请求不被中断。

## 后台任务和记录

后台每15秒扫描一次，数据库租约按全局配置限制并发，默认2、可设1～10。单轮超时默认120秒、可设30～300秒，租约为超时加60秒。降智账号在预算及其他健康规则允许时继续检测。周期按完成时间加间隔，并加 0～`min(30秒,间隔×5%)` 的抖动；首次开启和手动运行不加抖动。失效的旧任务不能覆盖新配置；已开始的旧租约保留到完成或过期以避免重叠检测；同一 token 尚未开始、但已禁用或配置修订已失效的预留，在 StartIQCheck 事务内释放，启用时按当前配置重新排队，拒绝启动不扣预算、不增加记录。已开始的过期任务记为中断、状态未知，释放检测限制并通知调度缓存；仅领取而未开始的过期任务保留原评分并重新排队。

每账号最多保存三轮，包含运行中、失败、取消和中断轮次；第四轮开始时在同一事务删除最早一轮。记录展示提取答案、判定原因、实际模型/深度、协议、格式、版本及耗时，原始回答可展开。旧记录保留 `candy-grader-v1` 原义，不倒推或改写历史判分。新记录为 `candy-v2` / `candy-grader-v2`。

响应读取上限为 256 KiB，保存回答上限为 64 KiB；不保存凭据和推理内容，不在通用日志重复保存正文。删除账号清理记录。三轮清理仅保证本项目数据，`store:false` 不控制第三方自身保留政策。

启动事务会在账号行锁内再次核查过载、限流、临时不可调度冷却及业务额度，防止领取任务后健康或额度变化被忽略；等待期间不扣检测预算、不新增记录。所有延期保留已知最晚约束，短冷却按实际时间到期，不放大到一分钟。批量更新同步清零配置重置时的繁忙计数，追加迁移244替换函数，保留旧迁移。记录弹窗只在打开时加载和挂载，关闭时清理轮询，减少账号列表首屏负担。

## 管理员接口

- `PUT /api/v1/admin/accounts/:id/iq-check`：部分更新，例如 `{"model":"my-model","reasoning_effort":"upstream_default","output_mode":"compat"}`；省略字段保留原值。
- `GET /api/v1/admin/accounts/:id/iq-check`：管理员只读检测状态，不返回凭据或租约令牌；包含连续繁忙延期次数 `busy_deferrals`。
- `GET /api/v1/admin/accounts/:id/iq-check/models?refresh=true`：只读上游目录，返回模型列表、能力来源、拉取时间、缓存/过期标志和错误代码。
- `POST /api/v1/admin/accounts/:id/iq-check/run`：立即排队；已有任务时复用，关闭检测时拒绝。
- `GET /api/v1/admin/accounts/:id/iq-check/results`：最近三轮记录。
- `GET /api/v1/admin/accounts/:id/iq-check/diagnostics`：下载最近三轮脱敏诊断JSON，不含原始回答或账号身份。
- 创建、编辑及批量编辑支持 `iq_check` 部分设置；详情和精简列表返回摘要。
- 列表支持 `iq_status=smart|degraded|unknown`，在数据库分页前过滤；省略时为全部。

- 账号检测可分别配置模型和思考深度，默认 `gpt-6-astra` / `low`；支持只读拉取上游模型、直接输入模型及 `upstream_default`。
- Responses 和 Chat 均请求简洁 JSON，可选严格 Schema。明确答案为 21 即通过，解释文字不影响判定；明确其他数值为降智。

- 记录统一展示提取答案，原始回答可展开；每个账号仍仅保留最近三轮。批量只更新选中字段。
- 数据库追加迁移 241；不改写旧迁移、旧记录与人工调度开关。

## 响应兼容与诊断（本地改进，尚未发版）

检测响应分为传输、格式识别、事件解码和答案判分。Responses 辅助事件不再要求符合完整 Response 对象；仅成功终态中的助手最终内容可以参与判分。关键字段重复、冲突终态、流内错误、缺少完成事件仍为未知。不会从推理或中间增量中的21提前判聪明。

响应头为空、笼统或与可识别 JSON/SSE 正文不一致时，进行有界格式识别并记录兼容处理；HTML等内容拒绝判分。正文上限256KiB、单事件128KiB、事件数4096、解压后同样有上限，总请求超时使用该账号设置（默认120秒）。gzip、deflate、br和zstd覆盖传输已解压和插件未解压响应。

检测记录增加可展开的诊断详情，包括阶段、原因代码、HTTP状态、媒体类型、协议、事件序号/类型、字段位置、字节数和解析器版本。字段均有长度上限，总JSON最多4KiB，不保存原始错误、推理、认证令牌或响应正文；随最近三轮记录同时清理。旧记录没有诊断字段时正常显示。

迁移242只追加可空diagnostic及大小约束，不修改240/241。旧程序可忽略新列；回滚源码或二进制不删除检测历史，也不是数据库降级操作。运行中关闭检测/更换配置仍丢弃旧结果，人工和额度限制保持有效。

本轮包含合成完整OAuth事件流和服务级测试；未取得生产失败原始流，不能将合成fixture宣称为生产根因已修复。部署验收需获授权后回放脱敏实际失败样本，再观察真实账号，明确区分协议解析成功与答案聪明。

部署版本以实际二进制-version/commit/hash为准；采用容器内自动更新时，镜像标签可能仍是旧版本。建议下一次正式部署固定对应发布镜像digest，或同时保留更新前二进制与升级记录，避免容器重建回退。此项为运维说明，本次不改变自动更新机制。
