# OpenAI 智商检测

账号列表中，“调度”之后的蓝色开关启用糖果题检测。仅 OpenAI 账号可用；新建、复制和导入账号默认关闭。编辑弹窗可设置 1～1440 分钟的间隔，默认 15 分钟。批量编辑支持同样设置；列表可以在数据库分页前按聪明、降智或未知筛选。

每次独立发送同一道糖果题，固定模型 `gpt-6-astra`、推理强度 `low`、`store:false`，不携带历史或会话 ID。提示要求简洁 JSON 对象，唯一字段为整数 `answer`；提示中不提供标准答案。兼容纯数字及带有明确最终结论的解释文字。最终答案为 21 时标记聪明，完整非空的其他回答标记降智；网络、认证、额度、模型不支持、不完整响应或超过读取上限时标记未知。推理和 commentary 内容不参与判分。

检测状态是独立调度限制：仅“开启且降智”阻止后续分配。聪明、未知或关闭检测都解除该限制，但不修改人工状态、调度开关或其他健康、过期及配额限制。正在执行的业务请求不被中断。单题结果代表这道题是否通过。

后台每 15 秒扫描一次，数据库租约保证各实例总计最多 10 轮检测并发，单轮超时 120 秒，租约 180 秒。关闭后重新开启或更换凭据时，旧结果不能覆盖新状态；旧租约在工作者完成或过期前保留，避免同一账号同时执行两轮。正常 OAuth 令牌轮换不会使检测失效。

每账号最多保存两轮记录，包含失败、取消和中断轮次；第三轮开始时在同一事务中删除最早一轮。记录包含题干版本、模型、推理强度、最终回答、原因及耗时，不保存推理内容或凭据。响应读取上限 256 KiB，保存回答上限 64 KiB。账号删除时清理记录。`store:false` 是请求参数，本项目无法控制上游自身的数据保留政策。

管理员接口：

- `PUT /api/v1/admin/accounts/:id/iq-check`：`{"enabled":true,"interval_minutes":15}`。
- `POST /api/v1/admin/accounts/:id/iq-check/run`：排队立即检测；已有活动租约时复用当前任务，关闭检测时拒绝。
- `GET /api/v1/admin/accounts/:id/iq-check/results`：最近两轮记录，按时间倒序。
- 创建、更新及批量更新账号支持 `iq_check` 设置；详情和精简列表返回 `iq_check` 摘要。
- 列表支持 `iq_status=smart|degraded|unknown`；省略时为全部。

源码按仓库原有分层存放：`backend/internal/pkg/iqcheck` 负责请求内容与解析，`service/iq_check_service.go` 负责后台执行，`repository/account_iq_check.go` 负责租约及记录，迁移为追加的 `240_account_iq_check.sql`；界面接入现有账号列表和编辑组件。Ent 与 Wire 生成文件随源码交付。
