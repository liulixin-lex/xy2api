# OpenAI 智商检测

检测使用固定糖果题：明确答案为 21 时判为“聪明”，其他明确数值为“降智”；网络、协议、空输出或答案冲突记为“未知”。最近一次有效判定独立保存，普通检测失败不会覆盖它。启用检测且有效判定为“降智”时，账号不参与业务调度。关闭检测立即解除检测自身的限制。

## 设置和排期

设置仅包含开关、间隔、模型、思考深度、回答格式和超时。新账号默认关闭，间隔 5 分钟，模型 `gpt-6-astra`，思考深度 `low`，兼容模式，超时 120 秒。现有账号的基础间隔保留。间隔允许 1～1440 分钟，超时允许 30～300 秒，超时与回答格式收在高级设置。复制、导入账号默认关闭检测；批量编辑只修改选中字段。

按固定间隔检测，连续失败时延长等待。正常轮次结束后按基础间隔排期，保留少量调度抖动。连续临时失败使用基础间隔的 1、2、4 倍，上限为基础间隔与 60 分钟中的较大值；成功后恢复基础间隔。连续协议失败第三轮冷却 30 分钟，之后 60 分钟。没有每日检测上限、节约模式或共享配额组。

普通 `http_403` 属于临时失败，首轮后按基础间隔自动续检，不在本轮立即补试。明确的凭据失效、权限拒绝、额度不足、模型或参数错误仍暂停，处理原因后可重新排队。失败保留上次有效判定，只有新有效答案才更新判定。

网络、超时、流读取中断以及 429/502/503/504 最多补试一次。补试以 `retry_wait` 持久化，释放并发名额和租约；等待 2～5 秒抖动与已知冷却中的最晚时间。整轮截止为两倍单次超时加 30 秒，重启后可继续领取，超出截止则结束本轮。插件内部重试次数不可见，核心对插件不增加补试。合法 `Retry-After` 为发送下限，无法表示的超大等待暂停请求。

账号业务额度、人工停用、健康冷却及并发限制继续生效。取得真实并发名额且通过账号行锁内的健康检查后才创建尝试；满载、冷却等等待不占历史记录。短暂满载在任务内等待 250/500/1000 毫秒重试，持续满载以 15～30 秒间隔继续等待。手动“立即检测”合并待执行任务，并遵守最小间隔和已知冷却。

部署可用 `IQ_CHECK_MAX_CONCURRENCY=2` 设置全局检测并发（1～10，各副本一致）。`IQ_CHECK_QUOTA_GROUPS` 已移除，不再读取。

## 检测会话与粘性

API Key 上游的每次实际 IQ 请求都使用新的 UUID 会话身份和 `prompt_cache_key`，包括手动检测、定时检测及持久化补试；不按账号、题目、任务或轮次复用标识。会话头在账号自定义头和模型映射之后统一处理，清除旧续接/亲和信息。仍检测指定账号，不借用业务用户粘性，也不清除正常业务会话的缓存或绑定；题目、判分、超时、补试次数和发送次数不变。

OAuth 检测不执行 API 号池身份轮换。它复用已有指纹收敛实现：关闭时保持原协议，设备模式收敛设备，设备+会话及完全收敛模式保持账号对应的稳定会话身份；请求头、内嵌 metadata 和正文共用一次解析出的身份。单个 OAuth 账号不会因解黏变成另一个账号。

新标识可以避免本地重复身份导致的持续亲和，但不能强制上游更换其隐藏号池账号，也不能保证每次独立抽样。正常业务请求仍采用既有缓存策略；检测本身主动放弃跨尝试的缓存亲和。

## 模型与回答格式

模型支持搜索、直接输入和只读同步上游模型目录。思考深度显示英文值，上游能力列表优先；`gpt-6-astra` 的参考值为 `low`、`medium`、`high`、`xhigh`、`max`。支持模型相关能力校验及自定义值。`default` 使用上游默认值，保存为 `upstream_default`，请求省略 effort 参数。

- **兼容模式**：用提示词要求 JSON；返回明确答案时也可判定，兼容更多上游。
- **严格格式**：额外使用 JSON Schema 约束输出，需要上游支持；格式有偏差但答案明确时仍可判定。

参考：[OpenAI 模型文档](https://developers.openai.com/api/docs/models/gpt-6-astra)、[推理指南](https://developers.openai.com/api/docs/guides/reasoning)。上游返回的模型名只是上游声明。

## 记录与诊断

保留最近三轮。摘要只显示当前判定、必要的上次有效结果时间、最近检测、下次检测以及一条原因。检测中显示“检测中”，硬暂停显示“待处理”。不显示预算、剩余次数、过期标签或连续繁忙次数。打开记录弹窗时自动刷新，刷新失败保留已加载记录，关闭后停止请求。

每轮显示判定、时间、答案、模型、英文 effort 和本轮耗时。有回答才提供原文入口，超过一次尝试才显示尝试明细。检测详情合并协议与 HTTP 状态、回答格式、首字节/请求耗时和 Token 用量；返回模型与请求模型不同时才显示返回模型。推理 Token 已包含在输出 Token 内，显示为“输出 N（含推理 M）”。本轮耗时来自 `latency_ms`，请求耗时来自诊断 `total_ms`，口径不同。

技术详情默认折叠，按请求、解析、版本分组，展示请求 ID、媒体类型、事件、计数、答案来源及版本。代码与请求 ID 可复制；缺失字段隐藏，未知枚举保留原值，不为旧记录补造诊断。`single_attempt` 表示本次尝试发送一次请求，不代表整轮只有一次请求；插件显示内部重试次数未知。

下载诊断仍使用版本 2：`version`、`rounds`、`hourly`，保留原始机器字段、最近三轮尝试和 30 天小时聚合，不包含原始回答、凭据或推理正文。实际响应读取和事件解码继续使用既有有界解析器与 `candy-grader-v2`，只接受完成响应，不根据中间推理或文本增量提前判定。

## 接口

- `PUT /api/v1/admin/accounts/:id/iq-check`：部分更新六项设置；省略字段保留原值，旧请求的废弃字段被忽略，不再保存。
- `GET /api/v1/admin/accounts/:id/iq-check`：只读状态，不返回凭据或租约令牌。
- `GET /api/v1/admin/accounts/:id/iq-check/models?refresh=true`：只读模型目录与能力信息。
- `POST /api/v1/admin/accounts/:id/iq-check/run`：合并并排队检测，关闭时拒绝。
- `GET /api/v1/admin/accounts/:id/iq-check/results`：最近三轮。
- `GET /api/v1/admin/accounts/:id/iq-check/diagnostics`：版本 2 诊断下载。
