# 份额调度

份额调度是 Sub2API 原版调度之外的可选调度器，每个分组独立选择，随时可以回到原版。它沿用账号自己的设置：

- **层级 = 账号优先级**：数字越小越先使用。新会话只进入当前**活动优先级**，即有可用账号的最小优先级。
- **权重 = 负载因子**：同一优先级内按负载因子比例分配新会话。负载因子未设置时按并发上限计算，并发也没有时按 1。权重会再乘上自动的健康系数与恢复爬升系数，见“自适应权重”。
- **会话保持**：同一会话尽量留在原账号，以保住上游提示缓存和首字速度；缓存过期后再按比例重新分配。

每个分组只有两项设置：调度方式（原版 / 份额）与会话保持。全局只有一个总开关。其余参数都是固定值，见“会话与缓存保护”。

设计与取舍见 [`openspec/changes/simplify-share-scheduling-20261020`](../openspec/changes/simplify-share-scheduling-20261020/design.md)；0.3.0 的首个版本见 [`replace-controlled-with-share-scheduling`](../openspec/changes/replace-controlled-with-share-scheduling/design.md)。

## 启用步骤

1. **管理后台 → 份额调度**：页头的**总开关**默认关闭。关闭时所有分组立即回到原版调度，各分组的设置保留，已有会话不迁移。
2. 左侧选择分组。分组列表显示调度方式、账号数、近 1 小时的缓存命中率与换号损失。
3. 在「流量分配」中核对各账号的优先级、负载因子与预计新会话份额。负载因子可以在表内直接修改，修改的是账号本身，会同时影响该账号所在的全部分组，表内会列出受影响的其他分组。
4. 点「切换为份额调度」。确认框显示切换后的预计份额与风险提示；总开关关闭时，确认会一并开启总开关。确认后立即生效：新会话按比例分配，已有会话留在原账号，缓存过期后再按比例重新分配。
5. 在「运行状况」中观察缓存命中率、因换号损失的缓存、首字延迟与错误率。切换后它们会与切换前同长度的窗口对比。异常时点「回到原版」。

账号的优先级、负载因子与「调度」开关都在「账号管理」中修改。账号管理按份额分组筛选时，会显示每个账号预计分到的新会话比例；关闭某个账号的调度时，会提示它在哪些份额分组里的新会话改由同优先级的其他账号承接。

## 流量分配

「流量分配」按优先级分段列出全部成员，包括停用、错误状态的账号：

| 列 | 含义 |
|---|---|
| 状态 | 可调度，或不可调度的原因与预计恢复时间 |
| 负载因子 | 账号负载因子；未设置时显示“按并发上限 N 计” |
| 预计新会话份额 | 活动优先级内可用账号按有效权重的占比，其余为 0。不可用的账号另外显示“恢复后”的份额 |
| 实际份额 | 近 1 小时本组成功请求中该账号的占比 |
| 失败率 | 近 30 分钟会触发自动降权的上游失败占比（见“自适应权重”），按该账号在全部分组的请求计算 |

预计份额只取决于优先级、负载因子、自动系数与账号当前是否可用，与分组当前的调度方式无关，所以原版分组上看到的就是切换后的预计值。它是新会话的期望比例：满载溢出与按请求的门禁（模型、渠道限制等）不计入。

确认框与预计份额会给出以下风险提示：

| 提示 | 条件 |
|---|---|
| 总开关关闭 | 本组暂按原版运行 |
| 没有可用账号 | 请求只能走末位兜底或无号兜底分组 |
| 最高优先级不可用 | 数值最小的优先级没有可用账号，新会话进入更低的优先级 |
| 流量过于集中 | 某账号预计分到 80% 以上的新会话，且同一优先级至少有 2 个可用账号 |
| 负载因子过大 | 负载因子 ≥999；它恢复可用时会拿到同一优先级的绝大多数新会话 |
| 正在爬升 | 账号刚从长时间不可用中恢复，权重正在回升 |
| 已自动降权 | 健康系数 ≤0.5；若持续，建议检查上游或停用 |

## 自适应权重

有效权重 = 负载因子 × 健康系数 × 爬升系数，至少为负载因子的 5%。两个系数都没有设置项，关闭网关韧性总开关后都为 1。它们只影响新会话、缓存过期后的重新分配与满载溢出的顺序；会话保持命中、满载判定与优先级都不受影响，所以不会把热会话迁走。

**健康系数**（0.2–1）：

- 统计近 30 分钟、按整分钟对齐的上游尝试。失败只计网关韧性会给短时冷却的类别：瞬时错误（5xx、传输错误）、首字超时、输出中途停滞。余额、鉴权、限流、降载、请求错误与客户端取消有各自的处理，不计入。
- 失败率 = 软罚类失败 ÷（成功请求 + 软罚类失败），按账号在全部分组计算。
- 对照同一分组、同一优先级的可用账号中最低的失败率（只取尝试数至少 20 次的账号；都不足 20 次时取有尝试的账号）。超出不到 3 个百分点不调整；之后每多 5 个百分点权重减半，最低 ×0.2，按 0.05 取整。小样本会先向同层最低失败率收缩，几次失败不会立刻大幅降权。
- 同一优先级只有一个可用账号时不调整。全员一起变差（上游事故）时彼此对照，也不调整。
- 失败率回落后，旧失败逐步移出窗口，约 30 分钟恢复到 ×1。
- 份额分组由后台每 60 秒刷新一次，只在至少一个分组按份额运行时查询。原版分组（以及总开关关闭时的份额分组）在打开「流量分配」、切换确认或排查工具时按需计算一次，只读本组成员，缓存 60 秒，所以切换确认显示的就是切换后的预计份额。
- 统计超过 5 分钟没有更新、查询失败、运维监控关闭时一律不调整，界面不显示健康系数。窗口内没有任何尝试的账号显示“数据不足（未降权）”。

**爬升系数**（0.1–1）：账号从长时间不可用恢复后，新会话权重在 10 分钟内从 ×0.1 线性回到 ×1，避免刚恢复（例如余额尚未真正补足）就接下大量新会话。触发条件：

- 余额暂停到期；
- 硬罚到期，包括超过 300 秒的限流；
- 本实例观察到账号连续至少 5 分钟不可用（停用、错误、关闭调度、管理员清除暂停等）后重新可用。观察最多晚 60 秒；进程重启后没有这段记忆，不会爬升。

30 秒级的短时冷却不触发爬升。

「流量分配」与「排查工具」逐项显示“负载因子 → 健康 ×a → 爬升 ×b → 有效权重 → 预计份额（不调整时的份额）”，并写明原因与预计恢复时间。

## 会话与缓存保护

以下规则都是固定值：

- **会话识别**：Anthropic、Gemini 等网关请求优先使用客户端显式会话标识（如 Claude Code 的 session id）；没有时使用对话锚点（API Key + 系统提示 + 首条用户消息，仅份额分组使用，跨轮稳定、不同 Key 不共享，不含工具定义）。OpenAI 请求沿用原版会话哈希。关闭「会话保持」时不绑定，每个请求按比例重新选账号，只适合图片、向量等无状态分组。
- **绑定**：命中即续期，空闲超过 1 小时失效，与原版粘性会话一致。绑定键格式与原版相同。
- **缓存寿命**：Anthropic 5 分钟，请求声明 1 小时缓存时为 1 小时；OpenAI 30 分钟；其他 5 分钟。低于模型最小可缓存长度的会话视为无缓存可保护。
- **满载**：新会话与溢出跳过负载率达到 100% 的账号，负载率 =（在途 + 排队）× 100 ÷ 负载因子，与原版相同。已绑定的会话只看并发槽：绑定账号槽满且缓存仍热时，按预计缓存 Token 等待（每 1k Token 100 毫秒，最多 15 秒，每账号最多排队 3 个请求），超时后溢出并改绑，顺序为先同一优先级、再下一优先级，同一优先级内同类账号（平台与账号类型相同）优先。
- **短时不可用**：绑定账号处于网关韧性的软罚（瞬时失败冷却、短限流、过载冷却等），且预计在 300 秒内、缓存过期前恢复时，只临时借用其他账号、不改绑，恢复后会话回到原账号继续读缓存。原因为空或不属于软罚的临时停调（凭证类、管理员规则类）与余额暂停是硬状态，下一次请求即改绑。关闭网关韧性总开关时回到 0.3.0 的规则：任何 300 秒内结束的状态都按短时不可用处理。
- **缓存过期后重新分配**：调整负载因子、优先级或账号恢复时，不迁移仍在缓存期内的会话；会话空闲超过缓存寿命后，下一次请求才按当前比例重新分配。所以修改后份额随新会话和冷会话逐步收敛，不会立即跳变。
- **回到高优先级**：高优先级恢复后，冷会话在它稳定 120 秒后迁回（健康问题解除后重新计时），热会话不迁移。

## 与网关韧性的关系

网关韧性（[说明](GATEWAY_RESILIENCE.md)）的罚则与会话处理在份额分组中按份额语义执行：

- **软罚**按“短时不可用”处理：临时借用、不改绑，原因 `soft_spill`。
- **会话连续失败**：同一会话在同一账号上 10 分钟内失败 2 次，改绑并在 10 分钟内回避该账号，原因 `resil_failure_streak`。
- **余额不足暂停**（原因以 `balance:` 开头）是硬罚，原因 `balance_exhausted`，绑定会话下一次请求即迁移；暂停到期后按“爬升系数”回升。
- **末位兜底**：分组内只剩软罚账号时，份额计划“放宽一轮”：软罚账号与只被会话回避的账号视为可用，仍按优先级与权重选择；原因 `last_resort_soft`。
- **无号兜底分组**的转投与切回不是份额放置决策，不进份额报表，计入韧性计数 `fallback_group`、`fallback_return`。
- 健康系数与网关韧性使用同一套失败分类：短时冷却处理“刚刚失败”，健康系数处理“持续时好时坏”的中期比例。
- 关闭网关韧性总开关后，软罚判定、余额暂停的硬罚处理与两个自动系数都回到 0.3.0 行为。

## 精度边界

- 份额作用于**新会话**的落点。会话长短、调用频率不同，按请求或 Token 统计的实际份额会偏离预计份额；短窗口、小样本偏差更大。
- 份额调度**不是硬上限**。需要硬封顶时使用账号自身的并发、RPM、窗口费用、额度等限制；这些限制照常生效，触发时请求溢出到其他账号并计入原因。
- 健康系数只会少降权、不会误降权：输出中途停滞不写入运维错误记录，单次请求的尝试被截断时早期尝试缺失，运维监控关闭时没有数据，这些情况都按“不调整”处理。
- 缓存归因按每 4 个会话抽 1 个统计。

## 运行状况与详细报表

「运行状况」比较当前窗口与切换前的同长度窗口（1、6、24 小时）：

| 指标 | 来源 | 原版分组 |
|---|---|---|
| 缓存命中率 | 成功请求的缓存读 Token ÷（输入 + 缓存读 + 缓存写 Token） | 有 |
| 因换号损失的缓存 | 缓存归因抽样中，缓存未过期就换号造成的未命中 Token 占比 | 有 |
| 首字延迟 | 成功的流式请求首字时间 P50 / P95 | 有 |
| 错误率 | 本组客户可见错误 ÷（成功请求 + 客户可见错误） | 有 |

- 切换时间在保存调度方式时记录（保留约 8 天）。没有记录时按策略更新时间估算，页面会注明。
- 切换不到一个窗口时，当前窗口从切换时开始，不混入切换前的数据。
- 基线与超过 2 小时的窗口按整点小时汇总，与精确时间最多相差 30 分钟。缓存归因的小时数据保留 8 天加 2 小时，更早的切换只对比数据库指标。

「详细报表」显示当前窗口的缓存命中与未命中分类（两种模式都有），以及只在份额模式下产生的数据：选号原因、账号被跳过的原因（满载、会话上限、Codex 额度压力等）、满载等待、尝试次数、份额主动迁移热会话的次数与原因。热迁移超过请求数的 0.1% 是建议回退的信号。

## 排查工具

用当前设置和账号状态模拟一次选号，不占用并发，也不写入会话绑定；分组仍在原版调度时同样可用。

- 不填会话哈希时模拟一个新会话，落点按有效权重随机，每次可能不同。
- 模型可以留空，表示不按模型过滤。
- 结果给出会话识别方式、当前绑定与空闲时长、缓存寿命与冷热、满载时最多等待、选号原因、尝试顺序，以及每个候选的优先级、负载因子、健康系数、爬升系数、有效权重、负载率与资格，并附网关韧性的解释。

## 不经过份额调度的请求

以下请求保持原版行为：

- OpenAI `previous_response_id` 续链、guardian 父账号等协议强续接（份额分组中记为协议续接）；
- OpenAI compact 请求、图片请求，以及质量路由已持有的会话；
- AI Studio 元数据接口与 `count_tokens`；
- 未分组账号（组 0）：不能在页面配置，始终使用原版调度。

Codex 额度压力只在份额分组中作为显式容量闸门；原版调度分组不变。

## 从 0.3.0–0.4.3 升级

- **层级与权重改取账号设置**：份额分组的层级改为账号优先级，权重改为负载因子。旧策略里的账号规则（层级、权重、缓存域、排空）不再生效。升级瞬间新会话分布可能改变，负载因子很大的账号会拿到绝大多数新会话；升级前在「流量分配」或确认框中核对预计份额，需要时先调整负载因子。修改负载因子同时影响该账号所在的原版分组，方向与原版一致（原版按负载率选号，负载因子越大越常被选中）。
- **影子对比已移除**：调度方式为“影子对比”的分组按原版运行，页面注明原为影子对比；重新选择调度方式即可覆盖。
- **已移除的设置**：缓存归因（改为常开，每 4 个会话抽 1 个）、归因抽样、保存决策样本；亲和键的 `session` 与 `prefix`（按 `auto` 运行）；绑定空闲过期、满载等待参数、等待超时溢出后的处理、短时不可用上限、缓存冷判定、满载与失败时的层级处理、迁回方式与稳定时长、强制回升截止；份额单位与纠偏；缓存域与排空。它们都按上面的固定规则运行。平滑下线改为把负载因子调到 1；立即下线仍是关闭账号的「调度」开关。
- **已移除的功能**：重平衡（清除绑定）、决策样本、选号开销统计、首字直方图（首字改由 `usage_logs` 精确统计）。`POST /groups/:id/rebalance` 与 `GET /groups/:id/decisions` 返回 `410`，原因 `SHARE_SCHEDULING_ENDPOINT_RETIRED`。
- **数据**：不新增迁移。旧策略的规则与参数在数据库中原样保留，保存只改调度方式与会话保持两项，旧设置文档中的旧开关也原样保留。
- **回退到 0.4.3 / 0.3.0**：旧版读到的是保存前的规则与参数，恢复升级前的行为；新版新建的策略在旧版下按旧缺省运行（权重取并发、层级取优先级）。升级期间对负载因子的调整不会体现在旧规则里。

## 运维

- 一键回退：关闭总开关，或把分组调度方式改回原版。两者都立即生效，不迁移已有会话。
- 保存带版本号；其他管理员先保存时返回冲突，页面提示重新载入。保存后通过 Redis 广播在各实例数秒内生效，每 30 秒另有一次全量刷新兜底。
- 策略读取失败时沿用最后已知值；冷启动读不到时按原版调度。已保存但无法解析的策略按原版处理，页面显示原因，重新选择调度方式即可覆盖。
- 统计异步批量写入 Redis，写入失败或队列繁忙时只丢弃统计，不重试、不影响选号。统计用于观测与灰度对比，不是逐请求的审计记录。
- 管理端对 `usage_logs`、`ops_error_logs` 的读取都在只读事务中执行，语句超时 5 秒；分组列表的 1 小时摘要与成员的 1 小时请求数在进程内缓存 30 秒。
- 管理接口位于 `/api/v1/admin/share-scheduling`，写操作由管理审计日志记录：

| 方法 | 路径 | 用途 |
|---|---|---|
| GET / PUT | `/settings` | 总开关 `{enabled}`；旧开关字段接受并忽略 |
| GET | `/groups` | 分组列表与 1 小时摘要 |
| GET / PUT | `/groups/:id/policy` | 读取分组设置与成员；保存 `{scheduler, session_keep, expected_version}` |
| POST | `/groups/:id/preview` | 切换前的预计份额与风险提示 |
| POST | `/groups/:id/explain` | 模拟一次选号 |
| GET | `/groups/:id/report?window=1h` | 运行状况与详细报表（窗口 1m–24h） |
| GET | `/accounts/:id/rules` | 账号在各份额分组中的预计份额（只读） |
| GET / POST | `/groups/:id/decisions`、`/groups/:id/rebalance` | 已退役，返回 `410` |

字段定义见 design §7。

## 灰度前基线

切换任何分组前，可在只读副本上执行 [`tools/share-scheduling/baseline.sql`](../tools/share-scheduling/baseline.sql)，灰度期间用相同窗口再执行一次对照：

```bash
psql "$DATABASE_URL" -v days=7 -f tools/share-scheduling/baseline.sql
```

脚本在只读事务中运行，输出：各分组按账号的请求 / Token / 标准成本份额；按分组、模型与输入大小分桶的缓存读占比与首字 P50/P95/P99；按模型族的首字斜率（每 1k 未缓存输入 Token 的毫秒数，满载等待按每 1k Token 100 毫秒）；以及按平台与入口的客户端显式会话覆盖率。
