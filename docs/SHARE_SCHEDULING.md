# 份额调度

份额调度按分组为账号设置**层级**与**权重**：新会话按权重比例分配到账号，已绑定的会话优先留在原账号，以保住上游提示缓存和首字速度。它是 Sub2API 原版调度之外的可选调度器，每个分组独立选择，随时可以一键回到原版。

设计与取舍见 [`openspec/changes/replace-controlled-with-share-scheduling`](../openspec/changes/replace-controlled-with-share-scheduling/design.md)。

## 启用步骤

1. **系统设置 → 网关 → 份额调度**：
   - **总开关**：默认关闭。关闭时所有分组立即回到原版调度（影子对比也停止），已保存的策略保留。
   - **缓存归因**：默认开启，原版调度分组同样统计，作为切换前后的基线。
   - **归因抽样**：默认每 4 个会话抽 1 个（1–64），用于换号归因与首字分位。
   - **保存决策样本**：每个分组保留最近 500 条决策，供报表查看。
2. **管理后台 → 份额调度**：左侧选择分组，在「策略」标签页设置层级、权重等，点「预览并保存」。
3. 建议先选择**影子对比**运行一段时间：请求仍由原版选号，后台计算份额调度的选择并记录一致率；在「报表」中确认份额、缓存读占比与首字没有恶化后，再切换为**份额调度**。

调度器有三种：

| 调度器 | 行为 |
|---|---|
| 原版调度（`sub2api`） | 沿用原版选号，策略只保存不生效。新分组默认如此。 |
| 影子对比（`shadow`） | 原版选号；同时无副作用地计算份额调度的选择，记录一致率与分歧原因。 |
| 份额调度（`share`） | 由份额调度选号。 |

## 账号规则

| 字段 | 含义 |
|---|---|
| 层级 | 数字越小越优先，与原版账号优先级同向。新会话只进入当前**活动层**（最低的、有健康未排空账号的层）。 |
| 权重 | 1–1000000。同层内按权重分配新会话。 |
| 排空 | 不再接新会话；已绑定会话在缓存变冷后迁走。可设「强制迁移截止」，到期后仍未迁走的会话按会话错峰 10 分钟迁移（会丢失缓存）。启用时至少保留一个未排空账号。 |
| 缓存域 | 只有**确认共享上游提示缓存**的账号才填同一标识，例如同一 Anthropic workspace、同一 OpenAI 组织与区域。溢出与故障转移优先选同域账号。同一缓存域不能跨平台。留空表示自成一域。 |

未配置的账号使用默认值：层级取账号优先级，权重取账号并发上限（可改为等权 1）。页面中的「目标 / 生效 / 容量」份额按当前草稿计算：目标是本层内权重占比；生效只计活动层中健康的账号；容量是本层并发占比。目标份额明显高于容量占比时，预览会给出 `capacity_mismatch` 提示。

账号表支持搜索、行内编辑和批量设置（层级、权重、缓存域、排空、恢复默认）。

## 会话与缓存保护

- **亲和键**：`auto`（默认）时，Anthropic、Gemini 等网关请求优先使用客户端显式会话标识（如 Claude Code 的 session id）；没有时使用对话锚点（API Key + 系统提示 + 首条用户消息，仅份额分组使用，跨轮稳定、不同 Key 不共享，不含工具定义）。OpenAI 请求沿用原版会话哈希。`session` 只使用显式会话标识，没有时按无会话处理；`prefix` 按 API Key + 系统提示分组，同一系统提示的请求共享绑定；`none` 不绑定，逐请求按权重分配（适合图片、向量等无状态分组）。
- **绑定**：命中即续期，空闲超过「绑定空闲过期」（默认 3600 秒）后失效。绑定键格式与原版一致。
- **缓存寿命**：Anthropic 默认 5 分钟，请求声明 1 小时缓存时为 1 小时；OpenAI 30 分钟；其他 5 分钟。可在「缓存冷判定」中固定秒数。低于模型最小可缓存长度的会话视为无缓存可保护。
- **满载等待**：绑定账号满载且缓存仍热时，按预计缓存 Token 等待：每 1k Token 100 毫秒，最多 15 秒，每账号最多排队 3 个请求。超时后溢出到该会话的 HRW 次选账号，并按「等待超时溢出后」改绑或保留原绑定。
- **短时不可用**：绑定账号预计在 300 秒内恢复（如短限流）时只临时溢出，不改绑；恢复后会话回到原账号继续读缓存。
- **冷窗口重对齐**：调整权重、排空（无截止）或高层恢复时，不迁移仍在缓存期内的会话；会话空闲超过缓存寿命后，下一次请求才对齐到当前理想账号。因此保存后份额会随新会话和冷会话逐步收敛，不会立即跳变。
- **层级回升**：默认「缓存变冷后迁回」，高层需稳定 120 秒。「立即迁回」和「强制回升截止」会迁移热会话、重建缓存，成本和首字延迟上升，仅在确有需要时使用。

## 精度边界与硬封顶

- 份额作用于**新会话**的落点。会话长短、调用频率不同，按请求、Token 或成本统计的实际份额会偏离目标；短窗口、小样本偏差更大。
- 「份额单位」只决定报表口径；单位为请求、Token 或标准成本时可开启温和/强纠偏，按统计窗口缓慢调整新会话权重，不迁移已有会话。单位为新会话时不支持纠偏。
- 份额调度**不是硬上限**。需要硬封顶时使用账号自身的并发、RPM、窗口费用、额度等限制；这些限制在份额调度中照常生效，触发时请求溢出到其他账号并计入原因。

## 保存、预览与冲突

- 保存前必须预览：显示新会话落点变化比例（抽样估算）、预计强制迁移会话数、截止已到的排空账号、以及风险提示（总开关关闭、没有健康账号、某层不可用、容量不匹配）。
- 策略带版本号，保存时校验版本。其他管理员先保存时返回冲突，页面保留你的草稿；点「载入最新版本并保留我的修改」会把修改重新套用到最新版本，核对后再保存。
- 切换分组不会丢失草稿，分组列表显示「草稿」标记；离开页面前会提示未保存的修改。
- 保存后通过 Redis 广播在各实例数秒内生效，每 30 秒另有一次全量刷新兜底。
- 迁移 `270` 会把旧「可控调度」的分组策略导入为未生效草稿（原版调度），页面会提示导入来源；确认后再切换调度器。

## 报表

「报表」标签按时间窗口（15 分钟至 24 小时）展示：

- 份额决策数、缓存读占比（缓存读 Token / 输入 Token）、换号致失占比（因换号造成的未命中 Token 占比）、热迁移、等待命中与平均等待、影子一致率；
- 目标与实际份额对比、纠偏系数；
- 决策原因、亲和键来源、跳过理想账号的原因、热迁移原因、影子分歧原因；
- 缓存归因（按输入 Token）：命中、低于最小可缓存长度、无会话、新会话、缓存过期、策略/满载/不可用/故障/其他换号、前缀变化；
- 按决策类型的首字延迟 P50/P95/P99；原版调度分组记为「原版调度」。
- 账号表现：每个账号被选中与被跳过的次数（按原因：满载、会话上限、Codex 额度压力等）、跳过率，以及该账号的首字 P50/P95。尝试 ≥ 10 次且跳过率 ≥ 20% 时提示：权重超出了账号并发能承接的量，可降低权重或提高并发上限。份额调度不会据此自动调权。
- 最近决策样本。

缓存归因与首字分位（含按账号）按归因抽样统计，分位取直方图桶上界（100 毫秒至 30 秒，超出显示「> 30 s」）。

## 解释与重平衡

- **解释**：输入模型、会话哈希、预计输入 Token（或粘贴请求体），用已保存的策略和账号当前状态模拟一次选号，显示亲和键来源、绑定与空闲、缓存寿命与冷热、等待预算、决策、绑定写入、尝试顺序和每个候选的资格。不占用并发、不写入绑定；分组仍在原版调度时同样可用。
- **重平衡**：清除分组的会话绑定，相关会话下一次请求按当前策略重新放置。默认只清除缓存已冷的绑定；「清除全部绑定」会迁移热会话。协议续接与响应归属记录不会被清除。

## 不经过份额调度的请求

以下请求保持原版行为：

- OpenAI `previous_response_id` 续链、guardian 父账号等协议强续接（份额分组中记为协议续接，不按份额重新选择）；
- OpenAI compact 请求、图片请求，以及质量路由已持有的会话；
- AI Studio 元数据接口与 `count_tokens`；
- 未分组账号（组 0）：暂不能在页面配置，始终使用原版调度。

Codex 额度压力只在份额分组中作为显式容量闸门；原版调度分组不变。

## 运维与回退

- 一键回退：关闭总开关，或把分组调度器改回「原版调度」。
- 策略读取失败时沿用最后已知值；冷启动读不到时按原版调度。已保存但无法解析的策略按原版处理，页面显示原因并以默认值供重新保存。
- 统计与决策样本异步批量写入 Redis，写入失败或队列繁忙时只丢弃统计（报表会提示丢弃数量），不影响选号。
- 管理接口位于 `/api/v1/admin/share-scheduling`，写操作由管理审计日志记录：

| 方法 | 路径 | 用途 |
|---|---|---|
| GET / PUT | `/settings` | 全局设置（PUT 只覆盖提交的字段） |
| GET | `/groups` | 分组列表与 1 小时摘要 |
| GET / PUT | `/groups/:id/policy` | 读取 / 保存策略，保存需 `expected_version` |
| POST | `/groups/:id/preview` | 保存前预览 |
| POST | `/groups/:id/explain` | 解释一次选号 |
| GET | `/groups/:id/report?window=1h` | 报表（窗口 ≤ 24h） |
| GET | `/groups/:id/decisions?limit=100` | 最近决策（1–500） |
| POST | `/groups/:id/rebalance` | 重平衡，`{"mode":"cold"}`（默认）或 `"all"` |
