## 冲突处理

官方以站点 origin 作为授权服务器 issuer，XY2API 原有只读 MCP 已占用根发现地址。因此保留完整管理资源 URL 作为 issuer，并使用 `/.well-known/oauth-authorization-server/api/v1/mcp` 发现管理 OAuth；SDK 端到端测试覆盖该发现流程。直接覆盖官方路由会破坏两类 MCP 并用。

管理配置只增加现有 settings 表中的 JSON 键，不需要迁移。预置默认记录会覆盖原部署的显式启用状态，因此只有管理员首次保存时才写入。读取配置失败或配置非法时禁止调用，不回退到可能已被管理员关闭的部署默认值。每个请求读取配置并限制数据库等待时间；关闭影响后续请求，不终止已执行中的工具，也不等同于撤销授权。

后台 GET/PUT 仅允许超级管理员 JWT 会话；PUT 复用敏感操作二次验证，成功保存写入操作审计。该路由不加入 MCP 工具目录。后台关闭后仍保留授权管理入口，便于撤销旧授权。配置规则、启用步骤及回退要求见 [管理 MCP 指南](../guides/management-mcp.md)。

## 验证范围

回归覆盖部署默认值与后台配置优先级、跨实例读取、非法地址及数据库错误、超级管理员浏览器权限、step-up 路由、关闭后的发现/注册/工具/刷新阻断、资源地址变更、恢复同一资源，以及前端加载失败、地址必填、保存与禁用。已有 OAuth SDK、权限边界、令牌轮换/撤销及双 MCP 共存测试继续运行。
