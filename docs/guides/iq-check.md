# OpenAI 智商检测

智商检测定期向 OpenAI 账号发送参数化的“糖果题”，判断上游是否把请求的模型偷偷换成了能力更弱的模型（俗称“降智”）。检测和冷却都以“账号 × 模型”为单位：某个模型被判为降智时，只暂停该账号上的这个模型，其他模型照常调度。本文面向管理 OpenAI 账号池的管理员。

## 适用账号与入口

- 适用于 OpenAI 平台的 API Key 账号（`apikey`）、OAuth 账号（`oauth`、`setup-token`），以及 `credentials.auth_mode` 为 `agentIdentity` 的 Agent Identity 账号。其他类型返回 `unsupported_account_type`。
- 没有全局开关，按账号、按检测目标开启。配置入口：
  - 账号列表的「智商检测」列：开关同时开关两个内置目标，自定义目标不受影响。
  - 编辑账号弹窗（仅 OpenAI 账号）与批量编辑。创建账号弹窗中没有该设置。
  - 账号操作菜单的「立即检测」「检测记录」，批量操作栏的「智商检测」。
- 账号列表可以按智商状态筛选（全部 / 聪明 / 降智 / 未知）。

## 检测目标

每个账号有一组检测目标，一个目标对应一个模型：

- 内置目标为 `gpt-6-astra` 和 `gpt-6.1-sol`，另外可以添加自定义模型。内置目标只能关闭，不能删除。
- 每个目标单独设置开关、思考深度、间隔和超时，单独判定、单独冷却：

| 设置 | 默认 | 范围 / 说明 |
|---|---|---|
| 思考深度 | `low` | 选“default”表示省略该参数，保存为 `upstream_default` |
| 间隔 | 5 分钟 | 1–1440 分钟 |
| 超时 | 120 秒 | 30–300 秒，在“高级”中设置 |

“出站模型”指账号模型映射之后实际发给上游的模型名。探针请求使用出站模型，门禁也按出站模型生效。

编辑弹窗只提交改动过的字段。批量编辑的每个字段默认为“不修改”，新增的自定义目标会加到所有选中账号。复制或导入账号后，全部目标一律关闭。

配置变化的效果：

| 变化 | 判定 | 排期 |
|---|---|---|
| 新建，或从关闭改为开启 | 未知 | 立即检测 |
| 从开启改为关闭、删除目标 | 改为未知，撤销冷却 | 进行中的一轮完成时作废 |
| 修改思考深度或超时 | 保留，直到得到新的有效结论 | 立即检测；进行中的一轮作废 |
| 只修改间隔 | 保留 | 下次检测时间按新间隔提前或不变 |
| 账号身份变化（见“门禁”） | 全部目标改为未知，撤销冷却 | 已开启的目标立即检测 |

## 判定

### 单题

| 情况 | 结果 | 原因代码 |
|---|---|---|
| 响应完整，且自报模型属于登记的降级替换 | 答错 | `model_mismatch`（优先于答案） |
| 响应完整，但同一来源内的模型声明互相矛盾，且其中有降级 | 未知 | `model_conflict` |
| 唯一明确的整数等于正确答案 | 答对 | `correct_answer` |
| 唯一明确的整数不等于正确答案 | 答错 | `wrong_answer`；等于朴素解时另作标记 |
| 网络、超时、HTTP 错误、额度、解析失败、空回答等 | 未知 | 沿用原有分类 |

只在完整成功的响应上判题。推理内容、半截的流、错误页、带答案字段的错误对象都不算回答。

### 一轮

一轮最多 5 次请求，未知的题不计入判定。遇到凭据、权限、额度、模型或参数不受支持这类不可重试的未知时，本轮立即结束。HTTP 403、429、`rate_limited`，以及带 `Retry-After` 的未知结果也不在本轮内重试，直接结束本轮，交给排期退避（错误体分类覆盖了原因时按真实 HTTP 状态判断）。

- **正常轮**：第一道有效题答对即判为聪明；第一道有效题答错时再出两题，有效题累计答错 2 题判为降智，后两题都答对判为聪明。出现答错的题之后，后续请求（包括未知后的重试）使用高一档的思考深度，档位顺序为 minimal → low → medium → high → xhigh → max；`max`、`upstream_default` 和未知的自定义档位不升档。
- **复检轮**（已判为降智的目标）：全部使用配置的档位。任何一题答错即维持降智，累计 3 题答对才恢复为聪明。
- 5 次请求用完仍无结论，本轮结果为未知。

**未知永远不改变判定**：不会新增冷却，也不会解除已有冷却；检测器停止运行时，降智也不会自动解除。

### 排期

| 本轮结果 | 下次检测 |
|---|---|
| 聪明 | 间隔加少量抖动，抖动不超过 30 秒与间隔 1/20 中较小的那个 |
| 降智 | 复检退避：30 秒、2 分钟、5 分钟、10 分钟，之后保持 10 分钟 |
| 未知（额度不足、HTTP 402） | 间隔与 15 分钟中的较大值 |
| 其他未知 | 间隔的 1、2、4 倍，上限为间隔与 60 分钟中的较大值 |
| 未知（凭据、权限、模型或参数不支持、无上限的 `Retry-After`） | 暂停自动检测，界面显示暂停原因 |

暂停在以下情况解除：修改开关、思考深度或超时；账号身份变化；Codex STATE 票据恢复后重新排队；手动检测没有再次遇到暂停类原因。只修改间隔不解除暂停。

上游给出 `Retry-After` 时，在它之前不发检测请求，手动检测也一样。

## 题目

题目沿用糖果题的题型与措辞，要求模型输出 JSON，数量参数随机：

- 圆形、五角星两种形状，苹果、桃子、西瓜三种口味，各数量在 4–9 之间均匀抽取；
- 表格的三列（口味）与两行（形状）顺序随机打乱。

正确答案由服务端用闭式解计算：形状可以凭手感区分，所以可以对两种形状分别决定摸几个，答案取总数最少的摸法。“朴素解”是不利用手感时的答案，只作诊断标记；在全部参数组合下朴素解都不等于正确答案。

每道题记录参数、行列顺序、最优摸法与朴素解，不保存完整题面与原文回答；题面文字固定，可由参数与行列顺序原样复原。版本号：题目 `candy-v3`、判题 `candy-grader-v3`、解析器 `iq-response-v7`。

解析限制：解压后总量不超过 8 MiB，单个 SSE 事件不超过 2 MiB，最终答案不超过 64 KiB，最多 4096 个事件。超限按未知处理，不截断后再猜答案。

## 自报模型识别

自报模型只是附加证据，主要判据仍是答题。上游可以改写声明（例如有的中转会把声明改回请求名），所以它只能发现没有被改写的替换。

**声明的来源**：

- 响应体：Responses 的 `response.created`、`response.in_progress` 与终态事件中的 `response.model`；Chat 每个 chunk（包括只带 usage 的尾帧）的顶层 `model`。
- 响应头：HTTP 头 `openai-model`，以及 `response.headers` 事件中的 `openai-model` / `x-openai-model`（键名不区分大小写）。
- 不从回答正文、工具参数中提取。

**以哪个来源为准**：OAuth 与 Agent Identity 账号（官方 Codex 后端）以响应头为准，缺失时退回响应体，因为官方后端会在响应体里回显请求名；API Key 账号以响应体为准，响应头只记录。两个来源都有值且不等价时按主来源分类，同时标记“来源不一致”。同一来源内优先取终态声明，没有时取第一个。

**规范化**（`openai.ModelIdentity`）：

- 忽略大小写；`_` 和空白改为 `-`，连续的 `--` 合并；只去掉 `openai/` 前缀；
- 日期快照接受 `-YYYY-MM-DD` 与 `-YYYYMMDD`，且必须是真实日期；至多一个思考深度后缀；
- 模型本体只识别 `gpt-<版本>-(astra|sol|terra|luna)`，版本不低于 5.6；裸名 `gpt-6` 视为 `gpt-6-astra`，`gpt-5.6` 视为 `gpt-5.6-sol`；
- 其他名字视为无法识别，不做猜测。

**类别**：

| 类别 | 条件 | 对本题的影响 |
|---|---|---|
| 一致 | 与发出的名字相同（不区分大小写） | 按答案判 |
| 等价 | 本体相同、快照不冲突，例如大小写不同、带 `openai/` 前缀、带日期快照或思考深度后缀 | 按答案判 |
| 快照不符 | 发出的名字固定了日期快照，声明的快照不同或缺失 | 按答案判，记录 |
| 版本更高 / 版本更低 | 变体相同、版本不同 | 按答案判，记录 |
| 关系未知 | 其他可识别的差异 | 按答案判，记录 |
| 无法识别 / 未声明 | 任一方不认识，或没有声明 | 按答案判 |
| **降级替换** | （发出的本体，声明的本体）属于降级组合 | **记为答错**，原因 `model_mismatch` |
| 声明冲突 | 同一来源内去重后仍有多个声明 | 其中有降级：本题记为未知（`model_conflict`）；没有降级：按答案判 |

**降级组合**：默认把 `gpt-6-astra`、`gpt-6.1-sol`、`gpt-6-sol`、`gpt-5.6-sol`、`gpt-5.6-terra` 换成 `gpt-5.6-luna` 视为降级；另外读取质量路由配置 `gateway.openai_quality_routing.rules`（有向的 from → to）追加组合。IQ 检测、质量路由与 usage 审计共用同一个分类函数，见 [OpenAI 会话质量路由](quality-routing.md)。网关不按版本号或变体名推断“更小”：新出现的替换形态会先以“关系未知”出现在记录里，人工确认后再登记为降级组合。

每题保存自报模型和类别；类别不是一致或等价、或出现来源不一致、声明冲突时，诊断里另写 `model_identity`（来源、发出的名字、响应体与响应头的声明各至多 4 个、标记）。记录弹窗中降级替换标红，声明冲突和来源不一致标黄。

## 门禁

判为降智后，账号 `extra.model_rate_limits` 中写入 `iq:<出站模型>` 键（`reason` 为 `iq_degraded`）。调度读取模型限流时一并读取这个键，因此只有该账号上的这个出站模型被移出候选。

- **fail-closed**：键存在就生效，与到期时间无关。只有复检判为聪明、关闭或删除目标、账号身份变化时才移除。
- **到期时间**：取下次复检的预计完成时间（下次检测时间与资源下限中较晚者，再加超时），每次复检刷新。界面据此显示“复检 hh:mm”；时间过后键仍然有效，界面改为“等待复检”。用于粘性清除与无号时的 `Retry-After` 时，剩余时间至少按 30 秒计，缺少到期时间时按 30 秒计。
- **共享键**：多个目标映射到同一个出站模型时，最后一个目标撤销后才删除该键。
- **在途请求**：门禁只影响选号，不中断在途请求；粘性会话在下一次请求时迁走。
- **compact**：compact 请求除请求模型自身的键外，还检查 compact 出站模型的键。compact 出站模型的计算顺序与转发相同：账号的 compact 映射优先，否则取全局 `gateway.openai_compact_model`（再经账号模型映射）。实际走 Chat Completions 的账号只按普通出站模型检查。
- **末位兜底**不放宽 `iq:` 键；**advanced 调度**的初筛按请求模型（含 compact 映射）检查 `iq:` 键，被冷却的账号不占候选名额。
- 进程内的“账号 × 模型”熔断器与本门禁并存，键的规范化方式相同，但存储与原因分开，候选需要同时通过两者。

以下操作不会清除或伪造 IQ 冷却：测试连接成功、清除限流、恢复状态、管理员编辑与批量编辑、导入导出（导出时剥离 `iq:` 键）、内部凭据持久化。账号列表在“降智”后显示下次复检时间，不计入普通模型限流，状态列也不显示。

**账号身份变化**会清除冷却并立即重检。触发身份变化的字段：账号类型与平台、所用代理；API Key、base_url、access / refresh token、ChatGPT account ID、请求头覆盖及其开关、User-Agent、模型映射；Responses 模式与支持标记、透传、TLS 指纹开关与指纹模板。OAuth 自动刷新令牌不算身份变化。

**已知限制**：

- 门禁按出站模型生效，同一账号上其他请求模型映射到同一个出站模型时会一起被挡。
- 粘性清除只按非 compact 的键判断；compact 请求在资格检查中才被拦截，最多多一次复核淘汰。
- compact 出站模型没有检测目标时，compact 请求只按请求模型自身的键拦截。

## 执行

- **并发**：每个副本运行一个检测循环，按“目标”领取。环境变量 `IQ_CHECK_MAX_CONCURRENCY` 控制全库同时持有租约的轮次（含题间等待），取值 1–10，默认 8，非法值按 8 处理（默认的 Docker Compose 文件不传递该变量，需要时加入 `xy2api` 服务的 `environment` 列表）。各副本用自己的配置值减去全库计数，因此各副本须配置一致。一轮的租约为 5 × 超时 + 120 秒，租约丢失时本轮记为 `lease_lost`。下次检测从上一轮完成时刻加间隔起算。
- **自动领取条件**：停调度、非 active、限流、过载或临时不可调度的账号不会被自动领取，其已启用目标显示为暂停（`account_unschedulable`，“账号不可调度”），只在显示时推导、不写库，账号恢复后自动继续。已禁用、已过期、冷却中或额度用尽的账号领取后推迟，不发请求。
- **账号并发槽**：每题先取一个账号并发槽，短暂等待 250、500、1000 毫秒。第一题前仍满载时推迟 15–30 秒再试；轮中仍满载时本轮结果为未知（`account_busy`）。题与题之间间隔 2 秒，或等到 `Retry-After`。
- **探针请求**：使用账号自定义的 User-Agent，没有时使用规范的 Codex 身份；API Key 账号每题使用新的会话标识与 `prompt_cache_key`，OAuth 账号按 Codex 指纹收敛设置会话头；请求设置 `store:false` 并流式读取；每次请求只发一次，不在内部重放；继续遵守请求头覆盖、代理与 Codex STATE 票据。

**检测间隔与检出速度**：上游往往在一段时间内持续降智，间隔越短，这段时间里被拦下的业务请求越多：1 分钟间隔下被拦截的比例约为 5 分钟间隔的两倍多，探针成本也相应增加。健康期平均每轮约 1 题。

与 Codex STATE 的联动（缺票时推迟、换票后重检、降智后换票）见 [Codex STATE](codex-state.md#与智商检测的联动)。

## 手动与批量检测

- 记录弹窗提供“检测此模型”与“全部检测”，账号菜单提供“立即检测”，批量操作提供“智商检测”（界面一次最多 200 个账号）。
- 手动检测不受开关、间隔、暂停状态和账号停调度的限制，停调度的账号也会发出真实请求；但仍遵守 `Retry-After` 等资源下限，并要求凭据可用。
- 目标正在检测时返回 `running`，否则排队并唤醒检测循环，返回 `queued`；重复点击合并为一次。
- 被拒时返回原因：`not_openai`、`credentials_unavailable`、`unknown_target`（指定的模型既不是已有目标也不是内置模型）、`not_found`（批量时账号不存在）。批量接口对整个被拒的账号返回 `{account_id, reason, targets: []}`。
- 已关闭的目标也可以手动检测，结果只写入记录，不改变判定与门禁。
- 目标处于排队或检测中时，界面每 3 秒刷新；记录列表只在第 1 页时随之更新，翻到历史页时冻结。

## 记录与诊断

- 记录保留 7 天，按“账号 × 模型”分页查看，每页 10 轮，可筛选“仅异常”：已完成且本轮结果或任一题不是答对的轮（包括低档答错、确认题通过的轮），进行中的轮不计入。
- 摘要先回答这个模型现在能不能用：判定、是否在冷却、下次复检时间、暂停原因，以及上次与下次检测时间。下次检测已到期但还未开始时显示“等待执行”，暂停时显示 `—`。
- 展开一轮后逐题显示：按出题时行列顺序排列的 2×3 数量表、正确答案与推导（例如“21 = 16 个圆形 + 5 个五角星”）和朴素解、模型答案与判定、自报模型与类别、思考深度与耗时。技术详情默认折叠，只显示请求 ID、耗时、Token；失败的题再显示 HTTP 状态、错误、`Retry-After` 与失败位置。
- 可下载诊断文件 `iq-check-diagnostics.json`（版本 3）：`{version: 3, targets: [{model, rounds: [...]}]}`，每个目标取 7 天内最近 100 轮。答对的题只保存紧凑诊断（请求 ID、HTTP 状态、首字节与总耗时、Token、存在时的自报模型诊断），答错与未知的题保留完整诊断。下载内容不含完整题面、推理正文、凭据和账号标识；模型答案经过规范化，超过 64 字节的置空。

## 管理接口

全部位于 `/api/v1/admin` 下：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/accounts/:id/iq-check` | `{targets: [...]}`：每个目标的配置、判定、`gate_active`、`gate_model`、`gate_reset_at`、`state`（`idle` / `queued` / `running` / `paused`）、暂停原因、上次与下次检测时间、进行中的轮次与已完成题数。没有目标时返回两个内置目标的默认值 |
| PUT | `/accounts/:id/iq-check` | `{targets?: [{model, enabled?, reasoning_effort?, interval_minutes?, timeout_seconds?}], remove?: [model]}`：按模型新增或修改，`remove` 删除目标。也接受旧的单目标格式 |
| POST | `/accounts/:id/iq-check/run` | `{models?: [...]}`：不带 `models` 时检测全部目标，并以关闭状态补齐缺失的内置目标 |
| POST | `/accounts/iq-check/run` | `{account_ids: [...], models?: [...]}`：批量检测 |
| GET | `/accounts/:id/iq-check/results` | `?model=&page=1&page_size=10&filter=`：该模型 7 天内的轮次与每题明细，返回 `{rounds, total, page, page_size}`。`page_size` 超出 1–50 时取边界值；`filter=abnormal` 只返回异常轮，其他非空值返回 400 |
| GET | `/accounts/:id/iq-check/diagnostics` | 下载版本 3 诊断 |
| GET | `/accounts/:id/iq-check/models` | 只读的模型目录与思考深度能力。目录缓存 5 分钟，`?refresh=true` 强制刷新；上游发现失败时最多沿用 24 小时内的旧目录 |

账号详情、列表和保存后的响应带有 `iq_targets` 摘要。创建、编辑、批量编辑和导入导出使用 `iq_check` 字段，内容为上面 PUT 的格式；导入时全部目标强制关闭。

## 升级注意事项

按“账号 × 模型”检测由迁移 `281_iq_targets.sql` 引入（新建 `account_iq_targets` 表，并把旧的单目标配置回填为两个内置目标与必要的自定义目标；只有旧版已开启检测且最近结论为降智的账号，才把降智迁给旧配置模型对应的目标）。从更早的版本升级时：先备份数据库，停止所有副本（旧程序不能与新程序同时运行），再启动新版本。启动时先对账再运行检测：为迁移来的降智目标写入 `iq:` 门禁、清理孤儿键、补回缺失的键；对账失败时程序不启动，避免在门禁缺失的状态下接流量。首检完成时间取决于目标数量、全局并发与账号资源。
