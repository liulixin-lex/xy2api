# 用量指标与导出

本文说明使用记录、Token 趋势、账号列表和运维看板上各项用量指标的计算口径，以及使用记录的后台导出任务如何启用和运行。指标都基于已记录的计费用量与耗时，不根据页面刷新速度或流式文本长度估算。读者是需要解读这些数字的管理员和运维，以及部署导出功能的运维。

## 单次请求平均 TPS

使用记录“延迟”列显示**平均TPS**，单位 **t/s**（每秒输出 Token 数）；运维页的单次请求速率叫“平均输出速率”，单位 tokens/s，口径相同。

```text
单次请求平均TPS = output_tokens × 1000 / duration_ms
```

- `duration_ms` 是该用量记录的完整请求耗时，包含首 Token 等待。流式与非流式使用相同公式。例如输出 100 Token、总耗时 3000 ms，结果为 33.3 t/s，与首 Token 耗时无关。
- 不用 `duration_ms - first_token_ms` 作分母：输出可能包含首个可见 Token 之前的推理 Token，也可能直到结束才返回缓冲的工具输出，现有记录也没有可靠的逐 Token 时间。因此它**不是**模型的纯解码速度。
- 输出计数可能已经包含推理 Token，不再额外相加。
- 只统计适用的 Token 请求，排除图片输出、视频、非 Token 计费和 Live/未知请求类型。输出或耗时不是有限正数时显示 `—`，不显示 0 t/s。
- 运维中的 P5/P10/P50 是筛选范围内各条有效记录速率的分位数，Avg 是这些单次速率的算术平均。

### 首字耗时字段

管理端使用记录的“延迟”列先显示“用户等待”（`end_to_end_first_output_ms`），下一行显示“末次首字”（`first_token_ms`）。用户端将 `first_token_ms` 显示为“首字”，首字和平均 TPS 均直接显示数值。运维看板的“用户等待”卡片展示端到端首输出耗时，底部另列“末次首字”的 P99 和 P50。

OpenAI 的 `first_token_ms` 仍由 `openai_ttft_mode` 控制：`semantic` 默认按首个事件，保活帧也可能计时；`visible` 按既有真实输出口径。它与质量判定的首个有效输出不同，不能只凭这一列判断账号会不会进后排。

| 字段 | 起点 | 用途 |
|---|---|---|
| `first_token_ms` | 最后一次上游尝试开始 | 使用记录行及运维看板的末次首字，沿用系统首 token 口径 |
| `end_to_end_first_output_ms` | 入站请求开始 | 首个有效事件成功交付到客户端的端到端时间，含上传、排队和先前失败尝试；分组体验显示 P50 / P90 |
| `attempt_first_output_ms` | 最终尝试开始 | 最终尝试的有效输出时间，内部记录 |

质量采样对每次流式尝试另记三个时间，起点均为发给该账号：

| 尝试字段 | 含义 |
|---|---|
| `first_event_ms` | 首个事件，沿用使用记录现有首 token 判据 |
| `ttfo_ms` | 首个有效输出，用于账号近期状况的首字统计和首字质量判定 |
| `first_answer_ms` | 首个答案正文；拒答、推理、工具输出可先触发有效输出，却不算答案正文 |

有效输出包括有内容的正文、拒答、推理或摘要、加密推理、工具名字或参数，以及可识别的托管工具调用。空白、不可见字符、角色、空增量、ID、签名、用量、进度和空终态不算；未知事件也不算。三个时间不保证固定顺序，没有观测到的为 `NULL`；非流式不采集这三个时间。完整判据见 [首字线](group-quality-gate.md#首字线)。

账号近期状况取近 1 小时流式尝试的首字中位数，超时排在最后，过半时显示“超时”。样本口径见 [账号列表](group-quality-gate.md#账号列表)。分组体验另给“从进入网关”与“从读完请求体”两组 P50 / P90，后者减去 `body_eof_ms`。使用记录行的 `first_token_ms`、`duration_ms` 不含此前失败尝试与换号等待；无账单行沿用自身的 `first_output_ms`、`duration_ms`。

### 派发前分段耗时

`dispatch_phases` 的阶段耗时记录读完请求体到首次派发之间的互斥阶段，单位毫秒，同名阶段累加；重试不重复累计。派发前被明确拒绝的请求冻结到拒绝点；没有完成观测的阶段不填。新记录同时携带 `count_version=2` 和 `dispatch_count` 元数据（不是毫秒）：统计所有平台实际启动的上游发送尝试，包含拨号失败和底层重发；无账单记录也可用此字段核对发送数。插件有过提交时另存 count_inexact=true（精确时省略）：成功或 request_sent=true 计 1，明确未发送计 0；单发补偿必须同时检查计数为 1 且精确。WS 新 turn 重置计数，同一 turn 内继续累加。历史无版本的记录保持旧口径，非 OpenAI 历史 0 不回填；详见[真实上游发送次数](gateway-resilience-observability.md#真实上游发送次数)。

| 字段 | 阶段 |
|---|---|
| `body_decode_ms` | 收完请求体后的剩余读取、解压 |
| `ingress_validation_ms` | 入口编码、规范化与模型校验 |
| `routing_validation_ms` | 路由、处理器读取与校验 |
| `user_admission_ms` | 用户槽位、计费准入、会话准备 |
| `account_selection_ms` | 选号 |
| `account_admission_ms` | 账号槽位、排队重选与准入终检 |
| `upstream_prepare_ms` | 上游请求构造与协议转换至发送 |

`pre_dispatch_ms` 是从入站起点到首次派发，包含上传；不能把它直接当成这些阶段之和。`body_eof_ms` 可用于分开上传等待与网关内处理。

### 利润判定依据

用量行与无账单行的 `profit_basis` 保存本次请求或 WebSocket 轮次的利润准入事实：`admitted` 对应最后真正发送的账号，`vetoes` 保留最近 8 条否决。未发送的候选不会覆盖已发送依据。

每条含 `account_id`、售价倍率 `sell`、上游倍率 `upstream`、来源 `source`、上限 `ceiling`、下限 `floor` 和结论 `verdict`。`source=upstream_probe` 表示采用可计算的探测值，`oauth_setting` 表示 OAuth 调度倍率设置，`stored` 表示存储倍率；未设的上下限可为空。固定号的结论为 `pinned`，不能据此推断利润为正。该快照解释当时为何准入或否决，不按当前账号倍率重算历史。

## 缓存读取占比

用量日志记录的是**计费用量**，页面显示的是**缓存读取占比**，不是上游真实的缓存命中率：

```text
缓存读取占比 = cache_read_tokens
             / (input_tokens + cache_creation_tokens + cache_read_tokens) × 100%
```

三类输入 Token 是互斥桶：`input_tokens` 是未缓存输入，`cache_creation_tokens` 是缓存创建，`cache_read_tokens` 是缓存读取。OpenAI 原始总输入含缓存明细，写入时已经减去缓存读取与创建；Anthropic 的输入本来就不含缓存桶。自行计算时不要再扣一次缓存，也不要把 `cache_creation_5m_tokens`/`cache_creation_1h_tokens` 再加到已经包含它们的创建总量上。

Gemini 的 prompt 计数包含缓存读取：未缓存输入按 `max(prompt - cached, 0)` 记录，不会出现负数；缓存读取保留原值。流式响应中某个计数缺失时沿用之前的值，明确给出的修正值（包括 0）会覆盖之前的值。

- 强制缓存计费和账号“缓存写入计费分类覆盖”会改变持久化的计费桶，因此这组数字不能还原真实上游命中情况，也不能当作请求命中次数占比。
- 趋势和区间统计先累加三类 Token 再套用同一公式，不平均各请求的百分比。例如一个 100 Token 全命中请求与一个 900 Token 未命中请求，区间占比是 10%，不是 50%。
- 没有有效输入（分母为 0）或字段异常时，用量明细显示 `—`，Token 趋势保留断点；有输入但没有缓存读取时才显示 0.0%。
- 渠道监控的用户接口隐藏了分子分母，对无有效输入返回 0，无法区分“无输入”和“有输入但未读取缓存”。

Anthropic 的 5m/1h 创建桶是 `cache_creation_tokens` 的明细，不应再与总量重复相加；OpenAI 网关原生 Anthropic 路径也按上游实际桶计费并保留明细。

**Anthropic 缓存 TTL**：用量接口返回 `anthropic_cache_ttl_policy`（`off`/`5m`/`1h`）与 `anthropic_cache_ttl_applied`（布尔），历史记录和非目标出口为 `NULL`，使用记录页面不显示。`applied=true` 只表示最终请求的缓存声明都符合指定 TTL，不表示供应商采用了该 TTL 或命中了缓存。价格与计费规则见[提示词缓存](caching.md)。

## 请求与实际推理档位

请求档位记录调用方的原始意图（包括显式 `none`）；HTTP 请求的实际档位只取最终发给上游的请求正文中的显式字段。两者分别保存，参数映射后不互相覆盖。模型不支持的普通档位按最近可用档位映射；只有 thinking 模式或预算时不推导计费档位。

HTTP 请求的正常结果与带部分用量的失败结果用同一个实际档位计费。`max`、`xhigh` 按各自已配置的倍率计；`ultra` 原值记录，倍率为 1；实际档位为空（正文没有档位字段、字段被删除或取值无法识别）时倍率为 1，不用请求档位、模型名后缀或 `thinking.enabled` 补值。

WebSocket 请求继续沿用既有档位与计费规则，仅通过模型名后缀指定的档位仍会参与记录与计费。

## 价格来源与版本

使用记录的 `pricing_source` 保存本次结算真正命中的模型键、查价来源、内容版本与有效单位价。分组或渠道只覆盖部分价格时，快照同时保留基础价卡及逐字段覆盖来源；图片与按次价格也保留实际单价。响应自报模型只有被既有计费规则采纳后才替换来源。记账恢复时沿用请求当时保存的价格，不重新查价。展示、估价和余额预留不记录回退告警，实际入账的回退才记录。

远程价格同步以实际下载正文的 SHA-256 作为内容版本和同步锚点。远端 hash 与正文暂时不一致时，仍可加载校验通过的正文，但不会提前确认尚未下载的版本；下一轮继续检查并下载更新。本地 fallback、override 文件变化按各自内容指纹重新加载。冷启动采用 fallback 文件时保留该来源，缓存重载后不变；旧缓存无法证明来源时留空。

价格目录、已配置的 fallback 与 override 都在整版校验通过后发布。有价条目的单价必须是有限非负数；出现文本 token 基础价时须同时提供输入与输出维度；只有缓存价而没有 token 或图片基础价的条目按原规则跳过，合法图片价和 embedding 输入价按各自维度校验，显式 `0` 是有效价格。局部 override 先与基础条目合并，再校验最终价格；配置文件缺失、损坏、非对象或独立覆盖项缺价时保留最后一个有效版本。撤销覆盖可将 override 内容改为 `{}`。首次启动没有有效价格版本且配置文件校验失败时，需修正文件后重启；升级前应检查已配置的 override 文件。

## Token 吞吐量

渠道监控和运维流量卡的 **Token 吞吐量（tokens/s）** 是统计窗口内全部计费 Token（输入、输出、缓存创建、缓存读取）除以窗口秒数。它随并发量变化，不能与单次请求平均 TPS 直接比较。渠道监控的 `TPM ÷ 60` 与之等价。

## 显示与公开

“系统设置 → 功能开关 → 管理员使用记录”控制缓存读取占比和平均 TPS 两项指标的显示，只影响显示，不影响统计与计费。

| 设置键 | 默认值 | 作用 |
|---|---|---|
| `admin_usage_cache_hit_rate_enabled` | 开 | 显示缓存读取占比。关闭后对管理员和普通用户都不显示 |
| `admin_usage_token_speed_enabled` | 开 | 显示平均 TPS。关闭后对管理员和普通用户都不显示 |
| `usage_cache_hit_rate_public` | 关 | 打开后普通用户的使用记录也显示缓存读取占比 |
| `usage_token_speed_public` | 关 | 打开后普通用户的使用记录也显示平均 TPS |

公开设置（`GET /api/v1/settings/public`）只给出生效结果 `user_usage_cache_hit_rate_enabled`、`user_usage_token_speed_enabled`：显示开关与公开开关都打开才为 `true`。管理员自己的“我的账户 → 使用记录”属于用户页面，同样按公开状态显示。用户接口本来就返回计算所需的 Token 与耗时，公开只决定页面是否展示，不是数据权限控制。

## 请求与实际推理档位

使用记录中，请求档位保留调用方写的原值（包括显式的 `none`）；实际档位是网关按[推理档位策略](groups.md#推理档位策略)处理后，最终发往上游的正文里显式写的档位。正文里没有档位字段时，实际档位为空，不从模型名后缀、默认值、thinking 模式或预算推出来。

## 结果

管理员使用记录（**使用记录 → 用量明细**）一次用户请求一行，失败与取消的请求也在其中。

| 列 / 标记 | 含义 |
|---|---|
| 结果 | 成功；已救回（至少实际发送两次，前次失败，最终完整交付）；失败（全部尝试失败、交付途中出错、号这一侧不可用）；已取消（用户自己断开）。升级前的记录与下列已知局限中未接入的请求类型显示“—” |
| 换号 n 次 | 相邻两次尝试换了账号的次数；同号重试不算 |
| 兜底 | 这次用的是该组此刻在后排的号（见 [分组质量门槛](group-quality-gate.md#选号)） |
| 接管 | 这一轮是会话被接管到新账号的那一轮 |
| 延迟 | 用户等待显示为灰色。色条上、下两端分别按末次首字和末次耗时着色。缺少末次首字时整条按末次耗时着色，缺失的耗时用灰色表示 |

- 用户自己的并发、额度、限流、鉴权等在选号之前就被拒的请求不进使用记录，看运维错误记录。
- 有尝试记录的行可展开，列出试过的每个号：账号、发出时间、首字、耗时、结果、报错类别。尝试记录只覆盖 OpenAI，保留 7 天。终态、状态码来源和报错类别与请求是否成功交付分开：正常完成不会因清理读错误判失败；单次交付即使有质量失败也不标“已救回”。非流式响应写入失败会记录客户端断开；原生 Anthropic 非流式出口在写出前已保存换算后的用量，写失败时输入、缓存读写仍保留。发送过程中 panic 不会把零值返回误记成成功，网关或未知类别不计入账号失败。
- WebSocket 实际拨号或握手失败也会记尝试，握手状态按真实上游来源归类；复用连接、本地排队满、等待连接超时或取消不新增拨号尝试。拨号失败不算实际发送，不能仅凭尝试条数推断“已救回”。
- 筛选新增“结果”；“账号”筛选的是最终账号。计费类筛选只匹配有账单的行。
- 顶部汇总的请求数、成功 / 已救回 / 失败、用户等待 P50 与样本数、缓存和费用都按当前筛选统计。
- 没有账单的请求存在表 `gateway_unbilled_requests`，保留期与使用记录相同。
- Responses、Chat、Messages、Images、Embeddings 与 Alpha Search 在准入后追踪网关请求 ID。Responses、Chat、Messages 的文本请求将 `request_scope` 记为 `text`。这三个入口的明确生图请求和 Images 记为 `image`，Embeddings 记为 `embedding`，Alpha Search 记为 `search`。分组近 60 分钟的文本统计只计 `text` 和历史空范围，旧记录不回填。
- Alpha Search 的成功收费行保存 `gateway_request_id` 与 `result`；准入后失败或取消且没有账单时，写一条未计费尾记录。金额与扣费规则不变。
- 显式文本请求在客户端断连、还未交付内容、已取得上游用量且明确免收时，也会用同一网关请求 ID 写一条未计费尾记录，范围为 `text`，结果为 `canceled`。
- 已知局限：WebSocket 直通二进制帧、`count_tokens` / `input_tokens`、独立 Web/X Search、SystemOne、Grok 媒体/语音/Realtime、Live 与批量图片入口的计费记录没有请求编号和结果。
- 每个请求只写一行：有账单时写使用记录，没有账单时写 `gateway_unbilled_requests`；记账失败时不再另补一行无账单记录。

原生非流式 Images 按实际返回的有效图片数收费：同一对象的非空字符串 `url` 或 `b64_json` 只计一张，不沿用请求的 `n`。零张图片不收按图或按次组件，已观测的真实 token 用量仍独立结算；空产物按失败记录，不重放生图。

## 用量与完成证据

用量行与无账单请求行保存 `usage_observed`、`usage_source`、`terminal_event_seen`、`terminal_event_valid`、`response_body_type`。这些是上游原始响应的内部证据，不改变发给客户端的用量字段、计数或原有合计。

- `NULL` 表示未知或历史记录；已观察到 usage 缺失、null 或空对象时为 `usage_observed=false`，合法计数明确为零时为 `true`。不从 Token 数、HTTP 200 或费用推导。
- `usage_source` 为 `missing`、`upstream_json`、`upstream_sse_terminal` 或 `upstream_sse_progressive`，对应实际保留的计数来源。
- JSON 响应的终态两位为 false；SSE 缺终态为 false/false，非法终态为 true/false，合法终态为 true/true。这些位不代表已送达或应当计费。
- `degradations` 在用量行、无账单行与错误行保存 `{field,action}`，动作仅为 `omit/map/default`，不保存原字段值或请求正文。
- 记账任务中途失败后恢复时，沿用请求当时保存的上游事实与价格快照，不重新判断用量来源或重新查价。

## 容量列的分组并发

账号列表和分组列表的容量列可以显示“当前并发 / 总并发 / 本分组并发”。绿色的第三个数是这些账号当前正在处理、且归属于该分组的请求槽位数；账号同时属于多个分组时各分组显示各自的数量，“当前并发”仍是账号的实际总槽位。第三个数不会超过第一个数；并发上限为 0（不限制）的账号没有槽位记录，第三个数始终为 0。

账号页只有筛选了一个具体分组时才显示第三个数；分组页每个分组都显示。读取失败时显示 0，不影响请求处理。已知局限：部分等待路径按 API Key 的分组而不是实际调度分组计数，回退分组下可能少算（不会多算）；智商检测和 Codex 工单的后台探测不计入任何分组。

## 运维看板的 SLA

运维看板的“SLA（排除业务限制）”只计状态码 ≥400 且没有标为业务限制的错误请求。

- **业务限制**（不计入 SLA）：用户自身条件或本地策略导致的失败，包括余额与额度、订阅、用户并发与 RPM 限制、Key 鉴权与 IP 限制、分组策略、本地模型配置（分组模型白名单、账号模型映射），以及上游的内容安全拒绝（内容拒绝的 code/type，或 400、403、451 上的内容安全文案，带账号措辞的除外）。
- **计入 SLA**：选号阶段找不到可用账号（无号 503，阶段 `routing`）、组内没有账号支持所请求的模型、`invalid_prompt`、普通 400 与上游 5xx。

快层确认的输出后失败（读流出错、缺终态、带内 `stream_failed`、停滞）会补记失败证据并归因到上游供应商。确认失败后客户端才取消、最终为 HTTP 200 的请求，与换号后恢复的请求一样写一条 2xx 恢复行：不计入错误总数、SLA 与请求错误列表，计入上游错误率与供应商错误列表。上游错误率按责任方 `provider` 统计并排除 429/529。详见[网关韧性](gateway-resilience.md)。

## OpenAI 服务档位

使用记录的服务档位取结算档。新版记录在 `service_tier_details` 保存证据版本、客户档位及其存在状态、出站档位、上游声明档位、结算档位、计费模型、倍率来源、赠免档和实扣。发生封顶时可查看封顶原因和对应金额。管理端还可查看分组归因、策略原因和价卡版本。历史记录没有档位证据时显示“未记录”。

新创建的 CSV 和 XLSX 导出追加“服务档位”和“服务档位详情”列。详情是 JSON，用户和受限运营只收到对账字段；管理员可导出完整证据。升级前创建的导出任务保持原有列。档位与价卡编辑见 [分组](groups.md#openai-分组-fast)。

## 后台导出

使用记录导出以后台任务运行：用户导出 CSV，管理员导出 XLSX，两者共用同一个 PostgreSQL 持久化任务引擎。浏览器只提交任务、查询状态和发起原生下载，不再逐页读取历史记录。

### 启用与配置

`usage_export.enabled` 默认 `false`，只控制新建任务；已有任务继续处理，完成的文件仍可下载。所有实例必须使用一致的配置；修改后需要重启生效。

| 配置键 | 默认值 | 说明 |
|---|---|---|
| `enabled` | `false` | 是否允许新建导出任务 |
| `allowed_user_ids` | `[]` | 非空时只有名单内的用户（含管理员）可以新建；空表示全部用户 |
| `directory` | `./data/usage-exports` | 本地存储目录。设置了 `DATA_DIR` 且未改默认值时为 `$DATA_DIR/usage-exports` |
| `concurrency` | `2` | 同时执行的任务数，取值 1–32 |
| `queue_limit` | `100` | 排队上限 |
| `max_rows` | `1000000` | 单个任务最多行数，不能超过 1,000,000；超出返回 `EXPORT_ROW_LIMIT`，不发布截断结果 |
| `max_file_bytes` | `536870912`（512 MiB） | 单个文件上限 |
| `task_disk_bytes` | `4294967296`（4 GiB） | 单个任务暂存磁盘上限 |
| `storage_bytes` | `21474836480`（20 GiB） | 已发布文件的总存储预算 |
| `free_bytes` | `2147483648`（2 GiB） | 需要保留的磁盘空闲空间 |
| `read_seconds` / `run_seconds` / `queue_seconds` | `300` / `900` / `1800` | 读取、执行、排队超时 |
| `retention_seconds` | `86400` | 完成文件的有效期 |
| `metadata_seconds` | `604800` | 任务记录保留时间 |
| `create_rpm` / `status_rpm` / `ticket_rpm` | `5` / `60` / `10` | 每用户新建、查询状态、申请下载凭证的每分钟次数 |
| `download_concurrency` | `2` | 同时进行的下载数，取值 1–32 |
| `storage.type` | `local` | `local` 或 `s3` |
| `storage.endpoint` / `region` / `bucket` / `prefix` / `access_key_id` / `secret_access_key` / `force_path_style` | 空 / `auto` / 空 / `usage-exports/` / 空 / 空 / `false` | S3 兼容存储的独立配置 |

这些键不在 `deploy/config.example.yaml` 中，需要时在配置文件里加 `usage_export:` 段，环境变量写法见[配置文件与环境变量](../deployment/configuration.md)。

**存储要求**

- 本地目录必须可写、不是 Web 静态目录，并有足够空间；不要用 `/tmp`。其中 `files/` 是发布的文件，`tmp/` 是暂存。多实例使用本地存储时必须挂载同一个共享目录。
- 使用 S3 时，bucket/prefix 应为私有；仍需要本地暂存磁盘。请为 bucket 配置对象生命周期和未完成分片清理，保留时间不短于 `retention_seconds`。
- 临时文件增长按周期监测，请用独立卷或文件系统配额提供硬上限。
- 数据库连接池需要容纳执行槽的会话锁、快照事务、心跳和正常业务连接。不要用事务池模式的 PgBouncer，它无法承载会话级 advisory lock。

### 工作方式

- 每个用户最多一个活动任务（含排队）。新建时在一个事务里检查队列、总存储预留和用户预算；相同 `Idempotency-Key` 且参数相同的活动任务不重复创建。已完成的任务再次创建会得到新快照。
- 读取在单个 `REPEATABLE READ READ ONLY` 事务中进行，通过数据库游标每批 2,000 行，关联名称在同一事务里读取，得到一致快照。读取中断或进程丢失的任务直接失败，需要新建，不跨快照续读。
- CSV 带 BOM、标准转义和公式文本防护；XLSX 为流式单工作表，文本与长数字作为字符串，金额按原列精度。发布前校验文件并计算 SHA-256 与长度。
- 后台每秒检查心跳、取消和临时目录预算，每分钟处理排队超时、失联任务、过期文件和孤儿暂存。逻辑过期或删除立即禁止下载。

### 接口

用户接口前缀 `/api/v1/usage/exports`，管理员接口前缀 `/api/v1/admin/usage/exports`。管理员导出另需普通管理员权限中的“使用记录”查看权限和“导出业务数据”开关（见[管理员与权限](admin-permissions.md)）。这些控制接口不计入 Heavy 限流额度。

| 方法 | 相对路径 | 行为 |
|---|---|---|
| `POST` | 空 | 创建任务，必须带 `Idempotency-Key`，返回 `202`；键冲突返回 `409` |
| `GET` | 空 | 最近 24 小时创建的任务分页列表 |
| `GET` | `/:id` | 状态、阶段、计数、快照、大小、过期时间 |
| `POST` | `/:id/cancel` | 取消排队或运行中的任务 |
| `DELETE` | `/:id` | 删除终态任务，立即撤销下载 |
| `POST` | `/:id/download-ticket` | 为当前登录会话签发 60 秒的一次性下载凭证 |
| `GET` | `/:id/download` | 浏览器原生流式下载 |

下载凭证通过 HttpOnly、SameSite=Strict、限定路径的短期 Cookie 传递，不出现在 URL、JSON 或访问日志里，服务端只保存其 SHA-256。兑换时重新检查创建者、账号状态、登录会话和管理员角色。不支持断点续传；下载失败后重新申请凭证下载同一文件即可，无需重新生成任务。

前端在有活动任务且页面可见时每 5 秒查询一次状态，隐藏或离开页面后停止查询，任务在后台继续。`429` 遵守 `Retry-After`。

常见错误码：`EXPORT_DISABLED`、`EXPORT_ALREADY_ACTIVE`、`EXPORT_QUEUE_FULL`、`EXPORT_STORAGE_FULL`、`EXPORT_RATE_LIMITED`、`EXPORT_IDEMPOTENCY_KEY_REQUIRED`、`EXPORT_IDEMPOTENCY_CONFLICT`、`EXPORT_ROW_LIMIT`、`EXPORT_SIZE_LIMIT`、`EXPORT_TIMEOUT`、`EXPORT_QUEUE_TIMEOUT`、`EXPORT_INTERRUPTED`、`EXPORT_NOT_READY`、`EXPORT_EXPIRED`、`EXPORT_INVALID_TICKET`。

### 观测

任务表记录排队时间、读取进度、快照、完成时间、文件大小、失败码和存储预留；结构化日志记录任务 ID、条数、执行耗时和下载字节数，不记录正文、凭证或存储密钥。建议观察排队与执行数量、失败与取消率、长事务、磁盘和下载流量。后台任务成功不等于用户下载成功。

建议先用 `allowed_user_ids` 对少量用户启用，在与生产相同的数据量下确认耗时、内存和磁盘占用后再全量开放。

### 停用与回滚

依次关闭 `enabled`、等待或取消活动任务、停止服务，再回滚应用。导出相关表由迁移 `252_usage_export_tasks.sql` 追加创建，回滚时不需要删表。

## 计量、结算与采购成本

用量表中的 token 和客户金额表示各自计量与结算口径；OpenAI 自愿补偿仅减少客户结算金额，原始 token、采购成本与账号配额不随抵扣减少。Claude/Gemini 现有缓存与 TTL 结算以及未送达 abuse 费用保持原公式。

管理员 API 新增两个字段（普通客户 API 不暴露采购价）：

- `supplier_cost_estimate`：可空金额，按补偿前的原始计量估计最终已观测尝试的采购成本，已包含账号倍率；NULL 表示未知或历史行，0 表示确认免费，不能再次乘倍率。
- `metering_adjustment`：可空 JSON，保存原始用量及 presence/source、调整类型、补偿前客户价 `customer_gross_cost`、净调整额 `customer_credit` 和采购来源 `supplier_cost_source`（contract/mirror/catalog/fallback/unknown）。TTL 与缓存补偿分列；abuse 旧公式的差额另列。无调整且成本已知时省略，成本未知时保留来源标记。净调整额由同一计价函数的前后结果求差；不是供应商发票或全链毛利保证。

后台看板和统计优先采用 `supplier_cost_estimate`，缺失时回退到 legacy 口径：`COALESCE(account_stats_cost,total_cost) × COALESCE(account_rate_multiplier,1)`；历史记录不回填。管理员 XLSX 导出版本 3 使用同一口径并附采购估计与计量调整两列，旧版本 1/2 仍可按原口径复现。普通客户 CSV 不包含这两列。

### OpenAI 换号后的缓存补偿

OpenAI text 请求因网关主动换号、提交迁移/接管/首输出交接或释放属主后，下一张落在新账号上的账单可获得缓存缺口补偿。释放到空属主时，新账单账号须不同于原账号；动作保留一小时，只供一张账单消费。客户自行换前缀、普通缓存未命中、未提交及身份/分组冲突不属于此范围。

参考为同 Key、组、路由会话、模型在网关动作前最后一张成功账单的缓存读比例；参考距本次账单不超过十分钟，且总输入比在 0.75–1.33 之间。总输入包含普通输入、缓存读和缓存写。缺口按同一价卡、倍率与服务档位规则重算客户金额，冻结后的参考不被后续冷请求覆盖。

仅实际发送一次且计数精确、无失败尝试、成功完成且采购成本已知的账单自动抵扣。抵扣后的收入不得低于采购估计成本除以 1−分组最低毛利；最低毛利使用选号时实际生效的利润门分组快照，关闭时按 0、配置未知时仅记凭证，补偿前已经越线时补 0，不额外加收。多发、请求内换号、插件等路径的发送计数不精确或成本证据缺失只在 `metering_adjustment` 保存待结算凭证与估计金额，实际扣费不变。它是自愿补偿政策，不代表供应商发票核对后的实际毛利保证。

自动抵扣减少余额或订阅用量、Key 配额及限额消耗，原始用量、采购成本与账号配额不变。动作按账单请求身份原子领取并保留一小时，SQL 意向提交前失败可重新读取同一动作；意向提交后恢复与重放复用冻结金额。独立 Redis 参考与动作键分别过期，不影响准入和余额预留；Redis 不可用或写入失败时按无参考处理，补偿为 0。
