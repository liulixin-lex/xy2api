# 分组质量门槛

OpenAI 分组用首字上限、报错上限、缓存下限判断账号质量。三条线独立给出**达标、未知、试用、后排**身份；后排仍可兜底，不等于停调。选号与接管见 [调度](scheduling.md)。

当前规则版本为 3.1。

## 生效范围

| 内容 | 范围 |
|---|---|
| 质量分层、试用、质量迁移 | OpenAI 平台分组 |
| 判定用的尝试记录 | OpenAI 文本请求：Responses（HTTP 与 WebSocket）、Chat Completions、Messages 兼容；图片、Embeddings、`count_tokens`、Alpha Search、live 不采样，也不分层 |

- 身份按**账号 × 模型 × 分组 × 线**保存；请求样本按账号 × 模型汇集，保留实际执行分组。不同分组可以用同一窗口里的真实请求，按各自门槛判定；没有会话的请求也记录实际分组。
- 每次真实上游尝试归到执行它的账号，WebSocket 实际拨号或握手失败也记录；复用连接、本地排队满、等连接超时、取消不额外记拨号尝试。拨号失败不算实际发送。首字按尝试取证；报错按同一请求在同一账号、模型上的最终结果归并。
- 不发主动探测。账号新加入或重新加入分组时，从当前窗口判定，不继承已移除的身份与档位。
- 重启后恢复已保存的身份、档位、期限，并分页加载最近 250 分钟证据，再从保存的评估时刻与证据窗口起点中较晚者继续。重启后加载完成前不按质量分层，总开关配置保持原值；进度与完成状态看 `sched_quality.loading`，见 [质量状态日志](gateway-resilience-observability.md#质量状态)。0.6.9 起的 v2 及更新样本照常进入判定窗口。0.6.9 之前的旧版采样（v1）只保留原始记录供查询。

## 设置

### 分组门槛

**分组管理 → 编辑 OpenAI 分组 → 质量门槛**：

| 界面 | 字段 | 范围 / 含义 |
|---|---|---|
| 质量门槛 | `enabled` | 三条线是否生效 |
| 首字上限 | `ttft_seconds` | 有限且大于 0 的秒数，从发给账号到首个有效输出 |
| 错误上限 | `max_error_rate` | 5%–100%；接口按比例传值 |
| 缓存下限 | `min_cache_ratio` | 0–100%；接口按比例传值 |
| 接管 | `takeover_idle_seconds` | 关 / 立即 / 5 / 15 / 30 分钟；从未设置的分组为 15 分钟，见 [会话接管](scheduling.md#会话接管) |

设置保存在 `group_quality_gate_policies` 的 `groups.<分组 ID>.v4`。保存要带整份设置的版本，冲突返回 409。保存前的“试算”用当前证据分别评估现行门槛和新门槛，列出每条线达标、未知、不达标的数量变化及变化账号；它不预测保存后的身份。保存分组门槛或全局首字规则前，会先按旧配置处理完积压至当前处理水位，再保存并重判；补跑失败则保存失败。

- **放宽**：提高首字或报错上限、降低缓存下限。只清被放宽线的身份、档位和入场记录，用当前窗口重判；保留最近确认不达标的时刻，供整组判断何时清档。首字线仍不达标时当场进后排；报错线和缓存线须之后连续两次普通评估都不达标才进后排。再次进后排时，其他线没有记录就从第 1 档开始，否则从组内保留的最高档升一档，最多第 5 档。
- **收紧**：已有身份不立即改变，之后按新门槛评估；报错线和缓存线仍须连续两次不达标。
- 关闭分组门槛会清除该分组质量状态与试用名额，关闭期间不判该分组的三条线，也不按质量分层；其他分组照常判定，接管仍按独立的接管设置。移出分组或删除账号也会清理对应状态。

分组的“仅允许 OAuth 账号”阻止新增 API Key 账号绑定，已有成员仍可调度，也可保存不新增绑定的其他改动。从其他分组复制成员时直接跳过不符账号。开关打开时，界面显示组内已有几个不符的成员。

### 阈值说明

编辑分组的“质量门槛”在各项旁边写明下面这些，都按已保存的设置显示（错误上限的数字取 `GET …/groups/:id/policy` 的 `effective_max_error_rate` 和 `error_trip_examples`，由判定用的同一个函数算出，保存后的响应也带），改了还没保存的值不影响它们，保存成功或重新载入后才更新：

- **错误上限**：生效的上限是分组上限和 5% 里较大的那个。上限 5% 时，50 个明确结果里至少 6 次失败、或 100 个里至少 10 次失败，才判坏一次；进后排还要相邻两次普通评估都判坏；进过后排的号恢复时，实测失败占比不能高于上限。上限很高时只列真能触发的示例：50 个全失败也判不坏就只写 100 个的那一项，100 个全失败也判不坏时写“100 个明确结果内不会判坏一次”。
- **缓存下限**：设在 85% 以上的分组，号在线附近反复进出的情况更集中（这是观察到的关系，不是规则）。已保存的下限高于 85% 时界面提示。
- **试用**：试用通过不代表稳定，只说明试用期间没有证据表明它差，之后照常评估。

### 首字线判定

**系统设置 → 网关服务 → 网关调度设置 → 首字线判定**对全部 OpenAI 分组生效：

| 界面 | 字段 | 默认 | 合法范围 |
|---|---|---|---|
| 把握 | `confidence` | 80% | 大于 50%、小于 100% |
| 容忍 | `tolerance` | 20% | 大于 0%、小于 100% |
| 比同伴高出 | `peer_margin` | 5 个百分点 | 不小于 0、小于 100 个百分点 |

任一数调高都算放宽：全部首字线按上面的放宽规则重判；同时有升有降也按放宽处理。只调低时，已有身份不动。界面提示经过回放的范围：把握 80%–95%、容忍 20%–25%、比同伴高出 5–15 个百分点；超出后提示“没有数据支持”。

### 全局开关

“质量调度”（`sched_quality_enabled`）默认开。关闭后，质量分层、试用限制、质量迁移与接管不生效；引擎仍照常判定并保存状态，记录与证据展示继续。质量视图过期时也暂停自动分层，界面提示“数据过期”。倍率区间、账号停调等准入条件照常检查。

## 状态

| 身份 | 如何进入与退出 |
|---|---|
| 达标 | 证据足够且通过本线；窗口滑动后证据不足会回到未知 |
| 未知 | 没有样本、证据不足或无法确认；正常参与选号，不限量 |
| 试用 | 后排到期，复核达标或不知道时进入；只用试用开始后的证据，按下文五项依次判断 |
| 后排 | 确认不达标，进入有期限的停留期；期内不提前放回，到期用新证据复核 |

三条线中任一条后排，合成位置就是后排；否则任一条试用就是试用；其余在前排。账号列表与分组汇总把前排继续分成“有一条线达标”的达标和其余未知。停调与豁免单独显示，不能用总体首字或报错数代替逐线身份。

## 判定

### 首字线

首字线**只用流式请求**。非流式不提供首字证据；只有非流式流量时首字线一直未知，账号“近期状况”的首字显示“—”；以非流式为主时也可能长期证据不足。

首字指从请求发给账号到**首个有效输出**，不含客户端上传和网关派发前等待。正文、拒答、推理文字或摘要、加密推理内容、有内容的工具名字或参数都可算；可识别的托管工具调用条目也可算。纯空白与不可见字符、空增量、角色帧、只有 ID 或签名、用量、保活、进度、空结束标记不算。不认识或有歧义的事件不当作有效输出，不设字符数门槛。

- 样本半衰期 30 分钟，最多看 4 小时；越新权重越高。小样本向同组同模型总体水平收缩，先验强度相当于 5 条样本。
- 用默认设置判不达标，须同时满足：有 80% 把握超限占比高于 20%；有 80% 把握比同组同模型的前排同伴高出 5 个百分点以上；超限来自至少 2 个会话。一次确认即可进后排。
- 判达标须折扣后样本不少于 20 条、至少 3 个会话；把结果不明样本都按超限算，估计占比仍不高于容忍，且没有确认比同伴差到规定幅度。
- 没有可比同伴，或前排同伴明确样本折扣后合计不足 20 条，保持未知；同伴包括达标、未知、试用号，不含后排。其他证据不足或计算未收敛也保持未知，面板显示原因。
- **结果不明**：没有观测到有效输出，且首输出超时时已等时间尚未达到本组上限，无法确定它最终会不会超限。这类样本不当作已确认达标；判达标时按超限处理。
- 首输出超时只在已等时间达到本组上限时提供超限证据，大输入用同一上限。换号后的首次尝试通常不进入首字判定。会话回到原归属号、等够本档时限仍无有效输出的超时，从 0.6.10 起计入首字判定，旧样本不追溯。

首输出守卫在已有守卫的 HTTP 路径使用相同内容判据：默认配置下，已识别的无效前奏先暂存，有效输出或终态提交后解除；未知事件保留原有转发方式，提交时也解除，采样仍不算有效输出。关闭相关前奏开关会恢复对应路径的原有提交方式。WebSocket 直通不增加前奏暂存，保留既有守卫行为。三个时间的含义见 [使用记录](usage.md)。

### 报错线

| 类别 | 是否计入失败 |
|---|---|
| 真实上游服务失败：5xx、连接或读写失败、明确过载或处理失败 | 计入；明确的处理失败即使包装成 400 也按原因归类 |
| 已开始有效输出后失败、没有正常结束 | 计入“输出中途中断”；非良性的 incomplete 即使已交付也可算质量失败 |
| 明确鉴权失效、余额或额度耗尽 | 计入“账号资格” |
| 明确账号限流、并发限额、上游号池耗尽 | 计入“账号容量”，按账号 × 模型 |
| 参数、类型、上下文长度、请求大小或本地拒绝 | 不计入 |
| 工具历史、续接不兼容等迁移造成的 400 | 不计入，单独统计 |
| 模型、协议、请求特征不兼容 | 不计入；只有明确的模型或协议 / 形态拒绝可打能力标记 |
| 首输出截止、网关预算、本地 WebSocket 消息大小上限、客户端取消 | 不计入；首输出截止由首字线判断 |
| 同号修复的中间发送 | 不计入，按最终结果；仅准备修复但未重发不算中间步骤 |
| 责任不清 | 未知，不猜成上游故障 |

看最近 60 分钟的最近 100 个请求名额。同请求同账号的重试按最终结果算一次；未结束、责任不清占未知名额，不用更早请求补位。

- 判达标：至少 50 个明确结果，未知按失败处理后的有把握下限也不高于分组上限。
- 判不达标：不足 50 个按成功补齐后，失败率的 95% Wilson 下界仍高于上限。
- 其余未知。普通评估每 5 分钟一次，连续两次不达标才进后排；中途通过或证据不足重新计数。

状态码与来源分开记录。网关合成的截止状态不能当成上游真实 5xx。WebSocket 实际拨号失败按上游连接失败归类，握手失败按上游真实状态与原因归类，5xx 计入失败；本地 16 MiB 消息读上限触发的失败归网关，不计入。发送过程中 panic 不会误记成功，网关或未知类别不计入账号失败。余额、鉴权等即时停调仍由韧性层处理，不等待统计判定。

### 缓存线

续接轮要求同组、同模型、同会话、同账号，上一轮成功完成，间隔不超过 5 分钟。本轮也成功且输入、缓存读取、缓存写入都已报告才取证；未报告的缓存读取保留为空，不冒充零。

本进程知道还有更近的前序请求尚未入账时，暂不把当前轮算作续接；前序入账后按实际顺序重算。长期表现仍用数据库里已记录的证据。

窗口为最近 30 分钟，按 Token 加权：缓存读取 ÷（未缓存输入 + 缓存读取 + 缓存写入）。至少 20 个续接轮后，命中率不低于下限为达标；低于下限且至少 2 个会话各自也低，才判不达标。整体低但仅一个会话低仍未知。连续两次普通评估不达标才进后排。

## 恢复时间与试用名额

- **停留阶梯**：第 1–5 档分别为 20、40、80、160、240 分钟。
- **到期复核**：仍不达标就升档续期，重新攒证据；达标或不知道都从到期时刻进入试用。自动恢复只有试用一条路。回到正常后先标“未知”（不知道），用回来后的请求重新判断是否达标。
- **取证起点**：后排复核、试用、回到正常后各看自己的时段。同一段证据不带入下一段，请求发起时刻须严格晚于该段起点，并且仍在取证窗口内。缓存判续接可用起点前真实上一轮确认接续，但不计上一轮的命中率。
- **试用名额**：账号 × 模型跨分组共用，通常同时 3 个会话。只限制新会话或本来需要换号的会话，已绑定会话含空闲回来的照常用；其他分组里达标或未知的会话不占名额。无会话请求也临时占一个名额，结束释放。
- **满额**：试用号移到第二层；第一层都不能接时仍可使用，不是硬性并发上限。会话迁走、名额释放或 10 分钟无新请求后回收；单个流式请求结束不等于会话结束。

试用按下表顺序判断，命中即止。同刻先看证据，再处理期限。

| 顺序 | 条件 | 结果 |
|---|---|---|
| 1 | 确认不达标 | 升档进后排，不等第二次 |
| 2 | 已满 15 分钟且达标 | 回正常 |
| 3 | 已到本轮试用期限（新试用为 120 分钟） | 回正常 |
| 4 | 满 60 分钟时，前 60 分钟没有本线可用样本 | 回正常 |
| 5 | 其余 | 留在试用 |

第 4 项只在满 60 分钟的时点检查一次。看本账号、本模型在试用开始后发起、当时已可见的样本，可跨分组：首字线看流式样本（含首输出超时），报错线看已结束且参与判断的尝试，缓存线看严格的续接轮。仍在途的请求也算有样本；资料不全时跳过这项，照常判断其他出口。

**再犯档位**按账号 × 分组 × 实际模型，由三条线共用。进后排或续期时，组内无记录用第 1 档，有记录就在最高档上升一档。同刻多条线确认不达标只升一次，且只把新档位写给这些线，其他线各自的转移和期限照常。整组三条线都在正常位置，且距最近一次确认不达标满 24 小时，才清除再犯档位。

处理晚了按原定时刻补判，缺的历史按不知道；缺少期限的异常记录按发现时到期处理。升级时已在后排、试用里的线保留原定到期时刻，从升级起按新规则走。旧后排到期时达标或不知道，进入新的 120 分钟试用；旧试用到原期限时若未判不达标就放回，也可在满 15 分钟且达标时提前放回。

引擎正常运行且没有人工操作时，按新规则进入后排的组，从最后一次确认不达标起最多再受限 360 分钟；每组任意 12 小时最多从非后排进后排 6 次，续期不计。

## 选号

| 层 | 账号 |
|---|---|
| 第一层 | 达标、未知、有试用名额的账号 |
| 第二层 | 试用名额满的账号 |
| 第三层 | 后排账号 |

每层内部依次：**固定号 → 优先级数值小者 → 已知且低倍率 → 负载低 → 最久未用 → ID**。新会话也按这个顺序选号。要求 compact 的请求先保留“已确认支持优于未知”的能力偏好，再比较这些顺序。

- 分组的“最低上游倍率”与最低毛利率换算的最高倍率共同形成区间。区间外完全不用，含粘性、重试、排队终检与末位兜底；下限独立于利润开关。固定号不受上下限限制，仍受质量三线与其他准入条件限制；固定号高于上限时预览提示亏损。
- 下限排除原号时，老会话换到区间内账号，新号成功后粘住；上限否决保留原绑定。上游倍率优先用可计算的新鲜探测值，算不出时回退存储值。
- 后排兜底仍按同层顺序，使用记录标“兜底”。借号不改原绑定，试用号排在借号候选最后，临时占请求名额。
- **老会话迁移**：报错线后排可迁；首字线后排只有该会话最近连续两个逻辑轮都在同号且超限才迁，重试合成一轮、换号首轮不算；缓存线后排不迁。须有能接的前排或取到名额的试用号，协议允许换号才执行。
- **接管**：达到接管空闲时间后，可由更高优先级的前排号接管；固定标志不参与接管比较，只设为固定不会拉走老会话。目标完成成功后才提交绑定；失败或取消保留原绑定，结果见换号日志。
- 迁移与接管都排除本会话首输出避让期内的目标（含到期时刻，忽略账号重置前写入的避让）。读避让失败就放弃换号；提交时在同一 Redis 脚本中复验。被避让的账号若仍合格，可作末位兜底，只救这一单，归属保留原处。

## 恢复与豁免

- **恢复状态**：清掉该账号全部分组、模型、线的身份、再犯记录与试用名额，取证从重置时刻开始；不删除原始尝试或判定记录，不取消豁免。同时清理可清自动状态与会话避让，返回已清、保留和失败项。人工停用、额度、过期、智商门和共享限制等保留。人工放宽与重置单独处理，不计入自动恢复的时间或频次上界。
- **豁免**：可选一个分组或全部分组，有期限或长期。内部照常判定，生效的豁免让质量后排、试用限制与质量迁移不生效；不绕过倍率、能力或停调。到期自动恢复质量规则。
- **停调**：手动或自动停调优先于质量位置；停用账号不特殊清空质量，身份按各自期限推进。要立即重判用恢复状态。

## 能力不兼容标记

上游一次明确拒绝模型、协议或流式 / 非流式形态，且尚无有效输出时，可留下标记。同一账号、上游模型、协议、形态的请求在 24 小时内避开它；模型拒绝覆盖该协议下两种形态。输入模态、客户端或工具等请求特征不兼容只归类，不扩大成整类标记。流内拒绝只在本次尝试最终以能力拒绝失败时落标记；之后成功、客户端断开、取消、网关截止或本地失败都不打。握手响应明确拒绝模型或协议时也可打标。

同键一小时内不重复写；被人工清除或满额淘汰后，再遇明确拒绝可重新记录。到期后由同类真实请求重新检验。账号平台、类型、凭据改变立即失效；只改优先级、并发或倍率不清。质量面板“自动状态 → 能力不兼容”可单独清除；恢复状态与清能力学习接口也可清除。显式生图、压缩和按模型分流协议等路径有自己的能力路由，不统一按此标记处理。

## 界面

### 账号列表

- 分组圆点的界面叫法是“正常、后排、试用、未知、豁免、停止”；“停止”与“豁免”优先显示，没有该组数据按“未知”。圆点“正常”对应质量达标。筛选为“正常、后排、试用、未知、豁免”，“正常”要求未停调、至少有一个 OpenAI 分组，且各 OpenAI 分组状态都是正常。
- 豁免只取消所覆盖分组的后排、试用效力；该分组有一条线达标时状态为正常，否则未知。“豁免”筛选单独匹配有豁免的账号，因此“正常”或“未知”筛选结果里仍可能看到优先显示的豁免圆点。
- “近期状况”按“首字 / 报错 / 缓存”三行汇总本账号近 1 小时各模型、各分组的实际流量，重置可缩短这个窗口。数值只描述近期流量，不参与门槛判定和选号。门槛按账号 × 模型取证，使用各分组的阈值和各线的窗口，所以分组圆点可能与近期读数不一致，判定结果看圆点。模型构成会影响读数，例如推理模型占比高时首字可能更长。网关首字等待时限改变时，超时次数和首字读数也可能变化。
- 悬停提示标题为“近 1 小时”，窗口因重置缩短时显示“HH:MM 起”。每行无数据时显示“—”，置灰时标注“样本不足”。
  - **首字中位**按近 1 小时有有效输出或超时的流式尝试统计。有输出的按首字耗时排序，超时排最后，偶数取中间靠前的样本。超时过半显示“超时”，恰好一半仍显示秒数。未出内容就报错或取消的尝试不计，出内容后中断或取消的照计。列出样本次数，少于 20 次置灰。
  - **超过 10 秒**显示慢尝试的占比和次数，并注明其中的超时数（有超时时）。有输出的尝试在首字严格超过 10 秒时算慢。超时只有等满 10 秒才计入分子和分母。分母少于 20 次置灰。
  - **报错**显示明确结果中归因于本账号的失败占比，并列出这类失败数 / 明确结果数。同一请求在同一账号和模型上的重试按最终结果算一次，少于 50 个明确结果置灰。
  - **缓存·续接轮**显示成功续接轮中缓存读取占输入 Token 的比例，以及纳入统计的轮数。只有完整上报输入、缓存读取和写入量的轮次才计入，少于 20 轮置灰。
- 悬停“近期状况”查看四行统计，点分组圆点打开质量详情。面板的“近期状况”显示同样四行，各分组门槛在“各分组”查看。面板使用“停调、豁免、前排、试用、后排”等位置名，三线身份为“达标、未知、试用、后排”。“各分组”按分组 × 模型列合成位置及三线身份，展开看样本、阈值、同伴证据、“为什么是未知”、“证据来自分组”和[最近评估](#为什么没判)。判定记录可展开证据、翻到更早记录。质量调度总开关关闭或本分组没开门槛时，面板显示“门槛已关闭”。
- 账号列表的分组提示、质量面板和长期表现明细都按实际时间显示：后排写第几档、几点复核；试用写几点开始、最晚几点结束。多条线合在一项时，取对应状态中最晚到期的那条并标出线名。刚回正常的线先显示未知。
- “过去 12 小时”位于“各分组”和“判定记录”之间，跟随模型页签，按分组列出[长期表现](#长期表现)。展开一行可看首字、缓存、超时、换号和分数的明细。近 12 小时有流量的退组行仍可查看。
- 每条线的证据和判定记录的依据都写明样本量“本组 / 全部”：首字线是样本条数，报错线是明确结果数，缓存线是续接轮数；全部含从别的分组借来的证据，两个数来自规则实际入证的同一组单位。首字线另写衰减后的权重“本组 / 全部”。报错线到期复核或试用时本可通过、因失败占比高于上限改判未知的，只在那次判定记录里写“失败占比高于上限，暂不恢复”。账号详情展示的是常规评估的证据。升级之前写下的记录没有这些数，显示未知，不按“证据来自分组”倒推。

### 分组页

看板可在“当前顺序”和“长期表现”间切换。“当前顺序”列出“前排、试用、试用（名额满）、后排、停调”，显示三线身份和固定开关。模型可以从有样本的模型里选，也可以直接输入模型名：只剩停调的号声明、近期没有流量的模型也能查。

看板上方写所选模型在本组的供给快照和快照时刻，用来回答“这个模型为什么没号了”：**声明支持**是声明支持这个模型的成员号数，含停用、停调的；**启用**是其中启用且可调度的；**此刻资格可接**是其中按看板的默认入口（流式 Responses / HTTP SSE）、此刻资格可接这个模型的号数，计入分组强制的服务档位及对应的定价准入，不检查空槽。读不到时三个数都显示未知。倍率区间外的行显示“不用 · 低于下限 / 高于上限”；停调行只显示停调，不显示原因。入口、档位或请求能力不同，以及 compact、借号等情形，都可能改变实际派发。

分组概览近 60 分钟的请求数、结果统计和首个有效输出延迟只计文本请求，不计 `search`、`image`、`embedding`；历史 `request_scope` 为空的记录仍按文本处理。

“全部模型”汇总按账号 × 模型计达标、未知、试用、后排；近 60 分钟首个有效输出给 P50 / P90，从进入网关、从读完请求体各算一组，并列迁移造成的 400 次数，以及近 24 小时进后排类判定（`enter`、`renew`、`trial_fail`）的次数和涉及的账号×模型数（去重；证据可以跨分组借用，判定次数可以远多于本组的请求数）。无数据为“—”；汇总独立刷新，不阻塞看板，一个分组统计查询慢时也不阻塞其他分组的读取。分组概览和筛选用有效身份；全局关闭、分组关闭或视图过期时不算质量后排 / 试用，面板仍可看原始证据。

#### 长期表现

一行是本组的一个账号 × 模型。可按模型、优先级筛选，也可只看标红的行。近 12 小时有流量的退组行仍可查看。

| 列 | 口径 |
|---|---|
| 账号、请求 | 请求为过去 12 小时最终由该账号在本组成功交付的请求数。选定模型时，份额按本组该模型的请求数计算 |
| 慢占比、超出、多出的慢请求 | 按本组现行首字秒数统计流式首派，再与同组同模型、同冷热的其他账号比较。默认按多出的慢请求从多到少排 |
| 续接缓存 | 按缓存线的续接轮定义统计 Token 读取比例 |
| 超时 | 本组此账号和模型等满首输出时限被截止的尝试数与占比 |
| 换号 | 只计已持久化且已提交的换归属事件，分首字超时交接、优先级接管、质量迁移、利润下限释放与其他 |
| 分数、现在 | 分数按账号 × 实际模型跨分组计算，只供管理员查看。界面把分数乘 100 显示。“现在”为三条线的当前身份 |

样本不足的指标只列计数，所有指标均未达到样本门槛的行排在最后。慢占比超出应有水平至少 10 个百分点且保守下界仍高于应有水平，或续接缓存低于本组下限时，行会标红。统计取过去 12 小时的尝试台账和已持久化的换号事件，每 5 分钟出一版。重启后重新装载，统计未齐时界面会提示。

#### 为什么没判

长期表现里标红、尚未进后排的线会显示没判的主因与持续时间。账号详情“各分组”的未知线也会显示具体原因。后排线的判定证据全部来自别的分组时会注明。

| 主因 | 含义 |
|---|---|
| `peer_short` | 同伴样本不够 |
| `own_short` | 本号样本不够 |
| `within` | 在线内 |
| `pending` | 有迹象，还在确认 |
| `trial_open` | 试用中，还没结论 |
| `over` | 判定超线，随实际动作记录 |
| `other` | 其他 |

每条线保留最近 8 段评估摘要，同一段的评估类型、动作和主因相同。界面读取与当前评估水位相符的最新一段。旧版本留下的评估没有摘要。判定记录仍只收录实际动作。

### 使用记录与运维面板

延迟的主值是**用户等待**，即端到端首输出：从请求进入网关到用户收到首个有效输出，含排队和之前失败的尝试。最后一次尝试的首字（“末次首字”，按系统的首 token 统计口径）降为辅助信息：首次超时后换号的请求，末次首字可能只有几秒，用户实际等了几十秒。

- **使用记录**：延迟列先写用户等待，下一行写末次首字，再写总耗时；没有记录的显示未知，悬停有原因。统计卡片给用户等待的中位数和参与的请求数（`GET /admin/usage/stats` 的 `e2e_first_output_p50_ms`、`e2e_first_output_samples`）。未计费请求没有末次首字。
- **运维面板**：“用户等待”卡片给端到端首输出的分位，提示里写“基于 N 个请求”；卡片底部一行是末次首字的 P99 / P50，健康分、定时报告和“高于阈值变红”仍按末次首字。升级前已汇总的整点小时没有端到端数据。整段都没有记录时显示未知。“明细”按用户等待从长到短排。自动或预聚合模式下，全局和平台的整点小时汇总不含无分组 Key 请求的末次首字和端到端首输出，原始查询会计入符合筛选条件的这类请求。见 [观测与排障](gateway-resilience-observability.md#管理后台)。
- 用户端的使用记录不变，仍显示首字。质量尝试另记首个事件、首个有效输出、首个答案正文，三者不保证固定顺序。使用记录还保留派发前分段耗时、利润准入依据与最近否决，见 [使用记录](usage.md)。

## 判定记录

判定记录保留 30 天，尝试记录保留 7 天，每小时清理；窗口之外的数据不参与判定。每条判定包含模型、分组、线、门槛、证据来源、档位与相关尝试；日志见 [质量状态](gateway-resilience-observability.md#质量状态)。

| 动作 | 含义 |
|---|---|
| `enter` | 进入后排 |
| `renew` | 到期仍不达标，升档续期 |
| `release` | 旧记录：后排到期达标，直接回前排 |
| `trial` | 后排到期达标或不知道，进入试用 |
| `trial_pass` | 试用满 15 分钟且达标，回正常，先标未知 |
| `trial_fail` | 试用不达标，升档进后排 |
| `trial_timeout` | 到期或满 60 分钟没有本线可用样本，回正常，先标未知 |
| `reset` | 管理员恢复 |
| `relax` | 放宽门槛，原后排或试用行清零重判；原达标或未知行不写此动作 |
| `clear` | 整组三线均在正常位置，且距最近一次确认不达标满 24 小时，清除有再犯记录的线的档位 |

**试用放回的原因**：新记录的依据里有 `release_reason`（`qualified` 达标、`no_samples` 没有本线可用样本、`deadline` 到期）和 `trial_duration_seconds`（本次试用的秒数）。面板也可展开查看流量与名额：

- 本组样本量只数本组入证样本；为 0 不等于没有跨组样本，也不代表命中 60 分钟出口。首字线另列“为什么是未知”的原因。
- 名额有三种结果，即试用期间遇到过名额已满、没有观察到名额已满、名额情况未知。读不到记录、满位时刻和试用的开始或截止相差不超过 2 秒而无法判断，或记录已被覆盖时，名额情况显示未知。“名额已满”按选号时实际取名额的结果记录。
- 依据里没有样本量（升级之前的记录）：旧判定，没有记录。

`until` 在 `enter`、`renew`、`trial_fail` 时是后排到期时间，`trial` 时是试用到期时间，其余为空。放宽首字线后，原后排或试用行若当场仍不达标，先记 `relax` 再记 `enter`；报错线和缓存线清零后仍须之后连续两次普通评估不达标才进后排。记录按判定时刻、ID 倒序翻页。人工重置的管理审计另记 `cleared_count`、`preserved_count`、`failed_count`，分别为已清、保留和失败项数。

## 管理接口

前缀 `/api/v1/admin/sched-quality`。权限仍受管理员资源范围约束，见 [管理员与权限](admin-permissions.md)。

| 接口 | 用途 | 权限 |
|---|---|---|
| `POST /accounts/summary` | 最多 1000 个账号的逐组有效身份、后排、试用及近期指标。`first_output` 为首字样本和中位数，`slow_10s` 为超过 10 秒统计，`error.failed` 为失败请求数，`cache` 为续接轮缓存比例和轮数。`recent_since` 为重置缩短窗口后的起点，其他情况为 `null` | `accounts:view` |
| `GET /accounts/attention` | 质量身份匹配账号 | `accounts:view` |
| `GET /accounts/:id` | 三线详情、证据、自动状态。每条线带 `last_eval` | `accounts:view` |
| `GET /accounts/:id/performance` | 账号近 12 小时表现，按分组 × 模型列出计数和分数 | `accounts:view` |
| `GET /accounts/:id/decisions` | 判定记录，`limit`、`before_id` 翻页 | `accounts:view` |
| `POST /accounts/:id/reset` | 恢复，返回已清、保留及失败项 | `accounts:manage` |
| `PUT` / `DELETE /accounts/:id/override` | 设置 / 取消豁免 | `accounts:manage` |
| `DELETE /accounts/:id/auto-states/*key` | 清除指定自动状态 | `accounts:manage` |
| `POST /groups/summary` | 有效身份个数、近 60 分钟首输出与迁移统计 | `groups:view` |
| `GET /groups/:id/policy` | 读取门槛 | `groups:view` |
| `PUT /groups/:id/policy` | 保存门槛，返回放宽线与清零行数 | `groups:manage` |
| `POST /groups/:id/policy/preview` | 当前证据的逐线试算 | `groups:view` |
| `GET /groups/:id/order` | 当前层、三线、固定、排除原因与顺序 | `groups:view` |
| `GET /groups/:id/performance` | 分组近 12 小时表现，按账号 × 模型列出计数和分数 | `groups:view` |
| `GET` / `PUT /ttft-rule` | 读写首字线三个参数，写入带版本 | 仅超级管理员 |

表现接口返回快照时刻 `at`、窗口起点 `window_from`、装载状态 `complete` 和过期标志 `stale`。比例由前端按计数计算。每条线的 `last_eval` 包含最新评估段的起止时刻（`since`、`at`）、次数（`count`）、动作（`acted`、`action`）及原因和证据缺口（`reason`、`causes`、`have`、`need`）。没有与水位相符的摘要时为 `null`。

账号表现接口在完整快照的 `groups` 中列出账号现属的 OpenAI 分组和有表现行的分组。各组的门槛设置取自生成这版统计时使用的配置，刚改过的设置最多 5 分钟后反映在下一版统计中。这版统计没有该组配置时（例如快照后新建的分组），`gate_enabled` 为 `false`。

| 字段 | 在哪返回 / 含义 |
|---|---|
| `trial_started_at` | 账号详情、账号和分组长期表现的逐线数据，以及账号列表摘要的试用项。RFC 3339 时间；逐线数据未在试用时为 `null` |
| `level` | 账号详情和长期表现的逐线数据、列表摘要的后排和试用项。后排档位从 0 数起（0–4），对应界面的第 1–5 档 |
| `until_line` | 列表摘要的后排和试用项，取 `ttfo`、`error`、`cache`，标出聚合项的 `until` 来自哪条线；同项的 `level` 或 `trial_started_at` 也来自该线 |
| `oauth_only_mismatch_count` | 分组管理接口返回的整数；`require_oauth_only` 打开时为现有的未删除 API Key 成员数，关闭时为 0 |

固定开关另走 `PUT /api/v1/admin/groups/:id/members/:account_id`，字段 `pinned`，需要 `groups:manage`。账号列表的 `sched_quality` 筛选值为 `normal`、`rear`、`trial`、`unknown`、`exempt`。

## 已知局限

- 受限后台密钥不能按质量身份筛选账号；非空 `sched_quality` 的非法值返回 400 `INVALID_SCHED_QUALITY`，合法值返回 403 `SCOPED_ADMIN_QUALITY_FILTER_UNSUPPORTED`。
- 质量筛选跨页全选时，如匹配超过 1000 个且取页间快照变化，选中集合可能漂移。
- 每个账号最多 32 条有效能力标记；满额时淘汰最早到期的。标记只是近期拒绝的记录，不是完整的能力目录。
- 试用名额是调度限制，不保证硬并发上限。多实例时钟偏差、结束试用后的跨实例清理及会话绑定与名额提交之间的间隙，可能短时少计或多计；遗留名额靠 10 分钟空闲回收。
- 关停时超过期限仍未结束的请求（含已升级的 WebSocket 连接），采样会丢失。
- 数据库时钟回拨超过 10 秒可能漏读样本，质量判断会缺少这部分证据。
- 历史只能补看证据保留窗口内的数据，读不全按不知道。发版或重启时已在试用的线，其 60 分钟检查按在途资料不全处理。评估水位为空的旧行若迟到补判，按处理时刻结算。
- 保存配置先处理到当前水位，水位之后约 10 秒内的事件按新配置评估。
- 分组级门槛关闭后，质量面板会提示“门槛已关闭”，账号列表的分组圆点仍显示未知。
- 可恢复的拒绝事件之后再碰到本地 WebSocket 读上限，采样仍可能显示能力拒绝；不计入报错失败，也不打能力标记。
- 拨号尚未结束时，引擎看不到这次尝试的在途观察；握手结束后才补入证据。
- 调度事件队列最前面一整页 200 条若全部持续失败，会挡住后面的事件，账号状态变化可能迟迟不能反映到选号。
- 新建分组时不做“无号可用”的保存确认，配置前应自行检查倍率区间与成员。
