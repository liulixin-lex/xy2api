# 分组质量门槛

每个 OpenAI 分组设置首字上限、报错上限、缓存下限。账号在某组某模型被判为**不达标**时排在正常账号之后，带恢复时间；正常账号都接不了时由它兜底。停用由账号开关与自动停用机制决定。选号与接管见 [调度](scheduling.md)。

## 生效范围

| 内容 | 范围 |
|---|---|
| 判定、不达标排序、兜底、接管 | OpenAI 平台分组 |
| 判定用的尝试记录 | OpenAI 文本请求：Responses（HTTP 与 WebSocket）、Chat Completions、Messages 兼容。图片、Embeddings、`count_tokens`、live 不记录，也不分层 |

- 判定单位是**账号 × 模型 × 分组**；尝试记录按账号 × 模型保存，带分组标记。同一个号可以在 A 组不达标、在 B 组正常。
- 每次真正发往上游的请求记一条尝试，算在执行它的账号上。
- 不达标只改变排序，不会让分组变成“无可用账号”。

## 设置

### 分组门槛

**分组管理** → 编辑 OpenAI 分组 → “质量门槛”：

| 界面 | 字段 | 范围 | 含义 |
|---|---|---|---|
| 质量门槛 | `enabled` | 开 / 关 | 三条线是否生效 |
| 首字上限 | `ttft_seconds` | 有限且大于 0 的秒数 | 发给账号到它出第一个字 |
| 报错上限 | `max_error_rate` | 5%–100% | 低于 5% 无法保存 |
| 缓存下限 | `min_cache_ratio` | 0–100% | 续轮的缓存读取占全部输入 |
| 接管 | `takeover_idle_seconds` | 关 / 立即 / 5 / 15 / 30 分钟 | 从未设置过的分组按 15 分钟；见 [会话接管](scheduling.md#会话接管) |

- 存在设置键 `group_quality_gate_policies` 的 `groups.<分组 ID>.v4`；版本号属于整份设置，别人先保存时返回 409。
- 保存前显示预览：按新值，此刻有哪些账号会变成不达标。
- 保存后立即生效，其他实例最长 30 秒内生效。

### 全局开关

**系统设置 → 网关服务 → 网关调度设置 → 质量调度**（`sched_quality_enabled`，默认开）。关闭后选号不分正常与不达标、不接管；判定、记录与展示照常，界面显示暂停标记。

## 状态

| 状态 | 含义 |
|---|---|
| 正常 | 未停用且不处于观察中；各组模型的质量见分组胶囊 |
| 观察中 | 账号近 60 分钟的首字样本少于 20 个，且没有任何组 × 模型不达标；按正常接请求 |
| 不达标 | 某组某模型过不了一条线；显示为 `分组名 不达标·首字 · 12:30 恢复`，多模型时带模型名 |
| 停用 | 手动关闭调度、设为 `inactive` 或触发自动停用，显示来源、原因与恢复时间；优先于观察中 |

## 判定

### 证据

每条线各自依次取：本组近窗 → 本组远窗 → 全部组近窗 → 全部组远窗，用第一个样本数够起判量的。都不够时这一条不判。

### 三条线

| 线 | 样本 | 窗口（近 / 远） | 起判 | 判不达标 |
|---|---|---|---|---|
| 首字 | 流式尝试；首字超时算超限；出字后失败或取消仍保留首字 | 30 / 60 分钟 | 20 个 | 超限比例的 95% Wilson 下界高于 10% |
| 报错 | 排除用户取消的尝试；上游错误、断流、超时、参数错误、404 等算报错，正常长度截断算成功 | 60 / 120 分钟 | 50 个 | 报错比例的 95% Wilson 下界高于报错上限 |
| 缓存 | 本次成功且三项 Token 已知的续轮：同组、同会话、同模型的前次尝试已成功完成，且账号相同 | 60 / 120 分钟 | 30 个续轮 | 缓存读取 ÷（未缓存输入 + 缓存读取 + 缓存写入）按 Token 加权低于下限 3 个百分点以上，且至少 2 个会话各自也低于该值 |

**快速通道**：5 分钟内最近 6 个首字样本有 5 个超限，立即判首字不达标，不等攒够 20 个。本组 5 分钟内够 6 个用本组，否则用全部组。

快速通道在每个首字样本完成时评估；三条线每分钟评估一次。

## 恢复时间

- **阶梯**：每轮时长为 20 → 40 → 60 → 90 → 120 分钟，120 封顶。放回后 30 分钟内再次不达标，进入下一级；连续正常满 30 分钟，下次从 20 分钟开始。
- **到点放回**：到点直接回到正常。只有一种例外：本轮开始后，该号在**其他组**有新完成的请求，且按本组的线当刻仍然不达标，就不放回，直接进入下一级；界面标明依据来自其他组。
- **证据起点**：进入不达标和续期都不清证据；到点放回、手动恢复之后，只看此后发出的请求。

## 选号

- 正常的号在前，不达标的号在后；同层内依次比较：账号优先级 → 倍率低者 → 负载低者 → 最久未用。
- 正常的号都不可用时，按同样顺序用不达标的号兜底；这次请求在使用记录里标“兜底”。
- 老会话的原号在本组不达标、且有正常的号能接时，下一轮换号；上游协议不允许换号的会话不换。
- 换号与接管都在目标号把这次请求完整做成功后才改绑定；失败时会话留在原号，2 分钟内不再试同一个号。

## 恢复与豁免

- **恢复状态**（账号行或详情，可批量）：清除不达标、阶梯级、判定旧证据、会话避让与可清自动停用，显示已清、保留及失败项。人工停用、额度、过期、智商门禁和共享代理限制保留；没有停用项时，恢复后显示“观察中”。
- **豁免**：某号在某组或全部分组暂不受门槛限制，可设到期时间。豁免期间内部判定照常进行，只是排序时按正常对待。

## 界面

### 账号列表

| 列 | 内容 |
|---|---|
| 状态 | 正常 / 观察中 / 停用·原因·恢复时间 |
| 优先级、倍率 | 默认显示；用于同层排序 |
| 首字 P50 · 报错 · 缓存 | 该号近 60 分钟（起点不早于最近一次手动恢复）、全部分组、全部模型的合计，旁边是样本数。红：这一项让它在某个组不达标（含豁免中的）；灰：样本数低于起判量（20 / 50 / 30） |
| 分组 | 不达标的组 × 模型，带原因与恢复时间 |

首字显示 P50，判定看超限比例的置信下界，因此 P50 在线内也可能首字不达标。

账号详情按组 × 模型列出：三条线、该组用来判的成绩（来源、窗口、样本数、超限或报错数）、结论、恢复时间与阶梯级；另有自动停用明细与豁免。

### 分组页

- 列表：三条线、接管、账号数（正常 / 不达标 / 停用，每号只算一次）。
- 近 60 分钟体验：请求级端到端首字 P50（含排队与换号等待）、失败比例、三桶 Token 加权缓存比、请求数。账号行与尝试展开使用尝试数据，使用记录行及汇总保留原首字、耗时。
- 详情：此刻的选号顺序；改门槛预览。

### 使用记录

结果列、兜底与接管标记、行展开与汇总见 [使用记录](usage.md#结果)。

## 判定记录

每次进入、续期、放回、手动恢复写一条判定记录（表 `sched_decisions`，保留 30 天）：规则版本、门槛、窗口、样本数、超限或报错数、证据来自本组还是全部组或其他组、涉及的尝试。同时输出日志 `sched_quality.state`（见 [观测与排障](gateway-resilience-observability.md#质量状态)）。

## 管理接口

前缀 `/api/v1/admin/sched-quality`：

| 接口 | 用途 |
|---|---|
| `POST /accounts/summary` | 账号列表的状态、三个数与不达标组（最多 1000 个账号） |
| `GET /accounts/:id` | 账号详情 |
| `POST /accounts/:id/reset` | 恢复状态，返回已清除与仍保留的项 |
| `PUT` / `DELETE /accounts/:id/override` | 设置、取消豁免 |
| `GET /accounts/attention` | 账号筛选：不达标、豁免、观察中 |
| `POST /groups/summary` | 分组列表的门槛、账号数与近 60 分钟体验 |
| `GET` / `PUT /groups/:id/policy` | 读取、保存分组门槛 |
| `POST /groups/:id/policy/preview` | 改门槛预览 |
| `GET /groups/:id/order` | 此刻的选号顺序 |

读取跟随“账号管理”“分组管理”的查看权限；恢复与豁免要“账号管理”的管理权限，保存门槛要“分组管理”的管理权限。
