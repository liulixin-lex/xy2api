# 调度

XY2API 收到请求后，要在 API Key 所属分组的账号中选出一个来转发。本文说明选号规则：优先级、倍率、负载与粘性会话，以及 OpenAI 分组的会话接管。适合配置账号池、调整流量分配的管理员。上游失败后的换号、冷却与兜底见 [网关韧性](gateway-resilience.md)；OpenAI 账号的逐线质量身份（达标 / 未知 / 试用 / 后排）与门槛见 [分组质量门槛](group-quality-gate.md)。

## 日常开关

在 **账号管理** 列表直接点击账号的“调度”开关即可，无需打开其他设置（账号字段 `schedulable`，接口 `POST /api/v1/admin/accounts/:id/schedulable`，请求体 `{"schedulable": true|false}`）。

- **开启**：账号可接收新请求，按下述规则参与选择。模型不支持、账号异常、限流或容量已满时仍会自动避开。
- **关闭**：停止向该账号派发新请求，已经派发的请求继续运行到结束，后续请求由其他合格账号承接。
- 每次操作只改变当前账号；批量操作只改变明确选中的账号。
- 关闭不会强制切断正在输出的内容，也不会把输出一半的回复换到另一个账号拼接。需要原账号继续的协议会话（如 `previous_response_id` 续链）在原账号关闭后不再续用它；WebSocket 的下一轮属于新请求。
- 平滑减少某个账号的新会话：把负载因子调小（最小 1）；立即停止：关闭“调度”开关。

## OpenAI 分组的选号顺序

OpenAI 分组按下表排定候选顺序，前一项分出先后就不再看后面：

| 序 | 比较项 | 规则 |
|---|---|---|
| 0 | 硬准入 | 不通过的账号不进候选：账号状态与调度开关、模型与能力、额度、限流与各类运行时阻断、利润门、智商门（见 [罚则与选号](gateway-resilience-routing.md#软罚与硬罚)）；带 `tools` 或 `functions` 的 Chat 请求按最终模型与实际发送的档位选择协议：GPT-6.1 Sol、Terra 必须走 Responses；GPT-6 Sol、Luna 只在实际发送 `none` 时可走 Chat。仅由 `thinking.type=disabled` 或模型名 `-none` 后缀推导、未写入请求正文的档位按缺省处理，选择支持 Responses 的账号 |
| 1 | 层 | 达标、未知、有名额的试用在第一层；名额满的试用在第二层；后排在第三层。身份按账号 × 模型 × 分组 × 线判，豁免不受质量分层限制 |
| 2 | 固定 | 分组成员的固定号排在同层最前，仍受质量与其他准入条件限制 |
| 3 | 优先级 | 账号编辑页的“优先级”，数字越小越先用 |
| 4 | 倍率 | 调度倍率低的在前。OAuth 账号取“OAuth 倍率”（未设置时用账号倍率）；API Key 账号优先取有效且可计算的“上游倍率自动探测”结果，算不出时用存储倍率。不按 Token 计费的请求不比较倍率 |
| 5 | 负载率 | （在途 + 排队）× 100 ÷ 负载因子，低的在前。负载因子（`load_factor`，最大 10000）未设置时按并发上限计，并发也没有时按 1；读不到负载时这一项不参与比较 |
| 6 | 最近使用 | 越久没用越靠前 |
| 7 | 账号 ID | 小的在前 |

上面这条请求能力条件在普通选号、粘性会话、末位兜底与排队后重选中都适用；末位兜底可以放宽软罚，但不放宽请求能力。账号配置写明了协议或模型路由时，以配置为准，不看自动探测的结果。需要 Responses、而分组里没有任何账号具备这一能力时返回 400 `invalid_request_error` / `responses_required`，`param` 为 `tools`（旧写法为 `functions`），细则见[客户端可见的行为](gateway-resilience-client.md#错误响应)；有能力的账号只是暂时繁忙时，按无号处理。

- **层与固定先于优先级**：同层、同固定状态内，优先级数值小者先用；倍率、负载只在此前各项相同时比较。新会话直接按这套顺序选号。要求 compact 的请求保留“已确认支持优于未知”的前置能力偏好。
- **后排仍可兜底**：前面层的账号都不能接时，按同样顺序使用后排。最低上游倍率与最高倍率是硬准入，区间外连末位兜底也不用；固定号免上下限，仍受质量三条线管。见 [倍率区间与固定号](groups.md#倍率区间与固定号)。
- 新会话、失败换号、迁移和[末位兜底](gateway-resilience-routing.md#末位兜底)复用此顺序；借号时试用号放在最后，临时占请求名额，不改原绑定。试用名额通常为账号 × 模型跨组共用 3 个；满额降层，不硬拒绝请求。
- 分组详情的“选号顺序”按这个顺序列出本组账号此刻的名次与层，见 [分组页](group-quality-gate.md#分组页)。

### 协议转换失败时换号重发

Chat Completions 请求走 Responses 上游时，只有转换原因是输出条目身份冲突（`conflicting_output_identity`），且满足以下条件，才换一个账号重发一次。流式和非流式都按这个原因判断。流式工具调用身份冲突（`tool_identity_conflict`）、输出序号冲突（`conflicting_output_index`）、输出身份歧义（`ambiguous_output_identity`）和无序号输出歧义（`ambiguous_unindexed_output`）沿用原来的错误处理，不记 `openai_conversion_retry`。

| 检查项 | 条件 |
|---|---|
| 可以重放 | 入口明确标记可重放，而且实际发出的请求体通过结构检查。续链、受保护交接、上游代执行工具、自定义工具、无法识别的输入或工具定义、含重复键的 JSON 都不重发；认识的客户端函数工具可以参与 |
| 还未交付 | 正文、工具片段和错误帧都未写给客户端；心跳不算输出。上游尚未报告用量，客户端未取消或断开 |
| 还有预算 | 原请求的时间、派发次数和换号额度均有余量；这种身份冲突每请求最多换号重发一次 |
| 另有合格账号 | 同分组、同实际调度模型、同优先级，且通过利润门。候选须走 Responses 上游，与原号使用同一种出站改写，两端的实际出站模型都须等于各自的调度模型。拿槽前后都检查；候选须能立即拿到并发槽，不排队，也不走末位兜底 |

重发前还会核对候选按正常流程构造的请求体与原号修复前的首份出站体一致，才用原号最后实际发出的请求体重发，转换从干净状态开始。账号类型、透传、Codex 等请求改写和实际服务档位不同都可能使候选不合格。开启透传且模型映射使出站模型改变的账号不能参与。独立工具输出条目改写为用户消息后，原本仅因输入无法识别而不能重发的 Chat 请求可能多发一次上游请求；换号时只选兼容未关闭的第三方 OpenAI API Key 账号。

没有重发就按原转换错误收口，客户端已取消时不再写错误。从决定选候选重发起，放弃原尝试的会话变更，不写避让、不记会话失败；之后找不到合格号或来不及发也一样。重发若成功，客户端只看到成功的结果；首输出前再次遇到转换错误按 502 收口，遇到其他错误按第二次的真实错误收口，已输出后沿用流中断处理。都不再换第三次。

同一个账号上的“修复后重发”和这里的换号重发分别计次，共用原请求预算。诊断见 [协议转换日志](gateway-resilience-observability.md#协议转换)。

## 其他平台的选号

Claude、Gemini、Antigravity 等平台的分组：

- **优先级**：数字越小越先使用。
- **负载**：同一优先级内按负载率选择（口径同上），负载因子越大越常被选中。同一排序组内随机打散。
- 账号的限流、异常保护与网关韧性的罚则在选号前过滤候选，见 [罚则与选号](gateway-resilience-routing.md#软罚与硬罚)；Claude 账号另有[判慢让位](gateway-resilience-routing.md#判慢让位与会话迁出claude)。

## 粘性会话

同一会话优先回到绑定的账号，以保持上游提示缓存命中。会话标识优先取客户端显式提供的（如 Claude Code 的 session id），没有时按请求内容派生。绑定空闲 1 小时后失效；OpenAI 的绑定时长由 `gateway.openai_ws.sticky_session_ttl_seconds` 控制（默认 3600 秒）。

Anthropic 请求没有显式会话标识时，兜底粘性键由客户端 IP、规范化的 User-Agent、API Key、分组、规范化的 system 与首条有效用户文本构成（去掉完整的 `<system-reminder>…</system-reminder>` 区间并折叠空白）。因此同一 Key、分组、IP、UA、system 与首条用户消息完全相同的独立对话会共享账号绑定；system 中按天变化的日期句也可能让会话每天换一次绑定。

### OpenAI 会话的去留

OpenAI 分组里已绑定账号（属主）的会话，按以下顺序决定这一次用谁：

1. **协议强续接**留在属主，永不因质量或优先级迁移：`previous_response_id` 续链、WebSocket 连接内的轮次与指定传输、Codex 子 agent 回到父线程，以及带协作或工具输出密文片段的请求。[会话质量路由](quality-routing.md)持有的会话同样不迁。
2. **属主被倍率下限排除**：释放原绑定，改选区间内账号，新号成功后粘住；上限否决保留原绑定。
3. **质量迁移**：报错线后排可迁；首字线后排须该会话在同号上最近连续两个逻辑轮都超限，重试合成一轮、换号首轮不计；缓存线后排不迁。目标须是能接的前排或取到名额的试用号，并通过下文的避让检查。
4. **其余保留属主**：包括不满足质量迁移条件的后排与原有试用会话，除非满足下面的“接管”。
5. 属主满载时的短等、借号与排队见“粘性账号满载时”；借号不改绑。

计划换号与接管都在目标账号完整交付后才改绑定。目标失败时，会话留在属主，且 2 分钟内不再试同一个目标。质量迁移、接管和释放原号后的换号都把目标在派发前失效计入避让。救场交接只把实际派发到目标后的失败计入避让。多实例共享这条避让记录。

**首输出避让与交接**。普通 OpenAI HTTP 流式文本会话命中原归属号，等够本档首输出时限仍无有效输出时，从截止时刻起优先避开该号，默认 10 分钟。临时借号保留原归属；没有其他合格候选时，仍合格的原号可作末位兜底。续链、WebSocket、Codex 子线程及 guardian 亲和会话、带密文片段的请求、生图和由[会话质量路由](quality-routing.md)持有的会话不走这条规则。

**质量迁移与接管的避让检查**。选目标时排除本会话处于首输出避让期的账号。到期时刻仍算避让；目标账号重置前写入的避让已失效。读取失败就放弃这次换号。提交时在同一 Redis 脚本中复验避让并改绑定。仍合格的避让账号可作末位兜底，只救这一单，归属保留原处。

同一请求被正常前排账号完整救回时，如果该号从尝试开始到首个有效输出的时间严格短于原号当时的实际时限，且避让已确认、当前绑定仍有效，收尾时可把归属交给救场号。试用、后排、临时借用或末位兜底的账号只救这一单。相等、缺时间、部分交付或取消都保留原归属。成功但不够快按正常交付处理，救场号不受罚。

### 会话接管

接管是把绑在较低优先级账号上的会话改绑到有空位的较高优先级账号，让新加入或刚恢复的高优先级账号尽快用起来。它对所有 OpenAI 分组生效，与该组是否打开质量门槛无关。新会话按候选顺序选号。

**设置**：分组管理 → 编辑 OpenAI 分组 → 质量门槛区块的“接管”（接口 `PUT /api/v1/admin/sched-quality/groups/:id/policy`，字段 `takeover_idle_seconds`）：

| 选项 | 值 | 含义 |
|---|---|---|
| 关 | `-1` | 不接管 |
| 立即 | `0` | 每次请求都检查 |
| 5 / 15 / 30 分钟 | `300` / `900` / `1800` | 该会话距上一条请求**开始**满这么久才接管。从未设置过的分组按 15 分钟 |

**目标账号必须同时满足**：

- 优先级严格高于当前属主；同优先级之间不接管；
- 目标在本组为前排（含豁免），原属主不必在前排；
- 固定标志不参与接管比较；只设为固定不会迁走老会话，仍比较优先级；
- 最近 60 秒内没有被观察到占满；
- 不在该会话 2 分钟内接管失败的目标里；
- 通过上文的首输出避让检查；
- 系统设置里的“质量调度”开启，且质量视图没有过期。

按选号顺序最多尝试 2 个目标，都不成则留在原属主。接管是尽力而为，不保证一有空位就迁。

改绑可能降低首轮缓存命中、增加输入成本与首字等待。缓存成本敏感的分组可选“N 分钟”或“关”。

## 粘性账号满载时

- 绑定账号满载时，先以 50 → 100 → 200 毫秒的退避重试原账号，最多 2 秒，不入队、尊重请求取消。
- 仍满则临时借用有即时空位的账号，会话绑定仍保留原账号：OpenAI 按上面的选号顺序；其他平台优先借本会话最近成功过的账号，否则按会话固定哈希顺序。不借负载率 ≥100% 或在用并发已满的账号。
- 全组没有即时空位时才进入排队等待：队列未满时等待原账号，队列已满时按备用等待时限与队列上限处理。
- Responses WebSocket 的后续 turn 抢不到账号槽时，同样短等最多 2 秒，仍满则以 1013 “account is busy, please retry later” 关闭；用户并发上限不足时立即关闭。WebSocket 每个 turn 成功后续期会话绑定（每连接最多每 5 分钟一次），连续工作超过绑定时长后重连仍回到原账号。
- WebSocket 跨轮模型核验按本轮模型与渠道映射判断，当前账号不支持时拒绝；模型冷却仍按本轮请求的模型检查。
- 排队已满或等待超时后，请求未取消且总预算仍有余额时，只再选一次有即时空位的合格账号；不再进入第二次队列。没有空位仍返回原来的 429 原因与重试提示，不增加上游尝试预算。
- 强续接（如续链）始终等待原账号，不参加这次本地重选。
- 请求总时间或上游尝试次数已经用完时不再重选；重选本身不额外占用上游尝试次数。
- 排队取得并发名额后，按最新账号状态重新核验准入，末位兜底也一样。OpenAI 选号复验读错或未通过时释放槽位和本次预留的试用名额。其他平台遇到临时读错时沿用原选号进入利润终检。确认账号失格时释放槽位并重选，会话登记保留至到期。立即取得槽位的路径不额外增加这次排队复查。

## 网关调度设置

在 **系统设置 → 网关服务 → 网关调度设置** 中配置：

| 设置 | 键 | 默认 | 说明 |
|---|---|---|---|
| 允许未分组 Key 调度 | `allow_ungrouped_key_scheduling` | 关 | 关闭时，未分配到任何分组的 API Key 请求返回 403 |
| 平台账号自动停调阈值 | `account_scheduling_thresholds` | 各平台 100（禁用） | 按平台设置 1–100 的百分比：账号当前原生用量窗口（OpenAI Codex、Anthropic 会话，或 Grok 请求/Token 利用率）达到该比例时临时移出调度，直到窗口重置；可在账号编辑页对单个账号覆盖 |
| 质量调度 | `sched_quality_enabled` | 开 | 见 [分组质量门槛](group-quality-gate.md#全局开关) |
| OAuth 倍率 | `openai_oauth_scheduling_rate_multiplier` | 空 | OpenAI OAuth 账号在选号顺序“倍率”一项使用的值；留空时用各账号自己的倍率，填写须为非负数 |
| 负载批量选号 | 配置文件 `gateway.scheduling.load_batch_enabled`（环境变量 `GATEWAY_SCHEDULING_LOAD_BATCH_ENABLED`） | true | 负载感知选号路径；关闭后选号不读取实时负载，Claude 判慢让位也不再工作 |

## 与网关韧性的关系

网关韧性默认开启，在上述规则之上增加软罚期间保留会话绑定、连续失败后改绑、没有健康账号时用软罚账号兜底、余额不足暂停、按模型冷却和 Claude 判慢让位等能力。关闭“会话失败改绑”（`session.enabled`）会停用首输出避让与救场交接。OpenAI 分组的质量迁移与接管仍由质量调度和各自条件控制。细则见 [罚则与选号](gateway-resilience-routing.md)。
