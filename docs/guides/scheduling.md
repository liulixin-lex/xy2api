# 调度

XY2API 收到请求后，要在 API Key 所属分组的账号中选出一个来转发。本文说明选号规则：优先级、倍率、负载与粘性会话，以及 OpenAI 分组的会话接管。适合配置账号池、调整流量分配的管理员。上游失败后的换号、冷却与兜底见 [网关韧性](gateway-resilience.md)；OpenAI 账号的质量状态（正常 / 不达标）与门槛见 [分组质量门槛](group-quality-gate.md)。

## 日常开关

在 **账号管理** 列表直接点击账号的“调度”开关即可，无需打开其他设置（账号字段 `schedulable`，接口 `POST /api/v1/admin/accounts/:id/schedulable`，请求体 `{"schedulable": true|false}`）。

- **开启**：账号可接收新请求，按下述规则参与选择。模型不支持、账号异常、限流或容量已满时仍会自动避开。
- **关闭**：停止向该账号派发新请求，已经派发的请求继续运行到结束，后续请求由其他合格账号承接。
- 每次操作只改变当前账号；批量操作只改变明确选中的账号。
- 关闭不会强制切断正在输出的内容，也不会把输出一半的回复换到另一个账号拼接。需要原账号继续的协议会话（如 `previous_response_id` 续链）在原账号关闭后不再续用它；WebSocket 的下一轮属于新请求。
- 平滑减少某个账号的新会话：把负载因子调小（最小 1）；立即停止：关闭“调度”开关。

## OpenAI 分组的选号顺序

OpenAI 分组的每次选号都按下表逐项比较，前一项分出先后就不再看后面：

| 序 | 比较项 | 规则 |
|---|---|---|
| 0 | 硬准入 | 不通过的账号不进候选：账号状态与调度开关、模型与能力、额度、限流与各类运行时阻断、利润门、智商门（见 [罚则与选号](gateway-resilience-routing.md#软罚与硬罚)） |
| 1 | 层 | 正常在前，不达标在后。不达标 = 该账号在本组、本模型上过不了门槛且未被豁免（见 [分组质量门槛](group-quality-gate.md)） |
| 2 | 优先级 | 账号编辑页的“优先级”，数字越小越先用 |
| 3 | 倍率 | 调度倍率低的在前。OAuth 账号取“OAuth 倍率”（未设置时用账号倍率）；API Key 账号取仍在有效期内的“上游倍率自动探测”结果，否则用账号倍率。不按 Token 计费的请求不比较倍率 |
| 4 | 负载率 | （在途 + 排队）× 100 ÷ 负载因子，低的在前。负载因子（`load_factor`，最大 10000）未设置时按并发上限计，并发也没有时按 1；读不到负载时这一项不参与比较 |
| 5 | 最近使用 | 越久没用越靠前 |
| 6 | 账号 ID | 小的在前 |

- **优先级严格分层**：只要更高优先级还有能用的正常账号，更低优先级就接不到新会话；倍率、负载只在同一优先级内比较。
- **不达标不是停用**：本组正常的账号都不可用时，仍按同样的顺序用不达标的账号兜底。要彻底停用请关闭“调度”开关。
- 新会话放置、失败换号、属主满载时借号、换号与接管的目标、[末位兜底](gateway-resilience-routing.md#末位兜底)都用这一个顺序。
- 分组详情的“选号顺序”按这个顺序列出本组账号此刻的名次与层，见 [分组页](group-quality-gate.md#分组页)。

## 其他平台的选号

Claude、Gemini、Antigravity 等平台的分组：

- **优先级**：数字越小越先使用。
- **负载**：同一优先级内按负载率选择（口径同上），负载因子越大越常被选中。同一排序组内随机打散。
- 账号的限流、异常保护与网关韧性的罚则在选号前过滤候选，见 [罚则与选号](gateway-resilience-routing.md#软罚与硬罚)；Claude 账号另有[判慢让位](gateway-resilience-routing.md#判慢让位与会话迁出claude)。

## 粘性会话

同一会话优先回到上次使用的账号，以保持上游提示缓存命中。会话标识优先取客户端显式提供的（如 Claude Code 的 session id），没有时按请求内容派生。绑定空闲 1 小时后失效；OpenAI 的绑定时长由 `gateway.openai_ws.sticky_session_ttl_seconds` 控制（默认 3600 秒）。

Anthropic 请求没有显式会话标识时，兜底粘性键由客户端 IP、规范化的 User-Agent、API Key、分组、规范化的 system 与首条有效用户文本构成（去掉完整的 `<system-reminder>…</system-reminder>` 区间并折叠空白）。因此同一 Key、分组、IP、UA、system 与首条用户消息完全相同的独立对话会共享账号绑定；system 中按天变化的日期句也可能让会话每天换一次绑定。

### OpenAI 会话的去留

OpenAI 分组里已绑定账号（属主）的会话，按以下顺序决定这一次用谁：

1. **协议强续接**留在属主，永不因质量或优先级迁移：`previous_response_id` 续链、WebSocket 连接内的轮次与指定传输、Codex 子 agent 回到父线程，以及带协作或工具输出密文片段的请求。[会话质量路由](quality-routing.md)持有的会话同样不迁。
2. **属主不达标**，且此刻有正常的账号能接：这一轮换到按选号顺序找到的正常账号。
3. **属主正常**：继续用属主，除非满足下面的“接管”。
4. 属主满载时的短等、借号与排队见“粘性账号满载时”；借号不改绑。

换号与接管都在目标账号把这次请求完整做成功后才改绑定；失败时会话留在属主，且 2 分钟内不再试同一个目标，多实例共享这条记忆。

### 会话接管

接管是把绑在较低优先级账号上的会话改绑到有空位的较高优先级账号，让新加入或刚恢复的高优先级账号尽快用起来。它对所有 OpenAI 分组生效，与该组是否打开质量门槛无关。新会话不涉及接管，本来就按选号顺序分给优先级最高的正常账号。

**设置**：分组管理 → 编辑 OpenAI 分组 → 质量门槛区块的“接管”（接口 `PUT /api/v1/admin/sched-quality/groups/:id/policy`，字段 `takeover_idle_seconds`）：

| 选项 | 值 | 含义 |
|---|---|---|
| 关 | `-1` | 不接管 |
| 立即 | `0` | 每次请求都检查 |
| 5 / 15 / 30 分钟 | `300` / `900` / `1800` | 该会话距上一条请求**开始**满这么久才接管。从未设置过的分组按 15 分钟 |

**目标账号必须同时满足**：

- 优先级严格高于当前属主；同优先级之间不接管；
- 在本组是正常账号（豁免中的按正常算）；
- 最近 60 秒内没有被观察到占满；
- 不在该会话 2 分钟内接管失败的目标里；
- 系统设置里的“质量调度”开启，且质量视图没有过期。

按选号顺序最多尝试 2 个目标，都不成则留在原属主。接管是尽力而为，不保证一有空位就迁。

改绑可能降低首轮缓存命中、增加输入成本与首字等待。缓存成本敏感的分组可选“N 分钟”或“关”。

## 粘性账号满载时

- 绑定账号满载时，先以 50 → 100 → 200 毫秒的退避重试原账号，最多 2 秒，不入队、尊重请求取消。
- 仍满则临时借用有即时空位的账号，会话绑定仍保留原账号：OpenAI 按上面的选号顺序；其他平台优先借本会话最近成功过的账号，否则按会话固定哈希顺序。不借负载率 ≥100% 或在用并发已满的账号。
- 全组没有即时空位时才进入排队等待：队列未满时等待原账号，队列已满时按备用等待时限与队列上限处理。
- Responses WebSocket 的后续 turn 抢不到账号槽时，同样短等最多 2 秒，仍满则以 1013 “account is busy, please retry later” 关闭；用户并发上限不足时立即关闭。WebSocket 每个 turn 成功后续期会话绑定（每连接最多每 5 分钟一次），连续工作超过绑定时长后重连仍回到原账号。
- 强续接（如续链）始终等待原账号。

## 网关调度设置

在 **系统设置 → 网关服务 → 网关调度设置** 中配置：

| 设置 | 键 | 默认 | 说明 |
|---|---|---|---|
| 允许未分组 Key 调度 | `allow_ungrouped_key_scheduling` | 关 | 关闭时，未分配到任何分组的 API Key 请求返回 403 |
| 平台账号自动停调阈值 | `account_scheduling_thresholds` | 各平台 100（禁用） | 按平台设置 1–100 的百分比：账号当前原生用量窗口（OpenAI Codex、Anthropic 会话，或 Grok 请求/Token 利用率）达到该比例时临时移出调度，直到窗口重置；可在账号编辑页对单个账号覆盖 |
| 质量调度 | `sched_quality_enabled` | 开 | 见 [分组质量门槛](group-quality-gate.md#全局开关) |
| OAuth 倍率 | `openai_oauth_scheduling_rate_multiplier` | 空 | OpenAI OAuth 账号在选号顺序“倍率”一项使用的值；留空时用各账号自己的倍率，填写须为非负数 |
| 负载批量选号 | 配置文件 `gateway.scheduling.load_batch_enabled`（环境变量 `GATEWAY_SCHEDULING_LOAD_BATCH_ENABLED`） | true | 负载感知选号路径；关闭后选号不读取实时负载，Claude 判慢让位也不再工作 |

## 与网关韧性的关系

网关韧性默认开启，在上述规则之上增加：软罚期间保留会话绑定、连续失败后改绑、没有健康账号时用软罚账号兜底、余额不足暂停、按模型冷却、Claude 判慢让位等。细则见 [罚则与选号](gateway-resilience-routing.md)。OpenAI 分组的不达标换号与接管不依赖韧性的“会话失败改绑”开关。
