# 调度

XY2API 收到请求后，要在 API Key 所属分组的账号中选出一个来转发。本文说明两种选号方式：默认的账号调度（沿用 Sub2API 原版规则：优先级、负载与粘性会话），以及按分组可选的份额调度（按负载因子比例分配新会话，并尽量把会话留在原账号以保住上游缓存）。适合配置账号池、调整流量分配的管理员。上游失败后的换号、冷却与兜底见 [网关韧性](gateway-resilience.md)，OpenAI 分组的质量排序见 [分组质量门槛](group-quality-gate.md)。

## 账号调度

### 日常开关

在 **账号管理** 列表直接点击账号的“调度”开关即可，无需打开其他设置（账号字段 `schedulable`，接口 `POST /api/v1/admin/accounts/:id/schedulable`，请求体 `{"schedulable": true|false}`）。

- **开启**：账号可接收新请求，按下述规则参与选择。模型不支持、账号异常、限流或容量已满时仍会自动避开。
- **关闭**：停止向该账号派发新请求，已经派发的请求继续运行到结束，后续请求由其他合格账号承接。
- 每次操作只改变当前账号；批量操作只改变明确选中的账号。
- 关闭不会强制切断正在输出的内容，也不会把输出一半的回复换到另一个账号拼接。需要原账号继续的协议会话（如 `previous_response_id` 续链）在原账号关闭后不再续用它；WebSocket 的下一轮属于新请求。
- 平滑减少某个账号的新会话：把负载因子调小（最小 1）；立即停止：关闭“调度”开关。

### 默认调度规则

- **优先级**：在账号编辑页设置，数字越小越先使用。
- **负载**：同一优先级内按负载率选择，负载率 =（在途 + 排队）× 100 ÷ 负载因子。负载因子（`load_factor`，最大 10000）未设置时按并发上限计，并发也没有时按 1。负载因子越大，越常被选中。同一排序组内随机打散。
- **粘性会话**：同一会话优先回到上次使用的账号，以保持上游提示缓存命中。会话标识优先取客户端显式提供的（如 Claude Code 的 session id），没有时按请求内容派生。绑定空闲 1 小时后失效；OpenAI 的绑定时长由 `gateway.openai_ws.sticky_session_ttl_seconds` 控制（默认 3600 秒）。
- 账号的限流、异常保护与网关韧性的罚则在选号前过滤候选，见 [罚则与选号](gateway-resilience-routing.md#软罚与硬罚)。

Anthropic 请求没有显式会话标识时，兜底粘性键由客户端 IP、规范化的 User-Agent、API Key、分组、规范化的 system 与首条有效用户文本构成（去掉完整的 `<system-reminder>…</system-reminder>` 区间并折叠空白）。因此同一 Key、分组、IP、UA、system 与首条用户消息完全相同的独立对话会共享账号绑定；system 中按天变化的日期句也可能让会话每天换一次绑定。

### 网关调度设置

在 **系统设置 → 网关服务** 中配置：

| 设置 | 键 | 默认 | 说明 |
|---|---|---|---|
| 允许未分组 Key 调度 | `allow_ungrouped_key_scheduling` | 关 | 关闭时，未分配到任何分组的 API Key 请求返回 403 |
| 平台账号自动停调阈值 | `account_scheduling_thresholds` | 各平台 100（禁用） | 按平台设置 1–100 的百分比：账号当前原生用量窗口（OpenAI Codex、Anthropic 会话，或 Grok 请求/Token 利用率）达到该比例时临时移出调度，直到窗口重置；可在账号编辑页对单个账号覆盖 |
| OpenAI 实验调度策略 | `openai_advanced_scheduler_enabled` | 关 | 只影响 OpenAI 账号间的选号逻辑 |
| 低倍率优先 | `openai_low_upstream_rate_priority_enabled` | 关 | 见下 |
| 低倍率优先的适用范围 | `openai_low_upstream_rate_priority_scope` / `openai_low_upstream_rate_priority_group_ids` | `all` / `[]` | `groups` 时只在所选 OpenAI 分组内生效；选“指定分组”但集合为空等于关闭 |
| 负载批量选号 | 配置文件 `gateway.scheduling.load_batch_enabled`（环境变量 `GATEWAY_SCHEDULING_LOAD_BATCH_ENABLED`） | true | 负载感知选号路径；Claude 判慢让位与替补排序依赖它 |

低倍率优先开启后，OpenAI 候选依次按优先级 → 负载 ≥80% 的置后 → 计费倍率（低的在前）→ 同倍率按预计首字 → 负载 → 最近使用排序。它在实验调度策略开启时不生效。分组开了质量门槛时先按质量档排序，以上顺序只在同一档内生效。保存后本实例即时生效，其他实例约 5 秒内生效。

### 粘性账号满载时

- 绑定账号满载时，先以 50 → 100 → 200 毫秒的退避重试原账号，最多 2 秒，不入队、尊重请求取消。
- 仍满则在同一比较档内临时借用有即时空位的账号：优先借本会话最近成功过的账号，否则按会话固定哈希顺序；会话绑定仍保留原账号。不借负载率 ≥100% 或在用并发已满的账号。
- 全组没有即时空位时才进入排队等待：队列未满时等待原账号，队列已满时按备用等待时限与队列上限处理。
- Responses WebSocket 的后续 turn 抢不到账号槽时，同样短等最多 2 秒，仍满则以 1013 “account is busy, please retry later” 关闭；用户并发上限不足时立即关闭。WebSocket 每个 turn 成功后续期会话绑定（每连接最多每 5 分钟一次），连续工作超过绑定时长后重连仍回到原账号。
- 强续接（如续链）始终等待原账号。

### 与网关韧性、质量门槛的关系

网关韧性默认开启，在上述规则之上增加：软罚期间保留会话绑定、连续失败后改绑、没有健康账号时用软罚账号兜底、余额不足暂停、按模型冷却、判慢让位等。开启了 [分组质量门槛](group-quality-gate.md)的 OpenAI 分组，候选先按硬准入 → 质量档 → 档内判慢后排 → 档内原有顺序排序。细则见 [罚则与选号](gateway-resilience-routing.md)。

## 份额调度

份额调度是按分组可选的调度器，默认关闭，随时可以回到原版。它沿用账号自己的设置，没有单独的账号规则：

- **层级 = 账号优先级**：新会话只进入当前活动优先级，即有可用账号的最小优先级。
- **权重 = 负载因子**：同一优先级内按负载因子比例分配新会话（未设置时按并发上限，都没有时按 1），再乘以自动的健康系数与爬升系数。
- **会话保持**：同一会话尽量留在原账号，以保住上游提示缓存与首字速度；缓存过期后再按比例重新分配。

每个分组只有两项设置：调度方式（原版 / 份额）与会话保持；全局只有一个总开关。其余参数都是固定值。

### 启用步骤

1. 打开 **份额调度** 页面，页头的 **总开关** 默认关闭。关闭时所有分组立即按原版调度，各分组的设置保留，已有会话不迁移。
2. 左侧选择分组。列表显示调度方式、账号数、近 1 小时的缓存命中率与换号损失。
3. 在“流量分配”中核对各账号的优先级、负载因子与预计新会话份额。负载因子可以在表内直接修改，改的是账号本身，会同时影响该账号所在的全部分组，表内列出受影响的其他分组。
4. 点“切换为份额调度”。确认框显示切换后的预计份额与风险提示；总开关关闭时，确认会一并开启总开关。确认后立即生效：新会话按比例分配，已有会话留在原账号。
5. 在“运行状况”中对比切换前后的缓存命中率、换号损失的缓存、首字延迟与错误率，异常时点“回到原版”。

账号管理按份额分组筛选时显示“份额”列，即该账号在该组预计分到的新会话比例；关闭某个账号的调度时，页面提示它在哪些份额分组的新会话改由同优先级的其他账号承接。

### 流量分配与风险提示

“流量分配”按优先级分段列出全部成员（含停用、错误状态的账号）：状态、负载因子、预计新会话份额（活动优先级内可用账号按有效权重的占比；不可用账号另外显示“恢复后”的份额）、实际份额（近 1 小时本组成功请求的占比）与失败率（近 30 分钟会触发降权的上游失败占比，按该账号在全部分组的请求计算）。预计份额与分组当前的调度方式无关，原版分组上看到的就是切换后的预计值；满载溢出与逐请求的门禁（模型、渠道限制等）不计入。

| 提示 | 条件 |
|---|---|
| 总开关关闭 | 本组暂按原版运行 |
| 没有可用账号 | 请求只能走末位兜底或无号兜底分组 |
| 最高优先级不可用 | 数值最小的优先级没有可用账号，新会话进入更低的优先级 |
| 流量过于集中 | 活动优先级至少有 2 个健康账号时，某账号预计分到 80% 以上的新会话 |
| 负载因子过大 | 负载因子 ≥999；它恢复可用时会拿到同一优先级的绝大多数新会话 |
| 正在爬升 | 账号刚从长时间不可用中恢复，权重正在回升 |
| 已自动降权 | 健康系数 ≤0.5；若持续，建议检查上游或停用 |

### 自适应权重

有效权重 = 负载因子 × 健康系数 × 爬升系数，至少为负载因子的 5%。两个系数都没有设置项，只影响新会话、缓存过期后的重新分配与满载溢出的顺序，不会把热会话迁走。关闭网关韧性总开关后两者都为 1。

**健康系数**（0.2–1）：

- 统计近 30 分钟的上游尝试。失败只计网关韧性会给短时冷却的类别：瞬时错误、首字超时、输出中途停滞；余额、鉴权、限流、降载、请求错误与客户端取消不计入。
- 失败率 = 软失败条数 ÷（用量条数 + 软失败条数），按账号在全部分组计算。
- 对照同一分组、同一优先级的可用账号中最低的失败率（只取尝试数至少 20 次的账号；都不足时取有尝试的账号）。超出不到 3 个百分点不调整，之后每多 5 个百分点权重减半，最低 0.2，按 0.05 取整。小样本会先向同层最低失败率收缩。
- 同一优先级只有一个可用账号、或全员一起变差（上游事故）时不调整。失败率回落后约 30 分钟恢复到 1。
- 份额分组每 60 秒在后台刷新一次。统计超过 5 分钟没有更新、查询失败或运维监控关闭时不调整。

**爬升系数**（0.1–1）：账号从长时间不可用恢复后，新会话权重在 10 分钟内从 0.1 线性回到 1，避免刚恢复（例如余额尚未真正补足）就接下大量新会话。触发条件：余额暂停到期；硬罚到期（含超过 300 秒的限流）；本实例观察到账号连续至少 5 分钟不可用（停用、错误、关闭调度等）后重新可用（按 60 秒采样，进程重启后没有这段记忆）。30 秒级的短时冷却不触发。

“流量分配”与“排查工具”逐项显示“负载因子 → 健康 × a → 爬升 × b → 有效权重 → 预计份额”，并写明原因与预计恢复时间。

### 会话与缓存保护

以下规则都是固定值：

- **会话识别**：优先使用客户端显式会话标识；没有时使用对话锚点（API Key + 系统提示 + 首条用户消息，仅份额分组使用，跨轮稳定、不同 Key 不共享）。OpenAI 请求沿用原版会话哈希。关闭“会话保持”时不绑定，每个请求按比例重新选账号，只适合图片、向量等无状态分组。
- **绑定**：命中即续期，空闲超过 1 小时失效，绑定键格式与原版相同。
- **缓存寿命**：Anthropic 5 分钟（请求声明 1 小时缓存时为 1 小时），OpenAI 30 分钟，其他 5 分钟。低于模型最小可缓存长度的会话视为无缓存可保护。
- **满载**：新会话与溢出跳过负载率达到 100% 的账号。已绑定的会话只看并发槽：绑定账号槽满且缓存仍热时，按预计缓存 Token 等待（每 1k Token 100 毫秒，最多 15 秒，每账号最多排队 3 个请求），超时后溢出并改绑，先同一优先级、再下一优先级，同一优先级内同类账号（平台与账号类型相同）优先。
- **短时不可用**：绑定账号处于网关韧性的软罚（瞬时失败冷却、短限流、过载冷却等），且预计在 300 秒内、缓存过期前恢复时，只临时借用其他账号、不改绑，恢复后会话回到原账号继续读缓存。余额暂停、凭证类与管理员规则类的临时停调是硬状态，下一次请求即改绑。
- **重新分配**：调整负载因子、优先级或账号恢复时，不迁移仍在缓存期内的会话；会话空闲超过缓存寿命后，下一次请求才按当前比例重新分配。份额因此随新会话和冷会话逐步收敛。
- **回到高优先级**：高优先级恢复后，冷会话在它稳定 120 秒后迁回，热会话不迁移。

### 与网关韧性的关系

- 软罚通常按“短时不可用”处理（原因 `soft_spill`）。OpenAI 同站断流暂停例外：有健康替代时直接改绑，暂停到期不回旧号。
- 会话连续失败：同一会话在同一账号上 10 分钟内失败 2 次，改绑并在 10 分钟内回避该账号（原因 `resil_failure_streak`）。
- 余额不足暂停是硬罚（原因 `balance_exhausted`），绑定会话下一次请求即迁移，到期后按爬升系数回升。
- 启用 OpenAI 质量门槛的分组，新放置与溢出候选按质量档 → 当前模型的判慢状态 → 原有份额顺序排序；合法的绑定属主保持第一位，不做质量迁出。
- 末位兜底：只剩软罚账号时，份额计划“放宽一轮”，软罚账号与只被会话回避的账号视为可用，仍按优先级与权重选择（原因 `last_resort_soft`）。
- 无号兜底分组的转投与切回不是份额放置决策，不进份额报表，计入韧性计数 `fallback_group`、`fallback_return`。
- 关闭网关韧性总开关后，软罚判定、余额暂停的硬罚处理与两个自动系数都回到不带韧性的旧规则：任何 300 秒内结束的状态都按短时不可用处理。

### 不经过份额调度的请求

以下请求保持原版行为：OpenAI `previous_response_id` 续链、Codex 子 agent 回到父线程账号等协议强续接（份额报表中记为协议续接）；OpenAI compact 请求、图片请求，以及质量路由已持有的会话；AI Studio 元数据接口与 `count_tokens`；未分组账号（组 0）。Codex 额度压力只在份额分组中作为显式的容量闸门。

### 运行状况与详细报表

“运行状况”比较当前窗口与切换前同长度的窗口（1、6、24 小时），原版分组同样有数据：

| 指标 | 来源 |
|---|---|
| 缓存命中率 | 成功请求的缓存读 Token ÷（输入 + 缓存读 + 缓存写 Token） |
| 因换号损失的缓存 | 缓存归因抽样中，缓存未过期就换号造成的未命中 Token 占比 |
| 首字延迟 | 成功的流式请求首字时间 P50 / P95 |
| 错误率 | 本组客户可见错误 ÷（成功请求 + 客户可见错误） |

- 切换时间在保存调度方式时记录（保留约 8 天）；没有记录时按策略更新时间估算，页面会注明。切换不到一个窗口时，当前窗口从切换时开始。
- 基线与超过 2 小时的窗口按整点小时汇总，与精确时间最多相差 30 分钟。缓存归因按每 4 个会话抽 1 个统计。
- “详细报表”显示缓存命中与未命中分类，以及只在份额模式下产生的数据：选号原因、账号被跳过的原因（满载、会话上限、Codex 额度压力等）、满载等待、尝试次数、热会话迁移的次数与原因。热会话迁移包含被动迁移（绑定账号不可用、失败换号、连续失败改绑、满载溢出、末位兜底），上游出问题时会明显升高；其中的“份额主动迁移”只在缓存变冷后发生，按设计应为 0，超过请求数的 0.1% 是建议回退的信号。

### 排查工具

用当前设置和账号状态模拟一次选号，不占用并发、不写入会话绑定，原版分组同样可用。不填会话哈希时模拟一个新会话（落点按有效权重随机，每次可能不同）；模型可以留空。结果给出会话识别方式、当前绑定与空闲时长、缓存寿命与冷热、满载时最多等待、选号原因、尝试顺序，以及每个候选的优先级、负载因子、健康系数、爬升系数、有效权重、负载率与资格，并附网关韧性的解释。

### 精度边界

- 份额作用于新会话的落点。会话长短、调用频率不同，按请求或 Token 统计的实际份额会偏离预计份额，短窗口、小样本偏差更大。
- 份额调度不是硬上限。需要硬封顶时使用账号自身的并发、RPM、窗口费用、额度等限制；触发时请求溢出到其他账号并计入原因。
- 健康系数只会少降权、不会误降权：数据缺失（停滞未写入运维错误记录、尝试被截断、运维监控关闭）时按“不调整”处理。

### 管理接口

接口位于 `/api/v1/admin/share-scheduling`，写操作记入管理审计日志：

| 方法 | 路径 | 用途 |
|---|---|---|
| `GET` / `PUT` | `/settings` | 总开关 `{enabled}`，默认关闭 |
| `GET` | `/groups` | 分组列表与 1 小时摘要 |
| `GET` / `PUT` | `/groups/:id/policy` | 读取分组设置与成员；保存 `{scheduler, session_keep, expected_version}`，`scheduler` 为 `sub2api`（原版）或 `share`，三项都必填 |
| `POST` | `/groups/:id/preview` | 切换前的预计份额与风险提示 |
| `POST` | `/groups/:id/explain` | 模拟一次选号 |
| `GET` | `/groups/:id/report?window=1h` | 运行状况与详细报表，窗口 1m–24h |
| `GET` | `/accounts/:id/rules` | 账号在各份额分组中的预计份额（只读） |

- 保存带版本号，其他管理员先保存时返回冲突，页面提示重新载入。保存后通过 Redis 广播在各实例数秒内生效，每 30 秒另有一次全量刷新兜底。
- 策略读取失败时沿用最后已知值；冷启动读不到时按原版调度。已保存但无法解析的策略按原版处理，页面显示原因，重新选择调度方式即可覆盖。
- 统计异步批量写入 Redis，写入失败或队列繁忙时只丢弃统计，不影响选号。统计用于观测与对比，不是逐请求的审计记录。
- 管理端读取 `usage_logs`、`ops_error_logs` 都在只读事务中执行，语句超时 5 秒；分组列表的 1 小时摘要在进程内缓存 30 秒。

### 回退

关闭总开关，或把分组调度方式改回原版，都立即生效，不迁移已有会话。

## 升级与回滚

- 早期的“智能可控调度”（策略分组、分配比例、调度模式切换）已移除，由份额调度替代。旧接口 `/api/v1/admin/scheduling/*` 及账号级调度控制、故障域接口统一返回 `410 Gone`，错误码 `SCHEDULING_RETIRED`。
- 份额调度的 `POST /groups/:id/rebalance` 与 `GET /groups/:id/decisions` 已退役，返回 `410`，原因 `SHARE_SCHEDULING_ENDPOINT_RETIRED`。原为“影子对比”的分组按原版运行，重新选择调度方式即可覆盖。
