# 邮件营销（群发）

超级管理员可以在「邮件营销」按注册日期和沉睡天数筛选普通用户，预览名单与邮件，先发测试邮件，再立即开始群发。邮件在数据库中排队，重启后仍能接续；支持暂停、继续、取消和人工重试失败邮件。第一版不支持定时发送。

## 开始前

配置全局 SMTP 和 HTTPS 站点地址。退订地址优先使用 API 基础地址，其次使用前端地址；两者都不能是 HTTP。营销邮件与验证码等系统邮件共用 SMTP 账号，请给系统邮件预留邮箱服务商额度的 20–30%。默认营销限速是每分钟 20 封、滚动 24 小时 500 封。

同一时间只能有一场发送中或已暂停的群发。先完成或取消当前群发，再创建下一场。创建并开始发送需要二次验证（仅在开启 step-up 时生效）；其余管理操作不要求额外二次验证。全部 16 个管理接口仅超级管理员可用，普通管理员无法通过权限勾选获得访问权。

## 圈人规则

时区必须为真实 IANA 名称（如 `Asia/Shanghai` 或 `UTC`），不接受空串和 `Local`。注册日期按所选 IANA 时区的当地日历计算，起止日期均包含在内；夏令时切换日按实际日历长度处理。

「沉睡 N 天」要求注册已满 N×24 小时，并且这段时间既没有面板活跃或登录，也没有 API Key 调用。注册后从没用过的用户满足注册时长也会入选。已删除的 Key 最近用过，仍算活跃，不依赖会定期清理的用量日志。

始终排除已删除、已停用、非普通用户，以及空邮箱、格式不合格或 `.invalid` 合成邮箱。同一邮箱忽略大小写、首尾空白后只发送一封。不接收名单按邮箱或用户 ID 匹配。

「本次排除」最多 1000 条，每行一个用户 ID 或邮箱。空白行忽略；邮箱一次批量解析并匹配所有同邮箱账号；找不到的条目会显示在预览结果中。跳过人数按「无有效邮箱 → 不接收名单 → 本次排除 → 重复邮箱」依次互斥计数。预览与实际创建使用相同规则，创建时再次查询并保存快照，因此其间用户数据变化可能导致人数变化。

## 内容、测试与退订

标题最多 200 个字符，Markdown 正文最多 100000 字节；允许超级管理员写内嵌 HTML。`{{username}}` 替换为用户名，为空时取邮箱 @ 前面的部分；`{{site_name}}` 替换为站点名。预览、测试和正式投递共用服务端渲染。管理页面必须在带空 sandbox 的 iframe 中显示返回的 HTML。

邮件同时提供纯文本与 HTML，自动追加中英双语退订页脚，以及 `List-Unsubscribe`、`List-Unsubscribe-Post` 邮件头。测试邮件也带有效退订链接，绑定实际测试收件邮箱。撞限速返回 `EMAIL_CAMPAIGN_RATE_LIMITED`（429），说明每分钟或 24 小时窗口；SMTP 失败返回 `EMAIL_CAMPAIGN_SEND_FAILED`（502），仅公开阶段和返回码，不公开服务器原始响应或凭据。Markdown 链接 URL 中的占位符在渲染后替换为 URL 编码值。详情预览暂不可渲染时仍返回详情，`preview_html` 为空；创建和查询的 `waiting_for_limit` 使用相同算法。

公开退订页使用中英双语居中卡片和转义后的站点名；不含脚本或外部资源，CSP 仅以固定哈希允许页面内联样式。打开退订链接只显示确认页，不修改数据，避免邮件扫描器误退订。确认按钮和支持 RFC 8058 的邮箱一键退订通过公开 POST 写入名单，重复提交结果一致。退订不影响验证码、余额提醒等系统邮件。用户退订后只有明确要求重新订阅时才应移除记录。

不接收名单可按邮箱或用户 ID 添加，也接受尚未注册的真实邮箱，以防后续注册。收件人快照生成后，每封投递前仍会检查删除、停用、角色、邮箱变更和最新退订状态；不再符合条件的邮件会跳过。

## 进度、限速和失败

进度实时按收件人状态统计。测试邮件、失败投递、人工重试都会占用营销限额。达到每分钟或滚动 24 小时上限时自动等待；修改限速会在下一封生效。限额只统计营销投递尝试，不包括验证码等系统邮件。

地址解析失败和 RCPT 5xx 拒收会进入失败名单，不增加连续失败次数；RCPT 4xx（除 421）也进入失败名单，但计入连续失败，因为通常与限流有关。失败原因保留 SMTP 阶段与返回码。连接、TLS、认证、发件人、RCPT 421 或服务器错误会把收件人留在队列，连续 5 次计数失败（含临时拒收和不确定结果）会自动暂停；认证返回 535 时立即暂停。成功一封后连续失败计数清零。修复配置后手动继续。

正文提交后连接断开、超时且未收到明确响应的邮件会标记为「可能已送达」，不自动重发。每次认领执行期限为 2 分钟，SMTP 截止时间固定为认领时间加 2 分钟；建立连接前在数据库核验状态、认领代数和期限。重启遗留、认领超过 5 分钟的投递也按「可能已送达」处理，旧 worker 恢复后不会再次投递。正文写入中途失败且结束符尚未提交属于确定未送达。人工重试前务必注意可能重复送达；仅已暂停或已完成的群发可重试失败邮件。

优雅停机先停止认领，给在途邮件 2 秒完成预算，超时再取消；随后最多额外等待 2 秒结果回写，完成后才释放数据库资源。结果用独立的短超时上下文回写：取消时确定未送达的放回待发送（活动已取消则跳过），不增加连续失败；已收到 DATA 的 250 则记成功，即使 QUIT 中断。只有取消时真正不确定的结果留给回收。

暂停或取消不能撤回已发出的邮件。为保证多个后端实例同时运行时也最多只有一封正在投递，发送器全局串行认领；取消会将剩余待发送项标记为跳过。正在投递的一封仍可能送达。发件服务商是否显示一键退订入口取决于其规则及 DKIM 是否覆盖退订头，页脚链接始终可用。

## 迁移 294

升级自动运行 `294_email_campaigns.sql`，新增活动、收件人快照、不接收名单、投递日志四张表；不修改 users 表或 ent schema。部分唯一索引在数据库层保证最多一场活动。退订签名密钥使用 security_secrets 中独立的原子初始化记录，不复用通知退订密钥。

发送限速保存在 settings 的 `email_campaign_send_limits` JSON 中，不出现在通用设置 DTO。限速日志保留至少最近 48 小时，发送器顺手清理旧日志。升级前请备份数据库；回退应用版本不会自动删除群发数据或撤回邮件，不应删除退订密钥或不接收名单。
