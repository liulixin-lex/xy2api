# Codex 协作消息与恢复

本文说明协作明文化的可见范围、终端用户应如何理解恢复结果，以及管理员逐站验收的方法。[English](codex-collaboration.en.md) · [设置参考](gateway-resilience-settings.md)

## 使用前知情

- 明文消息正文对本网关、该中转站及其上游可见。
- 正文会进入内容审核及其记录。
- 关闭开关不能撤回已发出的明文、客户端历史里的明文，以及已经进入审核记录或上游的正文。

新建 OpenAI 账号的“协作消息明文化”默认关闭，仅新建的路径保存显式布尔值；普通编辑和复制保留原配置，只有明确操作开关才覆盖。会更新已有账号的会话、Agent Identity 导入在开关未操作时不发送覆盖值；这类导入新建账号时可省略该字段，同样表示关闭。明确选择后发送 true 或 false。全局明文化开关、模型清单与账号开关共同决定新会话的转换资格。API Key 账号上已有明文标记的会话保留连续性，关闭账号开关不会撤回这些历史消息。关闭全局明文化开关停止新的转换，进行中的响应仍完成还原。

只转换符合条件的原生 Responses HTTP 协作请求。自定义协作命名空间下的消息始终保持密文，不受明文化开关影响。不要把开关开启当成已经成功投递的证据。

## 终端用户如何判断结果

子任务显示“已完成”，或主线程命令行成功退出，可能只是网关正常结束了一个不可读回合，**不代表任务已做**。阅读返回的 `Gateway notice`，核对实际结果后再继续：

- “任务尚未开始”的说明只在能证明未开始时出现。提供可读的任务副本后才能尝试重派。
- 说明提到此前工作可能已生效时，先检查文件、提交和外部操作，再决定哪些步骤需要重做。
- 主线程说明缺少输入时，补充缺失内容的明文副本；这条回复不确认任务完成。
- 同一任务再次投递失败时，改用其他执行路径或报告缺失输入，不要无限重派。
- 工具结果被替换成不可读占位时，它既不表示成功，也不表示失败。不要盲目重复有副作用的操作。

占位只替换不可读片段，其余信封与可保留内容继续传递。已经丢失的历史内容、reasoning 和缓存前缀不能通过关闭开关恢复。本地生成的结束说明不计费；真实上游工作按原规则记账，被放弃的可选尝试不向客户计费、不扣余额。

## 管理员逐站验收

只在获准的候选实例及测试分组中执行，不切换正式流量。每个计划启用的站点、模型及账号组合单独验收，也覆盖兜底与借用路径。下列口令均应临时生成，不使用真实用户任务。真实站点信息与请求关联资料留在受限验收记录中，不提交到公开仓库。

1. 确认离线测试及回放对照通过；所有新增行为关闭时与现有路径一致，阶梯开启且下述两个风险开关关闭时，现有修复必须先原样执行，原来能救回的请求仍成功。只有现有修复即将报错或不认领新密文证据时才进入阶梯；阶梯仍失败则返回保存的原有错误，状态码、错误码和可重试性不变。两个风险开关在负责人知情后单独验收。
2. 为每轮记录客户端核心版本、实际出站模型、实际账号与站点、请求关联标识和开关快照。先新建持久化原生 HTTP 会话：父线程发随机口令给子线程，子线程用 `send_message` 回传，再用 `followup_task` 完成新口令往返。核对正文完整，不能只看 HTTP 成功。
3. 保持同一会话和子线程，受控地把接收请求切到另一个待验站点，两个方向分别验证新的口令。不支持的组合不得凭单站结果视为通过。
4. 从根会话恢复旧会话，确认恢复请求同时包含已有协作成员与新增定义，再验证一次口令往返。未知客户端形态单独记录，不以改写成功代替内容校验。
5. 关闭账号明文化开关，在原会话继续发送一次。记录为正常继续、明确报错或静默丢失；静默丢失不通过。另建会话确认关闭后的新会话行为。
6. 开启恢复阶梯及测试分组范围的本地收尾，让接收请求受控地落到不能读取内容的账号。核对现有修复先执行，已成功的修复不进入阶梯；进入阶梯后核对恢复次序和占位文案，阶梯仍失败则返回原有错误。验证子线程结束后父线程收到说明，重派后能继续；验证主线程本地结束及命令行退出。核对本地部分和被放弃的可选尝试不向客户计费，每次入站请求只结算一次；可选失败不写账号故障、冷却、避让或解绑，记录和观测故障不阻塞交付。
7. 单独验证压缩、审查和结构化输出请求：不进入本地收尾，必要时走全部占位及现有修复；仍失败时错误形态不变。已经向客户端交付语义输出的请求不以本地成功结束掩盖失败。
8. 将八项配置逐个关闭，覆盖“阶梯开、优先保留内容关”“阶梯开、记录关”“阶梯开、本地收尾关”“阶梯关但依赖项仍保存开启值”。确认已有收尾线程可以续轮，不重复执行已产生的副作用。
9. 比较实际投递结果：完整被接受、丢失但通知已回到父线程、丢失且通知未确认、丢失但已写给用户、静默丢失、中断。通知写出不等于人或模型已读；HTTP 成功率和“已完成”状态不能替代验收。

## 开关关系与回退

八项配置位于韧性 JSON 的 `collab` 节。仅 `records` 默认开启；本地收尾默认 `off`，其余行为默认关闭。每次请求沿用开始时的设置快照。

| 条件 | 结果 |
|---|---|
| `ladder=false` | 使用现有修复，不执行优先保留内容、本地收尾及按记录路由，不读取已终结、已替换状态 |
| `ladder=true, lossless_first=false` | 先走现有修复，仅在即将报错或不认领新密文证据时进入阶梯 |
| `ladder=true, lossless_first=true` | 阶梯提前，减少静默丢失，但少数情况下可能增加报错 |
| `ladder=true, records=false` | 阶梯照常工作，按没有投递记录处理；已终结、已替换状态仍读写 |
| `ladder=true, record_routing=false` | 换号不带记录目标，重派不借用内容 |
| 本地收尾关闭或不覆盖分组 | 不产生新的本地收尾；阶梯仍读取已有已终结状态 |

`collab.lossless_first` 默认 false，依赖阶梯。开启后把阶梯提前到现有修复之前，减少静默丢失；输出后的失败、额外发送消耗共享上游额度及并发竞争仍可能在少数情况下增加报错。负责人知情接受风险后再单独决定是否开启。

`collab.strict_marker_veto` 默认 false。更严格的密文检查可能使现在能成功的消息失去明文标记，会增加报错，不建议开启。

关闭七项行为配置回到现有修复路径；观测、响应还原隔离及无开关的响应修正、界面变更需要版本回退。开启期间留下的记录按有效期消失，进程内记录在重启后丢失；已经交付的明文、占位、本地答复和已执行操作不可撤回。重新派发前仍需核对先前结果。

旧后端没有 `collab` 时，页面显示默认值但不会在未修改该节时发送它。服务端返回 null 或当前版本不支持的值时，仅禁用协作控件，其他设置仍可保存且不提交该节。支持的服务端原值和未知扩展字段（包括本地收尾内的字段）在普通保存及 JSON 往返中无损保留，不自动添加默认字段；JSON 不允许凭空增加或修改未知字段。明确修改已知字段后由页面及后端校验；若旧版本保存时丢掉该节，再升级会恢复默认值。回退前保存受限配置备份，重新升级后重新验收再启用。
