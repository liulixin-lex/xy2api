# 管理员与权限

XY2API 后台有两种管理员：超级管理员可以使用全部功能；普通管理员只能使用超级管理员逐人勾选的模块和开关，适合把日常运营（客服、账号维护、查看用量）交给团队成员而不交出系统设置和资金权限。本文面向需要任命、配置或排查普通管理员权限的超级管理员。

## 概览

| 角色 | `role` | 能做什么 |
|---|---|---|
| 超级管理员（界面显示“管理员”） | `admin` | 后台全部功能。全局 admin API Key 也按超级管理员处理 |
| 普通管理员 | `operator` | 只能使用权限表里勾选的模块和开关 |
| 用户 | `user` | 只有用户端功能 |

权限的组织方式：

- 每个模块分“查看”和“管理”两级，“管理”包含“查看”。
- 涉及资金或数据外流的操作各有一个独立开关，默认关闭。
- 系统设置、支付配置、凭据导入导出等只有超级管理员能做，权限表里不提供勾选。

**后端是安全边界**：每条后台接口都登记在权限目录中，按“模块 + 级别 + 开关”检查；没有登记的接口，普通管理员一律得到 `403`。前端会按权限隐藏菜单和按钮，即使漏掉了某个按钮，点击也只会得到 `403`。

## 任命普通管理员

在“用户管理”打开用户的编辑弹窗，把角色改为“普通管理员”，弹窗下方会展开权限表。新建用户时也可以直接选择“普通管理员”并勾选权限。

**权限表**

- 每个模块一行，有“查看”“管理”两个勾选框。勾选“管理”会同时勾上并锁定“查看”；取消“查看”会清空整行。
- 四个开关放在所属模块的行里，“导出业务数据”单独放在底部。每个开关旁有一句“开：… 关：…”的说明。
- 所在行既没有查看也没有管理时，该行的开关不能勾选；清空一行也会清掉它的开关。

**保存**

- 编辑已有用户时，先保存权限，再保存用户（含角色）。
- 新建普通管理员时，先创建账号，再保存权限。如果权限保存失败，重试只补存权限，不会重复创建账号；关闭表单后也可以从用户列表继续编辑。
- 新建超级管理员或普通管理员、涉及这两种角色的角色变更、保存权限表，都需要二次验证（step-up，在设置中开启时生效）。

**撤销**：把角色改回“用户”。权限数据保留但不再生效；重新任命时权限表显示旧的设置，保存后才生效，不会被静默恢复。

**生效时机**

- 每次请求都重新读取用户和权限，撤权或改权限在下一次请求生效。
- 运维监控的实时 QPS 连接每 30 秒复核一次，失去“运维监控”查看权限后断开。
- 前端收到权限类 `403` 时会重新拉取权限并刷新菜单，每 60 秒最多一次。

| 用户管理 `users` | 用户列表与详情、余额记录、用户的 API Key（打码）、用量与订阅 | 新建、编辑、停用、删除普通用户；批量改状态、并发与限额；用户属性、平台额度、更换分组、绑定登录方式、修改用户 API Key 的分组 |

| 客户服务 `support_tickets` | 工单与在线客服会话的列表、摘要、用户信息、对话与图片 | 回复、修改状态、删除工单、删除会话消息或整个会话、禁止用户发消息 |
| IP 管理 `proxies` | 代理列表、详情与统计（不含密码） | 编辑、测试、删除代理（新建与网络字段见“谁能修改网络设置”） |
| 安全审计 `security_audit` | 风控日志与状态、提示词审计事件（含完整提示词） | 修改风控配置（不含审计引擎、API Key、上游地址、模型和代理）、删除单个风控哈希、解封用户 |
| 兑换码 `redeem_codes` | 兑换码列表与统计 | 删除、作废未使用、已停用或已过期的普通兑换码 |
| 优惠码 `promo_codes` | 优惠码与使用记录 | 删除优惠码 |
| 邀请返利 `affiliates` | 邀请、返利与转账记录 | 修改用户的邀请码 |
| 订单管理 `orders` | 订单、支付概览与套餐 | 取消订单 |
| 使用记录 `usage` | 使用记录与统计 | 没有写操作，同查看 |
| 操作日志 `audit_logs` | 操作日志（请求体按下文脱敏） | 没有写操作，同查看 |
| 订阅 `subscriptions` | 订阅列表与进度 | 撤销、删除订阅 |

只有“查看”时，页面隐藏新增、编辑、删除、批量、行内开关、探测和测试等写操作入口。

分组质量门槛的策略写入跟随“分组管理”的管理权限，策略与状态读取跟随“账号管理”的查看权限（见[分组质量门槛](group-quality-gate.md)）；普通管理员不能借此修改账号成员关系或调度字段。

**跨模块读取**：页面上的下拉选择不需要单独勾选模块。

- 分组下拉：有账号、用户、渠道、订阅、公告、兑换码、安全审计、运维监控或订单任一模块的查看权限即可读取。
- 代理下拉：有账号或安全审计的查看权限即可读取，不含密码。
- 用户列表：有分组或订阅的查看权限即可读取。

在这些地方读到的数据同样按下文脱敏。

## 开关

| 开关 | 所在行 | 开 | 关 |
|---|---|---|---|
| 加减余额 `users.balance_adjust` | 用户管理 | 可以加减余额、设初始余额、发放和延期订阅、修改分组倍率和套餐价格 | 只能查看这些内容 |
| 退款 `orders.refund` | 订单管理 | 可以退款、查询退款、重新履约、处理返利提现 | 不能做这些操作；订单里的充值码打码显示 |
| 生成兑换码 `redeem_codes.issue` | 兑换码 | 可以生成兑换码和优惠码、批量修改，列表显示完整的码 | 不能生成，列表里的码打码显示 |
| 显示上游地址 `accounts.upstream_address` | 账号管理 | 显示并可修改账号接入地址和代理，可以新建和修改代理 | 不显示上游地址，不能修改地址和代理 |
| 导出业务数据 `data.export` | 底部 | 可以导出使用记录、兑换码等业务数据 | 不能导出 |

### 加减余额

“加减余额”覆盖所有会改变用户资金、价格或专属分组授权的操作：

- **余额**：加减用户余额；新建用户时设初始余额；为指定用户“生成并兑换”兑换码。
- **订阅**：发放、批量发放、延期、重置额度、恢复订阅。撤销订阅不需要该开关。
- **价格**：用户专属倍率与分组的每用户倍率表；分组的倍率、限额、长上下文、图片、视频、搜索、音频、高峰时段、利润控制等价格字段；已有分组的平台、强制 Fast、推理强度映射与最大推理强度；套餐的增删改；渠道的分组绑定、删除渠道，以及已绑定分组的渠道的定价、模型映射、计费模型来源、状态、账号统计定价规则；账号的缓存 TTL 覆盖与 OpenAI 长上下文计费；邀请返利比例。
- **分组授权**：给用户加专属分组；把用户或用户的 API Key 改到他还没有权限的专属分组。移除分组不需要该开关。

没有该开关时，分组管理还有以下限制：

- 新建分组只能是专属分组，不能设回退分组；编辑时不能改回退分组，但可以清除。
- 不能把专属分组改为公开，也不能重新启用已停用的分组；复制分组得到停用的副本，启用它同样需要该开关。
- 只能删除没有账号的分组，否则返回 `409 GROUP_NOT_EMPTY`。
- 编辑已有分组时不能通过切换平台来重置利润控制或 Fast 计费设置。未改变的价格字段可以原样保存。

没有该开关的普通管理员新建用户时：新用户余额为 0（即使设置里的默认余额更高），不发放默认订阅，不能设余额或授予专属分组，邮箱不能使用系统保留的 OAuth 合成域名。有开关时，新用户按注册默认值发放，与超级管理员相同。无论有没有开关，普通管理员给用户绑定登录方式时都不能写入身份元数据。

**账号放置**：有账号“管理”权限就能在新建、编辑、批量编辑时把账号加入或移出分组，也能复制账号、创建 Spark 影子账号，不需要“加减余额”。新建账号不指定分组时，与超级管理员一样绑定对应平台的默认分组。新建或编辑分组时“从其他分组复制账号”，除分组“管理”外还需要“加减余额”或账号“管理”之一，否则返回 `400 ADMIN_FIELD_FORBIDDEN`，字段为 `copy_accounts_from_group_ids`。

### 生成兑换码

没有该开关时，兑换码只能按用户邮箱搜索（必须包含 `@`），优惠码不能搜索，两者都不能按码排序；操作日志里兑换码与优惠码相关接口的查询参数整段显示为 `<query hidden>`。这样被打码的码不能靠搜索逐字试出来。

无论有没有该开关，批量修改只能改四种普通类型的兑换码；被管理员或普通管理员使用过的码只有超级管理员能改。

### 导出业务数据

- 导出使用记录还需要“使用记录”的查看权限（导出方式见[用量指标与导出](usage.md#后台导出)）。
- 导出兑换码还需要“兑换码”的查看权限和“生成兑换码”开关。
- 下载导出文件时按当时的权限再检查一次，撤权后已经拿到的下载链接也不能用。

### 显示上游地址

关闭时，除了界面上不显示，后端也不返回地址：

- 账号接口不返回接入地址，账号名称是普通文字，不能跳转。
- 测试账号、定时测试、智商检测等结果里的错误详情换成固定文字 `upstream error details hidden`，状态码和原因码保留。
- 渠道监控不返回检测地址；检测历史、“立即检测”结果和额度快照里的错误文字换成固定文字。
- 风控配置不返回上游地址，包括各审计引擎分别保存的地址。
- 操作日志请求体里的地址打码，任何字段里的网址换成 `[upstream]`；含网址的查询参数整段显示为 `<query hidden>`。
- 渠道监控 v2 的错误列表中，既没有“运维监控”查看权限也没有本开关时，错误文字换成固定文字，次数、分类和状态码保留。

`mixed_channel_warning` 这类机器码不会被替换，普通管理员仍能确认混合渠道提示。

## 谁能修改网络设置

没有“显示上游地址”权限的普通管理员不能设置或修改服务器连到哪里：账号的接入地址、自定义接入地址和接口协议，账号代理，模型同步预览的地址，代理的协议、主机、端口、登录信息和备用链；也不能新建代理。

有这项权限时，普通管理员可以在 API Key、上游（upstream）和 Bedrock 账号以及代理上查看并修改这些设置，但：

- 每个新地址都必须是公网地址。拒绝云元数据主机名，以及内网、本机、链路本地、CGNAT、IPv6 ULA 地址；直接写的 IP 和域名解析出的 IP 都检查，解析失败也按内网处理；设置里的 `allow_private_hosts` 对普通管理员不生效。不通过时返回 `400 ADMIN_FIELD_FORBIDDEN`，`cause=private_address`。
- 修改地址、代理、类型、接口协议、接入模式或区域时，账号保存的每个密钥（包括 new-api 访问令牌）都要填新值或清除，与原值相同的不算重填；没有重新提交的自定义请求头值会被丢弃。这防止已保存的密钥被带到新地址。缺少时返回 `400 ACCOUNT_API_KEY_REQUIRED`。
- 原样提交已打码用户名和密码的地址会保留原地址，不算修改；但不能把 `***@` 带到另一个地址。

这项权限是信任授权：地址只在保存时检查，不在每次连接时检查，之后域名可能被解析到内网（DNS 重绑定，超级管理员保存的地址也一样）。只把它授予你信任其管理上游网络的人。

其他细则：

- **OAuth 类账号**：OAuth、setup-token 和 service account 类账号的代理、类型和接入方式只能由超级管理员修改；重新授权只刷新令牌，不能在 OAuth 与 setup-token 之间切换。批量编辑从不修改网络设置。
- **新建账号**：没有这项权限时，账号使用平台默认地址，不带代理；上游（upstream）类型必须填地址，所以不提供。
- **编辑账号**：没有这项权限时，类型、接口协议、接入模式、AWS 区域和代理都不能改，地址输入框隐藏，后端保留原值。
- **代理**：“正在使用”指被账号直接使用、是账号回退前的原代理、在其他在用代理的备用链上，或被网页搜索、风控配置引用。正在使用的代理不能删除，状态不能改，有效期只能清除或延后，网络字段中只能改密码。未使用的代理改协议、主机、端口或用户名时必须同时填新密码。“恢复代理回退”只有超级管理员能做。
- **Bedrock**：普通管理员填写的 AWS 区域必须是 `us-east-1` 这样的格式。
- **Codex 工单**：普通管理员不能设置代理 URL，代理池只有超级管理员能管理。
- **渠道监控**：地址不需要这项权限，因为每次连接都会检查；新地址同样要通过公网地址检查；改地址、服务商或接口模式时必须重填 API Key。含请求头或非空覆盖请求体（`body_override`）的监控模板只有超级管理员能应用。没有账号查看权限时，不能设置监控关联的账号。
- **风控配置**：不能切换审计引擎，提交不同的 `engine` 返回 `400 ADMIN_FIELD_FORBIDDEN`。

## 只有超级管理员能做的事

- 用户角色与权限：创建或任命超级管理员、普通管理员，修改任何管理员，读写权限表。
- 全局 admin API Key 的查看、重新生成、删除。
- 系统设置（`/settings*`，含网关韧性、冷却、限流、邮件模板、网页搜索模拟、Codex 工单代理池）、数据管理与备份、版本检查、更新、重启、回滚。
- 支付配置与支付服务商。
- 账号与代理数据的导出、导入，从 CRS 同步账号；OpenAI 登录凭据与 2FA 密钥管理（见 [OpenAI 账号 2FA 登录导入](openai-totp.md)）。
- 插件与自定义管理页；客户服务与在线客服的开关和设置。
- 删除或销毁证据：清空操作日志、使用记录清理任务、清理系统日志、删除提示词审计事件、删除全部风控哈希。
- 运维与审计的系统级配置：数据保留等高级设置、运行日志与邮件通知配置、风控与提示词审计的 API Key 配置和测试、提示词审计端点探测。
- 账号：恢复代理回退；上游计费探测、Ollama Cloud 用量、OpenCode Go 用量的全局设置；OAuth 类账号的网络设置。
- 兑换码：删除或作废已使用的码；删除、作废或批量修改非普通类型的码。

## 保护措施

**目标用户**：普通管理员只能操作普通用户（`role=user`），不能操作超级管理员、其他普通管理员或自己，否则返回 `403 ADMIN_TARGET_FORBIDDEN`。按 API Key、订阅、订单或兑换码找到的用户同样检查；批量操作只要有一个目标不符合就整批拒绝；批量修改并发与限额时不能选“全部用户”。删除分组时如果分组里有管理员的订阅或专属授权，或修改每用户倍率、RPM 表时表里有管理员的行，也会被拒绝。

**角色**

- 普通管理员不能修改任何人的角色：请求里带 `role` 返回 `400 ADMIN_FIELD_FORBIDDEN`。
- 不能把最后一个超级管理员改成其他角色（普通管理员不算管理员）；超级管理员不能给自己降级。
- 权限修改前后的差异写入操作日志 `admin.operator_permissions.update`。

**敏感数据脱敏**（只对普通管理员，返回前处理）

- 用户 API Key 一律打码，只保留开头和结尾几位；用户搜索不匹配 API Key 内容。
- 代理密码一律不返回。账号的 API Key、new-api 访问令牌等密钥本来就不返回给任何人。
- 账号接入地址、渠道监控检测地址、风控各引擎地址和运维上游网址中的用户名和密码一律隐藏，即使有相应权限。
- 账号自定义请求头（`header_overrides`）、渠道监控与模板的请求头和非空覆盖请求体，值一律显示为 `******`；编辑时原样提交 `******` 会保留原值。
- 操作日志：普通管理员不能调用的接口（超级管理员专用、登录和用户端接口）的请求体显示为 `<request body hidden>`，查询参数不显示；请求体里的请求头值、刷新令牌（`rt`）和代理地址（`proxy_url`）一律打码。

**失败即拒绝**：普通管理员的权限读取失败时返回 `503 OPERATOR_ACCESS_UNAVAILABLE`；存储的权限数据不合法时按“没有任何权限”处理。普通管理员受后台限流约束，超级管理员仍然豁免。

## 后台模式与合规确认

- **后台模式**开启后，普通用户不能登录。普通管理员与超级管理员一样可以登录（密码、两步验证、Passkey、刷新令牌）、读取自己的资料、使用用户端功能；后台功能仍按权限表。
- **部署与运营合规确认**按人记录，普通管理员同样要完成（见 [admin-compliance.zh.md](../legal/admin-compliance.zh.md)）。确认之前，后台接口返回 `423 ADMIN_COMPLIANCE_ACK_REQUIRED`；读取自己权限的 `/api/v1/admin/me/access` 不受影响，菜单可以先加载。

界面上，侧边栏和命令面板只显示有查看权限的模块；系统设置、插件、版本标识、自定义菜单与自定义页面只对超级管理员显示。登录后进入第一个有权限的后台页面，一个都没有时进入个人资料页。

## 错误原因码

| 原因码 | HTTP | 含义 |
|---|---|---|
| `ADMIN_PERMISSION_DENIED` | 403 | 缺少模块权限或开关；`metadata.required` 为所需权限，例如 `accounts:manage`、`data.export`。未登记的接口也返回它，`required` 为 `catalog` |
| `SUPER_ADMIN_REQUIRED` | 403 | 只有超级管理员能做 |
| `ADMIN_TARGET_FORBIDDEN` | 403 | 目标用户不是普通用户，或是自己 |
| `ADMIN_FIELD_FORBIDDEN` | 400 | 提交了无权修改的字段，`metadata.field` 为字段名；`metadata.cause` 可能是 `private_address`、`invalid_region`、`noncanonical`（请求体有重复或只差大小写的同名键）、`proxy_in_use` |
| `ACCOUNT_API_KEY_REQUIRED` | 400 | 修改网络设置时没有重填已保存的密钥，`metadata.field` 为缺少的键 |
| `OPERATOR_NETWORK_CHANGE_FORBIDDEN` | 403 | 无权修改网络设置；`metadata.cause` 为 `address`（没有“显示上游地址”）、`refreshable_account`（OAuth 类账号）或 `bulk`（批量编辑） |
| `ADMIN_PERMISSION_INVALID` | 400 | 权限 JSON 不合法 |
| `OPERATOR_ACCESS_UNAVAILABLE` | 503 | 权限读取失败，按拒绝处理 |
| `ADMIN_ACTOR_MISSING` | 503 | 内部保护：服务函数没有收到调用者身份，未写入任何数据 |
| `ADMIN_REDACTION_FAILED` | 500 | 内部保护：脱敏失败，不返回原始内容 |
| `REQUEST_TOO_LARGE` | 413 | 带检查规则的接口，请求体超过 16 MiB |

## 接口

`GET /api/v1/admin/me/access`：所有能进后台的人都可以调用，前端用它决定菜单、路由和按钮。

```json
{
  "role": "operator",
  "is_super_admin": false,
  "modules": { "accounts": "manage", "usage": "view" },
  "flags": ["accounts.upstream_address", "data.export"],
  "settings": { "ops_monitoring_enabled": true, "payment_enabled": false },
  "custom_menu_items": []
}
```

`settings` 只包含后台页面需要的少数开关和费率（实际字段更多，上例只列两项）。超级管理员得到全部 18 个模块为 `manage`、全部 5 个开关；普通管理员的 `custom_menu_items` 总是空数组。

`GET` / `PUT /api/v1/admin/users/:id/operator-permissions`：只有超级管理员能调用，`PUT` 需要二次验证。请求体与返回体相同：

```json
{ "modules": { "accounts": "manage", "usage": "view" }, "flags": ["accounts.upstream_address", "data.export"] }
```

模块的值只能是 `view` 或 `manage`，没有权限的模块不写（`none` 不合法）；未知的键、模块、取值或开关返回 `400 ADMIN_PERMISSION_INVALID`。用户没有设置过权限时返回 `{"modules":{},"flags":[]}`。

## 限制与注意事项

- **账号与分组的管理权限可以间接影响价格**：有账号“管理”权限的普通管理员可以把高价账号放进便宜的分组；有账号或分组“管理”权限的可以修改模型映射、模型路由和组合路由（例如把便宜的模型名映射到高价上游模型）。用户按请求的模型计费，这些操作不需要“加减余额”。请只把这两个模块的管理权限交给可信的人。
- **账号倍率**：有账号“管理”权限可以修改账号的 `rate_multiplier`，它影响成本核算和账号额度，不影响用户支付的价格。
- **删除账号**：有账号“管理”权限可以删除已加入分组的账号，同时移除其分组绑定。
- **测试账号**：普通管理员能看到测试时上游返回的正常内容（例如模型回复）。没有“显示上游地址”时错误详情换成固定文字，但成功响应的 `message` 等字段只去掉网址，单独出现的主机名仍可能显示。
- **运维监控**：错误详情里可能显示上游地址，有“运维监控”查看权限就能看到，与“显示上游地址”无关。
- **额度模式的渠道监控**：没有账号查看权限的普通管理员不能把监控关联到账号，因此不能新建只支持额度模式的监控（例如 antigravity）。
- **首次绑定赠送**：普通管理员新建的用户以后绑定真实第三方登录身份时，仍可能领到该登录方式的首次绑定赠送（需超级管理员开启）。每个用户每种登录方式只能领一次。
- **权限是模块级的**：没有按分组或账号的隔离。通过[只读 MCP](mcp.md) 查询时遵循同一套权限。

## 升级与回滚

普通管理员权限存放在迁移 `282_admin_operator_permissions.sql` 创建的表 `admin_operator_permissions` 中（每个用户最多一行）。`operator` 是 `users.role` 列的一个取值，没有修改 `users` 表结构。只有角色为 `operator` 时才读取该行。

回滚到不支持普通管理员的旧版本前，先记下名单和权限：

```sql
SELECT u.id, u.email, p.permissions
FROM users u LEFT JOIN admin_operator_permissions p ON p.user_id = u.id
WHERE u.role = 'operator';
```

然后在启动旧版本之前，用一个事务执行（程序不会自动执行）：

```sql
BEGIN;
UPDATE users SET role = 'user' WHERE role = 'operator';
DROP TABLE IF EXISTS admin_operator_permissions;
DELETE FROM schema_migrations WHERE filename = '282_admin_operator_permissions.sql';
COMMIT;
```

必须同时删除 `schema_migrations` 中的记录：迁移程序按文件名跳过已执行的迁移，如果只删表，再次升级时不会重建，之后任命的普通管理员都会得到 `503 OPERATOR_ACCESS_UNAVAILABLE`。再次升级后按记下的名单重新任命。通用流程见[升级与回滚](../deployment/upgrade.md)。
