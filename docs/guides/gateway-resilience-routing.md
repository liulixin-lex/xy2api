# 网关韧性：罚则与选号

本文说明网关韧性怎样根据上游失败影响选号：失败如何分类，哪些失败让账号进入软罚或硬罚，首输出截止怎样计算，Claude 慢账号如何让位，模型级冷却、末位兜底与无号兜底分组如何工作。OpenAI 账号持续偏慢、错误偏多或缓存命中低时的处理见 [分组质量门槛](group-quality-gate.md)。适合需要解释“为什么这个请求换了号”“为什么这个账号暂时不被选中”的运维与管理员。设置项见 [设置参考](gateway-resilience-settings.md)，总体介绍见 [网关韧性](gateway-resilience.md)。

## 失败分类

每次上游失败都按状态码、错误码、错误类型、错误消息与流内事件归入一类，结果写入运维错误记录每次尝试的 `resilience_category`（总开关关闭时为空）。

| 类别 | 含义 | 换号 | 对账号的影响 |
|---|---|---|---|
| `BALANCE` | 上游余额或订阅共享额度不足 | 是 | 余额暂停（硬罚） |
| `AUTH` | 鉴权失败、账号停用 | 是 | 硬罚 |
| `RATE_LIMIT_RESET` | 限流且给出重置时间 | 是 | 按重置时间限流；超过 300 秒为硬罚 |
| `RATE_LIMIT` | 限流、未给重置时间 | 是 | 软罚 |
| `CAPACITY_SHED` | 上游明确的容量降载 | 是，只换一次且换到其他上游主机 | 不罚号 |
| `TRANSIENT` | 5xx、超时、传输错误、CDN 错误页 | 是 | 短冷却或按模型冷却（软罚） |
| `FIRST_OUTPUT_TIMEOUT` | 首输出截止到期 | 是 | 软罚；计划内截止不罚号 |
| `STALL` | 输出后停滞 | 否（已输出） | 软罚 |
| `MODEL_UNSUPPORTED` | 上游明确报告该模型不可用 | 是，不同号重试 | 账号 × 模型冷却 |
| `UPSTREAM_REQUEST_RESTRICTION` | 5xx 但错误类型为请求错误 | 是，不同号重试 | 不罚号 |
| `CLIENT_ERROR` | 请求本身的问题（参数、上下文超长、内容拒绝、会话状态拒绝） | 否 | 不罚号 |
| `CLIENT_CANCEL` | 客户端取消 | 否 | 不罚号 |

几条判定规则：

- 瞬时失败、首输出超时与停滞的账号冷却：上游带 `Retry-After` 时按它冷却，封顶 `failure.retry_after_cap_seconds`（默认 120 秒）；不带时，OpenAI 兼容账号冷却 `failure.transient_cooldown_seconds`（默认 30 秒），Anthropic、Gemini、Antigravity 账号改为按账号 × 模型逐级冷却（见“模型级冷却”）。
- 中转前面的 CDN 或代理写出的 5xx 错误页（Cloudflare 的 JSON 错误页、HTML 页面）按瞬时失败处理，即使文案提到 overloaded。
- `failure.decision_v2` 开启时，只有 `server_is_overloaded`、`slow_down`、529 与结构化的 overloaded 算容量降载；raw 429、“The service is busy”“Too many pending requests”“Concurrency limit exceeded”按瞬时或限流处理，可以换到同一主机上的其他账号。余额等更强的证据优先。
- 上游内容安全拒绝（如 `content_policy_violation`、`request_check_blocked`）不罚号、不换号，返回 400，运维记录标为业务限制，不计入 SLA。
- 一个上游响应只罚一次。池模式账号、管理员配置的自定义错误码与临时不可调度规则在韧性处理之前生效。

## 软罚与硬罚

| 档位 | 例子 | 普通选号 | 会话绑定 | 末位兜底 |
|---|---|---|---|---|
| 软罚 | 瞬时失败冷却、无重置时间的限流、403 计数冷却、按模型冷却、同站断流暂停 | 跳过 | 保留（同站断流暂停除外），冷却结束后会话回到原账号 | 可用 |
| 硬罚 | 停用、错误状态、鉴权失败、余额暂停、超过 300 秒的限流、管理员临时停调规则、智商检测降智 | 跳过 | 下一次请求即改绑 | 不可用 |

临时不可调度原因以 `transient:` 开头或为 403 计数冷却时是软罚；其余原因（包括原因为空的）一律按硬罚处理。

## 会话失败改绑

- 同一会话在同一账号上 `session.streak_window_seconds`（默认 600 秒）内连续失败 `session.streak_threshold`（默认 2）次，按属主删除绑定、改绑到其他账号，并在 `session.avoid_seconds`（默认 600 秒）内避开原账号。窗口按账号各自计算，同一会话在其他账号上的失败不延长它。
- 计入连续失败的类别：`RATE_LIMIT`、`TRANSIENT`、`FIRST_OUTPUT_TIMEOUT`、`STALL`。客户端错误、内容安全拒绝、会话状态拒绝、客户端断开与计划内首输出截止不计。
- 绑定账号只是普通软罚时保留绑定，本次由其他账号临时服务。
- OpenAI 账号的 `session.post_output_rebind`：已确认输出后的流内失败事件（如 `response.failed`）、读流出错、缺终态第一次发生就改绑。输出前失败仍按连续阈值。HTTP 请求内同一失败只改绑一次，WebSocket 每个 turn 各计一次。
- 请求 `input[]` 中的 `agent_message.content[]` 或数组形态 `function_call_output.output[]` 带 `type=encrypted_content` 片段时，密文只能由原账号解开，这类请求退回连续阈值规则，也不做 OpenAI 的后排迁出与接管、Claude 的判慢迁出。
- 上游在同一会话、同一账号上反复返回未知的终止拒绝（客户端错误类、且错误码不在已知清单内）时，达到连续阈值后暂避该账号（原因 `terminal_rejection_streak`），不罚号；同类拒绝在另一上游主机上也出现后停止暂避。

## 首输出截止

适用于受请求预算管理的流式文本请求。截止从本次尝试开始计时，等待响应头与等待第一个内容共用同一截止时刻；开场事件与心跳不解除截止。

### OpenAI

| 尝试 | 截止 |
|---|---|
| 热尝试：会话粘性命中绑定账号，且本请求此前没有上游失败 | 档位 `budget.first_output_timeout_seconds`（default 20 / high 25 / xhigh 30 / max 30 秒）；请求体 ≥256 KiB 至少 30 秒，≥512 KiB 至少 40 秒 |
| 冷尝试：换号或同号重试、新会话首轮、迁移后首轮、无会话标识 | 档位；请求体 ≥128 KiB 至少 45 秒，≥256 KiB 至少 75 秒 |
| 最后候选：末位兜底选中的账号、最后一次允许的尝试、组内唯一能服务该模型的账号 | 不按档位截断，只受剩余预算约束 |

- `budget.model_overrides` 按模型（精确名或 `前缀*`）覆盖档位，冷尝试同样取覆盖值与下限中较大者。
- 非最后候选的截止不短于本请求到这次尝试开始时已耗费的时间，再受剩余预算约束：上游都慢时，被截断的尝试逐次放宽。
- 截止到期按“计划内截止”处理：客户端行为不变（输出前换号，耗尽时 `error.type` 为 `first_output_timeout`），但不施加账号级流超时惩罚，不计入 API Key 健康熔断与会话失败。在 OpenAI 的[质量状态](group-quality-gate.md)里它照常算首输出超时（被预算截短且 `budget.budget_cut_attribution` 为 `enforce` 的除外）。
- 判断“唯一能服务该模型”时，其他账号要通过本请求完整的选号资格（能力与传输方式、隐私、利润门）；软罚账号算替代，硬罚不算。
- 要恢复更长的旧档位，直接修改 `budget.first_output_timeout_seconds`（例如 180/180/200/220），保存即生效。

### Anthropic、Antigravity 与 Gemini

- Anthropic 与 Antigravity 读 `budget.anthropic_first_event_timeout_seconds`（默认 90 秒）。
- Gemini 文本请求（原生、Messages 与 Chat 兼容入口）的非最后候选尝试受 `budget.gemini_first_event_timeout_seconds`（默认 60 秒）约束：流式到第一个真实内容（文本、函数调用或内联数据），非流式到完整响应。最后候选不设截止，一直等到第一个内容、终态或客户端断开。图片等非文本输出、countTokens、带 tools 的非流式请求不设截止。
- Gemini 流式文本请求输出后接入停滞检测（`stall.text_stall_seconds`）。

## 按模型瞬时屏蔽（OpenAI）

按账号与实际出站模型计：API Key 账号的普通瞬时失败（5xx 等）以及明确的模型不可用，连续第 2 轮起屏蔽 10、45、90、180、300 秒，之后保持 300 秒。冷却期间到达的失败（通常是同一批在途请求）算同一轮，不升级、不延长。

- 成功只在这次尝试的开始时间晚于最近一次失败时清除计数与屏蔽。
- 屏蔽是软罚：组内没有其他可用账号时，末位兜底照常使用它；会话绑定保留。
- 连续首输出超时不在这里处理，由质量状态的急性保护让账号冷却（见 [正常与冷却](group-quality-gate.md#正常与冷却)）。

## 模型级冷却（Anthropic、Gemini、Antigravity）

一个账号上某个模型持续失败时，逐级加长该模型的冷却，同账号的其他模型照常服务。池模式账号除外。

- 触发：不带 `Retry-After` 的瞬时失败，包括 HTTP 5xx 与 408、流内瞬时失败、首输出超时、停滞。模型取选号所用的请求模型。
- 阶梯与清零规则同上：连续第 2 轮起 10、45、90、180、300 秒，30 分钟无失败重新计数。
- 上游带 `Retry-After` 的瞬时失败仍按账号冷却。
- Gemini 同号重试：该账号 × 模型已有未清除的失败时直接换号；健康账号的偶发失败按 `budget.gemini_same_account_retries`（默认 1 次）同号重试。
- 选号解释填了模型时显示为软档，原因 `model_transient`。没有单独开关，随总开关生效。

## 模型不可用

- 上游以结构化错误码（如 `model_not_found`）或明确文案（如 “model is not supported”“model not found”“unknown model”）报告模型不可用时，各平台都换号，不在同一账号上重试。
- 400/404 上的明确模型错误让该账号对该模型 30 分钟不可用（持久化的模型限流），同账号其他模型照常服务，末位兜底在到期前不放回。
- OpenAI 兼容网关在输出前遇到的模型不可用（含仅有泛称 “not found” 的推理 404）按账号 × 实际出站模型的瞬时屏蔽处理（见“按模型瞬时屏蔽”），不写 30 分钟限流。
- 同一请求的模型不可用若已在另一个上游主机上出现，按请求级拒绝终止，不再继续换号；同主机的其他账号仍可尝试。候选耗尽时返回 404 模型不支持（OpenAI/Anthropic 为 `model_not_found`，Gemini 为 `NOT_FOUND`），不附重试建议。

## 判慢让位与会话迁出（Claude）

- 由 `anthropic_latency_hold` 控制。只采成功完成的流式粘性热尝试，从发送尝试到首个语义输出（开场、心跳、空或签名 delta 不算）；换号、同号重试、借用与迁出后的首轮不采样。
- 阈值 35%、固定 3 分钟，不递增；只在同优先级内后排，不跨优先级。
- 迁出目标须通过正常准入、与原账号同优先级、未判慢，并由实时负载确认有空槽；模型路由内的迁出只考虑路由集合。同一分组 + 会话成功迁出后 30 分钟内不再迁出（记 `cooldown`）。
- 需要默认开启的 `gateway.scheduling.load_batch_enabled` 与并发服务；缺少时不后排、不迁出。

## 同站断流暂停

见 [网关韧性](gateway-resilience.md#同站断流暂停-same_site_hold)。暂停不影响 OpenAI 质量状态的统计，断流照常计入错误维。

## 末位兜底

- 顺序：先转投无号兜底分组；否则先尝试本会话未暂避的候选，暂避的账号留作最后选择。两类内部，OpenAI 分组按[选号顺序](scheduling.md#openai-分组的选号顺序)排序（后排账号在后）；其他平台按优先级、再按罚期结束时间排序（同优先级内 Claude 判慢账号在后）。取第一个有空闲并发的账号；全部占满时排队等待排在第一的账号。
- 门禁与正常选号相同，只放宽软罚；超过窗口费用或 RPM 硬上限的账号不会被选中。
- 候选来自 2 秒的分组快照，派发前按账号当前状态再核对一次，快照之后被停用、删除、移出分组或进入硬罚的账号不会被选中。

## 智商检测的模型级门禁

OpenAI 账号的某个出站模型被 [智商检测](iq-check.md)判为降智后，只冷却“账号 × 出站模型”（持久化模型限流中的 `iq:<出站模型>` 键，原因 `iq_degraded`），同账号其他模型照常服务。该键按硬罚处理：末位兜底不放宽，绑定的会话下次请求迁走；“恢复状态”“清除限流”、测试连接成功与账号编辑都不会清除它，只有复检通过、关闭或删除检测目标才移除。

## 无号兜底分组

- 配置：在分组编辑页选择“无号兜底分组”，须为同平台、启用、非订阅的其他分组，不能指向自身，不能成环。
- 触发：认证后、模型解析前按组判断一次，不看请求模型。主分组没有可服务成员（平台、硬状态、利润门与韧性软罚都不通过；质量状态只决定前后排，不影响可服务数），且兜底组有可服务成员时转投。主分组有可服务成员但都不支持该模型时不转投；换号耗尽不跨组。
- 切回：进入兜底后按 API Key 记忆（Redis，`fallback_group.binding_ttl_seconds`）。主分组恢复后，从未转出的 Key 立即回到主分组；已转出、仍在请求的 Key 在主分组连续健康满 `return_stable_seconds` 后回来；空闲超过记忆时长的 Key 直接回主分组。会话粘性按分组隔离。
- 价格按服务分组：分组倍率、用户在兜底组的覆盖倍率、高峰系数、图片与视频价格、长上下文规则、渠道定价与计费模型都取兜底组；兜底组的“强制 Fast”“免费 Fast”规则照常生效（见 [分组](groups.md#openai-分组-fast)）。余额预留按兜底组估价。
- 授权与限额按原分组：模型白名单与模型列表（`/v1/models` 等始终按原分组返回）、图片与 `/v1/messages` 资格、分组 RPM、用户 × 分组计数、API Key 额度和余额检查。原分组允许、兜底组不支持的能力按无号返回 503，错误信息不提兜底组。
- 系统提示词用兜底组的配置。
- 用量记录：`usage_logs.group_id` 为实际服务的兜底组，`origin_group_id` 为原分组；扣款仍针对原 Key 和用户。用户侧只显示原分组；管理端用量主标签显示原分组，下方提示“兜底 → 兜底组名”，筛选、统计、导出按服务分组。
- 可服务数可用 `GET /api/v1/admin/groups/:id/profit-control-preview?margin=` 预览，返回 `{members, schedulable, passing, ceiling}`：成员总数、可调度成员数、其中通过利润门的成员数、价格换算上限。`margin` 取值 `[0,1)`，省略时用保存值；预览不保存配置。
