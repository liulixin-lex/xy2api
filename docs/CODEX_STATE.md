# Codex STATE 与智商检测

此功能从社区 sub2api-state-kit 的 ecf3b9acb6bd40ba9e920b1b21e3db446ecaaf27 提取增量，适配 XY2API 0.1.3 / Sub2API 0.2.6。它分别展示票据长度、完整响应的返回模型核验、原有 IQ 判分；任何一项都不能代替另外两项。

## 配置

先配置网关 STATE 总开关与动态代理池，为账号选择固定业务代理，再在账号编辑窗口保存独立的套餐、模型集合和缺票策略。Pro 使用 292，Team 使用 332，由管理员手动选择。Astra、Sol 分别维护票据；迁移时保留旧配置中的其他模型。新建、复制、导入账号默认关闭。

默认缺票暂停目标模型。`allow_unprotected` 允许不携带 STATE 转发，界面会明确显示“无票转发”；不会发送客户端提供的、过期或已撤销的 STATE。非目标模型保持原路由。

动态池支持 `{sid}`，以及社区的 1024proxy SID 刷新格式。可选外层 CONNECT 代理使用 YAML `gateway.openai_codex_ticket.harvest_dial_proxy_url`。代理密码不进入账号状态和诊断。

## 生命周期与恢复

采集使用动态出口；候选必须满足格式、套餐长度及完整响应实际模型要求，然后通过同账号固定业务代理复验。固定复验走业务插件／HTTP 传输选择，使用一次请求策略，禁止重定向。HTTP、SSE、JSON、压缩响应、Messages 转换和插件响应都使用相同核验；不能把 HTTP 200 或只有响应头当作通过。

默认有效期 60 分钟、提前 10 分钟续期、扫描 6 秒、单请求 25 秒。已有有效 YAML 配置继续生效。每轮最多 8 次候选，每次最多一次采集和一次固定复验；失败冷却 5 分钟。401、403、429 立即结束本轮，并遵守更长的 Retry-After 或账号冷却。认证和限流冷却在同账号所有模型间共享，切换套餐或账号开关不会清除；手动按钮不能绕过冷却。

运行状态保存在 accounts.extra，领取任务、续租、发布和撤销经过 PostgreSQL 行锁。`CODEX_TICKET_MAX_CONCURRENCY` 默认为 2，允许 1–10，限制整个集群；各实例须使用相同的并发上限及 YAML/环境兜底配置，变更这些部署配置时先停止旧工作者。运行时更换动态池应使用管理员全局设置。同账号只允许一个 STATE 探测任务，并共享业务并发限制。租约过期后可接管，旧租约不能发布。持久化失败不发布新票；续期失败继续使用旧票至原到期时间，重启不延长有效期。

守护绑定实际注入的账号、最终出站模型、配置修订和票据身份。仅完整成功响应中的模型不符或合法 312 实验信号可触发条件撤销；失败、截断、损坏、超限的响应不构成已确认异常。对于在终态处结束读取的协议转换，守护最多用 250 毫秒读完剩余 HTTP 数据以确认完整性，失败或超时不撤销。守护不重放请求、不改写响应或计费。15 分钟内三次恢复后再异常进入冷却。

受管理账号的 Responses WebSocket 使用逐轮 HTTP 桥接，以便每轮重新读取票据；已经建立的原生连接在配置变化后需要重连。

## IQ 联动

IQ 保留原题、思考深度、输出模式、判分、周期与冷却。最终出站前使用同账号同模型的票据并接受守护。受管理的检测复用业务传输，避免测试专用 TLS 设置造成差异。暂停策略下，缺票进入“等待 STATE”，发送前推迟，不覆盖最后有效判定。无票策略记录未保护。

首次恢复或异常换票成功后，只为已经开启 IQ 且模型匹配的账号安排一次复检。取得票据不会直接标为聪明。旧票据的迟到检测结果不能覆盖新恢复轮次。完整有效答错后，保留降智判定，并在同账号同模型至少间隔 15 分钟的限制内换票复检；网络错误与未知结果不触发。采集不受 IQ 的降智调度阻断，但继续遵守人工停用、有效期、限流和业务并发。

## API 与诊断

- `GET/PUT /api/v1/admin/accounts/:id/codex-ticket`：账号配置及逐模型状态。
- `POST /api/v1/admin/accounts/:id/codex-ticket/harvest`：可选 JSON `{"model":"gpt-6-astra"}`；未指定时请求已开启模型，重复请求合并。
- `GET /api/v1/admin/accounts/:id/codex-ticket/diagnostics`：每模型最近 20 条脱敏事件，以及采集轮次、成功、失败、守护触发的累计计数。

保留旧 `codex_turn_tickets` 摘要数组。普通账号编辑、导入和导出不能覆盖或泄露服务端票据、配置与运行状态。API 不返回原始 STATE、代理密码或完整业务响应。

## 升级与回退

升级前停止旧版采集工作者，备份数据库和配置。首次启动在构造网关并开放 HTTP 路由前，以带版本标记的幂等事务承接旧全局启用范围及 fail_closed；迁移失败则初始化失败。新建、复制、导入账号显式保存关闭配置，即使创建发生在迁移标记写入前，也不会被旧范围扫描自动开启。未过期旧票必须固定代理复验，保留原到期时间；失败后重新采集。缺少固定代理的账号显示配置原因。无新增 SQL 表或历史迁移修改。

源码交付与可执行回滚脚本位于 `/xy/artifacts/codex-state-upgrade/`。ROLLBACK.sh 接受一个源码归档副本，默认恢复同目录 BASELINE.tar.gz（原始 6c12e3f）。传入第二个参数 `phase1` 可仅回退二次优化，恢复 SECOND_PASS_BASELINE.tar.gz（一期 2a743f0）；它不操作数据库或运行服务。

回退程序前先停止新工作者、关闭 STATE 总开关，再部署旧程序并按旧策略恢复启用。旧程序不理解新租约，不能与新工作者并行运行。若要求完整恢复配置，使用升级前的数据库备份；不要从导出的公开账号数据恢复私有票据。

本地隔离验收的实际命令与结果以 VERIFICATION.txt 为准。生产启用前仍须使用测试账号覆盖两个续期周期，并连续观察 24 小时采集成功率、恢复耗时、续期失败、误撤销、无票转发与 IQ 有效结果。长度、模型字段和本地模拟测试不能证明真实上游会持续接受 STATE。

## 二次优化（2026-09-19）

票据封装使用严格 Base64URL 解码、0x80 版本字节、密文块对齐与内嵌秒级时间检查。该检查不能验签、解密或保证上游寿命。截止时间取首次观察时间加 TTL、内嵌时间加 TTL 减安全余量、原截止时间三者的最早值。余量为 30 秒与 TTL 十分之一中的较小值；候选时间超过当前时间 30 秒不发布。同一值重新取得、固定代理复验与重启均不延长原截止时间。版本标记 `codex_ticket_envelope_migration_v2` 只补齐私有时间元数据并缩短期限；已完成 v1 的数据库不会再次承接全局启用范围。

受管理响应头必须只有一个大小写不敏感的 STATE 值，重复相同值、冲突值、逗号合并或非法字符均拒绝用于采集；注入前清除同名变体。完整成功响应中的唯一合法 312 信号仍立即撤销本次实际使用票据，重复头本身不能触发撤销。模型不符可以独立触发守护。撤销在私有票据上保留 `revoked` 标记和原期限，不能注入，也不能作为旧票直接复验；再次采集到相同值时仍保留原截止时间。普通未受管会话的 opaque STATE 连续性不受封装规则影响。

HTTP 200 中的 JSON/SSE 明确失败也参与分类。认证、配额与限流停止本轮，限流/配额跨账号模型共享冷却；模型容量错误仅终止当前模型轮次。Retry-After、账号冷却与默认五分钟冷却取最晚时间。白名单错误码可进入诊断，上游原文和未知代码不会直接显示。

IQ 完成事务按账号后代理的顺序锁定当前记录，校验配置修订、票据身份、有效期和代理连接指纹。代理 ID 不变但连接配置改变时，迟到结果被取消，保留最后有效评分并安排当前配置检测。代理变更通过 outbox 更新调度快照。

扫描以 100 条为一页按 ID 回绕，仅读取待判定元数据，去除原始 STATE 与无关凭据；只有候选任务进入领取事务，一批只查询一次集群活跃租约数。调度缓存包含不含 STATE 的可用性提示，选中账号的最终注入仍读权威记录。缓存刷新前可能保守暂停，不能以陈旧缓存越过实际票据验证。

状态 API 增加 `issued_at`、`first_observed_at`、`last_replay_at`、`last_business_at`、`last_business_result`、`last_stage`、`last_reason`、`last_code`、`last_http_status`、`observed_length`、`updated_at`。业务观察的 verified 与采集复验、IQ 判分分开显示。中断、超限、损坏、失败、未知编码显示未确认。守护异常立即持久化；一般业务观察每 30 秒按账号合并，不触发调度快照写入。这些统计最多缓存 8192 个票据观察组，进程退出或达到上限可能丢失统计，不参与安全判断。

界面沿用账号模块的分隔线与表单样式：套餐与缺票策略并排，每模型默认显示票据、业务模型和 IQ 三项，时间与守护统计收进详情；失败原因与重试时间合并显示。页面显示数据更新时间及刷新失败，保留最后一次成功数据、未保存编辑和键盘焦点；页面隐藏暂停轮询，组件关闭或卸载停止轮询。重试按钮继续服从服务端冷却。

隔离 PostgreSQL 的扫描对照使用同一批 1,000／10,000 个账号、每账号两个模型。旧逐账号领取 SQL 模式分别产生 4,000／40,000 次查询和 1,000／10,000 次账号行锁；新投影分别为 11／101 次分页查询，健康账号无需领取事务。该对照衡量 SQL 模式，不代表旧版本完整进程或生产吞吐；实际耗时、锁等待与最终扫描回归输出保存在交付目录 `VERIFICATION.txt`。源码事务分别验证累计升级和仅二期升级，回滚归档按 SHA-256 和逐文件字节核对；它们不替代真实上游观察。
