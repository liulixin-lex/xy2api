# Anthropic API Key 请求兼容

“Claude Code 请求兼容”用于需要 Claude Code 请求特征的 Anthropic API Key 上游。管理员在账号创建、编辑或批量编辑中显式开启；默认关闭。客户端继续使用网关的既有接口和 Key。

## 适用范围

仅适用于 `platform=anthropic`、`type=apikey`。配置字段为 `extra.anthropic_compat_profile`，值为 `off` 或 `claude_code_v1`。账号认证方式、上游地址、代理、模型映射、倍率和分组准入保持现有语义。

首版候选映射后模型限定为 `claude-opus-4-8`、`claude-opus-5-5`，还须满足账号模型准入。某个供应商、模型或请求成功，不代表其他模型和全部功能可用；每个目标账号启用前须验收所需能力。

| 入口 | 兼容范围 | 边界 |
|---|---|---|
| Messages | 文本、流式、工具往返；来源可验证的签名历史 | 外来未知签名不能自动迁入新适配会话 |
| Responses HTTP | 既有转换覆盖的文本、工具和明确 Anthropic thinking envelope | 不支持任意密文、供应商保存的 previous_response_id 或 WebSocket |
| Chat Completions | 文本、流式和普通工具 | 无法回传签名的客户端不具备无损签名思考续轮能力 |
| count_tokens | 相同 prompt 的独立计数请求 | 依赖供应商计数端点；不支持时不伪造数值 |

Message Threads、compact 和依赖供应商保存状态的续接不由此开关自动支持。

## 请求处理

兼容层统一构造受控 User-Agent、X-App、API 版本、beta、最小身份文本块及租户隔离的 `metadata.user_id`。保留调用方其他 metadata、业务 system 的角色和内容、工具名称/schema/调用 ID，以及明确提供的生成参数。不会把 forced tool choice 改为 auto，不会删除签名或工具历史以制造成功。

首版冻结 API 版本 `2023-06-01`、legacy metadata 格式与 profile 修订；beta 集合取已验证的组合起点，不代表其中每一项均被单独证明必需。管理员 beta 策略不得被兼容层绕过；受控头和请求体必须一致。

已有完整且一致的原生 Messages CLI 请求，在不需要新增兼容改写时继续现有路径。仅伪造 User-Agent 不能得到旁路；已登记的签名来源检查优先于 CLI 外观判断。

新适配身份按用户、网关 Key、上游账号与显式会话隔离。无明确会话且无已知签名历史时，每个请求使用独立锚点，同一请求内部保持稳定，不按相同开场文本合并会话。

每次换号从逻辑原请求重新构造，清理上一个账号的派生状态，继续原请求预算。原 OAuth 路径、默认关闭账号及既有认证判断不因本开关扩展。

## 签名历史与错误

网关使用租户和 Key 作用域内的摘要来源索引识别 `thinking.signature`、`redacted_thinking.data`，只保存来源约束，不保存原始签名或请求正文。Responses 仅解码现有明确标记的 Anthropic envelope。

已知历史绑定原上游账号、profile、凭据端点、模型、最终 system/tools 和能力配置。账号不可用返回可重试状态；不跨号删除历史恢复。关键配置改变后，旧历史明确报不兼容。关闭 profile 或改成 CLI 外观不能绕过该检查。

流式内容可以实时返回；完整上游成功后，网关先原子保存本轮全部签名来源，再发送成功结束信号。只有 stop reason 而没有完整 message_stop、流内错误或截断均不能登记成功。登记失败时客户端收到协议错误，真实上游 usage 仍进入既有结算，不重发模型请求，也不将本地索引问题记成供应商账号故障。

携带签名时，Redis 查询失败与“查询成功但没有记录”不同：前者返回可重试状态错误，不能进入旧 CLI 旁路。因此 Redis 故障也可能暂时阻止存量签名 CLI 续轮。无签名且兼容关闭的请求不因来源查询增加 Redis 依赖。

新适配会话的工程边界采用每请求最多 128 个不同签名、请求或响应累计 opaque 数据各不超过 1 MiB、24 小时闲置有效期。流解析同时限制打开的内容块数量、单事件和暂存的成功尾部，避免上游持续输出造成无限积累。成功续轮刷新其全部已知历史，即使本轮没有新签名也不让活跃历史提前过期。这些是网关工程限制；超限或来源过期时明确报错，不截断历史，实际长会话分布需在部署验收中核对。选号前的来源查询按固定批次检查全部摘要，受原请求大小和时间预算约束；新适配的数量限制不用于拒绝来源全未知且可保持原路径的完整旧 CLI 请求。

## 配置与诊断

兼容模式与“仅替换认证”的 `anthropic_passthrough` 互斥。派生会话头 `X-Claude-Code-Session-Id` 由适配器管理，不能用静态账号请求头覆写。矛盾的受控头覆写、未知 profile、错误平台或账号类型在保存时拒绝，运行时仍检查一致性。

旧页面保存遗漏该字段或发送 `extra:{}` 时保留 profile；明确 `off` 才关闭，不改变其他 extra 字段的既有清空语义。身份种子由服务端管理，不由普通 DTO 或导出返回；新建、复制或导入账号重新生成，旧页面不能清空或注入它。

显式批量修改 profile 时，所有目标账号必须存在且满足配置要求；普通凭据或 extra 批量更新继续原有缺失账号处理语义，实际存在的兼容账号仍校验合并后的完整配置。

兼容账号诊断应发送普通客户端形态，经过实际适配并固定目标账号。以实际命中账号、完整终态及所需能力判断结果；旧 CLI 模板的连通性成功不能替代兼容验收，HTTP 200 也不能单独证明流成功。现有渠道监控仍反映所配置入口或分组的可用性，不等于其中某个账号已经通过兼容验收。

## 观测

事件 `gateway.anthropic_compat_attempt` 记录 `profile`、`profile_revision`、`entrypoint`、`decision`、`source`、`account_id`、`terminal`、`error_class`。记录不含原始签名、prompt、metadata、会话 ID 或认证头，入站 User-Agent 不因出站适配被改写。关闭兼容且无相关历史的请求不增加该事件。

## 部署与回滚

1. 部署后保留所有账号缺省关闭，保持数据库中受管密钥与 Redis 来源索引可用。
2. 在隔离流量中按目标模型验证三个入口的流/非流、业务 system、工具往返、所需签名续轮及计数；先确认实际命中目标账号。
3. 仅将已验能力接入普通流量。观察上游形态拒绝、真实终态、签名错误、首字和用量，不以测试 HTTP 状态代替真实完成率。
4. 回滚先暂停该账号承接普通流量，等在途请求结束并处理已绑定会话，再关闭兼容或回退版本。只关闭开关而继续发送普通请求会恢复原来的拒绝。

来源 HMAC 根独立于 JWT 和上游 Key，跨实例持久；进程重启不生成不同来源域。轮换须保留旧版本读取过渡，不能直接覆盖密钥使全部旧索引不可读。数据库密钥和 Redis 来源状态需纳入既有备份与恢复流程。

本地结构与故障回归证明实现边界，真实供应商能力须单独验收。完整实施记录见 [OpenSpec](../openspec/changes/claude-apikey-compat-20261110/)。

## 来源查询与运维边界

所有携带思考签名、redacted 数据或 Anthropic Responses 思考信封的请求，都会在选号前查询来源索引，包括未开启兼容模式的 API Key 账号和 OAuth 账号。来源查询失败时返回 `503 anthropic_compat_state_unavailable`，不向上游发起请求；这是签名来源保护的失败关闭行为，关闭账号兼容模式不会跳过该查询。无签名请求不增加这次来源查询。

profile 仅字段缺失或精确字符串 `off` 表示关闭；空串、null、`OFF` 和未知值会被正常写入口拒绝，库中异常值会使该账号退出兼容候选。每次转发尝试会重新计算 beta 过滤与工具名改写，跨号重试不沿用前一个账号的结果。
