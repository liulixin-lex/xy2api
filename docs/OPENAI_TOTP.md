# OpenAI 账号 2FA 登录与密钥管理

本功能管理上游 OpenAI 账号的邮箱、密码和 TOTP，与用户登录 XY2API 时使用的平台两步验证分别存储。平台两步验证的绑定、登录和停用流程保持原有行为。

## 登录导入

超级管理员在“账号管理 → 账号工具 → 2FA 登录导入”填写上游登录信息。本地 worker 完成登录后，服务端验证返回的 Session 身份并加密保存；管理员确认后沿用已有 Session JSON 导入逻辑创建账号。浏览器不接收 Session 令牌。

直接登录导入创建新账号，不自动覆盖已有账号的登录凭据。重复确认同一个任务应返回原导入结果。关闭弹窗前记下任务编号，再打开后可用编号恢复查询和确认导入。登录遇到验证码、安全挑战或网络错误时显示失败，不自动重试上游登录。

原有 JSON 文件、Session/PAT 导入仍可使用。直接登录需要额外安装本地登录运行时，不能把 JSON 导入当作已经具备直接登录。

## 已有账号的密钥管理

超级管理员从 OpenAI OAuth 母账号的操作菜单进入 2FA 管理，保存与账号邮箱一致的密码和当前 TOTP 密钥。影子账号、API Key 账号以及其他平台不能使用。

保存、启动轮换、恢复、导出和确认导入要求当前管理员已启用平台 TOTP，并通过近期二次验证。这些接口无条件要求二次验证，不受全局 step-up 开关关闭影响，管理员 API Key 不能代替已验证会话。普通管理员没有访问权限。

保存的登录秘密使用固定 `TOTP_ENCRYPTION_KEY` 加密，单独存储；普通账号的详情、列表、复制和批量导出不携带这些密码及 TOTP 密钥。未配置固定加密密钥时拒绝保存和运行任务。

## 轮换与中断恢复

轮换依次进入 `queued`、`running`、`enrolling`、`prepared`、`activating`、`verifying`，最后为 `succeeded`、`failed` 或 `uncertain`。

新候选密钥必须先写入加密的本地恢复日志并同步到磁盘，再由数据库持久化确认，才允许激活。激活请求、数据库确认或 worker 连接发生不确定结果时，任务进入 `uncertain`，锁定凭据修改和新轮换；数据库同时阻止删除、软删除或更改该账号的身份字段，以保留恢复材料。

恢复操作只验证“新密钥”或“旧密钥”，不会再次申请或激活一个新密钥。验证必须使用独立的登录会话；旧密钥失效的判断必须来自明确的 TOTP 拒绝，网络故障、密码错误和安全挑战不能算作密钥失效。无法确认时继续保持不确定状态。

不要通过删除任务、改数据库状态或删除本地恢复日志来解锁。应恢复原 worker、原持久目录及密钥，补回已写日志的候选，然后执行验证恢复。任务过期后旧 worker 不能复活租约或提交成功结果。

## 导出与数据保护

导出明确选择 `current`、`candidate` 或 `previous`。当前密钥仅在任务已解决时可导出；候选和旧密钥用于不确定任务的恢复。密码需要单独勾选。

导出响应和 worker 凭据响应使用 `Cache-Control: no-store`。请求审计只记录动作及安全元数据，省略登录秘密和导出正文。页面关闭、切换账号或卸载时清理输入和二维码，并忽略迟到的请求响应。下载文件包含秘密，应由管理员自行安全保管。

## 部署、备份与回退

默认仅具备平台二步验证并不足以运行本功能。需要匹配的 API、本地 worker、登录运行时、依赖，以及可写并支持同步到磁盘的持久恢复目录。worker 未就绪时拒绝新建登录和轮换任务。禁止把账号秘密交给默认第三方托管登录服务。

安装、固定依赖、环境变量、systemd 示例和离线预检见 [本地 Worker 部署](../deploy/OPENAI_TOTP_WORKER.md)。迁移 `284_openai_totp.sql` 新增专用凭据、任务及 readiness 表，checksum 与既有迁移一同登记；不得修改已部署迁移。

worker 使用专用的高强度 Bearer 密钥 `XY2API_OPENAI_TOTP_WORKER_SECRET`，与管理台账号凭据分开。只有 worker 可访问内部领取、阶段确认和完成接口；每个领取结果另带任务令牌。远程访问必须使用 HTTPS，禁止重定向和凭据跨站发送。

备份必须同时包含数据库、`TOTP_ENCRYPTION_KEY`、加密恢复目录及其加密密钥。缺少任一部分可能无法恢复正在轮换的账号。新增迁移只追加结构和 checksum，不修改已发布 SQL。

回退应用程序不能撤销 OpenAI 已激活的密钥。回退前先停止新任务、解决所有不确定任务，并核对当前有效密钥。不要清空仍有未解决任务的恢复目录。

## 接口与验证范围

账号管理接口位于 `/api/v1/admin/accounts/:id/openai-totp`，包括读取、保存、`rotate`、`reconcile` 和 `export`。直接登录接口位于 `/api/v1/admin/accounts/openai-login`。worker 内部接口位于 `/api/v1/internal/openai-totp`。

实现选择性参考 [ranxi2001/sub2api](https://github.com/ranxi2001/sub2api/tree/12a49ef4ef6a2f116389701ac8f1fe620f27bbf5) 的轮换状态机与本地加密恢复日志，并适配 XY2API 权限和导入流程。具名补丁为 `xy-managed-openai-totp`。这不是全量上游同步。

默认测试只使用本地 mock 和隔离数据库，不执行真实账号登录或 MFA 激活。OpenAI 网页 MFA 协议不是公开稳定 API；mock 通过证明本地安全边界和状态恢复，不能证明上游当前一定接受登录及换绑。
