# 普通管理员与后台权限

后台有两种管理员：

- **超级管理员**（角色 `admin`，界面显示为「管理员」）：可以使用后台全部功能。全局 admin API Key 也按超级管理员处理。
- **普通管理员**（角色 `operator`）：只能使用超级管理员逐人勾选的模块和开关。

权限的组织方式：

- 每个模块分「查看 / 管理」两级，管理包含查看。
- 涉及资金或数据外流的操作各有单独的开关，默认关。
- 系统设置、支付配置、凭据导入导出等只有超级管理员能做，权限表里不提供勾选。

后端是安全边界：

- 每条后台接口都登记在权限目录中，按「模块 + 级别 + 开关」检查；没有登记的接口，普通管理员一律得到 403。
- 前端按权限隐藏菜单和按钮。如果漏掉了某个按钮，点击也只会得到 403。

## 任命普通管理员

在「用户管理」打开用户的编辑弹窗，把角色改为「普通管理员」，弹窗下方会展开权限表。

**权限表**
- 每个模块一行，有「查看」「管理」两个勾选框：
  - 勾「管理」会同时勾上并锁定「查看」；
  - 取消「管理」后可以再取消「查看」，取消「查看」会清空整行。
- 四个开关放在它所属的行里，底部单独一行是「导出业务数据」。每个开关旁有一句“开：… 关：…”的说明，见下文“开关”。
- 所在行既没有查看也没有管理时，该行的开关不能勾选；清空一行也会清掉它的开关。

**保存**
- 先保存权限，再保存用户（含角色）。
- 两步都需要二次验证（step-up，在设置中开启时生效）。

**其他入口与规则**
- 新建用户时也可以直接选「普通管理员」。新建的普通管理员没有任何权限，要再到编辑弹窗里设置。
- 只有超级管理员能看到权限表、修改角色。用户列表的角色筛选和角色标识都包含「普通管理员」。
- **撤销**：把角色改回「用户」。权限数据会保留，但不再生效。重新任命时，权限表显示旧的设置，保存后才生效，不会被静默恢复。

**生效时机**
- 每次请求都会重新读取用户和权限，撤权或改权限在下一次请求生效。
- 运维监控的实时 QPS 连接每 30 秒复核一次，失去「运维监控」查看权限后断开。
- 前端收到权限类 403 时会重新拉取权限并刷新菜单，每 60 秒最多一次。

**跨模块读取**：页面上的下拉选择不需要单独勾选模块。例如：
- 分组列表：有账号、用户、渠道、订阅、公告、兑换码、安全审计、运维监控或订单任一模块的查看权限即可读取；
- 代理列表：有账号或安全审计的查看权限即可读取，返回时不含密码；
- 用户列表：有分组或订阅的查看权限即可读取。

在这些地方读到的数据照样按下文脱敏。

## 开关

**加减余额**（`users.balance_adjust`，用户管理行）

> 开：可以加减余额、设初始余额、发放和延期订阅、修改分组倍率和套餐价格。关：只能查看这些内容。

具体包括：
- **余额**：加减用户余额；新建用户时设初始余额；为指定用户「生成并兑换」兑换码。
- **订阅**：发放、批量发放、延期、重置额度、恢复订阅。撤销订阅不需要该开关。
- **价格**：
  - 用户专属倍率、分组的每用户倍率表；
  - 分组的倍率、限额、长上下文、图片、视频、搜索、音频、高峰时段、利润控制等价格字段；
  - 已有分组的平台、强制 Fast、推理强度映射与最大推理强度；
  - 套餐的新建、修改、删除；
  - 渠道的分组绑定与删除渠道，以及已绑定分组的渠道的定价、模型映射、计费模型来源、状态、账号统计定价规则与「将定价应用到账号统计」；新建时绑定分组也一样；
  - 账号的缓存 TTL 覆盖与 OpenAI 长上下文计费；
  - 邀请返利比例。
- **分组授权**：
  - 给用户加专属分组；
  - 把用户更换到他还没有权限的专属分组；
  - 把用户 API Key 改到他还没有权限的专属分组。

  移除分组不需要该开关。
- **分组**：没有该开关时有以下限制：
  - 新建分组只能是专属分组，不能设回退分组；编辑时不能改回退分组，但可以清除；
  - 不能把专属分组改为公开，也不能重新启用已停用的分组；
  - 只能删除没有账号的分组，否则返回 409 `GROUP_NOT_EMPTY`。

  编辑已有分组时不能通过切换平台来重置利润控制或 Fast 计费设置。未改变的价格字段可以原样保存；可选价格留空后再次保存仍为空，表单提交的 `-1` 与已保存的空值按相同值处理。

  复制分组得到的是停用的副本，启用它同样需要该开关。

**账号放置**（2026-10-28，所有者决定）

- 有账号「管理」（`accounts:manage`）权限就能在新建、编辑、批量编辑时把账号加入或移出分组，也能复制账号、创建 Spark 影子账号，不需要「加减余额」。
- 新建账号不指定分组时，与超级管理员一样绑定对应平台的默认分组（如果存在）。
- 新建或编辑分组时，从其他分组复制账号还需要分组「管理」权限，并满足「加减余额」或账号「管理」中的任意一项。只有分组「管理」、没有这两项时，返回 400 `ADMIN_FIELD_FORBIDDEN`，字段为 `copy_accounts_from_group_ids`。
- 账号计费类 extra、分组价格、渠道绑定分组与用户专属分组授权仍受原有「加减余额」规则保护。

**退款**（`orders.refund`，订单管理行）

> 开：可以退款、查询退款、重新履约、处理返利提现。关：不能做这些操作。

没有该开关时，订单里的充值码打码显示。

**生成兑换码**（`redeem_codes.issue`，兑换码行）

> 开：可以生成兑换码和优惠码、批量修改，列表显示完整的码。关：不能生成，列表里的码打码显示。

没有该开关时：
- 兑换码只能按用户邮箱搜索（必须包含 `@`）；
- 优惠码不能搜索；
- 两者都不能按码排序。

操作日志中兑换码与优惠码相关接口的查询参数也整段显示为 `<query hidden>`，包括兑换码导出和已有的日志记录。

这样被打码的码就不能靠搜索逐字试出来。

无论有没有该开关，批量修改只能改四种普通类型的兑换码；被管理员或普通管理员使用过的码，只有超级管理员能改。

**导出业务数据**（`data.export`，权限表底部）

> 开：可以导出使用记录、兑换码等业务数据。关：不能导出。

- 导出使用记录还需要「使用记录」的查看权限。
- 导出兑换码还需要「兑换码」的查看权限和「生成兑换码」开关。
- 下载导出文件时按当时的权限再检查一次，撤权后已经拿到的下载链接也不能用。

**显示上游地址**（`accounts.upstream_address`，账号管理行）

> 开：账号名称显示上游地址，可点击跳转，编辑时显示并可修改接入地址和代理（OAuth 类账号只读），可以新建和修改代理服务器。关：不显示上游地址，不能修改地址和代理。

关时，除了界面上不显示，后端也不返回地址：
- 账号接口不返回接入地址，账号名称是普通文字，不能跳转；
- 测试账号、定时测试、智商检测等结果里的错误详情换成固定文字 `upstream error details hidden`，状态码和原因码保留；
- 渠道监控不返回检测地址；检测历史和「立即检测」结果里的网络错误换成固定文字；
- 渠道监控的额度快照不返回具体错误文字，改用同样的固定文字；
- 风控配置不返回上游地址，包括各审计引擎分别保存的地址；
- 操作日志请求体里的地址打码，任何字段里的网址都换成 `[upstream]`；查询参数里含网址时整段显示为 `<query hidden>`。

渠道监控 v2 的错误列表中，既没有「运维监控」查看权限也没有「显示上游地址」时，错误详情里的文字换成固定文字，次数、分类和状态码保留。

`mixed_channel_warning` 这类机器码不会被替换，所以普通管理员仍能确认混合渠道提示。

能改什么见下一节。

## 谁能修改网络设置

没有「显示上游地址」（`accounts.upstream_address`）权限时，普通管理员不能设置或修改服务器连到哪里：
- 账号的接入地址、自定义接入地址和接口协议；
- 账号代理；
- 模型同步预览的地址；
- 代理的协议、主机、端口、登录信息和备用链。

他们也不能新建代理。

有这项权限时，普通管理员可以在 API Key、上游（upstream）和 Bedrock 账号以及代理上查看并修改这些设置，但有以下限制：
- 每个新地址都必须是公网地址。
- 修改地址或代理时，需要重新填写账号保存的全部密钥。
- 正在使用的代理保留原主机。

OAuth、setup-token 和 service account 类账号的代理、类型和接入方式只能由超级管理员修改，即使普通管理员有这项权限。批量编辑从不修改网络设置。

这项权限是一种信任授权：服务器在保存地址时检查，而不是每次连接时检查。所以只把它授予你信任其管理上游网络的普通管理员。

渠道监控的地址不需要这项权限，因为监控的每次连接都会检查。

**细则**
- **新建账号**：没有这项权限时，账号使用平台默认地址，不带代理。上游（upstream）类型必须填地址，所以不提供。类型、平台、接口协议与接入模式在新建时可以自由选择，因为它们只在平台内置的地址之间选择。
- **编辑账号**：没有这项权限时，类型、接口协议、接入模式、AWS 区域和代理都不能改，地址输入框隐藏，后端保留原值。
- **原样保存地址**：账号、渠道监控和风控配置中，原样提交已打码用户名和密码的地址会保留已保存的完整地址，不算修改网络设置。不能把 `***@` 带到另一个地址，否则返回 400 `ADMIN_FIELD_FORBIDDEN`。
- **公网地址检查**：
  - 拒绝云元数据主机名，以及内网、本机、链路本地、CGNAT、IPv6 ULA 地址，直接写 IP 和域名解析出的 IP 都检查；
  - 域名解析失败也按内网处理；
  - 设置里的 `allow_private_hosts` 对普通管理员不生效。

  不通过时返回 400 `ADMIN_FIELD_FORBIDDEN`，`cause=private_address`。
- **重填密钥**：
  - 改地址、代理、类型、接口协议、接入模式或区域时，账号保存的每个密钥（包括 new-api 访问令牌）都要填新值或清除。与原值相同的不算重填。
  - 没有重新提交的自定义请求头值会被丢弃。
- **代理**：
  - “正在使用”指：被账号直接使用、是账号回退前的原代理、在其他在用代理的备用链上，或被网页搜索、风控配置引用。
  - 正在使用的代理：状态不能改，有效期只能清除或延后；有这项权限时也只能改密码，其他网络字段不能改。
  - 未使用的代理改协议、主机、端口或用户名时，必须同时填新密码，旧密码不会发往新主机。
  - 改未使用代理的协议、主机或端口时，生效的主机（新填的，或原有的）都要通过公网地址检查。
  - 正在使用的代理不能删除，与有没有这项权限无关。
  - 「恢复代理回退」只有超级管理员能做。
- **OAuth 类账号**：重新授权只刷新令牌，不能在 OAuth 与 setup-token 之间切换。
- **Bedrock**：AWS 区域必须是 `us-east-1` 这样的格式，所有普通管理员都受此限制。
- **Codex 工单**：不能设置代理 URL，代理池只有超级管理员能管理。
- **渠道监控**：
  - 新地址同样要通过公网地址检查；
  - 改地址、服务商或接口模式时必须重填 API Key，之前保存的请求头和覆盖请求体只保留本次重新填写的；
  - 含请求头或非空覆盖请求体（`body_override`）的监控模板只有超级管理员能应用，普通管理员也不能把监控关联到这类模板；
  - 没有账号查看权限时，不能设置或修改监控关联的账号。
- **风控配置**：不能切换审计引擎；提交不同的 `engine` 返回 400 `ADMIN_FIELD_FORBIDDEN`。API Key、模型和代理按当前生效引擎的已保存配置检查。

## 只有超级管理员能做的事

- **用户角色与权限**：创建或任命超级管理员、普通管理员，修改任何管理员或普通管理员，读写权限表。
- **全局 admin API Key**：查看、重新生成、删除。
- **系统**：
  - 系统设置（`/settings*`），含网关韧性、冷却、限流、邮件模板、网页搜索模拟、Codex 工单代理池；
  - 数据管理、备份；
  - 版本检查、更新、重启、回滚。
  - 合规确认不在此列。
- **支付**：支付配置与支付服务商。
- **凭据导入导出**：
  - 账号数据的导出与导入、代理数据的导出与导入；
  - 从 CRS 同步账号。
- **插件与自定义管理页**：普通管理员的菜单里也不显示自定义菜单项。
- **删除或销毁证据**：
  - 清空操作日志、使用记录清理任务、清理系统日志；
  - 删除提示词审计事件；
  - 删除全部风控哈希。
- **运维与审计的系统级配置**：
  - 数据保留等高级设置、运行日志配置、邮件通知配置；
  - 风控与提示词审计的 API Key 配置和测试；
  - 提示词审计配置与端点探测。
- **账号**：恢复代理回退；上游计费探测、Ollama Cloud 用量、OpenCode Go 用量的全局设置；OAuth 类账号的网络设置。
- **兑换码**：删除或作废已使用的兑换码；删除、作废或批量修改非普通类型的兑换码。

## 保护措施

**目标用户**
- 普通管理员只能操作普通用户（角色 `user`），不能操作超级管理员、其他普通管理员或自己。否则返回 403 `ADMIN_TARGET_FORBIDDEN`。
- 按 API Key、订阅、订单或兑换码使用者找到的用户也一样检查。
- 批量操作里只要有一个目标不符合，整个请求被拒绝；批量修改并发与限额时不能选「全部用户」。
- 用户列表批量读取属性时会跳过超级管理员、普通管理员和自己；直接提交的属性批量读取请求只要包含其中一人，整批拒绝，在读取属性缓存前返回 403 `ADMIN_TARGET_FORBIDDEN`。
- 删除属性定义时，只要已有属性值属于超级管理员、普通管理员或自己，就会拒绝；已软删除用户留下的属性值也检查，不会删除任何属性值。
- 涉及管理员或普通管理员的分组操作也会被拒绝，这些分组由超级管理员处理：
  - 删除分组时，分组里有他们的订阅或专属授权；
  - 修改分组的每用户倍率或 RPM 表时，表里有他们的行，已软删除的用户也检查。

**角色**
- 普通管理员不能修改任何人的角色：请求里带 `role` 返回 400 `ADMIN_FIELD_FORBIDDEN`，读写权限表的接口只对超级管理员开放。
- **最后一个管理员保护**：把超级管理员改成任何其他角色（包括普通管理员）时，如果他是最后一个超级管理员，会被拒绝。普通管理员不算管理员。
- **不能给自己降级**：超级管理员不能把自己改成普通管理员或用户。
- **二次验证（step-up）**：以下操作都需要二次验证：
  - 新建超级管理员或普通管理员；
  - 角色变更涉及超级管理员或普通管理员时（改入或改出）；
  - 保存权限表。
- **日志**：
  - 权限的修改前后差异写入操作日志（`admin.operator_permissions.update`）；
  - 新建超级管理员或普通管理员时，服务器日志记录操作者、新用户和角色。
- 超级管理员可以停用或删除普通管理员。

**密钥与敏感数据脱敏**（只对普通管理员，返回前处理）
- 用户 API Key 一律打码，只保留开头和结尾几位；用户搜索不匹配 API Key 内容。
- 代理密码一律不返回。
- 账号接入地址、渠道监控检测地址、风控各引擎地址和运维上游网址里的用户名和密码一律隐藏，即使有「显示上游地址」或「运维监控」查看权限也一样。一个字段里有多个网址或网址嵌在查询参数里时，也逐个处理。
- 账号自定义请求头（`header_overrides`）、渠道监控与模板的请求头，值一律显示为 `******`。编辑时原样提交 `******` 会保留原值。
- 渠道监控和模板的非空覆盖请求体（`body_override`）一律显示为 `******`，与有没有「显示上游地址」无关。编辑时原样提交 `******` 会保留原值。
- 操作日志：
  - 普通管理员不能调用的接口（只有超级管理员能用的接口、登录接口和用户端接口）的请求体整段显示为 `<request body hidden>`，查询参数不显示；
  - 请求体里的请求头值、刷新令牌（`rt`）和代理地址（`proxy_url`）一律打码，网址里的用户名和密码一律去掉；
  - 没有「显示上游地址」时，地址字段打码，其他字段里的网址换成 `[upstream]`，含网址的查询参数整段隐藏；
  - 无法解析的请求体显示为 `<request body hidden>`。
- 兑换码、优惠码、订单充值码按对应开关打码，见上文。
- 账号的 API Key、new-api 访问令牌等密钥本来就不返回给任何人。

**修改地址时重填凭据**：见“谁能修改网络设置”。这条规则防止已保存的密钥被带到普通管理员新填的地址或代理。

**新用户不发放注册赠送**

没有「加减余额」的普通管理员新建用户时：
- 新用户余额为 0，即使设置里的默认余额更高；
- 不发放默认订阅；
- 不能设余额，不能授予专属分组；
- 邮箱不能使用系统保留的 OAuth 合成域名，修改邮箱时也一样。这类用户以后绑定真实邮箱时会触发首次绑定赠送。

另外，无论有没有开关，普通管理员给用户绑定登录方式时都不能写入身份元数据。有开关时，新用户按注册默认值发放，与超级管理员相同。

**失败即拒绝**
- 普通管理员的权限读取失败时返回 503 `OPERATOR_ACCESS_UNAVAILABLE`，不会放行。
- 目标分组不存在时返回 404，与超级管理员相同；只有读取失败等内部问题才返回 503，不把不存在的分组当作权限读取失败。
- 存储的权限数据不合法时按“没有任何权限”处理。
- 普通管理员受后台限流约束，超级管理员仍然豁免。

## 错误原因码

| 原因码 | HTTP | 含义 |
|---|---|---|
| `ADMIN_PERMISSION_DENIED` | 403 | 缺少模块权限或开关；`metadata.required` 为所需权限，例如 `accounts:manage`、`data.export`。未登记的接口也返回它，`required` 为 `catalog` |
| `SUPER_ADMIN_REQUIRED` | 403 | 只有超级管理员能做 |
| `ADMIN_TARGET_FORBIDDEN` | 403 | 目标用户不是普通用户，或是自己 |
| `ADMIN_FIELD_FORBIDDEN` | 400 | 提交了无权修改的字段，`metadata.field` 为字段名。`metadata.cause` 可能是 `private_address`（不是公网地址）、`invalid_region`（区域格式不对）、`noncanonical`（请求体不规范，例如有重复或只差大小写的同名键）、`proxy_in_use`（代理正在使用） |
| `ACCOUNT_API_KEY_REQUIRED` | 400 | 修改网络设置时没有重填已保存的密钥，`metadata.field` 为缺少的键 |
| `OPERATOR_NETWORK_CHANGE_FORBIDDEN` | 403 | 无权修改网络设置。`metadata.cause`：`address`（没有「显示上游地址」）、`refreshable_account`（OAuth 类账号）、`bulk`（批量编辑） |
| `ADMIN_PERMISSION_INVALID` | 400 | 权限 JSON 不合法 |
| `OPERATOR_ACCESS_UNAVAILABLE` | 503 | 权限读取失败，按拒绝处理 |
| `ADMIN_ACTOR_MISSING` | 503 | 受保护的服务函数没有收到调用者身份，没有写入任何数据 |
| `ADMIN_REDACTION_FAILED` | 500 | 脱敏失败，不返回原始内容 |
| `REQUEST_TOO_LARGE` | 413 | 带检查规则的接口，请求体超过 16 MiB |

最后四个是内部保护，正常请求不会遇到。

## Backend 模式与合规确认

**Backend 模式**
- 开启后，普通用户不能登录。普通管理员与超级管理员一样可以：
  - 登录：密码、两步验证、Passkey、刷新令牌；
  - 读取自己的资料，完成二次验证；
  - 使用用户端功能，例如下载自己的使用记录导出。
- 后台功能仍按权限表。

**合规确认**
- 普通管理员同样要完成「部署与运营合规确认」，按人记录，弹窗与超级管理员相同。
- 确认之前，后台接口返回 423。
- 读取自己权限的接口 `/admin/me/access` 不受这条限制，所以菜单可以先加载出来。

## 界面

- 侧边栏和命令面板只显示有查看权限的模块；系统设置和插件只对超级管理员显示。
- 登录后进入第一个有权限的后台页面；一个都没有时进入个人资料页。
- 版本标识、自定义菜单与自定义页面只对超级管理员显示。

## 接口

`GET /api/v1/admin/me/access`

所有能进后台的人都可以调用，不受合规确认拦截。前端用它决定菜单、路由和按钮。

```json
{
  "role": "operator",
  "is_super_admin": false,
  "modules": { "accounts": "manage", "usage": "view" },
  "flags": ["accounts.upstream_address", "data.export"],
  "settings": { "ops_monitoring_enabled": true, "payment_enabled": false },
  "custom_menu_items": []
}
```

- `settings` 只包含后台页面需要的少数开关和费率，普通管理员不读取 `/admin/settings` 与 `/admin/payment/config`。
- 超级管理员得到全部 17 个模块为 `manage`、全部 5 个开关。
- 普通管理员的 `custom_menu_items` 总是空数组。

`GET` / `PUT /api/v1/admin/users/:id/operator-permissions`

只有超级管理员能调用，`PUT` 需要二次验证。请求体与返回体相同：

```json
{ "modules": { "accounts": "manage", "usage": "view" }, "flags": ["accounts.upstream_address", "data.export"] }
```

- 模块的值只能是 `view` 或 `manage`。没有权限的模块不写，`none` 不合法。
- 未知的键、模块、取值或开关返回 400 `ADMIN_PERMISSION_INVALID`。
- 用户没有设置过权限时返回 `{"modules":{},"flags":[]}`。目标用户可以还不是普通管理员。

## 新增接口与后台代码

- 每条经过后台鉴权的接口都必须登记在权限目录 `backend/internal/pkg/operatoraccess/catalog.go`，写明模块、级别、开关、目标规则、字段规则和脱敏。路由枚举测试会让未登记的新接口失败。
- 账号、用户、分组的写入函数（例如 `CreateAccount`、`UpdateUser`、`DeleteGroup`）要求明确的调用者，以下三种之一：
  - 普通管理员的权限范围；
  - 超级管理员标记，由后台鉴权设置；
  - 系统标记。

  三者都没有时返回 503 `ADMIN_ACTOR_MISSING`，不写入任何数据。
- 后台任务调用这些函数时，必须用 `operatoraccess.WithSystemActor(ctx, "<任务名>")` 标记，并在 PR 中说明。

## 迁移与回退

迁移 `282_admin_operator_permissions.sql` 新建表 `admin_operator_permissions`：每个用户最多一行，`permissions` 为上文接口的 JSON，另有 `updated_by` 与 `updated_at`。校验值登记在 `backend/migrations/checksums.json`。

- 不修改 `users` 表。`operator` 是现有 `role` 列（`VARCHAR(20)`，没有 CHECK 约束）的新取值；ent schema 与 `/auth/me` 的返回结构不变。
- 只有角色为 `operator` 时才读取该行，其他角色的行被忽略。
- 用户是软删除，删除普通管理员不会触发级联删除，留下的行不起作用。
- 旧版本程序忽略这张表。

**回退到旧版本**

先记下普通管理员名单和他们的权限，回退后要重新设置：

```sql
SELECT u.id, u.email, p.permissions
FROM users u LEFT JOIN admin_operator_permissions p ON p.user_id = u.id
WHERE u.role = 'operator';
```

在启动旧版本之前，用一个事务执行以下语句。迁移文件头部有同样的说明，程序不会自动执行：

```sql
BEGIN;
UPDATE users SET role = 'user' WHERE role = 'operator';
DROP TABLE IF EXISTS admin_operator_permissions;
DELETE FROM schema_migrations WHERE filename = '282_admin_operator_permissions.sql';
COMMIT;
```

- 先把普通管理员降为普通用户，因为旧版本不认识这个角色。
- 同时删除 `schema_migrations` 中的记录。迁移程序按文件名跳过已执行的迁移，如果只删表，再次升级时不会重建它，之后任命的普通管理员都会得到 503 `OPERATOR_ACCESS_UNAVAILABLE`。
- 再次升级后表是空的，按记下的名单重新任命并设置权限。

## 已知限制

- **账号放置**（2026-10-28，所有者已接受）：有账号「管理」权限的普通管理员可以把高价账号放进便宜的分组，让用户以低价使用，效果类似降价。这与模型映射风险（E2/D12）同类；为日常账号管理放开放置，不新增开关，请只把账号管理权限交给可信的人。
- **模型映射**：有账号或分组「管理」权限的普通管理员可以修改账号的模型映射、分组的模型路由和组合路由，例如把便宜的模型名映射到高价的上游模型。用户按请求的模型计费，所以这些设置不需要「加减余额」。请只把这两个模块的管理权限交给可信的人。
- **地址检查只在保存时做**：
  - 有「显示上游地址」的普通管理员保存的域名，以后可能被解析到内网地址（DNS 重绑定）。超级管理员保存的地址也一样。
  - 以后会在每次连接时检查，在那之前这项权限只授予可信的人。
  - 没有这项权限的普通管理员不能写任何地址。
- **测试账号**：
  - 普通管理员测试账号时，能看到上游返回的正常内容，例如模型回复，因为这正是测试的用途。
  - 没有「显示上游地址」时错误详情换成固定文字。但成功响应里的 `message` 等字段只去掉网址，其中单独出现的主机名仍可能显示。
- **运维监控**：错误详情里可能显示上游地址。有「运维监控」查看权限就能看到，与「显示上游地址」无关。只通过「使用记录」查看错误详情、两项权限都没有的普通管理员，看到的上游错误信息换成固定文字。
- **额度模式的渠道监控**：没有账号查看权限的普通管理员不能把监控关联到账号，所以不能新建只支持额度模式的监控（例如 antigravity）。
- **账号倍率**：有账号「管理」权限的普通管理员可以修改账号自己的倍率 `rate_multiplier`。它影响平台的成本核算和账号额度，不影响用户支付的价格。
- **首次绑定赠送**：
  - 普通管理员新建的用户，以后绑定真实的第三方登录身份时，仍可能领到该登录方式的首次绑定赠送（需要超级管理员开启该赠送）。
  - 每个用户每种登录方式只能领一次，每次需要一个真实的第三方账号，成本与用户自己注册相同。
- **OAuth 类账号的令牌刷新**：超级管理员修改 OAuth 类账号的网络设置时，修改前已经开始的令牌刷新或请求，可能把旧身份下取得的令牌写回。这是原有行为，普通管理员不能触发。
- **Bedrock 区域格式**：只对普通管理员检查，超级管理员不受限制。
- **复制回退中的账号**：账号处于代理回退中，且原代理已被超级管理员删除时，有账号「管理」权限的普通管理员复制这个账号，副本会不经代理直连。前提是超级管理员先删除了仍被引用的原代理，普通管理员自己做不到这一步。副本是新账号，已有账号的出口不受影响。
- **删除账号**：有账号「管理」权限的普通管理员可以删除已加入分组的账号，删除时也会移除它的分组绑定，不另要求「加减余额」。这是删除账号本身的权限，不会增加余额或提高价格。
- **权限保存前的请求体读取**：保存权限表时，操作日志中间件会先读取并缓冲请求体，再由处理器检查二次验证。开启二次验证后，没有通过验证仍不能保存权限。
