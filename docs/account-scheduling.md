# 账号调度

## 日常开关

在「账号管理」列表直接点击「调度」开关，无需打开其他设置。

- **开启**：该账号可接收新请求，按 Sub2API 原版调度规则参与选择。模型不支持、账号异常、限流或容量已满时，仍会自动避开。
- **关闭**：停止向该账号派发新请求；已经派发的请求继续运行到结束。后续请求由其他合格账号承接。正常超时、客户端取消和上游错误仍按请求本身的规则处理。
- 每次操作只改变当前账号；不联动其他账号。批量操作只改变明确选中的账号。
- 保存期间开关显示忙碌状态，重复点击不重复提交；保存失败会提示，并保留实际开关状态。
- 关闭不会强制切断正在输出的内容，也不会把已输出一半的回复换到另一个账号拼接。需要原账号继续的协议会话（如 `previous_response_id` 续链）在原账号关闭后不再续用该账号；WebSocket 的下一轮属于新请求。

## 调度规则

网关使用 Sub2API 原版调度：

- **优先级**：在账号编辑页设置，数字越小越先使用。
- **负载与会话粘性**：同优先级内按负载率（在途加排队 ÷ 负载因子；未设负载因子时按并发上限）选择；同一会话优先回到上次使用的账号，以保持上游缓存命中。
- **调度相关设置**：在「系统设置 → 网关」中配置，包括是否允许未分组 Key 调度、平台账号自动停调阈值、低倍率优先和 OpenAI 实验调度策略。

## 分组质量门槛、排序与满载

质量门槛通过 `GroupQualityGateView` 读取。启用组只有软性质量档，不再因门槛排除账号；未启用组不分档。`OrderTier` 返回 0（正常）、1（待复测）、2（不达标），`MigrationTarget` 返回迁出目标的质量条件，`ExpectedP90Ms` 提供预计首字；未装配评估器时全部第 0 档、没有可迁目标。

- 普通选号、借用、高级调度与份额调度均按质量档排序。可用性统计与可用性兜底只看硬准入和原有韧性软罚，质量不达标不使整个组不可用。占槽后的 `SelectionAdmissionVetoLatest` 继续复核利润门，不因质量档变化释放槽位或断开 WebSocket。
- 启用门槛时，顺序为硬准入 → 质量档 0/1/2 → 档内判慢后排 → 档内原有排序；compact 能力分段仍保留。`openAICandidateLess` 的质量分档与低倍率优先无关。低倍率优先生效时，档内为优先级 → 负载 ≥80% 排后 → 上游 token 成本 → 同倍率预计首字 → 负载 → 最近使用 → ID。成本取 `openAISchedulingRate`；先按负载/最近使用建立稳定基序，再在同质量档、判慢状态、优先级、满载区间和倍率（以及 compact 能力档）内，仅重排有预测的位置；没有预测的位置保持基序，不限并发且未设置负载因子时 80% 项中性。未启用低倍率优先时仍按优先级、负载、最近使用，同排序组内随机打散。
- 随机打散、E2 缓存偏好、会话近期成功偏好、临时借用均不跨质量档和判慢分隔。高级调度按 0 未判慢 → 0 判慢 → 1 未判慢 → 1 判慢 → 2 未判慢 → 2 判慢六个池依次运行原有 TopK 与权重，缓存偏好和借用在池内，取到即停。未开门槛的高级调度保持原状；份额调度的新放置与 spill 候选按质量档 → 当前模型判慢状态 → 原共享顺序稳定排序，合法绑定属主保留，不执行质量迁出。
- 低倍率优先保留全局开关 `openai_low_upstream_rate_priority_enabled`，增加 `openai_low_upstream_rate_priority_scope`（`all`/`groups`，缺省 `all`）与 `openai_low_upstream_rate_priority_group_ids`（JSON 分组 ID 数组，缺省 `[]`）。指定分组且集合为空等于关闭。仍要求高级调度关闭、当前请求使用上游 token 成本；管理设置保存后本实例即时刷新，其他实例约 5 秒刷新。
- 门槛组统一迁出：绑定号为 2 档或本模型正处判慢时触发，不要求低倍率优先；原版和高级调度共用 `migrateOpenAILatencyHeldOwner`。续链、WebSocket、迁出保护、质量路由持有绑定和固定续轮豁免；固定账号本身不豁免判慢迁出。
- 带协作或工具输出密文片段的请求同样不做软迁移：仅识别 `input[]` 内 `agent_message.content[]` 和数组形态 `function_call_output.output[]` 中的 `type=encrypted_content`。HTTP Responses（含透传）及接受 Responses 形状 `input[]` 的 Chat Completions 在选号前设置；WebSocket 首帧选号前设置（连接内不重选号，客户端重连后的新连接首帧照样判定）；reasoning／compaction 顶层密文不算。硬准入、失败类改绑、新会话放置、利润门与旧粘性逃逸保持原有规则。
- 迁出目标须通过硬准入、未判慢、有实时空位且 `MigrationTarget` 为真。普通组要求首字已测到且预计 P90 ≤0.9X，错误/缓存无当前不达标和坏记忆；严格组要求三维都有统计且处于恢复线内，并且没有当前不达标。固定账号不享目标例外。先用快照过滤质量、判慢与请求兼容性，再批量过滤满载候选；随后按档内顺序逐个做 DB 复核与占槽，第一个同时通过的候选才是目标，未尝试及满载候选不做逐号 DB 复核。候选复核或占槽失败时尝试下一个，全部失败保留原绑定。占槽后以 `OpenAIStickyRebindCache.CompareAndSwapSessionAccountID` 原子改绑；CAS 适用于新旧会话键。CAS 失败/报错或缓存不支持 CAS 时放弃本次迁出，已占目标槽位释放，原绑定不被主动删除。
- 仅改绑成功登记同组+会话 5 分钟冷却（进程内 LRU，最多 16384 键）并记录 Warn `group_quality_gate.migrate`，字段为 `session_hash` 前缀、`group_id`、`from_account_id`、`to_account_id`、`trigger`（`tier`/`latency_hold`）。失败类改绑不受该冷却限制。原号恢复后只成为候选，不主动迁回；重启清空冷却，各实例独立。
- 原版无 LoadBatch、负载感知和高级调度的粘性账号满载时，短间隔退避重试原号最多 2 秒，尊重请求取消且不入队。仍满则排除原号，在比较键确定的最优档内，优先借用本会话最近成功的账号，否则按会话固定哈希顺序抢即时空位，绑定保留原号。已知负载时不借负载率 ≥100%（有排队）或在用并发已满的账号；先抢槽再复核账号，复核失败即释放；每次借用最多抢槽、复核各 64 次，用尽即等原号；读取候选失败时记 warn `openai_sticky_capacity_list_failed`（`group_id`、`account_id`、`error`）并等原号。原版兼容循环（WebSocket 入口、图片请求）的借用只选支持所需传输方式与图片能力的账号，同一次选号最多短等一次。
- 会话绑定的续期与首次绑定使用同一 TTL：`gateway.openai_ws.sticky_session_ttl_seconds`（默认 3600），份额调度组用份额 TTL。Layer 1 复核读取账号出错（不是账号不存在）时只跳过本次、不删绑定；账号不存在、不可调度、不合格或被利润门否决仍删除绑定。
- 旧质量路由已接管绑定时，只在 otherProvider / otherAccount 两个层级借用或选择 fallback 等待号，保留真实请求排除集，不进入逐个放行坏号的层级；只有坏号空闲时仍等健康原号。同一比较档内重复借用保持稳定，临时借用不写回质量绑定。
- WebSocket 后续 turn 抢不到账号槽时，先用同一退避（50→100→200ms，最多 2 秒，不入队、尊重取消）短等，仍满才以 1013 “account is busy, please retry later” 关闭；用户并发上限不足时仍立即关闭。该短等对所有经 Responses WebSocket 接入的平台生效。
- WebSocket 连接每个 turn 成功后续期（分组, 会话）绑定，每连接最多每 5 分钟一次（TTL 更短时为 TTL/2）。只续不建，只在绑定仍指向本连接账号时续；借用连接、无会话哈希和质量路由接管的会话不续。TTL 取 `gateway.openai_ws.sticky_session_ttl_seconds`（默认 3600），份额调度组用份额 TTL。连续工作超过 TTL 后重连仍回到原账号。
- 全组没有合格的即时空位才返回最终 WaitPlan；队列未满时等待原号，队列已满时使用 fallback 等待时限与队列上限：无 LoadBatch 路径仍等原号，负载感知与高级调度按 Layer 3 选择比较器最优账号。非 OpenAI 原版负载感知路径的原号队列满时，先尝试 Layer 2 的即时空位，再进入 fallback 等待。只有选中账号不同于原号才标记 spillover；原号上的 fallback 等待仍为粘性命中，保持首输出截止口径。处理器仍只为最终 WaitPlan 加减一次排队计数。强续接继续等待原账号。
- 末位兜底仍只放宽原有软罚；选中启用门槛组的 2 档账号时记录 `group_quality_gate.last_resort`（`group_id`、`account_id`）。利润门、智商、余额、鉴权、模型支持都不能放宽。利润终检否决用尽重选预算时，客户端仍收到既有的 503，错误码不变。

门槛规则与实现契约见 [OpenAI 质量路由](OPENAI_QUALITY_ROUTING.md) 和 [本次 OpenSpec](../openspec/changes/group-quality-gate-v3-20261104/design.md)。

## 网关韧性（0.4.0）

0.4.0 起，网关韧性在原版调度之上加了以下规则，默认开启，可在「系统设置 → 网关 → 网关韧性」逐项关闭（关闭后回到 0.3.0 行为）。详见 [网关韧性](GATEWAY_RESILIENCE.md)。

- **软罚保留绑定**：瞬时失败冷却、无重置时间的 429 冷却等软罚期间，账号平时不被选中，但会话绑定保留，冷却结束后会话回到原账号；停用、错误、余额不足暂停等硬状态才清除绑定（OpenAI 按模型的瞬时屏蔽仍按原逻辑清除，见该文档“已知限制”）。
- **会话改绑**：同一会话在同一账号上 10 分钟内连续失败 2 次，改绑并在 10 分钟内避开该账号。
- **末位兜底**：分组内没有无罚账号时，先转投配置的无号兜底分组；没有兜底分组时，按优先级与罚期结束时间使用软罚账号，同优先级内 OpenAI 与 Claude 判慢期账号排在后面，单号分组不再整组不可用。
- **余额不足暂停**：上游余额不足的账号暂停调度，在账号列表显示为临时不可调度，原因以 `balance:` 开头；「恢复状态」立即放回。0.4.12 起到期后仍不足会逐级加长（默认 5、15、60 分钟），请求成功或「恢复状态」后复位。欠费且暂时不用的账号，直接关掉「调度」开关。
- **模型不可用（0.4.12）**：上游以结构化错误码或几种明确的消息报告某个模型不可用时，本请求换号，该账号对这个模型 30 分钟不被选中，同账号的其他模型照常服务；末位兜底不放宽。见 [网关韧性](GATEWAY_RESILIENCE.md) §4.9。
- **模型级冷却（0.4.9）**：Anthropic、Gemini、Antigravity 账号上某个模型连续失败时，从第 2 轮起只冷却该模型（10、45、90、180、300 秒），同账号的其他模型照常服务；属于软罚，末位兜底可用。上游带 `Retry-After` 时仍冷却整个账号。见 [网关韧性](GATEWAY_RESILIENCE.md) §4.6。
- **选号解释**：运维页「网关韧性」面板底部可查看任一分组每个账号的罚则档位、原因与恢复时间；带请求模式的解释与兜底判定、分组可用数同口径（平台资格、硬状态、利润门、软罚与质量熔断），另外排除已学到的能力限制。
- **智商检测的模型级冷却**：OpenAI 账号的某个模型被智商检测判为降智后，只冷却该账号的这个出站模型（`iq:` 模型限流键），同账号的其他模型照常服务。复检 3 题全对后才恢复，末位兜底不放宽，「恢复状态」与「清除限流」也不会解除。账号列表的智商检测列在该模型的“降智”后显示复检时间。见 [OpenAI 智商检测](OPENAI_IQ_CHECK.md) 与 [网关韧性](GATEWAY_RESILIENCE.md) §4.8。
- **OpenAI 判慢让位**：账号×模型按 5 分钟时间常数衰减计数，有效样本 ≥6 且尝试级可见首字 ≥10 秒的占比 ≥30% 时触发。距上次结束 ≤30 分钟再次触发时，让位 3→6→12→15 分钟封顶，否则从 3 分钟开始；期间继续积累，触发时清零。启用门槛时档内后排，未启用时原版选号排到候选末尾；到期只解除后排，不表示质量恢复。
- **未开门槛组的 OpenAI 判慢迁出**：原版选号保留既有行为：绑定号判慢，同组存在未判慢、准入合格且实时有空位的替代时，按属主解除绑定再正常选号；没有目标时保留绑定。高级调度不新增判慢迁出。启用门槛组使用上文的统一迁出。
- **Claude 判慢与迁出**：原生及 API Key 透传只采成功流式粘性热尝试的语义首输出，按账号与实际出站模型计数，阈值保持 35%、固定 3 分钟，不跟随 OpenAI 的递增参数。只在同优先级段内后排；迁出目标还须通过正常准入、与 owner 同优先级、未判慢且新鲜负载有空槽，模型路由内限于路由集合。属主删除出错时保留绑定；比较确认绑定已变时重新读取并使用新 owner，读不到则正常选号。同一分组+会话成功迁出后 30 分钟内保留绑定并记 `cooldown`，状态在进程内、多实例各自计算；迁出首轮不采样。
- **替补账号**：原版负载感知选号中，绑定账号不可用或本请求已换号时，同优先级、负载率不超过最低负载率加 20 个百分点、同成本与 compact 层级的候选，按会话近期成功时间、完整缓存证据、稳定哈希与账号 ID 排序；启用门槛时候选须处于同一质量档与判慢分段；开启低倍率优先时还须处于同一 80% 负载区间。三条满载路径抽取其中的近期成功、稳定哈希与 ID 顺序用于临时借用：同一优先级、成本与 compact 档位内按近期成功、会话哈希排序，只取消最低负载加 20 个百分点的限制；启用门槛时仍保留质量档位与判慢边界，启用低倍率优先时还保留 ≥80% 负载边界，有低于 80% 的同档空闲候选时不会因近期成功借到快满账号；借用仍保留 compact 档位顺序，并把判慢账号放在健康账号之后。近期成功只记完整成功且已送达语义输出，按分组、会话和实际出站模型隔离；进程内最多 16,384 个键、每键 3 个账号、每账号 60 分钟过期。模型沿用端点和候选的实际转发规则，且不重复映射。健康 owner 保持粘性，份额调度沿用自己的分配策略。详见 [网关韧性](GATEWAY_RESILIENCE.md) §4.9。
- 判慢降序与会话迁移随韧性总开关，会话迁移另外要求“会话失败改绑”开启；OpenAI 没有另设开关，Claude 另受默认开启的 `anthropic_latency_hold` 控制，关闭后状态失效，重开只用新样本。高级调度与份额调度不使用它们。慢失败冷却与首输出截止分热、冷尝试对所有选号方式生效，见 [网关韧性](GATEWAY_RESILIENCE.md) §4.5。
- Claude 判慢后排与迁出只在缺省开启的原版负载批量选号（`gateway.scheduling.load_batch_enabled=true`）生效；关闭该设置或未配置并发服务时走旧选择器，不应用这两项行为。

## 已退役的智能可控调度

2026-10-10 起，智能可控调度（策略分组、分配比例、等待与自动换号、调度模式切换）已完全移除：

- 「账号调度」页面和「系统设置 → 网关」顶部的模式切换不再显示。
- 旧管理接口 `/api/v1/admin/scheduling/*` 及账号级调度控制、故障域接口统一返回 `410 Gone`，错误码 `SCHEDULING_RETIRED`。
- 账号的「调度」开关、优先级、限流与异常保护保持原有含义。

替代方案「份额调度」默认关闭，按分组启用：同样按账号优先级分层，同一优先级内按负载因子比例分配新会话，并尽量把会话留在原账号以保护缓存命中。它没有单独的账号规则，账号的优先级、负载因子与「调度」开关就是它的配置。使用说明见 [份额调度](SHARE_SCHEDULING.md)。

## 负载因子与份额分组

- 修改负载因子会同时影响该账号所在的全部分组：原版分组里负载因子越大越常被选中，份额分组里按负载因子比例分到新会话。
- 账号列表按份额分组筛选时显示“份额”列，即该账号在该组预计分到的新会话比例；关闭某个账号的「调度」时，页面提示它在哪些份额分组的新会话改由同优先级的其他账号承接。
- 平滑减少某个账号的新会话：把负载因子调小（最小 1）；立即停止：关闭「调度」开关。
