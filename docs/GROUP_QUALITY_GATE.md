# 分组质量门槛

分组质量门槛按“分组 × 账号”在进程内评估 OpenAI 账号质量。策略关闭或没有策略条目时，调度行为保持原样；状态不写入账号调度字段、临时停用字段或分组成员关系。多实例各自计算，不使用 Redis 保存门槛状态。

## 策略与默认值

设置键为 `SettingKeyGroupQualityGatePolicies`（存储名 `group_quality_gate_policies`），值是带 `version` 的 JSON：

```json
{"version":3,"groups":{"7":{"enabled":true,"max_error_rate":0.10,"max_warm_ttft_p90_ms":20000,"fast_warm_ttft_p90_ms":10000,"pinned_account_ids":[101]}}}
```

错误率默认 10%，续轮首字 p90 熔断线默认 20000 ms，快档线默认 10000 ms。快档线只参与排序，不触发熔断。错误率取值为 `(0,1]`；首字阈值为 1000–600000 ms，且快档线小于熔断线。固定账号必须是当前成员；只有 OpenAI 分组可以启用门槛。

策略写入携带 `expected_version`，版本不一致返回 409，成功后版本加一。保存成功后本实例立即用新策略：关闭门槛即刻停止否决（其他实例最长约 1 分钟），排序档位不变，状态接口的 `enabled` 与否决结果在下一轮评估后更新；新启用的分组在下一轮评估后进入状态接口。关闭门槛视为正在进行的熔断在关闭时刻结束，重新开启后不按熔断前的数据再次熔断，熔断次数保留。

## 指标与有效数据

评估器在后台循环启动后立即运行首轮，不阻塞服务装配，之后每 60 秒运行一次；每轮整体超时为 30 秒。成员通过一次查询加载必要字段（包括未启用门槛、但需要快慢档排序的 OpenAI 分组），不加载代理或完整分组关系。指标查询固定读取最近 2 小时 5 分钟，在只读事务中执行并设置 5 秒语句超时。错误率窗口为 15 分钟，分母为成功请求与软失败之和（同一请求在同一账号上既有用量行又有软失败时，例如出字后断流，只计 1 次请求、1 次软失败；错误行按 `client_request_id`/`request_id` 对齐用量行的 `client:`/`local:` 请求 ID，空 ID 不去重），至少 20 个请求且至少 5 个软失败才可熔断。软失败沿用韧性 TRANSIENT、首字超时、STALL 和未分类的非取消 `request_error`；429、余额、鉴权、容量削峰、模型不支持和用户取消不计入。

软失败读取 `ops_error_logs`，该表只在运维监控开启（`ops_monitoring_enabled`）时写入。关闭运维监控时软失败恒为 0，错误率门槛实际失效，只剩续轮首字门槛；启用质量门槛前须确认运维监控已开启。

续轮首字 p90 使用同一会话、同一账号、前一请求间隔不超过 5 分钟的流式成功请求，窗口为 30 分钟，至少 10 个样本。续轮零缓存率窗口为 2 小时，仅统计提示 token（`input_tokens + cache_read_tokens + cache_creation_tokens`）至少 2048 的续轮，至少 20 个样本时用于快档排序；超过 30% 会降到其他档，不会熔断。

有效数据起点是窗口起点、`group_quality_reset_at`、该账号在本组最近一次熔断结束和进程启动时刻中的最晚者。成员移出分组（或分组停用）后，其熔断次数、熔断状态与上次熔断结束时间在熔断结束后 2 小时内保留，期间再加回即沿用；期间有新的手动重置则不沿用。缺席成员不出现在状态接口。熔断结束后不再使用熔断前样本，重启后不读取启动前样本；试用状态只保存请求标识集合（最多 20 个）及这些请求的软失败标识集合。每轮重新扫描试用开始与当前时刻减去 125 分钟两者中较晚者之后的数据，请求按请求标识去重，软失败按 `(request_id, account_id, at_unix_ms)` 去重，确保晚写入的记录仍可计入。计数取集合大小；较早的已计入记录滑出窗口后仍保留在集合中，不会为长时间试用扩大查询范围。

数据新鲜度只看 `usage_logs` 的最新行（没有任何用量行时按无样本处理），错误日志的新记录不能掩盖用量写入停滞。查询失败或用量超过 5 分钟未更新时沿用上一轮指标、不新增熔断（包括试用再熔断），已有熔断照常到期转试用；成员信息可读取时仍处理管理端重置。每个连续 stale 期间只记录一次 `group_quality_gate.evaluate_failed`，携带原因及 stale 时长；恢复正常评估后才允许再次熔断。

## 状态、熔断与保底

状态为合格、熔断或试用。熔断退避为 5、10、20、30 分钟封顶；连续 2 小时未再次熔断时清零。到期后，新数据仍超线进入下一档；触发熔断的每项指标都有足够的新样本，且所有样本足够的指标不超过上限 80% 时转合格；其他情况进入试用。试用从本次熔断结束时刻开始计数（熔断到期到下一轮评估之间的请求计入试用）；试用前 20 个请求内软失败达到 2 次或满足熔断条件时再次熔断，满 20 个请求转合格。

评估结果分别给出可用、达标、固定、保底保留和状态。可用复用现有硬状态分级，并在利润门开启时检查分组利润上限；可服务由 `groupMemberServable` 统一判断，另外排除韧性软罚和质量否决。保底目标为 `min(max(2, ceil(可用数/2)), 可计入数)`；可计入成员排除固定且不达标账号。不足时按熔断时保存的超线程度从轻到重保留账号；同分优先上一轮已保底保留的账号，再按账号 ID 稳定排序，无新数据不会逐轮漂移；目标不可达时可计入成员全部保留。固定账号不被质量否决，但不达标时不计入保底分子。

档位 0 为合格快档，档位 1 为试用，档位 2 为其他。首字没有数据算快档；样本不足沿用上次档位最长 6 小时；熔断结束清除档位记忆。没有启用门槛的分组只有 0、2 档。门槛状态只影响本组选择，最后兜底是否放宽质量门槛由调度与兜底模块处理。启用门槛的分组不再做 0.4.9 的判慢会话迁移（按最近一次评估判断），慢账号由续轮首字 p90 熔断改绑；判慢降序照常。

## 利润门与可服务数

利润门成本统一由 `openAIProfitGateCost` 计算。先校验原始 `rate_multiplier`：nil、负数、NaN、Inf 拒绝，0 合法。OpenAI API Key 使用定价时刻的新鲜探测（含上游高峰），过期或缺失时使用账号倍率；OAuth 使用现有运行时参考倍率，显式清空参考倍率时使用账号倍率。其他 token 平台沿用已校验的账号倍率。请求和抢槽后终检都使用同一个 `pricingAt`；等待期间刷新账号快照，但不改定价时刻。

OAuth 成本检查只读现有调度设置缓存，不查询数据库。启动设置加载流程会预热一次，使用原加载器的 singleflight 与查询超时；不运行 OpenAI 调度的实例也会加载已保存的参考倍率。缓存过期后沿用最后发布值，由原设置加载器或管理端设置更新刷新。

售价使用服务计价分组的用户覆盖倍率或默认倍率，再乘该组高峰；开关、毛利率和安全缓冲使用被调度分组。`groupProfitCeiling` 按分组默认倍率估算保底、兜底与运维可服务数，不针对特定用户。运维分组可用账号数、`group_available_accounts` 与 `group_available_ratio` 告警都由 `groupMemberServable` 计数；固定但不达标的账号免于质量否决，只要其他条件满足就计入。平台总数和账号级状态展示保持原口径。

成员平台资格复用调度器规则：同平台成员可用；Anthropic/Gemini 组也接受已启用混合调度的 Antigravity 成员；组合组接受其成员的具体平台。兜底触发、运维可用数、保底分母与利润预览采用同一资格规则，两道门都关闭时不会因平台不同而漏算这些成员。

分组可用数从本版起是“可服务”口径，即使两道门都关闭也与旧版不同：旧版只看启用、可调度、未限流、未过载、未临时停用；新口径另外排除额度耗尽、到期待暂停等硬状态成员，以及平台资格不符的成员（如未开混合调度的 Antigravity 账号）。可用数因此可能比旧版低，告警阈值按新口径核对。

## 管理接口

普通管理员的策略与状态读取沿用账号管理查看权限，策略写入沿用分组管理管理权限并进入审计。没有账号查看权限的管理员在分组页看不到门槛列，也不发起策略与状态请求；编辑框只提示需要账号查看权限才能配置质量门槛。利润门预览沿用分组管理查看权限：

- `GET /api/v1/admin/group-quality-gate/policies`
- `PUT /api/v1/admin/group-quality-gate/policies/:group_id`
- `GET /api/v1/admin/group-quality-gate/status`
- `GET /api/v1/admin/groups/:id/profit-control-preview?margin=0.2`

状态接口的 `group_id` 可选。不带参数时返回全部已启用门槛的分组，`account_metrics` 覆盖这些分组的全部成员；带参数时只返回该组，即使未启用门槛也返回成员指标并标记 `enabled=false`。状态快照包含 `generated_at`、`stale`、账号指标、状态、熔断结束时间、原因、档位、可用、达标、固定、保底保留和实际否决结果。`groups`、`accounts`、`reasons` 始终是数组（空集合为 `[]`），`account_metrics` 始终是对象（空集合为 `{}`）。`summary.eligible` 是未被否决的成员数，包含试用、固定及保底保留；`summary.ejected` 是实际否决数；`summary.trial` 单独统计试用数，属于 eligible 的子集。

每个 `groups[].accounts[]` 成员的 `metrics` 是本组判定实际使用的有效数据，包含 `calls`、`soft_failures`、`error_rate`、`warm_samples`、`warm_ttft_p90_ms`。`calls`、`soft_failures`、`warm_samples` 始终为实际计数；`error_rate=null` 表示总数 <20 或软失败 <5，未达判定条件；`warm_ttft_p90_ms=null` 表示续轮样本 <10。重启前、重置前及本组熔断结束前的旧数据按有效起点排除；过期熔断也不再显示触发熔断那轮的旧指标。

`headroom` 只使用成员 `metrics` 中非 null 的 `error_rate` 与 `warm_ttft_p90_ms`，取最小的 `1 − 实测值 / 上限`：负数表示超线，0 表示压线；两项均为 null 时返回 `null`。后端返回的成员余量与成员有效指标同源；顶层 `account_metrics` 保持完整窗口，供账号行及熔断中的提示显示，具体界面取值见下文。策略校验失败沿用 `{code, message, reason, metadata}` 错误结构，`reason=INVALID_GROUP_QUALITY_GATE_POLICY`，`message` 说明具体字段约束或非成员账号，`metadata.field` 标出字段。

利润门预览返回 `{members, schedulable, passing, ceiling}`：全部成员数（含停用成员）、排除硬状态与软罚后的可调度数、其中通过利润门的数量，以及换算的上游倍率上限。预览不计质量熔断，便于单独评估利润设置；`margin` 范围 `[0,1)`，省略时使用保存值，安全缓冲按 0。上限与成本在同一当前时刻计算，即使利润门尚未开启也可预览；不保存任何配置。非法参数或不支持利润门的平台返回 400，分组不存在返回 404。

## 管理界面

OpenAI 分组的编辑框显示质量门槛与本组固定账号芯片多选，展示已选数量、限制列表高度，成员超过 8 个时提供名称或 ID 搜索；简洁模式隐藏门槛区块和列表门槛列，创建分组后再进入编辑配置。保存先写分组，再按 `expected_version` 写门槛；无改动不写策略。门槛保存失败时保留弹窗与门槛输入：版本冲突（409）重新读取版本并提示确认后再次保存，400 按 `metadata.field` 标出对应输入，其他失败说明“分组已保存，门槛未保存”；再次保存时分组没有改动就不重复提交，也不重复做利润门全挡确认。成员列表最多加载 1000 个；列表不完整时保留未加载到的固定账号并按 `#ID` 显示，只在列表完整时去掉已离组的 ID。关闭门槛只提交关闭开关，保留原有阈值与固定账号设置。

利润控制支持的平台均可预览。手动开启且毛利率为空或 0 时填 20%；之后毛利率框留空按默认 20% 校验、提交与预览，显式填 0 仍为 0；安全缓冲不显示，编辑旧组时先并入毛利率，再以安全缓冲 0 保存，保持有效上限。没有价格权限的管理员不提交利润字段。有可调度成员但零通过时红字并要求保存确认，只有一个通过时黄字；没有可调度成员时中性提示、不作全挡确认。预览按已保存的分组倍率、高峰与平台计算；同次编辑改变这些字段时，保存后重新打开查看对应的新预览。

账号列表显示各组的合格、熔断、试用、固定和保底保留状态，并显示三项窗口指标；续轮零缓存率在样本至少 20 且超过 30% 时标红。分组列表把门槛列放在账号数之前，以两行显示“合格 n / 熔断 m”；刚启用尚未评估显示“等待评估”，停用组或门槛关闭显示“—”，读取失败明确显示“读取失败”。状态随列表加载刷新，最多每 60 秒拉取一次。悬停或键盘聚焦分组单元格可查看原因、实测值、阈值和余量；触屏点按直接进入编辑。

提示面板按分组显示状态、原因和“指标 / 实测 / 上限”表。合格、试用成员的实测与余量使用该成员的有效 `metrics` 和后端 `headroom`；熔断中（包括保底保留，以及状态为熔断的固定成员）改用同一快照的完整窗口 `account_metrics`，标注“熔断时窗口”，前端按同样的样本门槛与公式计算余量。这是完整滚动窗口的显示口径，不新增冻结在熔断时刻的历史快照。余量仅在低于 20% 时提示，负值红色、其余黄色。

错误率尚未达判定条件但已有请求时，显示软失败数/请求数及“未达判定条件”，不标红；无请求时显示“无数据”。首字样本不足时显示“样本不足”，无样本时显示“无数据”。账号行的紧凑指标仍用完整窗口，只有样本满足条件且超过该账号已评估分组的最严上限才标红；零缓存沿用至少 20 个样本且超过 30% 的条件。固定标记使用锁图标并保留读屏文字；固定/保底说明各保留一句，利润预览保持一行，零通过时的保存确认不变。

## 恢复与观测

只有 `POST /api/v1/admin/accounts/:id/recover-state` 通过 `AccountRecoveryOptions.ResetGroupQualityGate` 写入 `accounts.extra.group_quality_reset_at`，写入使用 JSONB 合并，不丢失其他字段。进程运行期间新出现或变化的重置时刻，在下一轮评估清除该账号当时所在全部分组的熔断、清零次数并转试用；同一重置按账号只生效一次，之后新加入分组的账号按普通成员取数（数据起点仍不早于重置时刻），不再转试用；没有上一轮记录的成员遇到新重置时，试用起点不早于上一轮评估；早于或等于进程启动的历史重置只作为数据起点，不在重启后重新转试用。成功测试恢复和 OpenAI 额度重置不设置该选项。

手动重置与熔断到期转试用记录 `trial`；试用转合格、到期直接合格记录 `recover`。状态转换事件为 Warn 级（进入运维系统日志），每次转换一条，字段含 `group_id`、`account_id`、`from`、`to`、`reason`（触发指标、`ejection_expired`、`trial_passed`、`manual_reset`、`gate_disabled`）与 `strike`。事件使用统一前缀：`group_quality_gate.eject`、`group_quality_gate.trial`、`group_quality_gate.recover`、`group_quality_gate.guard_hold`、`group_quality_gate.last_resort`、`group_quality_gate.evaluate_failed`。

## 升级说明

本版本起，OpenAI OAuth 账号的利润门成本从各账号的 `rate_multiplier` 改为全局 OAuth 调度参考倍率（默认 1.0）；显式清空参考倍率才使用账号倍率。原始账号倍率仍须合法。已开启利润门且含 OAuth 成员的分组，上线前应核对全局参考倍率与利润上限；新口径可能减少可服务成员并触发兜底或无可用账号。账号侧用量成本与扣费记录的倍率口径不因此改变。

## 回退

关闭分组门槛即可回到原有选择行为；门槛状态是进程内快照，不写入账号调度字段、临时停用字段或成员关系。该功能不增加数据库迁移。
