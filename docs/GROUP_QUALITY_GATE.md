# 分组质量门槛 v3

门槛按“账号 × OpenAI 分组 × 首字／错误／缓存”每分钟独立评估，给候选排序与会话迁出提供质量档。质量不达标的账号仍可接流量；硬准入、利润门、判慢与急性保护由各自模块负责。状态、投票与坏记忆都保存在进程内，不写账号调度字段、成员关系或 Redis。每个实例从共享数据库独立评估；重启时错误维和缓存维从最近 6 小时事实热启动，首字维仍从进程启动后重新学习。

## 策略、默认值与保存

设置键是 `SettingKeyGroupQualityGatePolicies`（存储名 `group_quality_gate_policies`），保留版本号和每组旧字段，新增独立 `v3` 子对象：

```json
{"version":10,"groups":{"7":{"enabled":true,"max_error_rate":0.10,"max_warm_ttft_p90_ms":20000,"fast_warm_ttft_p90_ms":10000,"pinned_account_ids":[101],"v3":{"enabled":true,"max_ttft_p90_seconds":15,"max_error_rate":0.10,"min_cache_keep_rate":0.50,"strict":false}}}}
```

| v3 字段 | 含义与范围 | 没有子对象时的缺省 |
|---|---|---|
| `enabled` | 只允许 OpenAI 组开启 | 继承该组旧 `enabled` |
| `max_ttft_p90_seconds` | 首字上限 X，5–60 的整数秒 | 15 |
| `max_error_rate` | 错误上限 Y，0.05–0.50 | 0.10 |
| `min_cache_keep_rate` | 缓存保持下限 Z，0.50–0.70 | 0.50 |
| `strict` | 无结论的账号进入 1 档 | false |

子对象存在时完全采用其中的值，显式关闭不继承；非法值不补成缺省。读取接口为缺少子对象的组补出有效 `v3`，但不写库。保存只接收 `policy.v3`，它是必填项；请求里即使携带旧字段，也不采纳。旧 `enabled`、`max_error_rate`、`max_warm_ttft_p90_ms`、`fast_warm_ttft_p90_ms`、`pinned_account_ids` 按库中原值保存，保留缺失、null、数值编码与账号顺序；不再归一化旧字段。新建策略只设置 v3 时，旧启用值为 false。

写入需要 `expected_version`；版本冲突返回 409，成功后版本加一。校验失败返回 `INVALID_GROUP_QUALITY_GATE_POLICY`，`metadata.field` 定位 `v3` 或 `v3.<字段>`。本实例保存关闭后立即停止质量排序和质量迁出，其他实例在下一轮加载时生效。新统计与分档在下一次评估更新；尚未评估的未知账号，普通组为 0 档、严格组为 1 档。

旧固定账号列表继续生效：固定账号质量档为 0，显示“固定”及真实三维状态。固定不代表达标，不豁免判慢、急性保护或迁出目标条件；判慢仍可触发其绑定会话迁出。

## 数据与严格续轮

启动后后台先热启动并评估一次，此后每 60 秒评估。在线评估每轮整体超时 30 秒、语句超时 5 秒；热启动载入使用独立 20 秒语句超时和 60 秒总预算。载入前用有限 `count+1` 检查 LAG/freshness 范围内的原始 `usage_logs` 行数和错误事件数，各不得超过 200,000；载入后的观测也有 200,000 行上限。重放截止保留启动时刻的秒偏移，freshness 同时使用每分钟在该截止前的最新写入，避免分钟内较晚写入遮蔽较早写入。热启动超时、超限或查询失败时记 `group_quality_gate.warm_start_failed` Warn，保持空状态并继续普通评估。只为启用的 OpenAI 组产生质量档，但 B1 基线覆盖所有 OpenAI 账号，包括不在已启用组里的账号。

- 成功取 `usage_logs`，要求 `actual_cost > 0 OR output_tokens > 0`。零成本、零输出占位行参与相邻判断，不计成功；占位在其他账号上会打断续轮，占位在同账号上不打断，但上一提示为零时下一行不进缓存样本。
- 严格续轮在同一 `(api_key_id, group_id, session_id)` 内按 `created_at, id` 找紧邻上一个请求，要求同账号、同模型、间隔不超过 5 分钟、会话标识非空。按本次服务组 `group_id` 分区，不能先按目标账号过滤再做 LAG。
- 错误维和缓存维的样本下界取窗口起点与该账号 `group_quality_reset_at` 的最晚者；首字维额外取进程启动时刻的最晚者。上一个请求早于对应下界或重置时刻的请求不算严格续轮。
- 首字只读 `usage_logs.attempt_first_output_ms`，即最终尝试开始到首次语义输出，排除排队、选号及此前失败尝试的等待。速度样本要求新列大于 0；0、负数或 NULL 排除，不补值。缓存和 e_G 构成不受此限制。不回落到 `first_token_ms` 或 `end_to_end_first_output_ms`，不受 `openai_ttft_mode` 影响。两项旧首字字段及近期表现的口径保持原样。
- 同账号同请求有任何上游失败事件（含首字截止）时，其用量不计速度样本；其他账号救回的最终成功照常计入。空请求 ID 无法对齐，成功行照常计入。失败排除仅用于 B1／GM30；缓存保持率和 e_G 构成仍使用满足成本或输出条件的严格续轮用量，不按失败事件排除。已接受边界：日志没有可与用量对齐的最终尝试 ID，同账号原地重试先败后成会被保守少记。

数据陈旧只看 `usage_logs` 最新行，错误日志不能掩盖用量写入停滞。超过 5 分钟未更新或查询失败时，本轮不投票、不改变质量状态、不刷新或清除坏记忆，沿用上一快照；每个连续陈旧期间只记录一次评估失败事件。管理员明确发出的恢复指令仍清空对应账号状态。没有任何用量行时按无样本处理。

## 账号统计与分组首字预测

### 首字维

请求单元由“模型 × 推理强度 × 本轮提示总量档 × 缓存是否保持”组成。提示总量为输入、缓存读取、缓存写入 token 之和；四档为 `<20k`、`20–60k`、`60–120k`、`≥120k`。缓存保持指本轮读取至少达到上一请求提示量的 50%。

B1 取最近 2 小时的成功严格续轮，先求单元内每个账号的首字中位数，再求账号中位数的中位数。单元至少有 3 个账号、30 个样本才有效。不足时按以下顺序退化，模型与推理强度始终不变：

1. 完整单元。
2. 合并缓存保持与未保持。
3. 相邻两档固定合并：前两档合并、后两档合并。
4. 合并全部提示档。

GM30 取账号最近 30 分钟可匹配 B1 的样本，从新到旧，每会话最多 3 个、每账号最多 50 个。会话按 API Key、服务组和会话 ID 区分。每个比值为样本首字除以对应 B1，封顶 4；至少 10 个样本、3 个会话才可用，系数为比值的几何平均。

e_G 使用本组最近 6 小时的成功严格续轮，请求形状先匹配当前 B1，再从新到旧取最多 100 条；至少 50 条时，求这些 B1 预期首字的 P90。请求可来自本组任意服务账号；不借用其他组的构成。该样本自身没有新首字列也可贡献构成，只要其单元匹配当前 B1。不足 50 条显示“本组样本不足”。

预计 P90 = GM30 × e_G。超过 X 为越线，不超过 X 为达标；此前失败或仍有坏记忆时，须不超过 `0.9 × X` 才能投恢复票。任一系数不可用则首字维无结论。

### 错误维

失败取 `ops_error_logs.upstream_errors`，沿用软失败分类：`TRANSIENT`、`STALL`、未分类且非取消的 `request_error`；门槛 v3 排除 `first_output_timeout`／`FIRST_OUTPUT_TIMEOUT`。余额、鉴权、429、容量削峰、请求不支持与客户端取消不计入。近期表现仍包含首字截止；份额健康的分类保持不变。

按 `(账号, 请求 ID, 事件毫秒时刻)` 去重。同请求同账号同时有用量和软失败（例如输出后断流），只计失败、不再计成功；被其他账号救回的失败仍归出错账号。空请求 ID 各自计数。先去重，再取最近 30 分钟内最多 100 个成功或软失败事件，至少 20 个才判定。

失败率 `> Y` 且失败至少 5 次为越线；失败率 `≤ Y` 为达标，恢复要求 `≤ 0.8 × Y`。Wilson 95% 区间只用于展示，不参与错误维判定。错误日志依赖 `ops_monitoring_enabled`，上线前必须确认已开启，否则错误维缺少失败事实。

### 缓存维

取成功严格续轮，要求本轮、上轮提示量均至少 2048 token，且本轮提示至少为上轮的 50%，排除收缩请求。最近 30 分钟最多 40 个样本，至少 20 个才判定。保持的定义为本轮缓存读取至少达到上一轮提示量的 50%。

保持率 Wilson 95% 上界 `< Z` 为越线；点估计 `≥ Z` 为达标及恢复；二者之间是中间带。少于判定样本数时仍展示已有点估计和样本数，但状态为无结论。

### 查询成本与边界

在线用量查询覆盖 `max(当前时间−6 小时, reset_at)` 之后的 OpenAI 用量，含用于相邻判断的占位行；热启动载入再向前扩 30 分钟以复现 LAG。可利用 `idx_usage_logs_created_at` 的时间范围和 `idx_usage_logs_account_created_at` 的账号时间范围，与账号主键连接后按会话排序；不得只读当前组成员。热启动先以 `LIMIT 200001` 的计数子查询限制 LAG/freshness 范围的原始用量行及错误事件展开量，再执行会话窗口和指标载入；freshness 聚合、错误展开或观测输出超限均整次回退，不静默截断历史。B1 在服务层限 2 小时，账号统计限 30 分钟，e_G 匹配有效单元后才限 100 条。

错误查询使用 `idx_ops_error_logs_created_at` 时间范围后展开 `upstream_errors`，按观测中的 OpenAI 账号及目标成员筛选、去重。事件账号不一定是错误主行最后的 `account_id`，不能仅依赖主行账号索引过滤。最新用量时间可由 `idx_usage_logs_created_at` 取得。

每分钟用量处理量是 OpenAI 6 小时行数 U6（若速率为 R 行／分钟，最多约 `360R` 行），会话排序约 `O(U6 log U6)`；错误展开量是相同时间范围错误行中尝试事件数 E6，去重约 `O(E6 log E6)`。不是“100 条查询”，也不扫描全部历史。未增加索引；部署规模下实际耗时和 EXPLAIN 需在获授权的验收环境核对，不能以小型集成测试证明生产容量。

## 状态机、分档与恢复

每个账号、每组、每维每分钟最多一票。连续两次越线才确立 `fail`，连续两次达标才确立 `pass`；中间带保留已确立状态并打断连续票，没有有效统计则为 `none` 并打断连续票。坏记忆按维独立保存：最后一次处于 fail 起两小时内，且尚未连续两次恢复到 pass。其他维度达标不能清除它。

| 质量档 | 条件 | 显示状态 |
|---|---|---|
| 2 | 任一维当前 fail | `failing`，不达标 |
| 1 | 无当前 fail，但无结论维有坏记忆；或严格模式下任一维无结论 | `retest`，待复测 |
| 0 | 其余 | 三维均 pass 时 `passing`，否则 `unknown` |
| 0，固定 | 旧固定账号 | `pinned`，显示实际维度状态 |

未启用组的 `OrderTier` 始终返回 0。账号离组后，从发现离组起保留状态两小时，期间重新加入沿用；超过两小时丢弃。重启时错误维和缓存维从最近 6 小时的库中事实热启动，首字维仍清空并重新学习；重放是单向近似，相对现状只会更接近在线，相对在线主要偏差偏乐观。热启动失败时退回原有空状态。普通组从 0 档未知开始，严格组从 1 档开始；首字维结论仍取决于实际流量与 B1／e_G 样本量。

`POST /api/v1/admin/accounts/:id/recover-state` 通过 `AccountRecoveryOptions.ResetGroupQualityGate` 写入 `accounts.extra.group_quality_reset_at`（RFC3339，含亚秒精度，JSONB 合并保留其他字段）。下一轮清空该账号各组状态与坏记忆，数据窗口截断在重置时刻，随后按从未测过处理。成功测试恢复和额度重置不写这个标记。

## 选号、迁出与利润门

启用组按硬准入、质量档 0→1→2、档内判慢后排，再按原档内规则排序。低倍率优先只决定档内次序，不决定门槛是否生效。高级调度按“质量档 × 判慢”分池，随机打散、缓存偏好和借用不能越池；共享调度只接入分档。详细规则见 [账号调度](account-scheduling.md)。

绑定号为 2 档或本模型正在判慢时可触发统一质量迁出；续链、WebSocket、指定传输、既有迁出保护和质量路由持有的绑定继续豁免。固定号不因质量降档，但判慢仍可迁出。

带协作或工具输出密文片段的请求同样不做软迁移：`input[]` 内的 `agent_message.content[]` 或数组形态 `function_call_output.output[]` 含 `type=encrypted_content` 时，适用与续链相同的迁出保护；reasoning／compaction 顶层密文不算。带这些片段的请求，P1-B 退回连击规则；硬准入与其他失败类改绑仍按原规则执行，详见[网关韧性](GATEWAY_RESILIENCE.md)。

目标必须通过硬准入、未判慢、有空位，并满足质量条件：

- 任何维当前 fail 的账号都不能成为目标，包括固定号。
- 普通组：首字预测有效且 `≤0.9X`；错误、缓存没有当前 fail，也没有有效坏记忆。
- 严格组：三维统计有效，预计 P90 `≤0.9X`、错误率 `≤0.8Y`、缓存点估计 `≥Z`；不额外要求两次 pass 投票已经完成，但当前 fail 尚未恢复的账号仍被排除。

目标按档内顺序选择并显式绑定；占槽失败保留原绑定。成功质量迁出后同组同会话冷却 5 分钟；P1-B、失败连击、同站暂停与硬冷却引起的失败改绑不受此限制。没有合格目标则保留原绑定；原号恢复后不会主动迁回。

利润门继续使用已有 `openAIProfitGateCost` 与分组利润上限，和质量门相互独立。OpenAI API Key 新鲜成本探测、OAuth 调度参考倍率、用户覆盖与高峰计价、槽位复核沿用既有规则。可服务数与兜底只按硬不可用、韧性软罚和利润门判断；2 档质量本身不触发无号兜底。跨平台成员资格及利润预览价格上限的计算不变。

## 管理接口与展示

权限沿用账号管理查看、分组管理查看／管理及现有审计：

- `GET /api/v1/admin/group-quality-gate/policies`
- `PUT /api/v1/admin/group-quality-gate/policies/:group_id`
- `GET /api/v1/admin/group-quality-gate/status?group_id=7`
- `GET /api/v1/admin/groups/:id/profit-control-preview?margin=0.2`

状态顶层为 `{generated_at, stale, groups}`。无 group_id 时只返回启用的活动 OpenAI 组；指定 group_id 时也可查询关闭的组，显示关闭及未知状态。组字段为 `group_id`、`enabled`、生效的 `policy`（即 v3 子对象）、`expected_p90_ms`（e_G，缺失 null）、`expected_samples`、`summary`、`accounts`。汇总分别计 `passing`、`unknown`、`retest`、`failing`、`pinned`，互不重叠。

账号字段为 `account_id`、`status`、`tier`、`pinned`、`latency_hold`、`ttft`、`error`、`cache`。三维都有 `state`、`value`、`samples`、`bad_until`；首字另有 `factor`、`sessions`，错误另有 `failures`，错误和缓存另有 `wilson_low`／`wilson_high`。首字 value 为毫秒预测，错误／缓存 value 为比例；无数值为 null，未达样本门槛不会显示达标。`bad_until` 是最后 fail 加两小时，有效坏记忆不存在时为 null。

`latency_hold` 提供仍在让位的模型列表与最晚到期时间 `{until, models}`；未接入查询或没有有效让位时为 null。到期只移除让位标记，不显示“已恢复”。`SetLatencyHoldLookup` 由装配层接入判慢查询。`ExpectedP90Ms` 为调度提供 GM30 × e_G 的整数毫秒预测，缺少任一值则不可用；`MigrationTarget` 只返回目标的质量条件，硬准入与槽位由选号负责。

利润预览保持 `{members, schedulable, passing, ceiling}` 形状：成员总数、可调度成员数、其中通过利润门的成员数、价格换算上限。`passing` 与质量门槛无关，不按质量状态或固定账号标记计数。margin 仍为 `[0,1)`，省略用保存值，预览安全缓冲为 0，不保存配置。

## 事件与验收

事件使用 Warn，写入 `ops_system_logs`（`message` 为事件名，字段在 `extra`）。队列满时可能丢事件，计数是下限；多实例分实例统计。

| 事件 | 时机 | 字段 |
|---|---|---|
| `group_quality_gate.tier` | 已有前一成员快照时，每次组内档位改变；首次评估不记 | `account_id`、`group_id`、`from_tier`、`to_tier`、`dimension`、`value` |
| `group_quality_gate.migrate` | 每次成功质量迁出 | `session_hash` 前缀、`group_id`、`from_account_id`、`to_account_id`、`trigger`（`tier`／`latency_hold`） |
| `group_quality_gate.last_resort` | 既有末位兜底 | 沿用既有字段 |
| `group_quality_gate.evaluate_failed` | 每个连续陈旧或失败期间首次 | `reason`、`stale_duration` |

旧的硬熔断、退避、观察期、快档记忆、六小时快档重测和质量保底逻辑及其专有事件已退役。每日质量迁出按事件统计，判慢触发单列；档位分布结合状态接口与事件分析。首次评估只建立快照，不记档位变化事件；热启动重建错误维和缓存维，首字维按进程启动分段，非固定账号在普通组从 0 档、严格组从 1 档开始，固定账号始终为 0 档。需要清除错误/缓存坏记忆时使用已有 `recover-state`。

本批次不提供“本组样本不足占比”和“无合格目标占比”的直接计数。前者用 `usage_logs` 按 e_G 的窗口、严格续轮和当前 B1 匹配规则离线重算；后者按 `group_quality_gate.tier` 与 `openai_account_latency_hold_started` 事件重建档位和判慢状态，作离线近似。事件不包含当时的全部目标资格和空位，近似结果不能视为线上实际无目标比例。判慢及急性保护事件见 [网关韧性](GATEWAY_RESILIENCE.md)。

## 升级与回滚

迁移 289 为 `usage_logs` 添加可空 BIGINT `attempt_first_output_ms`，无缺省、无索引、不回填；ALTER 需短暂表锁，按低峰执行。v3 与写入新列的代码、设置和前端同版上线。参数在 [部署 runbook](../deploy/README.md#门槛-v3-升级与回退) 设置；上线后 48 小时核对新列非空率（OpenAI 成功流式目标 ≥95%）、与端到端首字／判慢样本的差异、档位分布与迁出数量。生产核对必须另行授权。

旧策略字段不被新版写入，因此回滚到 0.5.1 时仍用原 v2 配置；旧版忽略 v3 子对象与新列，列可保留。只建立过 v3 的组在旧版视为未启用；旧版保存会丢弃 v3，再升级时重新按“没有子对象”继承。低倍率优先若设为指定分组，回滚前先决定旧全局开关。关闭新版组门槛立即让该组回到无质量档排序；P1-B 与同站暂停分别用韧性开关回退。按版本回滚的验收线及七天对照见 [v3 tasks](../openspec/changes/group-quality-gate-v3-20261104/tasks.md)。
