# 设计：客户服务（悬浮在线客服 + 工单整合）

## 产品形态

一个客服中心，两种通道：在线客服（新）和工单（现有，基本不变）。

| | 在线客服 | 工单 |
|---|---|---|
| 用途 | 随时问、快速答 | 需要排查、跟踪的正式问题 |
| 结构 | 每个用户一条长期会话，无标题和分类 | 一个问题一张工单，有标题、分类和状态 |
| 内容 | 文字 + 图片 | 纯文字 |
| 结束 | 客服标记已解决后移出待办，用户再发消息自动重开 | 关闭后需要重开 |

- 用户：全站气泡（可拖动、自动靠边、默认右下角，位置按设备记忆），面板分「消息」「工单」；菜单「客户服务」打开 `/support-tickets` 中心页。气泡角标 = 客服新回复 + 工单未读。
- 访客：看得到气泡，面板显示固定欢迎语、`contact_info` 和登录／注册入口，不调用需要登录的接口。
- 客服（管理员和获授权的普通管理员）：`/admin/support-tickets` 分「会话」「工单」；收件箱按等待开始时间排序；可回复（含图）、标记已解决、撤回客服消息、删除用户消息、删除会话、禁止发消息。收件箱里每条客服消息显示用户是否已读。
- 双向撤回与身份：用户发出 2 分钟内可撤回自己的消息（数据库时钟判断，迁移 288 允许 `deleted_by_role='user'`），撤回后若没有剩下的未回复用户消息则结束等待；客服撤回客服消息不限时（沿用删除接口，与作者同侧即标为 `recalled`）。用户只看到「客服 #账号 ID」（`staff_id`），接口不给用户客服名称、邮箱和客服读游标（`peer_read_message_id` 恒为 0）。后台提醒为角标、标题前缀 `(N)`、可选提示音和桌面通知。管理员和普通管理员不显示气泡。
- 开关：`support_ticket_enabled`（客户服务总开关，控制菜单、页面、工单）与 `support_chat_enabled`（在线客服，默认关闭，控制气泡和聊天）同时打开才有聊天。

## 关键决策

1. **聊天单独建表。** 工单有标题必填、四种状态、关闭拒收、200 条上限和 `xy-support-tickets` 钉住的测试与 literal；把聊天塞进去需要改已发布迁移的 CHECK 和大量分支。统一的收件箱与角标在前端合成。
2. **沿用权限模块 `support_tickets`。** 改 key 会让已保存的普通管理员权限失效；只改展示名为「客户服务」。查看权限读会话，管理权限回复、标记已解决、删除、禁言。
3. **自适应轮询，不做 WebSocket/SSE。** 用户 JWT 只接受 Header；长连接绕过逐请求的令牌、开关和用户状态校验，在线更新重启时也要排空连接；生产 CDN 行为不在仓库内。人工客服约 3 秒送达足够。
4. **图片存 PostgreSQL。** 现有 `ImageStorage` 与异步生图共用总开关，链接是公开或 24 小时预签名；本地磁盘不在备份内。代价是图片进入数据库备份，用保留天数控制。
5. **命名统一 `support_chat_*`。** 避开 `chat/completions`、`live`、`realtime`、`session`、`conversation`、`messages` 等已被网关或 Codex 占用的词。

## 数据与并发

- 迁移 287：`support_chats`（每用户一行；`waiting_since`、最近消息 id、读游标、`revision`、`content_version`、禁言字段）、`support_chat_images`（BYTEA，可清理；`(chat_id,id)` 唯一，消息以复合外键引用同会话图片）、`support_chat_messages`（`author_role` 含预留的 `bot`、`client_msg_id` 幂等、删除墓碑）。
- **顺序约束**：所有插入消息的事务先锁会话行（`lockSupportChatRow`），再取消息 id，使 id 顺序等于提交顺序，`after_id` 轮询不漏消息。用户路径先取每用户的 advisory lock，再用 `INSERT … ON CONFLICT DO UPDATE` 懒创建并锁行。
- **等待队列**：用户消息设置 `waiting_since = COALESCE(waiting_since, NOW())`，客服回复和标记已解决清空它；system 消息不改它，bot 消息不清空它。待回复 = `status='open' AND waiting_since IS NOT NULL` 且用户未删除。
- **读游标**：`GREATEST(cur, LEAST(n, last_message_id))`，只进不退、不越界；GET 不顺带标记已读。
- **标记已解决** 带 `last_seen_message_id`，期间有新的用户消息时返回 409，避免把未回复的消息藏起来。
- **幂等**：同一 `client_msg_id` 重发返回原消息（`duplicate: true`），不再计入限流、不重复存图。

## 轮询与审计

- 用户：聊天可见时 3 秒，2 分钟无新消息降到 8 秒，后台标签页停止；面板收起时角标 60 秒刷新（用户刚发过消息的 10 分钟内 15 秒）。一次请求返回消息、对方读游标、状态和未读数。
- 客服：只轮询 `GET /admin/support-chats/summary`（只有计数，不审计）；`version = SUM(revision)` 变化才拉列表和会话。提醒以 `latest_user_message_id` 增大为准，多标签页按用户去重。
- 审计：列表、详情、消息和图片读取都是敏感读取；增量消息轮询没有新消息时跳过审计；读游标上报跳过审计；两个发消息接口不记录请求体。现有工单审计不变，工单 summary 仍被审计，所以提醒不调用它。

## 图片

- 前端：先画到 canvas（去元数据、按 EXIF 摆正），长边 ≤ 2560；PNG 重编码 ≤ 1 MB 保留 PNG，否则 WebP 0.85（浏览器不支持则 JPEG 白底）；超过 1 MB 逐级降质再缩小。
- 后端：按 magic bytes 判定 jpeg/png/webp，读头部尺寸；单张 ≤ 1.5 MiB、边长 ≤ 4096、像素 ≤ 16.7M；请求体 ≤ 2 MiB。`content_type` 以识别结果为准。返回头含 `nosniff` 与 `CSP: sandbox`，已清理或已删除返回 410。
- 清理：leader 锁定时任务读取配置（开关关闭也清理，读配置失败则跳过本轮），按批把超过保留天数及已删除用户的图片置空。

## 限流

用户每分钟 20 条、每天 300 条；每天 30 张图、合计 20 MiB；客服不限。被禁言的用户发消息返回 403，提示改用工单。

## 不在本期

SSE 推送、正在输入与客服在线状态、常用回复、会话转工单、多客服分配、邮件或 Telegram 提醒、AI 首答、工单图片、访客匿名聊天、全站图片总量预算。
