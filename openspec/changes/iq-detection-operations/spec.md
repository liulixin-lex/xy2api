# 检测执行与展示规范

## 状态不变量

- 评分 status、执行 execution_state、新鲜度 freshness 相互独立。延期不是作答失败；过期不是新评分。
- 仅 enabled=true 且 status=degraded 阻止质量调度；其他人工、健康、配额限制保持独立。
- pending 是数据库预留，running 必须已经提交开始事务。只有提交开始事务才占一次预算和一条记录。
- token 不匹配、started_at 非空的延期请求不得释放当前任务；started_at 非空的重复启动不得再发送。
- 未开始的已过期租约或旧 revision 不得进入开始事务；释放后按当前配置排队，保持原预算和冷却。
- 仅保留最近三轮实际开始的任务；等待重试不挤掉历史。
- StartIQCheck 在账号行锁内复核 overload_until、rate_limit_reset_at、temp_unschedulable_until；领取后新增的健康冷却仍须阻止启动，等待期间不预占账号或共享预算、不创建记录。多个冷却取最晚到期时间。
- 同一事务复核API key账号的总、日、周业务额度；人工状态、账号/共享组冷却、预算同时存在时保留最晚可执行时间。DeferIQCheck不得用较短重试覆盖账号已知的上游冷却或预算下限。

## 繁忙调度

设账号上限 C、有效占用 U。按用户最终要求，尽量使用已有空闲容量，取消额外预留一个名额和等待三次后升级的规则：

| 条件 | 检测允许获取的上限 |
| --- | --- |
| C > 0 | C |
| C <= 0 | 沿用原有无限制语义；数据库每账号单租约仍有效 |

直接调用既有Redis原子AcquireAccountSlot，以包含普通/Live槽位的实际容量作准入，不再额外预读占用。有限额账号的Redis获取失败返回concurrency_unavailable，不当作账号繁忙。C<=0沿用不占槽的无限制语义。

原子获取因满载失败时，在本次领取内等待250、500、1000毫秒后再次尝试，合计最多4次获取、额外等待1.75秒（不含Redis调用耗时）。成功即启动；取消立即终止等待；Redis错误立即结束。只有持续满载才写入一次繁忙延期，等待尝试不创建检测记录、不扣预算。

连续繁忙延期以数据库同token未开始事务自增，最多1000，仅用于记录页诊断，不决定准入容量；重复回调不重复增加。持续满载的下一轮为now + 随机[15,30]秒，15秒扫描会增加离散等待。健康短冷却按实际最晚到期时间返回，不强行增加到一分钟。Retry-After、最小间隔、日预算和共享组约束保持有效。

### 场景：有余量的高并发账号

WHEN C=10、U=1、预算及健康通过 THEN 一次开始事务、一条记录、一个检测请求，完成后释放名额。

### 场景：小并发仍有空位

WHEN C=2、U=1 THEN 无需累计延期次数，立即允许原子竞争第2个名额。WHEN 前两次获取满载但随后释放 THEN 同一领取内启动，不记录account_busy延期。

### 场景：满载与竞争

WHEN 有界等待后原子获取仍因满载失败 THEN 无上游请求、预算不变、历史不变、评分不变，并记录account_busy。

### 场景：缓存故障

WHEN 有限额账号的Redis获取失败 THEN 无请求，原因concurrency_unavailable，不能显示为账号繁忙。

### 场景：失效与重复任务

WHEN 配置已改变且任务未开始 THEN 释放自己的旧预留，按当前 revision 排期；WHEN 已开始或 token 不同 THEN 保持租约。WHEN 租约已过期 THEN 拒绝开始，无预算或记录增加。

## API

新增 GET /api/v1/admin/accounts/:id/iq-check，沿用管理员认证，返回 IQCheck.Summary()；剔除 revision、lease_token 和 lease_until，不返回账号凭据。非法 ID/平台返回现有错误，账号不存在沿用仓储错误。

新增 summary 字段 busy_deferrals?: number，旧账号未保存时默认为 0。原 GET results 继续返回数组；不改已有 API 响应结构。GET 状态和 GET 记录分开拉取，并不构成数据库一致性快照；执行中的跨请求时间差通过后续轮询收敛，UI 不据此更改服务端评分。

## 前端

账号列表一行显示：蓝色启闭开关 + 聪明/降智/未知；关闭显示未开启。评分按钮直达记录。运行中显示刷新图标，暂停显示提示图标，过期显示时钟；不在列表输出执行说明、原因和绝对时间。

记录页优先显示当前执行状态和原因、最近检测、下次可执行、UTC 当日剩余次数；繁忙时显示连续等待次数。下方按实际开始时间倒序展示三轮评分、答案、模型、深度及耗时。原文和诊断默认折叠。暂停/关闭不显示误导性的下次时间。

只在弹窗打开时轮询：running/pending 每 5 秒，其余每 15 秒；页面隐藏时暂停网络轮询。关闭/切换取消读取，迟到结果不得覆盖新账号。刷新失败显示明确错误并保留历史；手动排队阻止重复点击，返回最早时间而不是保证立即执行。诊断下载必须完成浏览器文件落盘并能解析为 JSON。

记录弹窗使用异步组件，仅选择账号打开记录时加载和挂载，关闭后卸载并清理轮询。账号列表首屏不静态加载记录详情模块。

桌面与 390px 宽屏幕不得水平溢出，控件支持键盘与可见焦点，状态不只依赖颜色。沿用现有 Vue、BaseDialog、Icon、表格和颜色系统。
