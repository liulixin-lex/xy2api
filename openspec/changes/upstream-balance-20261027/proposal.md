# 账号页「上游余额」列

## 背景

管理员在账号管理页看不到每个上游 API Key 账号还剩多少钱，只能逐个登录上游网站查看。这些上游基本是 sub2api（含 XY2API）与 new-api：

- sub2api 的 `GET /v1/usage` 只用 Key 就能读到余额；
- new-api 只用 Key 能读到 Key 剩余，钱包余额需要访问令牌。

现有的 CN 余额检查有两个问题：

- 不区分接入地址，中转的 Kimi Key 会被发到 Moonshot 官方的余额接口；
- 对中转账号也按官方余额停调度。

用户 2026-10-27 批准方案，要求：

- 每分钟刷新；
- 只用 Key 最好，需要额外凭据时在添加账号时填写；
- 不收集密码。

## 变更内容

1. 后台每分钟采集一次符合条件的 API Key 账号的上游余额：
   - 只存 Redis，不写 `accounts` 表、不触发调度事件；
   - 全集群每分钟只有一个实例采集。
2. 自动识别上游类型：
   - sub2api：读 `/v1/usage`；
   - new-api：读 billing 两个接口，填了访问令牌时另读 `/api/user/self` 的钱包。
   - 口径分为钱包、Key额度、订阅。
3. 新增只读接口 `GET /api/v1/admin/accounts/upstream-balances?ids=`，只读缓存，绝不触发上游请求。
4. 账号页新增「上游余额」列，默认显示，页面每 30 秒读取一次：
   - 超过 3 分钟未更新且之后有失败时变灰，超过 10 分钟一律变灰；
   - 悬停显示口径、原因与更新时间。
5. API Key 账号新增凭据字段：
   - `newapi_access_token`：敏感字段，返回时脱敏，`null` 清除；
   - `newapi_user_id`。
   - 创建与编辑弹窗增加可折叠小节「new-api 钱包余额（可选）」。
   - 站点变化时，已保存的令牌由后端删除。
6. 接入地址不是官方域名的 kimi、deepseek 账号：
   - 不再走 CN 余额检查与渠道监控的 CN 余额查询；
   - 用量列里的 CN 余额子单元格隐藏，余额改由新列显示。

## 兼容与回退

- 不新增迁移和设置项。Redis 键在 48 小时内自然过期。
- 回退到旧版本前，要先清除所有访问令牌。旧版本不认识 `newapi_access_token` 是敏感字段，会在接口中原样返回。
- 回退后，中转的 kimi、deepseek 账号恢复由 CN 余额检查探测。

## 不做

- 不收集上游用户名和密码，不做自动登录。
- 不存余额历史，不画曲线。
- 不新增开关、阈值告警或按余额停调度。
- 运维监控错误详情里可能出现的上游地址不在本变更处理。
