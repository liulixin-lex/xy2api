# 输出后失败尝试补记与归因修正

HTTP 流在向客户端输出内容后发生读流出错、缺终态或停滞时，快层可能已确认账号失败，运维记录却缺少该次上游尝试。分组质量门槛与份额健康因而漏读软失败，门槛还可能把同请求用量算成成功；缺少上游上下文的错误也可能归为平台内部。

0.5.1 在快层确认失败后保存事实，在运维记录归因前补齐缺失的尝试。每次实际发送建立去重边界，同号重发也独立判断；已有本次同账号事件时保留原类别。补项只作证据，不重复惩罚、不改变计费或最终状态码。归因随上游上下文修正，指标与列表的口径变化见 [design.md](design.md)。

不新增开关、迁移或部署前提；不修改门槛与份额调度阈值、快层判据，不补记 WebSocket 或回填历史。规格见 [spec.md](specs/gateway-resilience/spec.md)，任务见 [tasks.md](tasks.md)。
