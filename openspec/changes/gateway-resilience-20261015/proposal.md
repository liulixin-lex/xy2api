# 网关韧性：重试、调度、判定与保活的上线级优化（xy2api 0.4.0 + XY-image 0.0.17）

## 背景

2026-10-15 对生产做了只读分析，数据窗口为 48 小时，另加 25 分钟实时抓取。完整证据见 [`evidence/production-analysis.md`](evidence/production-analysis.md)。数据库、Redis 与主机资源始终健康。影响用户体验的主要是网关自身在重试、调度、判定和保活上的缺陷，不是上游。

- **CDN 切断：首包前没有任何输出。**
  - 阿里云 ESA 原为 90 秒，已调为 300 秒；Cloudflare 固定 125 秒（非企业版不可调）。网关从选号到收到上游响应头的整个阶段，不向客户端写任何字节，约 2% 的 API 请求因此被切断。
  - 被切断的请求里，有相当一部分网关仍跑完并计费：2 小时样本 43 次，实时 25 分钟 16 次。
  - `response_header_timeout` 为 600 秒，首输出超时未开启，坏账号在 CDN 切断之前不会被放弃。
- **余额不足导致整组无号。**
  - Anthropic、Grok 等平台的中转账号第一次返回 403“余额不足”就被永久置错，Claude Max 组因此出现 9 次整组无号，最长 1.5 小时，每次都靠人工恢复。
  - 429 正文实为余额不足时，只按限流冷却 2 秒，真实请求被反复拿去试探。
- **失败尝试代价高、换号慢。**
  - API Key 账号遇到上游 5xx/524/超时不冷却。单次失败尝试的 P50 为 60–125 秒，换号后成功的请求 P50 约 95 秒。
  - Gemini 在同一账号上原地重试 5 次（退避 1–16 秒）。
- **流内失败不换号，会话又粘回原账号。**
  - 中转上游先回 200，33–105 秒后在流内发出“忙”或“限流”。此时已有输出，网关只能透传失败。
  - 粘性会话又把 Codex 的重连送回同一账号，同一会话在 8 分钟内连续失败 9 次。
  - 上游中途停住时，Codex 自身的 300 秒空闲计时先触发。
- **错误语义引发重试风暴。**
  - “无号”503 不带 `Retry-After`，Codex 一个失败回合约产生 30 次请求。
  - 单号组被摘除后，一个客户端 2 分钟内重试了 141 次。
- **“余额不足”误报。** 用户看到的“余额不足”几乎都来自本站计费：
  - 约 500 次（48 小时）是余额为正、只是在途预留之和超过余额，被直接拒绝；
  - 真正泄漏的上游余额错误只有 4 次。
- **现存缺陷（源码确认）。**
  - 流间隔检测的 ticker 周期等于阈值，实际在 T 到 2T 之间才触发（G2）。
  - Anthropic 心跳后的错误帧缺少 `event: error`，SDK 会静默丢弃（G3）。
  - 心跳先写出后，暂存的账号响应头（含 `x-codex-turn-state`）丢失（G8）。

生态调研覆盖 36 个精选项目和 349 个候选项目，另有 new-api、LiteLLM、Portkey，以及 Codex、Anthropic SDK 源码。借鉴点与许可证约束见 [`evidence/research-summary.md`](evidence/research-summary.md)。上游 Sub2API 在 v0.2.15 之后没有对应修复，本次改动全部是 xy2api 自有补丁。

## 变更内容

按能力分为 8 个规格，详见 `specs/` 与 [`design.md`](design.md)：

1. **上游失败分类**（`upstream-failure-classification`）
   - HTTP 应答、流内 `failed`/`error` 事件、网络错误、本地超时统一归入一套类别：余额、凭据、限流（有或无重置时间）、忙或容量降载、瞬时 5xx、首输出超时、停滞、客户端取消、客户端错误、内容策略、上下文超长、模型不支持。
   - 每个类别决定三件事：是否换号、是否同号重试、账号罚则是硬还是软。
   - 上游余额与本站用户余额严格区分。
2. **账号罚则与余额恢复**（`account-penalties-and-balance-recovery`）
   - 罚则分为硬、软两类。
   - 余额不足走可恢复状态机：正常、疑似、耗尽、恢复中。（2026-10-17 晋级前精简：改为暂停 `balance.pause_seconds` 后由真实请求重试，取消状态机、探测与余额告警，见 design §3.2。）
   - 探测方式：sub2api 系 `GET /v1/usage`（不消耗推理）、new-api 系兼容接口（上线前实测）、1 Token 生成探测（有日预算）。
   - 半开逐步恢复，管理员可点“已充值”立即复检。
   - 非 OpenAI 平台的 403 改为与 OpenAI 一致：计数加临时冷却。
3. **会话失败处理与末位兜底**（`session-failure-handling`）
   - 单次瞬时失败保留绑定，只临时溢出。
   - 10 分钟内同一会话在同一账号失败 ≥2 次，或出现确定性状态，才在同层按权重改绑。
   - 份额调度分组复用其 `soft_spill`/`spill_rebind` 语义；原版调度实现同义的最小规则。
   - 层级、优先级、权重只由管理员决定，自动机制只做临时跳过或排除。
   - 只剩软罚账号时取罚期最短者兜底，不再因软罚返回“无可用账号”。
4. **无号兜底分组**（`availability-fallback-group`）
   - 新增分组字段，只在“组内无可用账号”时转投一次兜底组。
   - 同平台、环检测，按兜底组计费并对用户可见。
   - 主组连续健康 120 秒后切回。
5. **请求预算与重试**（`request-budget-and-retry`）
   - 每个请求一份预算：最多 4 次上游尝试；文本请求首输出前总时长不超过 240 秒（低于 Codex 的 300 秒）。
   - 同号重试只用于请求级容量降载和池模式配置码，每账号最多 1 次；Gemini 原地重试从 5 次降为 1 次。
   - 客户端断开时立即停止所有等待。
6. **首包前保活、首输出超时与停滞判定**（`pre-output-keepalive`）
   - 只对经 CDN 进入的流式请求生效（Caddy 按回源 IP 注入 `X-XY-Edge`）。
   - 通过鉴权、计费、参数校验与选号后，15 秒内仍无上游响应头，才提交 SSE 头并每 10 秒发一次心跳。
   - 心跳格式：OpenAI 用注释行；Anthropic 用 `event: ping`；Gemini 不发，也不提前提交；选中官方 OAuth 账号时不提前提交。
   - 首输出超时分档：默认 60 秒，high/xhigh 120 秒，max 180 秒；最后一个候选不设单次超时。（2026-10-15 按生产 7 天首字分布校准为 default/high 180 秒、xhigh 200 秒、max 220 秒，见 design §7.4。）
   - 已输出后停滞 120 秒判定为断流，按 5 秒粒度检查。
   - 已输出后的失败按协议写可重试的终止帧，并立即关流。
   - 图片端点与异步图片任务豁免。
7. **客户端断开与计费**（`client-disconnect-and-billing`）
   - 一个语义字节都未送达就断开：立即取消上游，不写用量、不计费，另存一份运营可见的“未送达记录”。
   - 部分送达后断开：最多再读上游 180 秒，按已得到的用量计费。
   - 同一 Key 每小时首输出前断开超过 30 次，之后的此类断开按上游成本计费（防滥用）。
8. **错误语义与防风暴**（`error-semantics-and-storm-protection`）
   - 状态码保持不变。
   - 无号 503 带 `Retry-After`（2–30 秒）；配置类 503 带 `Retry-After: 60` 与 `x-should-retry: false`；全部限流的 429 也带 `Retry-After`。
   - 无号结论负缓存 2 秒。
   - 同一 Key 30 秒内出现 ≥10 次相同的 503，原样快速返回，不再执行选号和内容审计。
   - 异步图片先做准入检查，再做内容审计。
   - 上游余额问题只给管理员看。
   - 用户自身余额不足统一为 403 `INSUFFICIENT_BALANCE`，并换用本站专用文案（2026-10-17 用户要求文案保持 0.3.0 原文 `Insufficient account balance`，见 design §9.5）；在途预留超额改为 429 加 `Retry-After`，并改进预留估算。

配套：修复 G2、G3；增加可观测性，包括断开阶段、未送达、切断率、预算耗尽、快速失败、余额状态（随余额精简取消）、兜底使用；管理后台新增“网关韧性”设置卡与运维面板；新增 runbook 与预上线验证方案。XY-image 0.0.17 的配套改动见 [`xy-image-appendix.md`](xy-image-appendix.md)。

## 非目标

- 不改配置类错误的 HTTP 状态码。定价限制、仅限 Claude Code 维持 503，只增加重试提示头。
- 不做同源（共享额度域）联动，不做按 Key 的有序多分组，不做 reasoning 暂存。
- 不给 API Key 账号做通用健康熔断与降权，份额调度也不启用纠偏。这些属于 P2，只给进入条件（见 tasks 第 15 节）。
- 不做灰度阶段：开发完成后在测试服务器完整验证，再提 PR、发版。
- 不向 Sub2API 官方仓库提交任何改动。
- 未经用户单独授权，不推送、不合并、不发版、不部署生产，不修改 DNS。

## 已定稿的决策

以下决策由 2026-10-15 与用户的逐轮访谈确定。“推荐”指用户明确选择按推荐方案或调研方案执行。

| 编号 | 问题 | 决定 |
|---|---|---|
| D1 | 规划范围 | P0 与 P1 做到可上线（实现规范、测试门禁、回退）；P2 只给进入条件与粗设计 |
| D2 | 零字节未送达的计费 | 立即取消上游，不向用户计费 |
| D3 | 何时提前提交 SSE 头 | 通过鉴权、计费、校验与选号后，15 秒内仍无上游响应头才提交并开始心跳；只对流式请求 |
| D4 | 会话失败处理 | 分级处理：单次瞬时失败保留绑定、临时溢出；10 分钟内同一会话同一账号失败 ≥2 次，或出现确定性状态，在同层按权重改绑；并发满、TTFT 抖动、客户端错误不改绑；不改层级与权重；复用份额调度语义；阈值可配，Explain 可见 |
