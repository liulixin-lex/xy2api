# 普通管理员角色与逐人权限

## 背景

后台只有一种管理员，进了后台就拥有全部权限。运营者想让别人帮忙处理账号、用户和订单，就只能交出全部权限，包括：

- 加减余额、改价格、退款、生成兑换码等资金操作；
- 导出业务数据；
- 上游地址、代理与密钥；
- 系统设置、支付配置与备份。

用户 2026-10-27 批准方案，要求：

- 新增「普通管理员」角色，权限分「查看 / 管理」两级，逐人勾选；
- 在用户编辑弹窗里设置，不新建管理员管理页；
- 涉及资金或数据外流的操作各有单独开关，默认关；
- 账号页「点击账号名称跳转到上游网页」也是一个开关：关时不显示上游地址、不能跳转，开时才显示并可跳转；
- 界面上每行一个简单控件，放在它所影响的那一行，用“开：… 关：…”一句话说明，不加多余开关。

## 变更内容

1. 角色与存储：
   - `users.role` 新增取值 `operator`，不改 `users` 表与 ent schema；
   - 迁移 `282_admin_operator_permissions.sql` 新建表 `admin_operator_permissions`，每个普通管理员一行 JSON。
2. 权限模型：
   - 17 个模块，各取「无 / 查看 / 管理」之一；
   - 5 个开关：`users.balance_adjust`、`orders.refund`、`redeem_codes.issue`、`data.export`、`accounts.upstream_address`，默认关；
   - 系统设置、支付配置、凭据导入导出、插件、证据删除等标为只有超级管理员能做。
3. 权限目录与中间件：
   - 每条经过后台鉴权的接口（509 条，含 payment 管理组、`/api/v1/pages`、WebSocket 与下载票据）登记为一行，写明模块、级别、开关、目标规则、字段规则与脱敏；
   - 新中间件 `AdminPermission()` 按目录检查，未登记的接口一律拒绝。
4. 规则：
   - 目标保护：普通管理员只能操作普通用户，不能操作管理员、其他普通管理员或自己；
   - 字段规则：资金、价格、账号放置、角色字段需要对应开关或被拒绝；
   - 账号凭据：修改网络设置时重填全部已保存密钥，OAuth 类账号的网络设置只有超级管理员能改；
   - 脱敏：API Key、代理密码、请求头、兑换码，以及没有开关时的上游地址与错误详情。
5. 角色保护：
   - 最后一个管理员保护与不能给自己降级扩展到“从 admin 改成任何其他角色”；
   - 任命或撤销普通管理员、修改权限需要二次验证，权限的前后差异写入操作日志。
6. 新接口：
   - `GET /api/v1/admin/me/access`，不受合规确认拦截；
   - `GET` / `PUT /api/v1/admin/users/:id/operator-permissions`，只有超级管理员能调用。
7. 其他调用点：
   - Backend 模式下普通管理员可以登录；
   - 管理端导出的下载在下载时复核权限；
   - 渠道监控 v2 对有渠道查看权限的普通管理员显示管理员视图；
   - 运维监控实时 QPS 连接每 30 秒复核权限。
8. 前端：
   - 权限 store、路由守卫、侧边栏与命令面板过滤；
   - 只读页面隐藏写操作入口，403 时刷新权限；
   - 用户编辑弹窗的权限表；
   - 普通管理员的合规确认。

## 兼容与回退

- 超级管理员的行为不变，`/auth/me` 与 `/admin/settings` 的契约快照不变。
- 迁移 282 只新建表。回退步骤见 [`docs/ADMIN_PERMISSIONS.md`](../../../docs/ADMIN_PERMISSIONS.md) 的“迁移与回退”：
  - 先把普通管理员降为普通用户；
  - 删除新表，并删除 `schema_migrations` 中该迁移的记录。
- 本变更叠加在 PR-B（[`upstream-balance-20261027`](../upstream-balance-20261027/)，PR #158）之上：
  - PR-B 的余额读接口登记为账号查看；
  - PR-B 的 `newapi_access_token` 按已保存的密钥处理，修改网络设置时同样需要重填。

## 不做

- 不新建管理员管理页，不做权限模板。
- 不按账号或分组划分数据范围：账号查看可以看到全部账号。
- 不加连接时的公网 IP 检查，地址只在保存时检查（后续加固）。
- 运维监控错误详情中的上游地址不脱敏。
- 账号模型映射、分组模型路由与组合路由不加开关。
- 不处理上游的 `adm_sc_` 范围化 Key。下次同步引入时再定，至少保证只有超级管理员能签发。
