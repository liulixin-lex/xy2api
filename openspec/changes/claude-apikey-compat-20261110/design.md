# 设计契约

## 配置

`extra.anthropic_compat_profile` 只接受 `off`、`claude_code_v1`，缺省关闭，仅适用于 Anthropic API Key。创建、编辑、批量和导入使用同一校验；旧页面未提供该键或提交 `extra:{}` 保留现值，显式 `off` 才关闭。其他 extra 字段的既有清空语义不变。

兼容模式与 `anthropic_passthrough` 互斥，受控请求头不得被矛盾覆写。账号身份种子由服务端创建、持久保留；DTO、导出不返回种子，新建/复制/导入不信任输入种子。实际调度快照和管理诊断读取同一配置。

显式批量 profile 修改要求目标集合完整；普通凭据和 extra 批量更新保留既有缺失 ID 语义，已加载的账号仍校验合并后的完整兼容配置，种子轮换仍由同次 SQL 按账号范围执行。

## 请求与身份

静态 profile 定义唯一，正式转发、账号诊断与计数共用。首版候选映射后模型为 `claude-opus-4-8`、`claude-opus-5-5`，与账号既有模型准入取交集；这是实现范围，不能代替具体供应商的能力验收。

每次尝试从逻辑原请求构造不可变计划：冻结 profile 修订、模型、beta、最终 system/tools、身份及凭据端点指纹。换号清理上一尝试的派生状态，不重置请求预算。

普通请求使用最小身份块、原分组 system、原业务 system；复用既有前缀保护。工具定义、调用配对、消息块和明确采样/输出参数保持，不复制 OAuth 默认参数、工具改名或业务提示词。

身份按已认证用户、网关 Key、上游账号和显式会话作用域派生。没有显式会话或已知签名来源时，使用请求级随机锚点；不凭相同开场文本合并会话。metadata 使用固定 legacy 格式；其他业务 metadata 字段保留。

原生 Messages 完整 CLI 旁路必须同时满足头、身份块和 metadata 结构一致且不需要任何新增兼容改写。已知 profile 签名的来源保护先于旁路，不以 UA 作为权限或信任凭据。

## 签名来源与完成边界

独立、跨实例持久的服务端 HMAC 根为来源索引生成键，按租户、网关 Key、块类型和 opaque 值区分。账号身份种子与索引根分工；不从上游 Key 或 JWT 派生。复用现有 security secret 原子初始化设施，不增加逐请求数据库读写。

Redis 只保存摘要键与账号/profile/模型/前缀/能力/身份锚点约束，不保存原始签名、正文或完整 metadata。批量校验请求内全部签名；混合、未知、失效或超限的历史不能新进入 profile。Responses 只识别现有明确标记的 Anthropic thinking envelope。

已知签名在选号前解析并固定原账号。账号不可用或索引暂不可用返回明确可重试状态，不能转给另一账号、普通 API Key 或 OAuth。profile 关闭及 CLI 外观不能绕过已知来源；本地来源索引不替代上游对消息前缀与签名的验证。

新适配路径不运行删除 thinking、签名或工具历史的修补。前缀或关键配置变化使旧历史明确不兼容，不重写历史继续。

只有完整成功响应才能原子登记本轮全部签名。流式以真实 `message_stop` 为必要结束条件，`message_delta.stop_reason` 不足以证明成功。暂存成功结束信号组合，登记成功后再发送原生与转换协议的成功终态；普通内容继续流动，不缓冲整段回复。

登记失败发送对应协议的错误，不重新请求模型、不切号、不作为供应商故障；真实 usage 按既有规则结算。客户端断开后在既有预算内排空到完整成功仍可登记。失败、截断或未完成响应不登记。

## 入口、观测与运维

Messages 支持原生对话、工具及来源可验证的签名续轮；Responses 仅支持既有转换可保留的能力；Chat 支持文本及普通工具，不承诺无法回传签名的思考续轮。计数使用相同 prompt 投影，移除生成专用字段，不伪造计数或 usage。

账号诊断从普通请求形态经过同一适配器，固定目标账号并报告实际命中和终态。旧 CLI 连通性测试与该诊断口径区分。日志保留实际入站 UA，只记录低基数决策/错误类与账号等已有标识，不记录完整 prompt、身份或认证头。

部署默认关闭。目标供应商按模型和入口完成有限合成验收后才接普通流量；回滚先摘除普通流量，等在途结束，再关闭 profile 或回退。此开发任务不执行生产配置或部署。
