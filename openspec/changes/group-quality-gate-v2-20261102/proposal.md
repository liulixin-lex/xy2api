# 分组质量门槛第二版：按用户可见首字判定、两档排序、限时观察与慢号迁出

0.4.16 上线的分组质量门槛在生产上暴露了四个问题：

1. **度量错了**：门槛读 `first_token_ms`，缺省口径（`openai_ttft_mode=semantic`）把中转站在思考期间发的保活空帧也算作首字。有的站点语义首字 p90 只有 2.5s，用户实际要等 14s，门槛把这类号当作快号；门槛组 15% 的续轮流量落在这类号上。
2. **无数据当作快档**：改绑时约四分之三的会话落到慢号或无数据号上。无数据号随后的用户首字 p90 约 20s，在各类里最慢。
3. **会话不离开慢号**：门槛组关闭了 0.4.9 的判慢迁移，只靠熔断改绑。首字介于快档线和熔断线之间的号，既不熔断，也不迁出。
4. **恢复卡住**：熔断到期后，账号因没有新数据而进入试用。试用要攒满 20 个请求才退出，却排在所有快档号之后，分不到流量，实测卡过 5 小时以上。手动恢复同样转入试用；账号菜单在只有门槛状态时也不显示“恢复状态”。

本变更做五件事：

1. **度量**：续轮首字改用端到端首字（`end_to_end_first_output_ms`，为 0 时回落到 `first_token_ms`）。用量记录的首字和 `openai_ttft_mode` 不变。
2. **两档排序**：
   - 快档 = 样本足够，且 p90 ≤ min(快档线, 组内最快 + 4s)；
   - 慢号归“其他”，档内仍按倍率排序；
   - 档位记忆：样本不足时 30 分钟内沿用上次按数据判定的档位，之后 6 小时内快过的排快档重新检验，否则归“其他”；熔断与恢复不清空记忆；
   - 不再有试用档。
3. **限时观察**：试用不再降档，前 20 个请求或 30 分钟先到为准结束；期间 2 次软失败仍会再熔断。手动恢复走同一路径，账号菜单在门槛熔断、保底保留或观察中时提供“恢复状态”。
4. **门槛组慢号迁出**：绑定号 p90 超过快档线，并且有快档成员此刻有空位时，解除绑定、正常选号。复用 0.4.9 判慢迁移的候选检查，不加冷却或新状态。
5. **可观测**：`guard_hold`、`last_resort`、新增的 `migrate` 事件为 Warn，写入运维系统日志；状态接口给出每组实时快档线。

不做：
- 全局切换 `openai_ttft_mode`；
- 新配置项、数据库迁移、门槛状态持久化；
- 迁移冷却、请求大小归一化、故障域；
- 影子期。
