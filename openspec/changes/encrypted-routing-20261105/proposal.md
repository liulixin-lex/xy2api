# 零中断的加密态与路由：空白占位、包装错误帧、状态类修复、forbidden 软冷却

本变更处理 0.5.3 中以下几类输出前中断：

1. **空白占位被当成输出**。部分中转站在真实输出之前先发一条只含空白的 assistant 消息。网关把它算作“已开始输出”，之后上游的任何失败都不能换号或修复，只能作为流内失败交给用户。
2. **包装错误帧被读错**。中转把上游 HTTP 错误包成流内帧（`event: error` + `proxy.upstream_error`，或 `response.failed` + `upstream_error`）。包装 400 被读成 502，有时整帧被当成输出。
3. **协作密文拒绝缺少槽位修复**。S2/S3/S4 标识会话或协作密文的状态类拒绝，并不证明密文的签发来源。既有 rs/cmp 修复未覆盖 amsg/fco 的目标密文槽位，单纯换号不能保证恢复。
4. **输出前的通用 forbidden 原样回 403**。空白占位回到输出前之后，直接写出的 HTTP 403 不提供与可重试流内失败相同的客户端恢复语义。

本变更一次发布，内容如下：

1. **空白占位不算输出**：逐事件暂存符合白名单的开场与纯空白文本，不把 refusal、非文本、未知或畸形载荷当作空白。遇到首个可见事件或通过既有守卫的成功终态时，按原序冲刷；只有开场与空白时发生失败则丢弃暂存。Chat/Messages 兼容转换在首次提交前同样暂存，之后照常转换空白。
2. **输出前心跳按客户端选择**：Codex 收到完整的 `event: ping` 事件（Codex 按事件重置空闲计时）；其他客户端仍收注释心跳，因为部分 SDK 要求首个事件必须是 created。
3. **包装错误帧**：严格校验两种已证实的形状，按“迟到的上游 HTTP 状态”路由，畸形帧按协议失败处理并计数。包装 401/403 命中请求级拒绝时按请求级终止，否则走 forbidden 软冷却；两种情况都不进入凭证处罚。
4. **M3 状态类修复**：符合资格的 OpenAI 原生与直通 Responses 遇到输出前的 S2/S3/S4 或包装 400 时，在既有有界修复规则下，把 amsg/fco 中目标密文槽位换成固定占位后同号重放；无法继续修复时回避当前号，最多换一次号，再失败则以可重试的形式终止。Bad 按组、会话、账号隔离；S4 对唯一点名且有合格引用的新槽位立即学习，S2/S3/包装 400 的批量学习须等上游接受派生请求。
5. **输出前流内 forbidden**：排除请求级拒绝后作为瞬时类换号。OpenAI API Key 账号在韧性失败处理启用且有结构化证据时记账号×模型软冷却，不停号、不计 403 连续失败；用尽时默认写可重试的 502，仍受通用回合封顶和客户端自身重试上限约束。
6. **最小计数**：`resilience.*` 结构化日志，用于验收和盯副作用，不记录密文。

不新增配置开关、迁移或 Redis 依赖，前端没有改动。行为说明见 [`docs/GATEWAY_RESILIENCE.md`](../../../docs/GATEWAY_RESILIENCE.md)，规格见 [specs/gateway-resilience/spec.md](specs/gateway-resilience/spec.md)，任务与验收见 [tasks.md](tasks.md)。

## 不做

- 钉号或偏好签发号，签发记录或索引；
- 对未命中当前拒绝或本号 Bad 的槽位主动占位，或额外主动剥离 rs/cmp；既有有界修复保留；
- 在既有有界开场暂存之外新增整响应缓冲、延迟真实输出，或为占位流单独设置首字超时；
- 影子模式、测试矩阵，把 Bad 放进 Redis；
- WebSocket、compact 的专用实现；Chat/Messages 与 WS HTTP 桥不接 M3；
- 明文默认生效与 conflict 修正、删除 P1-B 守卫读点、`sticky_bypass` 诊断。这三项后续单独处理。

## 已知差异（接受）

- M3 终止不计入通用的回合重试上限（turn cap）：未提交时写 HTTP 502，已提交时写 `response.failed` / `server_error`。这两种可重试形式仍受单请求预算和 Codex 自身重试上限约束。
- 包装 401/403 命中上下文超限时，未提交写 HTTP 400 `context_length_exceeded`。Codex 0.166 把它归为 InvalidRequest，不进入 ContextWindowExceeded，因此不保证本轮自动压缩恢复。
- 真实输出之后断流、所有候选都失败、首输出前总预算耗尽，这些情况仍会中断。文本请求的 `budget.pre_output_budget_seconds` 缺省为 240 秒（可配 60–290 秒）；空白占位回到输出前之后，真实首输出晚于该预算也会中断。`resilience.blank_placeholder_outcome` 记录这类请求的结局，作为是否调整预算的依据。
