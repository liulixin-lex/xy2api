# OpenAI智商检测的低负载、可诊断监测改进

状态：方案已形成，业务实现待后续执行。基于已发布0.0.9及本地OAuth协议修复；不把未部署修复当作生产现状。

目标是减少无效探测、避免检测与业务争抢资源，并保持用户确认的糖果题判据：明确答案21为聪明、明确其他数值为降智、无法取得可判定答案为未知。可以降低额外负载及提升故障可解释性；无法承诺OpenAI不会误判，也不设计伪造用户身份、掩盖自动化或绕过上游限制的机制。

当前存在可核实的问题：每个账号按固定周期重复同题；IQ租约只限制IQ任务之间的并发，未接入业务并发名额；失败统一按普通周期再次排队；手动运行可在上轮结束后不断追加；没有每日探测预算和清晰的等待/暂停原因；HTTP非200仅保留状态码，无法区分暂时限流与需人工处理的额度/权限问题。API key分支也复用了Codex探测头，需要按端点梳理。

计划新增：

1. 按真实协议和端点建立可审计请求配置；保留独立会话、简洁JSON、模型/思考深度配置和本地判分。
2. 共享业务并发名额、去重排队、每账号及上游配额组预算；检测优先级低于业务，服务器限流提示优先。
3. 保留默认固定间隔；提供显式可选的节约探测模式，稳定通过后15→30→60分钟，明确增加的发现延迟。
4. 把已完成的assessment、待运行/延期/暂停的execution以及原账号调度条件分开；等待没有新答案，不覆盖旧结论。
5. 补充有界错误码、用量与排期诊断；正文仍只留最近两轮，提供最近两轮的支持材料下载，不自动发送。
6. 以相同合成输入验证判分不变，以虚拟时钟和数据库/Redis集成验证预算、并发与退避；真实账号仅在后续获授权后小范围验收。

不新增题目轮换、伪装会话、模型裁判、故障后切换账号求正确答案或多次采样直到通过。保持原题才能维持当前判分含义；更全面的业务质量评测可另立离线项目，不能把其结论混进糖果题自动启闭。
