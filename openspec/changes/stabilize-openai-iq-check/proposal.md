# OpenAI 智商检测稳定性与自定义检测配置

状态：规划完成，业务实现待实施。基于 `main` / `dff987fb16d206e354a21bd4055987c2b5d73549`，当前产品版本为 `0.0.8`。

## Why

现有检测兼容 JSON、纯数字和解释文字，但外层 JSON 指令与题干末尾的纯数字要求冲突。答案提取使用最后命中的正则和浮点数比较，可能误判不确定答案、解释中的反例、重复 JSON 字段和精度边界。只修改检测间隔也会重置结果，导致原有降智限制被解除。

用户还要求在编辑界面的检测间隔旁选择检测模型和思考深度；模型可以从当前账号上游拉取，也可以手动输入。现有模型列表接口存在本地默认列表回退，模型同步接口还会持久化账号元数据，不能把它们直接当成无副作用的“该账号实际支持”查询。

## What Changes

- 统一题目与输出指令，优先请求简洁、唯一 `answer` 字段的 JSON；仍接受纯数字和明确结论的解释文字。
- 将答案提取与判分分开：明确答案为 21 时聪明，明确其他数值时降智；无法可靠提取答案、拒答或协议异常时未知，并显示具体原因。
- 保留单次判定。答错后不反复请求直到答对；未知仍解除检测自己的调度限制，人工、额度及其他限制保持有效。
- 编辑区同排放置“检测间隔 / 检测模型 / 思考深度”，移动端纵向排列；默认仍是 15 分钟、`gpt-6-astra`、`low`。
- 模型输入采用可搜索、可自定义的单选框，提供拉取按钮；真实列表、参考能力与手动输入标注来源。拉取失败仍能编辑和保存自定义模型。
- 思考深度优先展示该模型上游声明的选项；提供“上游默认（不发送参数）”。缺少能力信息时使用参考选项且不宣称支持，不静默降低深度。
- 修正修改间隔导致重置的行为；修改模型、深度或请求配置后，旧任务不得提交，立即按新配置重新检测。
- 记录显示统一的提取答案、判定原因和本轮模型/深度；原始回答保留在可展开区，每账号仍只保留两轮。
- 经验证支持结构化输出的组合可选择严格格式；默认兼容模式，不按 OAuth/API key 类型假定支持，不自动切换模型、深度或协议。

**拟变更的判定语义：** 当前“非空但无法解析”以及“21 还是 29”会被归入降智或误判聪明；新方案统一归为未知。明确回答 29 仍立即降智。未知按用户已确认规则交回原调度，不伪装为聪明。

**由最新需求替代的旧约束：** 模型与思考深度由固定常量改为每账号配置，`gpt-6-astra` / `low` 仅作为默认值。旧接口省略新字段时必须保留已有配置。

## Scope

本轮产出方案、设计、验收规格与任务清单，不实施功能、不调用真实账号、不发布新版本。后续实施继续使用仓库标准目录和追加式迁移。单题检测仍仅表示该题表现；模型与深度不同的结果应显示各自配置，不能当作同一条件的横向评测。

多次投票、连续两次确认后停用、未知时保留历史降智封锁、自动改模型重试，以及“继续检测但强制使用”均不纳入本方案默认行为。这些会改变已经确认的调度规则。

## Impact

改动集中于 `backend/internal/pkg/iqcheck/`、账号 IQ 领域对象/仓储/服务/DTO、模型发现公共逻辑、`frontend/src/components/account/IQCheckSettings.vue`、账号编辑与批量编辑、检测记录弹窗、类型和中英文文案。拟新增只读模型发现接口，不改变已有列表/同步接口的契约。
