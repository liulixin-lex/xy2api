# OpenAI IQ 检测改进验收规格

## ADDED Requirements

### Requirement: 每账号检测参数

系统 SHALL 在 OpenAI 编辑区的间隔旁提供模型与思考深度；模型可拉取或自定义，默认 `gpt-6-astra` / `low`，间隔默认15分钟。

#### Scenario: 自定义模型保存
- **WHEN** 用户填写不在目录中的合法模型 ID 并保存
- **THEN** 精确保存该 ID，后续检测使用它，不经过业务映射或改回默认模型。

#### Scenario: 深度省略
- **WHEN** 用户选择 `upstream_default`
- **THEN** Responses 不发送 `reasoning.effort`，Chat 不发送 `reasoning_effort`，记录显示上游默认；不得把该选项改成 `none`。

#### Scenario: 旧接口及列表开关
- **WHEN** 已有自定义模型/深度的账号收到仅含开关或间隔的更新
- **THEN** 保留已有模型、深度和格式设置，不因缺字段重置。

#### Scenario: 能力冲突
- **WHEN** 新选模型明确不支持当前深度
- **THEN** 表单标记冲突并要求选择有效值；不能静默降低深度。能力未知时允许自定义值并说明未知。

### Requirement: 只读模型发现

系统 SHALL 通过指定账号的认证和传输拉取上游模型，不将默认模型或映射别名伪装成已支持。

#### Scenario: 拉取失败
- **WHEN** 上游拒绝列表请求、返回空目录或网络失败
- **THEN** 展示准确状态；旧缓存有时间与过期标识；用户仍可手动输入，IQ 状态及账号配置不变。

#### Scenario: 模型元数据缺失
- **WHEN** 上游只返回 ID
- **THEN** 模型可选，参考深度与上游声明区别标识，不把参考档位视作账号能力证明。

#### Scenario: 切换账号与凭据草稿
- **WHEN** 弹窗切换账号或用户修改未保存的身份配置
- **THEN** 旧请求不能覆盖新表单；凭据草稿保存前不能展示旧配置列表为新配置实际支持。

### Requirement: 统一答案契约

系统 SHALL 仅发送同一道题及一致格式要求，不发送标准答案。严格输出参数 SHALL 使用对应协议位置，且不得限制答案只能为21。

#### Scenario: 相同答案不同格式
- **WHEN** 完整回答为 `21`、`{"answer":21}`、`{"answer":"21"}` 或明确答案21的解释
- **THEN** 均为聪明；界面显示提取答案21，原始文本保留原样。

#### Scenario: 明确错误
- **WHEN** 完整回答明确为29或其他不等于21的数值
- **THEN** 本轮立即为降智，不因文本含21而通过，也不重试直到答对。

#### Scenario: 有歧义或结构损坏
- **WHEN** 回答为“21还是29，无法确定”、重复 answer 键、损坏 JSON 或无答案
- **THEN** 为未知且给出原因，不从歧义/损坏文本猜测数字。

#### Scenario: 解释包含反例
- **WHEN** 回答明确答案21，随后仅以否定/反例讨论29
- **THEN** 为聪明，不能以最后出现的数字覆盖明确答案。

#### Scenario: 数值精度
- **WHEN** JSON 回答为21.0000000000000001
- **THEN** 精确判定不等于21，标记降智，不经浮点舍入变成聪明。

#### Scenario: 格式或模型参数不支持
- **WHEN** 上游拒绝 strict 格式、模型或推理参数
- **THEN** 未知并记录原因，保留配置，不自动换模型/降深度/换协议重问。

### Requirement: 完整独立请求

系统 SHALL 不携带上一轮对话，只解析完整终结的最终回答；记录与实际请求使用同一配置快照。

#### Scenario: 流缺失或拒答
- **WHEN** 只有 delta、截断、读取错误、拒答或冲突终结事件
- **THEN** 未知；推理、commentary 和未完成文本中的21不参与判分。

### Requirement: 状态与配置变更

系统 SHALL 保留独立 IQ 限制，未知/聪明/关闭检测仅解除自己的限制；人工停用等仍有效。

#### Scenario: 只改间隔
- **WHEN** 降智账号的间隔从15分钟改为30分钟
- **THEN** 保持降智状态、revision 和有效任务；仅按最新间隔排下一次任务。

#### Scenario: 修改检测模型或深度
- **WHEN** 旧任务运行时保存新检测参数
- **THEN** 同事务更新 revision、状态未知并排队新配置，旧结果不能覆盖；同账号任务不重叠。

#### Scenario: 正常令牌刷新
- **WHEN** OAuth 正常轮换令牌
- **THEN** 不视为更换账号或检测参数，不取消有效结果。

#### Scenario: 工作者失联
- **WHEN** 租约过期且任务未完成
- **THEN** 原轮次为未知/中断，释放该轮质量限制并排新轮；与正常提交并发时保证唯一有效提交。

### Requirement: 两轮记录和可核查展示

系统 SHALL 至多保留每账号两轮数据，每轮显示实际请求模型/深度、判题版本、规范化答案和原因。

#### Scenario: 第三轮开始
- **WHEN** 新建第三轮记录，无论它之后成功、失败或取消
- **THEN** 在同一事务删除第一轮，只留最近两轮，正文不复制到通用日志/缓存。

#### Scenario: 旧版记录
- **WHEN** 展示升级前记录
- **THEN** 保留原始模型与题干版本，不伪装为新配置或新判分版本。
