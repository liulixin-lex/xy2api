# 分组质量门槛与兜底计费

运营现在靠手工维持“账号质量与分组倍率相匹配”：频繁地改账号所属分组、开关调度、恢复状态、手动测试。成员太少的分组曾因唯一的主力账号余额暂停而整组无号。

本变更做五件事：

1. **分组质量门槛**：每个 OpenAI 分组可开门槛。系统每分钟按账号级的实测错误率与续轮首字 p90 判定，不达标的账号在该组熔断，到时自动恢复。带保底、试用、固定账号，“恢复状态”时一并重置。
2. **排序**：开启低倍率优先时，按“快档 → 优先级 → 成本 → 负载 → 最近使用”选择，慢的便宜号不会卡住首字。粘性账号满载时，先借用空闲账号，不再排队。
3. **利润门**：成本改用与排序相同的实时倍率，开启时默认毛利率 20%，保存前预览能通过的成员数。
4. **兜底分组**：触发判定计入利润门与质量熔断。到了兜底组，按兜底组的规则选号，并改回按兜底组计费；权限与限额仍按原组。这取代 0.4.6 的“按原分组计价”。
5. **可用数**：分组可用账号数计入两道门，现有告警直接可用。

不做：零缓存门槛、分组级智商要求、按模型判定兜底、影子模式、观察期、自动改写成员关系、数据库迁移。设计见 [design.md](design.md)，任务见 [tasks.md](tasks.md)。
